# การดีบักในเบราว์เซอร์

ก่อนจะเขียนโค้ดที่ซับซ้อนขึ้น มาทำความรู้จักการดีบักกันก่อน

[การดีบัก](https://en.wikipedia.org/wiki/Debugging) คือการตามหาและแก้ข้อผิดพลาดในสคริปต์ เบราว์เซอร์สมัยใหม่ทุกตัวและสภาพแวดล้อมการทำงานส่วนใหญ่มีเครื่องมือดีบักมาให้ โดยอยู่ในหน้าจอเฉพาะของเครื่องมือนักพัฒนา เราจึงดูการทำงานของโค้ดทีละขั้นและตามได้ง่ายขึ้นว่าเกิดอะไรขึ้นตรงไหน

บทนี้จะใช้ Chrome เป็นตัวอย่าง เพราะมีเครื่องมือที่เราต้องใช้ครบ ส่วนเบราว์เซอร์อื่นก็มีขั้นตอนคล้ายกัน

## แผง "Sources"

Chrome แต่ละเวอร์ชันอาจมีหน้าตาต่างจากภาพเล็กน้อย แต่ส่วนประกอบหลักยังพอหาได้ไม่ยาก

- เปิด [หน้าตัวอย่าง](debugging/index.html) ใน Chrome
- กด `key:F12` เพื่อเปิดเครื่องมือนักพัฒนา (Mac: `key:Cmd+Opt+I`)
- เลือกแผง `Sources`

ถ้าเปิดเป็นครั้งแรก หน้าจอจะมีหน้าตาประมาณนี้:

![ตำแหน่งปุ่มเปิดรายการไฟล์ในแผง Sources](chrome-open-sources.svg)

ปุ่ม <span class="devtools" style="background-position:-172px -98px"></span> ใช้เปิดแท็บรายการไฟล์

ลองกดปุ่มนี้แล้วเลือก `hello.js` จากรายการแบบต้นไม้ หน้าจอจะออกมาประมาณนี้:

![แผง Sources แสดงรายการไฟล์ทางซ้าย ซอร์สโค้ดตรงกลาง และเครื่องมือดีบักทางขวา](chrome-tabs.svg)

แผง Sources แบ่งเป็น 3 ส่วน:

1. แท็บ **Page** แสดงไฟล์ HTML, JavaScript, CSS และไฟล์อื่นที่หน้าเว็บโหลดมา รวมถึงรูปภาพ ส่วนไฟล์จากส่วนขยาย Chrome ก็อาจแสดงตรงนี้ด้วย
2. ส่วน **Code Editor** แสดงซอร์สโค้ดของไฟล์ที่เลือก
3. ส่วน **Debugger** รวมเครื่องมือที่ใช้ดีบัก เดี๋ยวเราจะลองใช้กัน

ถ้าอยากเพิ่มพื้นที่ดูโค้ด กดปุ่ม <span class="devtools" style="background-position:-172px -122px"></span> อีกครั้งเพื่อซ่อนรายการไฟล์ได้

## Console

กด `key:Esc` แล้ว Console จะเปิดขึ้นมาด้านล่าง เราพิมพ์คำสั่งตรงนี้แล้วกด `key:Enter` เพื่อรันได้เลย

เมื่อคำสั่งทำงานเสร็จ ผลลัพธ์จะแสดงอยู่ใต้คำสั่งนั้น

ในภาพนี้ `1+2` ได้ผลลัพธ์เป็น `3` ส่วน `hello("debugger")` ไม่ได้กำหนดค่าที่จะคืน ผลลัพธ์จึงเป็น `undefined`:

![Console แสดงผลลัพธ์ 3 จาก 1 + 2 และ undefined จาก hello("debugger")](chrome-sources-console.svg)

## Breakpoints

คราวนี้มาดูว่าโค้ดใน [หน้าตัวอย่าง](debugging/index.html) ทำงานอย่างไร เปิดไฟล์ `hello.js` แล้วคลิกเลขบรรทัด `4` — คลิกที่ตัวเลข `4` โดยตรง ไม่ใช่ที่ตัวโค้ด

เท่านี้ก็ตั้ง breakpoint แรกได้แล้ว ลองตั้งอีกจุดด้วยการคลิกเลขบรรทัด `8`

หน้าจอควรออกมาประมาณนี้ โดยสีน้ำเงินคือตำแหน่งที่ต้องคลิก:

![Breakpoint ที่บรรทัด 4 และ 8 พร้อมรายการ Breakpoints ทางขวา](chrome-sources-breakpoint.svg)

*Breakpoint* คือตำแหน่งที่เรากำหนดให้ดีบักเกอร์หยุดการทำงานของ JavaScript โดยอัตโนมัติ

ระหว่างที่โค้ดหยุด เราตรวจค่าตัวแปรหรือรันคำสั่งใน Console ได้ จึงค่อย ๆ ไล่ดูได้ว่าปัญหาเกิดตรงไหน

รายการ breakpoint ทั้งหมดอยู่ในส่วน `Breakpoints` ของ Debugger ถ้าตั้งไว้หลายจุดในหลายไฟล์ รายการนี้ช่วยให้เรา:
- ไปยังโค้ดตรง breakpoint ได้ทันทีด้วยการคลิกรายการ
- ปิด breakpoint ชั่วคราวด้วยการเอาเครื่องหมายถูกออก
- ลบ breakpoint ด้วยการคลิกขวาแล้วเลือก Remove
- จัดการ breakpoint ด้วยวิธีอื่นอีกหลายแบบ

```smart header="Breakpoint แบบมีเงื่อนไข"
*คลิกขวา* ที่เลขบรรทัดเพื่อสร้าง breakpoint *แบบมีเงื่อนไข* ได้ ดีบักเกอร์จะหยุดตรงจุดนี้เฉพาะเมื่อนิพจน์ที่ใส่ไว้ตอนสร้างมีค่าเป็น truthy (JavaScript มองค่านั้นว่าเป็นจริง)

วิธีนี้เหมาะกับกรณีที่ต้องการหยุดเฉพาะเมื่อตัวแปรหรือพารามิเตอร์ของฟังก์ชันมีค่าตามเงื่อนไข
```

## คำสั่ง "debugger"

เราสั่งให้โค้ดหยุดจากในสคริปต์ได้โดยใส่คำสั่ง `debugger` ไว้ตรงตำแหน่งที่ต้องการ:

```js
function hello(name) {
  let phrase = `Hello, ${name}!`;

*!*
  debugger;  // <-- ดีบักเกอร์จะหยุดตรงนี้
*/!*

  say(phrase);
}
```

คำสั่งนี้มีผลเมื่อเปิดเครื่องมือนักพัฒนาอยู่เท่านั้น ถ้าไม่ได้เปิด เบราว์เซอร์จะข้ามคำสั่งนี้ไป

## หยุดแล้วสำรวจสถานะของโค้ด

ตัวอย่างนี้เรียก `hello()` ระหว่างโหลดหน้า หลังตั้ง breakpoint แล้ว วิธีเริ่มดีบักที่ง่ายที่สุดจึงเป็นการโหลดหน้าใหม่ด้วย `key:F5` (Windows, Linux) หรือ `key:Cmd+R` (Mac)

เมื่อโค้ดทำงานมาถึง breakpoint ดีบักเกอร์จะหยุดที่บรรทัด 4:

![ดีบักเกอร์หยุดที่บรรทัด 4 และแสดง Watch, Call Stack และ Scope ทางขวา](chrome-sources-debugger-pause.svg)

ลองเปิดส่วนข้อมูลใน Debugger ที่ลูกศรในภาพชี้ไว้ แต่ละส่วนช่วยให้เราตรวจสถานะของโค้ดขณะนั้นได้:

1. **`Watch` — แสดงค่าปัจจุบันของนิพจน์ที่ต้องการติดตาม**

    กดเครื่องหมายบวก `+` แล้วใส่นิพจน์ ดีบักเกอร์จะแสดงค่าของมัน และคำนวณค่าใหม่ให้อัตโนมัติขณะที่โค้ดทำงานต่อ

2. **`Call Stack` — แสดงลำดับการเรียกฟังก์ชันที่ซ้อนกันอยู่**

    ตอนนี้ดีบักเกอร์หยุดอยู่ใน `hello()` ซึ่งสคริปต์ใน `index.html` เป็นผู้เรียก เนื่องจากสคริปต์ส่วนนั้นไม่ได้อยู่ในฟังก์ชัน จึงแสดงชื่อว่า "anonymous"

    ถ้าคลิกรายการใน `Call Stack` เช่น "anonymous" ดีบักเกอร์จะพาไปยังโค้ดที่เกี่ยวข้อง และเราจะตรวจตัวแปรของโค้ดส่วนนั้นได้
3. **`Scope` — แสดงตัวแปรที่เข้าถึงได้จากจุดปัจจุบัน**

    `Local` แสดงตัวแปรภายในฟังก์ชัน ค่าของตัวแปรเหล่านี้ยังแสดงกำกับอยู่บนซอร์สโค้ดด้วย

    `Global` แสดงตัวแปรระดับ global ซึ่งประกาศอยู่นอกฟังก์ชัน

    ในส่วนนี้ยังมีคีย์เวิร์ด `this` ซึ่งเรายังไม่ได้เรียน แต่จะได้เจอกันในบทถัด ๆ ไป

## ไล่การทำงานของโค้ดทีละขั้น

เมื่อโค้ดหยุดแล้ว เรา *ไล่ดู* การทำงานของสคริปต์ทีละขั้นได้

ปุ่มที่ใช้ควบคุมอยู่ด้านบนของ Debugger ลองดูทีละปุ่มกัน
<!-- https://github.com/ChromeDevTools/devtools-frontend/blob/master/front_end/Images/src/largeIcons.svg -->
<span class="devtools" style="background-position:-146px -168px"></span> — "Resume": ทำงานต่อ, ปุ่มลัด `key:F8`
: ให้โค้ดทำงานต่อ ถ้าไม่มี breakpoint จุดอื่น โค้ดจะทำงานจนจบโดยไม่หยุดอีก

    เมื่อกดปุ่มนี้ เราจะเห็นผลดังภาพ:

    ![ดีบักเกอร์หยุดในฟังก์ชัน say ที่บรรทัด 8 และ Call Stack มี say, hello และ anonymous](chrome-sources-debugger-trace-1.svg)

    โค้ดทำงานต่อจนถึง breakpoint อีกจุดใน `say()` แล้วหยุด ลองดู `Call Stack` จะเห็นว่ามีรายการเพิ่มขึ้นอีกหนึ่งชั้น เพราะตอนนี้เราอยู่ข้างใน `say()`

<span class="devtools" style="background-position:-62px -192px"></span> — "Step over": รันคำสั่งถัดไปแต่ *ไม่เข้าไปในฟังก์ชัน*, ปุ่มลัด `key:F10`
: ถ้าคำสั่งถัดไปเรียกฟังก์ชัน ปุ่มนี้จะรันฟังก์ชันนั้นจนจบโดยไม่พาเราเข้าไปดูข้างใน ไม่ว่าจะเป็นฟังก์ชันที่เราเขียนเองหรือฟังก์ชันที่ JavaScript มีมาให้แล้วอย่าง `alert`

    เมื่อฟังก์ชันทำงานเสร็จ ดีบักเกอร์จะหยุดที่บรรทัดถัดจากคำสั่งเรียกฟังก์ชัน

    ใช้ปุ่มนี้เมื่อเราไม่จำเป็นต้องดูว่าข้างในฟังก์ชันทำงานอย่างไร

<span class="devtools" style="background-position:-4px -194px"></span> — "Step into", ปุ่มลัด `key:F11`
: รันคำสั่งปัจจุบัน ถ้าคำสั่งนั้นเรียกฟังก์ชันที่เข้าไปดูได้ ดีบักเกอร์จะหยุดที่บรรทัดแรกของฟังก์ชันนั้น ใช้ปุ่มนี้เมื่อต้องการไล่ดูว่าข้างในฟังก์ชันทำงานอย่างไร

<span class="devtools" style="background-position:-32px -194px"></span> — "Step out": ทำงานต่อจนจบฟังก์ชันปัจจุบัน, ปุ่มลัด `key:Shift+F11`
: รันโค้ดที่เหลือในฟังก์ชันปัจจุบันให้จบ แล้วกลับไปหยุดที่บรรทัดถัดจากจุดที่เรียกฟังก์ชันนั้น ปุ่มนี้ช่วยได้เมื่อเผลอกด "Step into" เข้าไปในฟังก์ชันที่ไม่เกี่ยวกับปัญหา แล้วอยากออกไปให้เร็วที่สุด

<span class="devtools" style="background-position:-61px -74px"></span> — เปิดหรือปิด breakpoint ทั้งหมด
: ปุ่มนี้ไม่ทำให้โค้ดเดินหน้าต่อ แต่ใช้เปิดหรือปิด breakpoint ทุกจุดพร้อมกัน

<span class="devtools" style="background-position:-90px -146px"></span> — ตั้งค่าการหยุดอัตโนมัติเมื่อเกิด exception (ข้อผิดพลาดที่โค้ด `throw` ขึ้นมา)
: เลือก `Pause on uncaught exceptions` เพื่อหยุดเมื่อเกิด exception ที่ไม่มีโค้ดจัดการ ถ้าต้องการหยุด exception ที่ `try/catch` จัดการไว้ด้วย ให้เลือก `Pause on caught exceptions` เพิ่ม เมื่อดีบักเกอร์หยุด เราจะตรวจตัวแปรและสถานะของโค้ดตรงจุดนั้นได้

```smart header="ไปต่อจนถึงบรรทัดนี้ (Continue to here)"
คลิกขวาที่บรรทัดโค้ดเพื่อเปิดเมนู แล้วเลือก "Continue to here" ได้

คำสั่งนี้เหมาะกับเวลาที่ต้องการข้ามโค้ดหลายขั้นไปยังบรรทัดหนึ่งโดยไม่ต้องตั้ง breakpoint เพิ่ม
```

## การบันทึก log

ถ้าต้องการส่งข้อมูลจากโค้ดไปแสดงใน Console ใช้เมธอด `console.log` ได้

ตัวอย่างนี้จะแสดงค่าตั้งแต่ `0` ถึง `4` ใน Console:

```js run
// เปิด Console เพื่อดูผลลัพธ์
for (let i = 0; i < 5; i++) {
  console.log("value,", i);
}
```

ผู้ใช้ทั่วไปจะไม่เห็นข้อมูลนี้ เพราะผลลัพธ์อยู่ใน Console ถ้าอยากดู ให้เปิดแผง Console ในเครื่องมือนักพัฒนา หรือกด `key:Esc` ขณะอยู่ในแผงอื่นเพื่อเปิด Console ไว้ด้านล่าง

ถ้าใส่ log ไว้ตามจุดสำคัญ เราก็ตามได้จากข้อมูลเหล่านั้นว่าเกิดอะไรขึ้น โดยไม่ต้องใช้ดีบักเกอร์

## สรุป

เราหยุดสคริปต์เพื่อดีบักได้ 3 วิธีหลัก:
1. ตั้ง breakpoint
2. ใช้คำสั่ง `debugger`
3. เปิด `Pause on uncaught exceptions` หรือ `Pause on caught exceptions` ในส่วน `Breakpoints` เพื่อให้หยุดเมื่อเกิด exception

เมื่อโค้ดหยุด เราตรวจค่าตัวแปรและไล่เส้นทางการทำงานเพื่อหาจุดที่ผิดพลาดได้

เครื่องมือนักพัฒนายังทำอะไรได้อีกมาก คู่มือฉบับเต็มอยู่ที่ <https://developer.chrome.com/docs/devtools/>

เนื้อหาในบทนี้เพียงพอสำหรับเริ่มดีบักแล้ว ถ้าต้องทำงานกับเบราว์เซอร์บ่อย ค่อยไปศึกษาความสามารถขั้นสูงจากคู่มือเพิ่มเติม

อีกวิธีที่ช่วยให้คุ้นกับเครื่องมือเร็วขึ้นคือลองคลิกส่วนต่าง ๆ แล้วดูว่าเกิดอะไรขึ้น อย่าลืมลองคลิกขวาเพื่อสำรวจคำสั่งในเมนูด้วย
