# Polyfills และ Transpilers

JavaScript มีความสามารถใหม่เพิ่มเข้ามาเรื่อยๆ ข้อเสนอแต่ละอย่างต้องผ่านการวิเคราะห์และพิจารณาก่อน เมื่อเห็นว่าควรเพิ่มเข้ามาในภาษา จึงค่อยๆ เข้าไปอยู่ในเอกสารที่ <https://tc39.github.io/ecma262/> และกลายเป็นส่วนหนึ่งของ[ข้อกำหนด](https://www.ecma-international.org/publications-and-standards/standards/ecma-262/)

แต่การมีฟีเจอร์อยู่ในข้อกำหนด ไม่ได้ทำให้เอนจิ้น JavaScript ทุกตัวรองรับพร้อมกัน แต่ละทีมเลือกเองว่าจะพัฒนาฟีเจอร์ไหนก่อน บางครั้งจึงอาจรองรับข้อเสนอที่ยังเป็นฉบับร่าง ขณะที่ฟีเจอร์ในข้อกำหนดบางอย่างต้องรอต่อไป เพราะทำยากกว่าหรือมีลำดับความสำคัญต่ำกว่า

ช่วงหนึ่งๆ เอนจิ้นจึงอาจรองรับมาตรฐานได้เพียงบางส่วน

ถ้าอยากรู้ว่าเอนจิ้นแต่ละตัวรองรับฟีเจอร์ไหนแล้วบ้าง ลองดูตารางที่ <https://compat-table.github.io/compat-table/es6/> ตารางนี้ยาวทีเดียว เพราะ JavaScript ยังมีเรื่องให้เราเรียนรู้อีกเยอะ

ฝั่งคนเขียนโปรแกรมก็ย่อมอยากใช้ฟีเจอร์ใหม่ๆ เพราะหลายอย่างช่วยให้เขียนโค้ดได้สะดวกขึ้น

ปัญหาคือผู้ใช้อาจเปิดเว็บด้วยเอนจิ้นรุ่นเก่าที่ไม่รู้จักฟีเจอร์เหล่านั้น แล้วเราจะทำให้โค้ดสมัยใหม่ทำงานบนเอนจิ้นแบบนี้ได้อย่างไร?

เครื่องมือสองประเภทช่วยปิดช่องว่างนี้ได้:

1. Transpilers
2. Polyfills

บทนี้จะพาไปดูว่าเครื่องมือแต่ละประเภทแก้ปัญหาคนละแบบอย่างไร และควรหยิบตัวไหนมาใช้เมื่อไร

## Transpilers

เอนจิ้นรุ่นเก่าอาจติดปัญหาตั้งแต่ตอนอ่านโค้ด หากเจอไวยากรณ์ที่ไม่รู้จัก มันก็รันโค้ดต่อไม่ได้

[Transpiler](https://en.wikipedia.org/wiki/Source-to-source_compiler) แก้ปัญหานี้ด้วยการอ่านซอร์สโค้ดสมัยใหม่ แล้วเขียนออกมาเป็นซอร์สโค้ดอีกชุดที่ใช้ไวยากรณ์เก่ากว่า แต่ยังทำงานตามเจตนาเดิม

ตัวอย่างเช่น ก่อนที่ตัวดำเนินการ nullish coalescing `??` จะกลายเป็นส่วนหนึ่งของ ECMAScript 2020 เอนจิ้นรุ่นเก่าบางตัวอาจไม่รู้จักโค้ดอย่าง `height = height ?? 100` ส่วน transpiler จะแปลง `height ?? 100` เป็น `(height !== undefined && height !== null) ? height : 100` แทน

```js
// ก่อนรัน transpiler
height = height ?? 100;

// หลังรัน transpiler  
height = (height !== undefined && height !== null) ? height : 100;
```

โค้ดที่แปลงแล้วไม่เหลือไวยากรณ์ `??` เอนจิ้นรุ่นเก่าจึงอ่านและรันได้

โดยทั่วไปเราจะรัน transpiler ระหว่างขั้นตอน build แล้วนำโค้ดที่แปลงเสร็จไปไว้บนเซิร์ฟเวอร์ ผู้ใช้จึงได้รับโค้ดที่เหมาะกับเอนจิ้นเป้าหมายตั้งแต่แรก

[Babel](https://babeljs.io) เป็นเครื่องมือที่ใช้ทำงานลักษณะนี้

ระบบ build อย่าง [webpack](https://webpack.js.org/) ตั้งค่าให้เรียก transpiler ทุกครั้งที่โค้ดเปลี่ยนได้ เราจึงรวมการแปลงโค้ดไว้ในขั้นตอนพัฒนาได้โดยไม่ต้องสั่งเองทีละครั้ง

## Polyfills

ฟีเจอร์ใหม่ไม่ได้มีแค่ไวยากรณ์หรือตัวดำเนินการ บางฟีเจอร์เป็นฟังก์ชันในตัวที่เอนจิ้นรุ่นเก่าไม่มี

เช่น `Math.trunc(n)` ใช้ตัดส่วนทศนิยมของตัวเลขออก ดังนั้น `Math.trunc(1.23)` จึงคืนค่า `1`

ถ้าเอนจิ้นไม่มี `Math.trunc` ต่อให้อ่านไวยากรณ์ของโค้ดได้ ก็เรียกฟังก์ชันนี้ไม่ได้อยู่ดี

กรณีนี้ไม่จำเป็นต้องเขียนโค้ดใหม่ด้วย transpiler เพราะไวยากรณ์ไม่ได้เป็นปัญหา เราแค่ต้องเพิ่มฟังก์ชันที่ขาดไปก่อนเรียกใช้

สคริปต์ที่เพิ่มหรือปรับฟังก์ชันให้เอนจิ้นมีความสามารถตามที่ต้องการเรียกว่า "polyfill" พูดง่ายๆ คือเติมส่วนที่เอนจิ้นขาดให้ครบ

polyfill สำหรับ `Math.trunc` เขียนได้แบบนี้:

```js
if (!Math.trunc) { // ถ้าไม่มีฟังก์ชันนี้
  // ก็เขียนขึ้นมาเอง
  Math.trunc = function(number) {
    // Math.ceil และ Math.floor มีอยู่แม้ในเอนจิ้น JavaScript โบราณ
    // จะอธิบายเพิ่มเติมในบทถัดๆ ไป
    return number < 0 ? Math.ceil(number) : Math.floor(number);
  };
}
```

เงื่อนไขบรรทัดแรกทำให้เราเพิ่มฟังก์ชันเฉพาะตอนที่เอนจิ้นไม่มี `Math.trunc` อยู่แล้ว เมื่อเรียกใช้ภายหลัง โค้ดส่วนที่เหลือจึงไม่ต้องสนใจว่าเอนจิ้นมีฟังก์ชันนี้มาให้เองหรือได้มาจาก polyfill

JavaScript เปิดให้สคริปต์เพิ่มหรือแก้ไขฟังก์ชันได้ แม้แต่ฟังก์ชันในตัว เราจึงสร้าง polyfill ด้วยวิธีนี้ได้

ไลบรารี polyfill ที่น่าสนใจ เช่น:
- [core-js](https://github.com/zloirock/core-js) รองรับฟีเจอร์จำนวนมาก และเลือกใช้เฉพาะที่ต้องการได้
- บริการ [polyfill.io](https://polyfill.io/) สร้างสคริปต์พร้อม polyfill ให้ตามฟีเจอร์และเบราว์เซอร์ของผู้ใช้

## สรุป

เราเรียนรู้ฟีเจอร์ภาษาใหม่ๆ รวมถึงฟีเจอร์ที่อยู่ระหว่างพัฒนาได้ โดยไม่ต้องรอให้ทุกเอนจิ้นรองรับพร้อมกัน

หลักเลือกใช้จำง่ายๆ ถ้าเอนจิ้นไม่รู้จักไวยากรณ์หรือตัวดำเนินการใหม่ ให้ใช้ transpiler แปลงโค้ด ส่วนฟังก์ชันในตัวที่เอนจิ้นไม่มีให้เติมด้วย polyfill โค้ดชุดเดียวกันอาจต้องใช้เครื่องมือทั้งสองประเภท

เมื่อคุ้นเคยกับ JavaScript มากขึ้นแล้ว ลองตั้งค่าระบบ build ด้วย [webpack](https://webpack.js.org/) และปลั๊กอิน [babel-loader](https://github.com/babel/babel-loader) เพื่อให้ขั้นตอน transpile ทำงานอัตโนมัติได้

แหล่งข้อมูลดีๆ ที่แสดงสถานะการรองรับฟีเจอร์ต่างๆ ได้แก่:
- <https://compat-table.github.io/compat-table/es6/> — สำหรับ JavaScript แท้ๆ
- <https://caniuse.com/> — สำหรับฟีเจอร์ที่เกี่ยวข้องกับเบราว์เซอร์

ป.ล. ถ้าเดโมในบทเรียนไม่ทำงาน ให้เช็กก่อนว่าเบราว์เซอร์รองรับฟีเจอร์ที่ใช้หรือไม่ เดโมส่วนใหญ่ทำงานได้กับเบราว์เซอร์สมัยใหม่
