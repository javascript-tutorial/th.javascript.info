# Optional chaining '?.'

[recent browser="new"]

Optional chaining `?.` ช่วยให้เราเข้าถึงพร็อพเพอร์ตี้ที่ซ้อนกันอยู่ในออบเจ็กต์ได้อย่างปลอดภัย แม้พร็อพเพอร์ตี้บางตัวระหว่างทางจะไม่มีอยู่ก็ตาม

## ปัญหาเมื่อพร็อพเพอร์ตี้ไม่มีอยู่

ถ้าเพิ่งเริ่มเรียน JavaScript เราอาจยังไม่เคยเจอปัญหานี้ แต่ในการใช้งานจริงพบได้บ่อยทีเดียว

สมมติว่าเรามีออบเจ็กต์ `user` สำหรับเก็บข้อมูลผู้ใช้

ผู้ใช้ส่วนใหญ่มีที่อยู่ในพร็อพเพอร์ตี้ `user.address` และมีชื่อถนนอยู่ใน `user.address.street` แต่ผู้ใช้บางคนไม่ได้กรอกที่อยู่ไว้

ถ้าเราอ่าน `user.address.street` ของผู้ใช้ที่ไม่มีที่อยู่ โปรแกรมจะเกิด error:

```js run
let user = {}; // ผู้ใช้ที่ไม่มีพร็อพเพอร์ตี้ "address"

alert(user.address.street); // Error!
```

ผลลัพธ์นี้เป็นพฤติกรรมปกติของ JavaScript เพราะ `user.address` มีค่าเป็น `undefined` การอ่าน `user.address.street` จึงเกิด error

แต่ในหลายกรณี เราอยากได้ `undefined` ซึ่งสื่อว่า "ไม่มีชื่อถนน" มากกว่าจะให้โปรแกรมเกิด error

ลองดูอีกตัวอย่างหนึ่ง ในการพัฒนาเว็บ เราเรียกเมธอด `document.querySelector('.elem')` เพื่อหาออบเจ็กต์ที่ตรงกับ element บนหน้าเว็บ ถ้าไม่พบ element นั้น เมธอดจะคืนค่า `null`

```js run
// document.querySelector('.elem') เป็น null ถ้าไม่พบ element
let html = document.querySelector('.elem').innerHTML; // เกิด error ถ้าค่าเป็น null
```

เมื่อ element ไม่มีอยู่ การอ่านพร็อพเพอร์ตี้ `.innerHTML` จาก `null` ก็จะเกิด error เช่นกัน แต่ถ้าการไม่มี element เป็นเรื่องปกติ เราอาจอยากข้าม error แล้วให้ผลลัพธ์เป็น `html = null` แทน

เราจะทำแบบนั้นได้อย่างไร?

วิธีตรงไปตรงมาคือใช้ `if` หรือตัวดำเนินการแบบมีเงื่อนไข `?` ตรวจค่าก่อนเข้าถึงพร็อพเพอร์ตี้:

```js
let user = {};

alert(user.address ? user.address.street : undefined);
```

วิธีนี้ใช้ได้และไม่เกิด error แต่โค้ดยังเยิ่นเย้อ เพราะต้องเขียน `user.address` ซ้ำสองครั้ง

ถ้าใช้วิธีเดียวกันกับ `document.querySelector` จะได้แบบนี้:

```js run
let html = document.querySelector('.elem') ? document.querySelector('.elem').innerHTML : null;
```

โค้ดนี้เขียน `document.querySelector('.elem')` ซ้ำสองจุด ถ้าค้นหาครั้งแรกเจอ element ก็จะเรียกเมธอดเดิมซ้ำอีกครั้งโดยไม่จำเป็น

ถ้าพร็อพเพอร์ตี้ซ้อนกันลึกกว่านี้ โค้ดก็ยิ่งอ่านยากและต้องเขียนส่วนเดิมซ้ำมากขึ้น

ลองใช้วิธีเดียวกันเพื่ออ่าน `user.address.street.name`:

```js
let user = {}; // ผู้ใช้ไม่มีที่อยู่

alert(user.address ? user.address.street ? user.address.street.name : null : null);
```

แค่ไล่อ่านว่าแต่ละ `?` คู่กับ `:` ตัวไหนก็ชวนสับสนแล้ว

เราย่อโค้ดลงได้เล็กน้อยด้วยตัวดำเนินการ `&&`:

```js run
let user = {}; // ผู้ใช้ไม่มีที่อยู่

alert( user.address && user.address.street && user.address.street.name ); // undefined (ไม่เกิด error)
```

การใช้ AND เช็กตลอดเส้นทางช่วยยืนยันว่าทุกส่วนมีอยู่ ถ้าส่วนไหนไม่มี การประเมินผลจะหยุดตรงนั้น แต่โค้ดก็ยังไม่กระชับเท่าที่ควร

เรายังต้องเขียนชื่อพร็อพเพอร์ตี้ซ้ำอยู่ดี เช่น โค้ดข้างบนมี `user.address` ถึงสามจุด

ภาษา JavaScript จึงเพิ่ม optional chaining `?.` เข้ามาเพื่อแก้ปัญหานี้

## Optional chaining

Optional chaining `?.` จะหยุดประเมินผลเมื่อค่าที่อยู่ข้างหน้า `?.` เป็น `undefined` หรือ `null` แล้วคืนค่า `undefined`

**เพื่อให้เนื้อหากระชับ ต่อจากนี้เราจะบอกว่าค่า "มีอยู่" เมื่อค่านั้นไม่ใช่ทั้ง `null` และ `undefined`**

พูดอีกแบบคือ `value?.prop` ทำงานดังนี้:

- ทำงานเหมือน `value.prop` เมื่อ `value` มีอยู่
- คืนค่า `undefined` เมื่อ `value` เป็น `undefined` หรือ `null`

ทีนี้เราก็เข้าถึง `user.address.street` อย่างปลอดภัยด้วย `?.` ได้:

```js run
let user = {}; // ผู้ใช้ไม่มีที่อยู่

alert( user?.address?.street ); // undefined (ไม่เกิด error)
```

โค้ดสั้นลง อ่านง่าย และไม่ต้องเขียนส่วนเดิมซ้ำ

ตัวอย่างที่ใช้กับ `document.querySelector` เขียนได้แบบนี้:

```js run
let html = document.querySelector('.elem')?.innerHTML; // เป็น undefined ถ้าไม่พบ element
```

แม้ตัวออบเจ็กต์ `user` เองจะไม่มีอยู่ เราก็ยังอ่าน `user?.address` ได้:

```js run
let user = null;

alert( user?.address ); // undefined
alert( user?.address.street ); // undefined
```

สังเกตว่า `?.` จะตรวจเฉพาะค่าที่อยู่ข้างหน้าตัวมัน ไม่ได้ทำให้พร็อพเพอร์ตี้ถัดไปเป็น optional ตามไปด้วย

ตัวอย่างเช่น ใน `user?.address.street.name` ถ้า `user` เป็น `null` หรือ `undefined` นิพจน์จะคืนค่า `undefined` โดยไม่เกิด error แต่ถ้า `user` มีอยู่ JavaScript จะเข้าถึงส่วน `.address.street.name` ตามปกติ ถ้าพร็อพเพอร์ตี้ใดอาจไม่มีอยู่ด้วย ก็ต้องเปลี่ยน `.` ตรงจุดนั้นเป็น `?.`

```warn header="อย่าใช้ optional chaining มากเกินไป"
เราควรใช้ `?.` เฉพาะจุดที่ตรรกะของโปรแกรมยอมรับได้ว่าค่าบางอย่างอาจไม่มีอยู่

ตัวอย่างเช่น ถ้าตามตรรกะแล้วออบเจ็กต์ `user` ต้องมีอยู่เสมอ แต่ `address` จะมีหรือไม่มีก็ได้ เราควรเขียน `user.address?.street` แทน `user?.address?.street`

ถ้า `user` กลายเป็น `undefined` เราจะได้เห็น error และแก้ข้อผิดพลาดนั้น แต่การใส่ `?.` มากเกินไปอาจซ่อนข้อผิดพลาดในจุดที่ควรเกิด error ทำให้ตามหาและแก้ไขได้ยากขึ้น
```

````warn header="ตัวแปรที่อยู่หน้า `?.` ต้องประกาศไว้แล้ว"
ถ้าไม่มีการประกาศตัวแปร `user` เลย การเขียน `user?.anything` จะเกิด error:

```js run
// ReferenceError: user is not defined
user?.address;
```
ตัวแปรต้องประกาศไว้ก่อน เช่น ประกาศ `user` ด้วย `let`, `const` หรือ `var` หรือรับ `user` มาเป็นพารามิเตอร์ของฟังก์ชัน เพราะ optional chaining ใช้ได้เฉพาะกับตัวแปรที่ประกาศไว้แล้วเท่านั้น
````

## การประเมินผลแบบ short-circuit

`?.` จะหยุดประเมินผลทันทีเมื่อค่าทางซ้ายไม่มีอยู่ พฤติกรรมนี้เรียกว่า short-circuit

ดังนั้น ถ้าในนิพจน์เดียวกันยังมีการเรียกฟังก์ชันหรือการคำนวณต่ออยู่ทางขวาของ `?.` JavaScript จะไม่ประเมินส่วนเหล่านั้น

ตัวอย่างเช่น:

```js run
let user = null;
let x = 0;

user?.sayHi(x++); // user เป็น null จึงไม่เรียก sayHi และ x++

alert(x); // 0 เพราะค่าไม่เพิ่มขึ้น
```

## รูปแบบอื่น: ?.() และ ?.[]

Optional chaining `?.` ไม่ใช่ตัวดำเนินการ แต่เป็นโครงสร้างไวยากรณ์พิเศษที่ใช้กับฟังก์ชันและวงเล็บเหลี่ยมได้ด้วย

เช่น เราใช้ `?.()` เรียกฟังก์ชันที่อาจไม่มีอยู่

ในโค้ดต่อไปนี้ ผู้ใช้บางคนมีเมธอด `admin` ส่วนบางคนไม่มี:

```js run
let userAdmin = {
  admin() {
    alert("I am admin");
  }
};

let userGuest = {};

*!*
userAdmin.admin?.(); // แสดง I am admin
*/!*

*!*
userGuest.admin?.(); // ไม่มีอะไรเกิดขึ้น เพราะไม่มีเมธอดนี้
*/!*
```

ทั้งสองบรรทัดใช้จุดอ่านพร็อพเพอร์ตี้ `admin` ก่อน (`userAdmin.admin` และ `userGuest.admin`) เพราะเราถือว่าออบเจ็กต์ผู้ใช้มีอยู่ จึงอ่านพร็อพเพอร์ตี้นี้ได้อย่างปลอดภัย

จากนั้น `?.()` จะตรวจค่าทางซ้าย กรณี `userAdmin` มีฟังก์ชัน `admin` จึงเรียกฟังก์ชันนั้น ส่วน `userGuest` ไม่มีฟังก์ชันนี้ การประเมินผลจึงหยุดโดยไม่เกิด error

ถ้าต้องการเข้าถึงพร็อพเพอร์ตี้ด้วยวงเล็บเหลี่ยม `[]` แทนจุด `.` ก็ใช้รูปแบบ `?.[]` ได้ รูปแบบนี้ช่วยให้อ่านพร็อพเพอร์ตี้จากออบเจ็กต์ที่อาจไม่มีอยู่ได้อย่างปลอดภัยเช่นเดียวกัน

```js run
let key = "firstName";

let user1 = {
  firstName: "John"
};

let user2 = null;

alert( user1?.[key] ); // John
alert( user2?.[key] ); // undefined
```

เรายังใช้ `?.` ร่วมกับ `delete` ได้:

```js run
delete user?.name; // ลบ user.name ถ้า user มีอยู่
```

````warn header="ใช้ `?.` อ่านและลบได้ แต่ใช้เขียนค่าไม่ได้"
Optional chaining `?.` ใช้ทางซ้ายของการกำหนดค่าไม่ได้

ตัวอย่างเช่น:
```js run
let user = null;

user?.name = "John"; // Error เพราะใช้แบบนี้ไม่ได้
// เพราะนิพจน์นี้จะกลายเป็น: undefined = "John"
```

````

## สรุป

Optional chaining `?.` มีสามรูปแบบ:

1. `obj?.prop` — คืนค่า `obj.prop` ถ้า `obj` มีอยู่ ไม่อย่างนั้นจะคืนค่า `undefined`
2. `obj?.[prop]` — คืนค่า `obj[prop]` ถ้า `obj` มีอยู่ ไม่อย่างนั้นจะคืนค่า `undefined`
3. `obj.method?.()` — เรียก `obj.method()` ถ้า `obj.method` มีอยู่ ไม่อย่างนั้นจะคืนค่า `undefined`

ทั้งสามรูปแบบใช้ไม่ยาก `?.` จะตรวจว่าค่าทางซ้ายเป็น `null` หรือ `undefined` หรือไม่ ถ้าไม่ใช่ JavaScript ก็จะประเมินผลต่อไปตามปกติ

เราต่อ `?.` หลายตัวเพื่อเข้าถึงพร็อพเพอร์ตี้ที่ซ้อนกันได้อย่างปลอดภัย

อย่างไรก็ตาม ควรใช้ `?.` เฉพาะจุดที่ตรรกะของโปรแกรมยอมรับได้ว่าค่าทางซ้ายอาจไม่มีอยู่ เพื่อไม่ให้ optional chaining ซ่อนข้อผิดพลาดที่เราควรเห็น
