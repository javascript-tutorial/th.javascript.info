# เมธอดของออบเจ็กต์และ "this"

โดยปกติเราสร้างออบเจ็กต์ขึ้นมาแทนสิ่งต่าง ๆ ในโลกจริง เช่น ผู้ใช้หรือคำสั่งซื้อ:

```js
let user = {
  name: "John",
  age: 30
};
```

ผู้ใช้ไม่ได้มีแค่ข้อมูล แต่ยัง *ทำ* สิ่งต่าง ๆ ได้ด้วย เช่น เลือกสินค้าในตะกร้า เข้าสู่ระบบ หรือออกจากระบบ

ใน JavaScript เราแทนการกระทำเหล่านี้ด้วยฟังก์ชันที่เก็บอยู่ในพร็อพเพอร์ตี้ของออบเจ็กต์

## ตัวอย่างเมธอด

เริ่มจากทำให้ออบเจ็กต์ `user` ทักทายได้:

```js run
let user = {
  name: "John",
  age: 30
};

*!*
user.sayHi = function() {
  alert("Hello!");
};
*/!*

user.sayHi(); // Hello!
```

ตรงนี้เราใช้นิพจน์ฟังก์ชัน (Function Expression) สร้างฟังก์ชัน แล้วนำไปเก็บไว้ในพร็อพเพอร์ตี้ `user.sayHi`

จากนั้นเรียกฟังก์ชันด้วย `user.sayHi()` เท่านี้ออบเจ็กต์ `user` ก็ทักทายได้แล้ว

ฟังก์ชันที่เป็นพร็อพเพอร์ตี้ของออบเจ็กต์เรียกว่า *เมธอด*

ในตัวอย่างนี้ เราจึงมีเมธอด `sayHi` ของออบเจ็กต์ `user`

จะนำฟังก์ชันที่ประกาศไว้ก่อนหน้ามาใช้เป็นเมธอดก็ได้:

```js run
let user = {
  // ...
};

*!*
// ประกาศฟังก์ชันก่อน
function sayHi() {
  alert("Hello!");
}

// จากนั้นเพิ่มเป็นเมธอด
user.sayHi = sayHi;
*/!*

user.sayHi(); // Hello!
```

```smart header="การเขียนโปรแกรมเชิงวัตถุ"
การเขียนโค้ดโดยใช้ออบเจ็กต์แทนสิ่งต่าง ๆ เรียกว่า [การเขียนโปรแกรมเชิงวัตถุ](https://en.wikipedia.org/wiki/Object-oriented_programming) หรือเรียกสั้น ๆ ว่า "OOP"

OOP เป็นเรื่องใหญ่ที่มีรายละเอียดให้ศึกษาอีกมาก เราต้องตัดสินใจว่าจะใช้ออบเจ็กต์อะไร และให้ออบเจ็กต์เหล่านั้นทำงานร่วมกันอย่างไร เรื่องเหล่านี้เป็นส่วนหนึ่งของการออกแบบสถาปัตยกรรม หนังสือที่อธิบายเรื่องนี้โดยตรงมีหลายเล่ม เช่น "Design Patterns: Elements of Reusable Object-Oriented Software" โดย E. Gamma, R. Helm, R. Johnson, J. Vissides และ "Object-Oriented Analysis and Design with Applications" โดย G. Booch
```

### เมธอดแบบย่อ

เวลาเขียนออบเจ็กต์ด้วย `{...}` หรือที่เรียกว่า object literal เราเขียนเมธอดแบบสั้นได้:

```js
// ออบเจ็กต์เหล่านี้ทำงานเหมือนกัน

user = {
  sayHi: function() {
    alert("Hello");
  }
};

// เมธอดแบบย่อดูดีกว่า
user = {
*!*
  sayHi() { // เหมือนกับ "sayHi: function(){...}"
*/!*
    alert("Hello");
  }
};
```

เราไม่ต้องเขียน `"function"` เหลือเพียงชื่อเมธอด `sayHi()` ตามด้วยโค้ดของเมธอด

สองรูปแบบนี้ไม่ได้เหมือนกันทุกอย่าง ยังมีความต่างเล็กน้อยเรื่องการสืบทอดของออบเจ็กต์ ซึ่งจะได้เรียนกันภายหลัง แต่ความต่างนั้นยังไม่สำคัญในตอนนี้ แทบทุกกรณีจึงนิยมใช้รูปแบบสั้น

## "this" ในเมธอด

เมธอดมักต้องใช้ข้อมูลที่เก็บอยู่ในออบเจ็กต์เพื่อทำงาน

เช่น โค้ดภายใน `user.sayHi()` อาจต้องใช้ชื่อของ `user`

**เมธอดใช้คีย์เวิร์ด `this` อ้างถึงออบเจ็กต์ได้**

เมื่อเรียกเมธอดแบบ `object.method()` ค่า `this` คือออบเจ็กต์ที่อยู่ "หน้าจุด" หรือออบเจ็กต์ที่ใช้เรียกเมธอดนั่นเอง

ลองดูตัวอย่าง:

```js run
let user = {
  name: "John",
  age: 30,

  sayHi() {
*!*
    // "this" คือออบเจ็กต์ที่เรียกเมธอด
    alert(this.name);
*/!*
  }

};

user.sayHi(); // John
```

ขณะที่ `user.sayHi()` ทำงาน ค่าของ `this` จะเป็น `user`

เราจะอ้างถึงออบเจ็กต์ผ่านตัวแปรภายนอกโดยไม่ใช้ `this` ก็ได้:

```js
let user = {
  name: "John",
  age: 30,

  sayHi() {
*!*
    alert(user.name); // ใช้ "user" แทน "this"
*/!*
  }

};
```

แต่โค้ดแบบนี้เปราะ ถ้าเก็บออบเจ็กต์เดียวกันไว้ในตัวแปรอื่น เช่น `admin = user` แล้วเขียนค่าใหม่ทับ `user` เมธอดจะไปอ้างถึงค่าจากตัวแปร `user` แทนออบเจ็กต์ที่เรียกมัน

ลองดูตัวอย่าง:

```js run
let user = {
  name: "John",
  age: 30,

  sayHi() {
*!*
    alert( user.name ); // ทำให้เกิด error
*/!*
  }

};


let admin = user;
user = null; // เขียนทับเพื่อให้เห็นชัดเจน

*!*
admin.sayHi(); // TypeError: Cannot read property 'name' of null
*/!*
```

ถ้าเปลี่ยน `user.name` ใน `alert` เป็น `this.name` โค้ดก็จะทำงานถูกต้อง เพราะตอนเรียก `admin.sayHi()` ค่า `this` คือ `admin`

## "this" ไม่ได้ผูกกับออบเจ็กต์ตายตัว

ใน JavaScript คีย์เวิร์ด `this` ทำงานต่างจากภาษาโปรแกรมส่วนใหญ่ เราเขียน `this` ไว้ในฟังก์ชันใดก็ได้ แม้ฟังก์ชันนั้นจะไม่ได้เป็นเมธอดของออบเจ็กต์

ตัวอย่างนี้เขียนได้โดยไม่ผิดไวยากรณ์:

```js
function sayHi() {
  alert( *!*this*/!*.name );
}
```

JavaScript จะกำหนดค่าของ `this` ตอนเรียกฟังก์ชัน โดยดูจากวิธีที่ฟังก์ชันนั้นถูกเรียก

ตัวอย่างต่อไปนี้นำฟังก์ชันเดียวกันไปใช้กับออบเจ็กต์สองตัว แต่ละครั้งที่เรียกจึงได้ `this` คนละค่า:

```js run
let user = { name: "John" };
let admin = { name: "Admin" };

function sayHi() {
  alert( this.name );
}

*!*
// ใช้ฟังก์ชันเดียวกันในออบเจ็กต์สองตัว
user.f = sayHi;
admin.f = sayHi;
*/!*

// แต่ละครั้งที่เรียกจะได้ this คนละค่า
// "this" ภายในฟังก์ชันคือออบเจ็กต์ "หน้าจุด"
user.f(); // John  (this == user)
admin.f(); // Admin  (this == admin)

admin['f'](); // Admin (จะเข้าถึงเมธอดด้วยจุดหรือวงเล็บก็ไม่ต่างกัน)
```

จำกฎง่าย ๆ ไว้ว่า เมื่อเรียก `obj.f()` ค่า `this` ระหว่างที่ `f` ทำงานคือ `obj` ในตัวอย่างข้างต้น `this` จึงเป็น `user` หรือ `admin` ตามออบเจ็กต์ที่อยู่หน้าจุด

````smart header="เรียกฟังก์ชันโดยไม่มีออบเจ็กต์: `this == undefined`"
เรียกฟังก์ชันโดยไม่มีออบเจ็กต์ก็ได้:

```js run
function sayHi() {
  alert(this);
}

sayHi(); // undefined
```

ใน strict mode การเรียกแบบนี้ทำให้ `this` เป็น `undefined` ถ้าพยายามเข้าถึง `this.name` ก็จะเกิด error

ส่วนใน non-strict mode ค่า `this` จะเป็น *global object* ซึ่งบนเบราว์เซอร์คือ `window` เราจะได้เรียนเรื่องนี้ในบท [](info:global-object) พฤติกรรมนี้ตกทอดมาจาก JavaScript รุ่นแรก ๆ และ `"use strict"` ช่วยปิดพฤติกรรมดังกล่าว

โดยทั่วไป การเรียกฟังก์ชันที่ใช้ `this` โดยไม่มีออบเจ็กต์ถือเป็นข้อผิดพลาดในการเขียนโปรแกรม เพราะฟังก์ชันนั้นคาดว่าจะถูกเรียกผ่านออบเจ็กต์
````

```smart header="ผลของ `this` ที่ไม่ได้ผูกกับออบเจ็กต์ตายตัว"
ถ้าเคยใช้ภาษาโปรแกรมอื่นมาก่อน อาจคุ้นกับ `this` ที่ผูกอยู่กับออบเจ็กต์ตั้งแต่ประกาศเมธอด ทำให้ `this` อ้างถึงออบเจ็กต์นั้นเสมอ

แต่ `this` ใน JavaScript ไม่ได้ผูกไว้แบบนั้น ค่าของมันไม่ขึ้นอยู่กับว่าเราประกาศเมธอดตรงไหน แต่ขึ้นอยู่กับออบเจ็กต์ที่อยู่ "หน้าจุด" ตอนเรียก

รูปแบบนี้มีทั้งข้อดีและข้อเสีย ฟังก์ชันเดียวกันนำไปใช้ซ้ำกับออบเจ็กต์หลายตัวได้ แต่ความยืดหยุ่นก็เพิ่มโอกาสเขียนผิด

แทนที่จะตัดสินว่าการออกแบบนี้ดีหรือไม่ดี เราจะเรียนรู้วิธีใช้ให้ถูกต้อง เพื่อใช้ประโยชน์จากมันและเลี่ยงปัญหาที่อาจเกิดขึ้น
```

## Arrow function ไม่มี "this" ของตัวเอง

Arrow function มีลักษณะพิเศษคือไม่มี `this` เป็นของตัวเอง เมื่ออ้างถึง `this` ภายใน arrow function ค่านั้นจะมาจากฟังก์ชันปกติที่ครอบอยู่ด้านนอก

เช่น ในตัวอย่างนี้ `arrow()` ใช้ `this` จากเมธอด `user.sayHi()` ด้านนอก:

```js run
let user = {
  firstName: "Ilya",
  sayHi() {
    let arrow = () => alert(this.firstName);
    arrow();
  }
};

user.sayHi(); // Ilya
```

ลักษณะนี้มีประโยชน์เมื่อไม่ต้องการ `this` ค่าใหม่ แต่อยากใช้ `this` จากบริบทด้านนอก เราจะเจาะลึกเรื่อง arrow function กันอีกครั้งในบท <info:arrow-functions>

## สรุป

- ฟังก์ชันที่เก็บไว้ในพร็อพเพอร์ตี้ของออบเจ็กต์เรียกว่า "เมธอด"
- เมธอดทำให้ออบเจ็กต์ "ทำอะไรบางอย่าง" ได้ เช่น `object.doSomething()`
- เมธอดอ้างอิงออบเจ็กต์ได้ผ่าน `this`

ค่าของ `this` ถูกกำหนดตอนเรียกฟังก์ชัน:
- ตอนประกาศฟังก์ชัน เราเขียน `this` ไว้ได้ แต่จะยังไม่รู้ค่าจนกว่าจะเรียกฟังก์ชัน
- คัดลอกฟังก์ชันไปใช้กับออบเจ็กต์อื่นได้
- เรียกฟังก์ชันแบบเมธอด `object.method()` เมื่อไหร่ `this` ตอนนั้นก็คือ `object`

อย่าลืมว่า arrow function ไม่มี `this` ของตัวเอง ถ้าอ้างถึง `this` ภายใน arrow function ค่านั้นจะมาจากบริบทด้านนอก
