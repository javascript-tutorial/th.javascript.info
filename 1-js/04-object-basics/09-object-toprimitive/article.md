# การแปลงออบเจ็กต์เป็นค่าพื้นฐาน

ถ้าเราเอาออบเจ็กต์มาบวกกัน `obj1 + obj2` ลบกัน `obj1 - obj2` หรือแสดงผลด้วย `alert(obj)` จะเกิดอะไรขึ้น?

JavaScript ไม่เปิดให้เราเขียนเมธอดเฉพาะเพื่อกำหนดการทำงานของตัวดำเนินการแต่ละตัวกับออบเจ็กต์ ต่างจากบางภาษาอย่าง Ruby หรือ C++ ที่เขียนเมธอดพิเศษไว้จัดการการบวกหรือตัวดำเนินการอื่น ๆ ได้

ในสถานการณ์เหล่านี้ JavaScript จะแปลงออบเจ็กต์เป็นค่าพื้นฐานโดยอัตโนมัติก่อน แล้วจึงนำค่าพื้นฐานนั้นไปคำนวณ ผลลัพธ์ที่ได้ก็เป็นค่าพื้นฐานเช่นกัน

นี่เป็นข้อจำกัดสำคัญ เพราะผลลัพธ์ของ `obj1 + obj2` หรือการคำนวณแบบอื่นจะเป็นออบเจ็กต์อีกตัวไม่ได้

ตัวอย่างเช่น ต่อให้สร้างออบเจ็กต์ไว้แทนเวกเตอร์ เมทริกซ์ หรืออะไรก็ตาม เราก็นำออบเจ็กต์เหล่านั้นมาบวกกันแล้วหวังว่าจะได้ “ออบเจ็กต์ผลรวม” กลับมาไม่ได้ JavaScript ไม่รองรับการออกแบบแบบนั้น

ในโปรเจกต์จริงจึงแทบไม่เห็นการคำนวณกับออบเจ็กต์โดยตรง ถ้าเจอ ส่วนใหญ่มักเกิดจากเขียนโค้ดพลาด มีเพียงบางกรณีเท่านั้นที่ตั้งใจทำแบบนี้

บทนี้จะอธิบายว่า JavaScript แปลงออบเจ็กต์เป็นค่าพื้นฐานอย่างไร และเราปรับผลการแปลงนั้นเองได้อย่างไร

เรื่องนี้มีประโยชน์อยู่สองอย่าง:

1. ช่วยให้เราแกะรอยได้ว่าเกิดอะไรขึ้นเมื่อเผลอนำออบเจ็กต์ไปใช้กับตัวดำเนินการ
2. ช่วยให้เข้าใจกรณีที่ใช้การแปลงแบบนี้ได้อย่างเหมาะสม เช่น การลบหรือเปรียบเทียบวันที่ ซึ่งเป็นออบเจ็กต์ `Date` เราจะได้เรียนเรื่องนี้ในบทต่อ ๆ ไป

## กฎการแปลง

ในบท <info:type-conversions> เราได้เรียนรู้กฎการแปลงค่าพื้นฐานเป็นตัวเลข สตริง และบูลีนไปแล้ว แต่ยังเว้นเรื่องออบเจ็กต์ไว้ ทีนี้เมื่อรู้จักเมธอดและ symbol แล้ว เราก็เติมส่วนที่ขาดไปได้

1. ไม่มีการแปลงออบเจ็กต์เป็นบูลีน เพราะออบเจ็กต์ทุกตัวมีค่าเป็น `true` เมื่ออยู่ในบริบทที่ต้องการบูลีน จึงเหลือเพียงการแปลงเป็นตัวเลขและสตริง
2. การแปลงเป็นตัวเลขเกิดขึ้นเมื่อเราลบออบเจ็กต์หรือส่งออบเจ็กต์ให้ฟังก์ชันคณิตศาสตร์ เช่น เรานำออบเจ็กต์ `Date` มาลบกันได้ โดย `date1 - date2` จะได้ระยะเวลาที่ห่างกันระหว่างวันที่ทั้งสอง เรื่องนี้จะอธิบายในบท <info:date>
3. การแปลงเป็นสตริงมักเกิดขึ้นเมื่อต้องแสดงออบเจ็กต์ด้วย `alert(obj)` หรือใช้งานในลักษณะใกล้เคียงกัน

เรากำหนดวิธีแปลงออบเจ็กต์เป็นสตริงหรือตัวเลขเองได้ด้วยเมธอดพิเศษของออบเจ็กต์

ต่อไปเราจะไล่ดูกลไกนี้ทีละขั้น เพื่อให้เห็นว่า JavaScript เลือกวิธีแปลงอย่างไร

## Hint

JavaScript รู้ได้อย่างไรว่าควรแปลงออบเจ็กต์เป็นชนิดไหน?

การแปลงชนิดมีสามรูปแบบ แต่ละรูปแบบใช้ในสถานการณ์ต่างกัน ค่าที่บอก JavaScript ว่าควรใช้รูปแบบไหนเรียกว่า “hint” ตามที่อธิบายไว้ใน [ข้อกำหนดของภาษา](https://tc39.github.io/ecma262/#sec-toprimitive):

`"string"`
: ใช้เมื่อต้องแปลงออบเจ็กต์เป็นสตริง เช่น ส่งออบเจ็กต์ให้ `alert` ซึ่งต้องการสตริง:

    ```js
    // แสดงผล
    alert(obj);

    // ใช้ออบเจ็กต์เป็นคีย์ของพร็อพเพอร์ตี้
    anotherObj[obj] = 123;
    ```

`"number"`
: ใช้เมื่อต้องแปลงออบเจ็กต์เป็นตัวเลข เช่น ตอนคำนวณ:

    ```js
    // แปลงโดยตรง
    let num = Number(obj);

    // คำนวณ (ยกเว้นเครื่องหมายบวกแบบสองข้าง)
    let n = +obj; // เครื่องหมายบวกแบบข้างเดียว
    let delta = date1 - date2;

    // เปรียบเทียบว่าน้อยกว่าหรือมากกว่า
    let greater = user1 > user2;
    ```

    ฟังก์ชันคณิตศาสตร์ส่วนใหญ่ที่ JavaScript มีให้ก็แปลงค่าด้วย hint นี้เช่นกัน

`"default"`
: ใช้ในกรณีที่ตัวดำเนินการยังระบุไม่ได้ชัดว่าต้องการค่าชนิดไหน ซึ่งเกิดขึ้นไม่บ่อยนัก

    ตัวอย่างเช่น เครื่องหมายบวกแบบสองข้าง `+` ใช้ได้ทั้งต่อสตริงและบวกตัวเลข เมื่อได้รับออบเจ็กต์เป็นค่าฝั่งใดฝั่งหนึ่ง จึงใช้ hint `"default"` แปลงออบเจ็กต์ก่อน

    การเปรียบเทียบออบเจ็กต์ด้วย `==` กับสตริง ตัวเลข หรือ symbol ก็ระบุไม่ได้ชัดว่าควรแปลงเป็นชนิดไหน จึงใช้ hint `"default"` เช่นกัน

    ```js
    // เครื่องหมายบวกแบบสองข้างใช้ hint "default"
    let total = obj1 + obj2;

    // obj == number ใช้ hint "default"
    if (user == 1) { ... };
    ```

    ตัวดำเนินการเปรียบเทียบมากกว่าหรือน้อยกว่าอย่าง `<` และ `>` ก็ใช้ได้กับทั้งสตริงและตัวเลข แต่กลับใช้ hint `"number"` แทน `"default"` ด้วยเหตุผลทางประวัติศาสตร์

แต่เวลาใช้งานจริง กลไกนี้ไม่ได้ซับซ้อนมากนัก

ออบเจ็กต์ทุกชนิดที่ JavaScript มีมาให้ ยกเว้น `Date` จะจัดการ `"default"` แบบเดียวกับ `"number"` และออบเจ็กต์ที่เราเขียนเองก็ควรทำแบบเดียวกัน

ถึงอย่างนั้น เรายังควรรู้จัก hint ทั้งสามแบบ เพราะเดี๋ยวจะเห็นว่าแต่ละแบบมีผลอย่างไร

**เมื่อต้องแปลงออบเจ็กต์ JavaScript จะค้นหาและเรียกเมธอดสามตัวนี้ตามลำดับ:**

1. เรียก `obj[Symbol.toPrimitive](hint)` ซึ่งมีคีย์เป็น symbol ของระบบชื่อ `Symbol.toPrimitive` ถ้ามีเมธอดนี้อยู่
2. ถ้าไม่มี และ hint เป็น `"string"`
    - ลองเรียก `obj.toString()` หรือ `obj.valueOf()` ตามลำดับ โดยใช้เมธอดที่มีอยู่
3. ถ้าไม่มี และ hint เป็น `"number"` หรือ `"default"`
    - ลองเรียก `obj.valueOf()` หรือ `obj.toString()` ตามลำดับ โดยใช้เมธอดที่มีอยู่

## Symbol.toPrimitive

เริ่มจากเมธอดแรกกัน JavaScript มี symbol ในตัวชื่อ `Symbol.toPrimitive` สำหรับใช้เป็นชื่อเมธอดที่ทำหน้าที่แปลงออบเจ็กต์ เขียนได้แบบนี้:

```js
obj[Symbol.toPrimitive] = function(hint) {
  // เขียนโค้ดแปลงออบเจ็กต์เป็นค่าพื้นฐานตรงนี้
  // ต้องคืนค่าเป็นค่าพื้นฐาน
  // hint เป็นค่าใดค่าหนึ่งใน "string", "number", "default"
};
```

ถ้ามีเมธอด `Symbol.toPrimitive` JavaScript จะใช้เมธอดนี้กับทุก hint โดยไม่ต้องหาเมธอดอื่นต่อ

ตัวอย่างนี้ ออบเจ็กต์ `user` กำหนดเมธอดนี้ไว้:

```js run
let user = {
  name: "John",
  money: 1000,

  [Symbol.toPrimitive](hint) {
    alert(`hint: ${hint}`);
    return hint == "string" ? `{name: "${this.name}"}` : this.money;
  }
};

// ตัวอย่างการแปลง:
alert(user); // hint: string -> {name: "John"}
alert(+user); // hint: number -> 1000
alert(user + 500); // hint: default -> 1500
```

จากโค้ดนี้ เมื่อ JavaScript แปลง `user` ค่าที่ได้จะเป็นสตริงที่บอกข้อมูลของออบเจ็กต์หรือจำนวนเงิน ขึ้นอยู่กับ hint ที่ได้รับ เมธอด `user[Symbol.toPrimitive]` เพียงเมธอดเดียวจึงจัดการการแปลงได้ทุกกรณี

## toString/valueOf

ถ้าไม่มี `Symbol.toPrimitive` JavaScript จะมองหาเมธอด `toString` และ `valueOf` แทน:

- เมื่อ hint เป็น `"string"` จะเรียก `toString` ก่อน ถ้าไม่มีเมธอดนี้หรือเมธอดคืนออบเจ็กต์แทนค่าพื้นฐาน จึงค่อยเรียก `valueOf` ดังนั้น `toString` จึงมาก่อนเมื่อแปลงเป็นสตริง
- สำหรับ hint อื่น จะเรียก `valueOf` ก่อน ถ้าไม่มีเมธอดนี้หรือเมธอดคืนออบเจ็กต์แทนค่าพื้นฐาน จึงค่อยเรียก `toString` ดังนั้น `valueOf` จึงมาก่อนเมื่อคำนวณ

เมธอด `toString` และ `valueOf` มีมาตั้งแต่ยุคแรก ๆ ก่อน JavaScript จะมี symbol ทั้งคู่จึงเป็นเมธอดที่ใช้ชื่อแบบสตริงทั่วไป และเป็นอีกวิธีดั้งเดิมสำหรับกำหนดการแปลง

เมธอดเหล่านี้ต้องคืนค่าพื้นฐาน ถ้า `toString` หรือ `valueOf` คืนออบเจ็กต์ JavaScript จะข้ามผลลัพธ์นั้นไปเหมือนกับว่าไม่มีเมธอดอยู่

ออบเจ็กต์ทั่วไปมีเมธอด `toString` และ `valueOf` เป็นค่าเริ่มต้นแบบนี้:

- เมธอด `toString` คืนสตริง `"[object Object]"`
- เมธอด `valueOf` คืนออบเจ็กต์ตัวเดิม

ลองดูตัวอย่าง:

```js run
let user = {name: "John"};

alert(user); // [object Object]
alert(user.valueOf() === user); // true
```

ดังนั้นถ้าใช้ออบเจ็กต์ในตำแหน่งที่ต้องการสตริง เช่น ส่งให้ `alert` ค่าเริ่มต้นที่เห็นคือ `[object Object]`

`valueOf` แบบเริ่มต้นมีไว้ให้เห็นกลไกครบถ้วนเท่านั้น เมธอดนี้คืนออบเจ็กต์ตัวเดิม JavaScript จึงข้ามค่านั้นไป เหตุผลที่ออกแบบไว้แบบนี้เป็นเรื่องตกทอดจากอดีต ในทางปฏิบัติจึงนับว่าไม่มีเมธอดนี้ก็ได้

ทีนี้ลองกำหนดเมธอดเหล่านี้เพื่อปรับการแปลงเอง

ตัวอย่างต่อไปนี้ทำให้ `user` ทำงานเหมือนตัวอย่างก่อนหน้า แต่ใช้ `toString` ร่วมกับ `valueOf` แทน `Symbol.toPrimitive`:

```js run
let user = {
  name: "John",
  money: 1000,

  // สำหรับ hint="string"
  toString() {
    return `{name: "${this.name}"}`;
  },

  // สำหรับ hint="number" หรือ "default"
  valueOf() {
    return this.money;
  }

};

alert(user); // toString -> {name: "John"}
alert(+user); // valueOf -> 1000
alert(user + 500); // valueOf -> 1500
```

ผลลัพธ์เหมือนกับตัวอย่างที่ใช้ `Symbol.toPrimitive` ก่อนหน้านี้

หลายครั้งเราต้องการรวมการแปลงทุกแบบไว้ในที่เดียว กรณีนี้กำหนดเพียง `toString` ก็พอ:

```js run
let user = {
  name: "John",

  toString() {
    return this.name;
  }
};

alert(user); // toString -> John
alert(user + 500); // toString -> John500
```

เมื่อไม่มี `Symbol.toPrimitive` และ `valueOf` เมธอด `toString` จะรับหน้าที่แปลงออบเจ็กต์เป็นค่าพื้นฐานทุกกรณี

### เมธอดแปลงค่าคืนค่าพื้นฐานชนิดใดก็ได้

ข้อสำคัญคือ เมธอดที่ใช้แปลงออบเจ็กต์ไม่จำเป็นต้องคืนค่าพื้นฐานชนิดเดียวกับที่ hint ระบุ

JavaScript ไม่ได้บังคับว่า `toString` ต้องคืนสตริง หรือ `Symbol.toPrimitive` ต้องคืนตัวเลขเมื่อได้รับ hint `"number"`

ข้อบังคับมีเพียงอย่างเดียว คือเมธอดเหล่านี้ต้องคืนค่าพื้นฐาน ไม่ใช่ออบเจ็กต์

```smart header="เกร็ดจากประวัติของภาษา"
ด้วยเหตุผลทางประวัติศาสตร์ ถ้า `toString` หรือ `valueOf` คืนออบเจ็กต์ JavaScript จะไม่แจ้งข้อผิดพลาด แต่จะข้ามค่านั้นไปเหมือนกับว่าไม่มีเมธอดอยู่ เพราะในยุคแรก ๆ JavaScript ยังไม่มีแนวคิดเรื่องข้อผิดพลาดที่ดีนัก

แต่ `Symbol.toPrimitive` เข้มงวดกว่า เมธอดนี้ *ต้อง* คืนค่าพื้นฐาน ไม่เช่นนั้นจะเกิดข้อผิดพลาด
```

## การแปลงต่ออีกขั้น

ตัวดำเนินการและฟังก์ชันหลายอย่างแปลงชนิดข้อมูลให้เอง เช่น การคูณ `*` จะแปลงค่าทั้งสองข้างเป็นตัวเลข

ถ้าค่าที่ส่งเข้าไปเป็นออบเจ็กต์ การคำนวณจะมีสองขั้นตอน:
1. แปลงออบเจ็กต์เป็นค่าพื้นฐานตามกฎที่อธิบายไว้ข้างต้น
2. ถ้าการคำนวณต้องการค่าอีกชนิดหนึ่ง ก็แปลงค่าพื้นฐานที่ได้ต่อไป

ตัวอย่าง:

```js run
let obj = {
  // เมื่อไม่มีเมธอดอื่น toString จะจัดการการแปลงทั้งหมด
  toString() {
    return "2";
  }
};

alert(obj * 2); // 4, ออบเจ็กต์แปลงเป็นค่าพื้นฐาน "2" แล้วการคูณจึงแปลงค่านั้นเป็นตัวเลข
```

1. การคูณ `obj * 2` จะแปลงออบเจ็กต์เป็นค่าพื้นฐานก่อน ซึ่งได้สตริง `"2"`
2. จากนั้น `"2" * 2` จะกลายเป็น `2 * 2` เพราะ JavaScript แปลงสตริงเป็นตัวเลข

แต่เครื่องหมายบวกแบบสองข้างจะต่อสตริงในสถานการณ์เดียวกัน เพราะตัวดำเนินการนี้รับสตริงได้:

```js run
let obj = {
  toString() {
    return "2";
  }
};

alert(obj + 2); // "22" ("2" + 2), การแปลงเป็นค่าพื้นฐานได้สตริง => จึงต่อสตริง
```

## สรุป

ฟังก์ชันและตัวดำเนินการหลายอย่างของ JavaScript ต้องการค่าพื้นฐาน จึงแปลงออบเจ็กต์ให้โดยอัตโนมัติ

การแปลงมีสามแบบ แยกตาม hint:
- `"string"` ใช้กับ `alert` และการทำงานอื่นที่ต้องการสตริง
- `"number"` ใช้กับการคำนวณ
- `"default"` ใช้กับตัวดำเนินการบางตัว โดยทั่วไปออบเจ็กต์จะจัดการแบบเดียวกับ `"number"`

ข้อกำหนดของภาษาระบุว่าตัวดำเนินการแต่ละตัวใช้ hint ใด

ขั้นตอนการแปลงมีดังนี้:

1. เรียก `obj[Symbol.toPrimitive](hint)` ถ้ามีเมธอดนี้
2. ถ้าไม่มี และ hint เป็น `"string"`
    - ลองเรียก `obj.toString()` หรือ `obj.valueOf()` ตามลำดับ โดยใช้เมธอดที่มีอยู่
3. ถ้าไม่มี และ hint เป็น `"number"` หรือ `"default"`
    - ลองเรียก `obj.valueOf()` หรือ `obj.toString()` ตามลำดับ โดยใช้เมธอดที่มีอยู่

เมธอดเหล่านี้ต้องคืนค่าพื้นฐานจึงจะใช้แปลงค่าได้

เวลาใช้งานจริง แค่กำหนด `obj.toString()` เป็นจุดเดียวสำหรับแปลงออบเจ็กต์เป็นสตริงที่คนอ่านเข้าใจได้ เช่น ใช้ตอน log หรือดีบั๊ก ก็มักเพียงพอแล้ว
