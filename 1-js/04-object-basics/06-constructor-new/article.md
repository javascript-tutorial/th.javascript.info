# ฟังก์ชันคอนสตรักเตอร์และตัวดำเนินการ "new"

ไวยากรณ์ `{...}` สร้างออบเจ็กต์ได้ทีละตัว แต่หลายครั้งเราต้องสร้างออบเจ็กต์หน้าตาคล้ายกันหลายตัว เช่น ผู้ใช้หลายคนหรือเมนูหลายรายการ

งานแบบนี้ใช้ฟังก์ชันคอนสตรักเตอร์ร่วมกับตัวดำเนินการ `"new"` ได้

## ฟังก์ชันคอนสตรักเตอร์

ฟังก์ชันคอนสตรักเตอร์ก็คือฟังก์ชันธรรมดา เพียงแต่มีข้อตกลงร่วมกันอยู่สองข้อ:

1. ตั้งชื่อโดยขึ้นต้นด้วยตัวพิมพ์ใหญ่
2. เรียกใช้ผ่านตัวดำเนินการ `"new"` เท่านั้น

ตัวอย่างเช่น:

```js run
function User(name) {
  this.name = name;
  this.isAdmin = false;
}

*!*
let user = new User("Jack");
*/!*

alert(user.name); // Jack
alert(user.isAdmin); // false
```

เมื่อเรียกฟังก์ชันด้วย `new` JavaScript จะทำตามขั้นตอนนี้:

1. สร้างออบเจ็กต์ว่างขึ้นมาใหม่ แล้วกำหนดออบเจ็กต์นั้นให้ `this`
2. ทำงานตามโค้ดในฟังก์ชัน ซึ่งโดยทั่วไปจะเพิ่มพร็อพเพอร์ตี้ให้ `this`
3. คืนค่า `this`

พูดอีกแบบคือ `new User(...)` ทำงานคล้ายโค้ดนี้:

```js
function User(name) {
*!*
  // this = {};  (เกิดขึ้นโดยอัตโนมัติ)
*/!*

  // เพิ่มพร็อพเพอร์ตี้ให้ this
  this.name = name;
  this.isAdmin = false;

*!*
  // return this;  (เกิดขึ้นโดยอัตโนมัติ)
*/!*
}
```

ดังนั้น `let user = new User("Jack")` จึงให้ผลเหมือนกับ:

```js
let user = {
  name: "Jack",
  isAdmin: false
};
```

ถ้าต้องการสร้างผู้ใช้คนอื่น ก็เรียก `new User("Ann")`, `new User("Alice")` ต่อไปได้เลย โค้ดสั้นและอ่านง่ายกว่าการเขียนออบเจ็กต์ด้วย `{...}` ใหม่ทุกครั้งมาก

นี่คือหน้าที่หลักของคอนสตรักเตอร์: รวมโค้ดสำหรับสร้างออบเจ็กต์ไว้ให้เรียกซ้ำได้

จะใช้ฟังก์ชันไหนเป็นคอนสตรักเตอร์ก็ได้ ยกเว้น arrow function ที่ไม่มี `this` แค่เรียกฟังก์ชันนั้นด้วย `new` ก็จะทำงานตามขั้นตอนข้างต้น ส่วนการขึ้นต้นชื่อด้วยตัวพิมพ์ใหญ่เป็นข้อตกลงที่ช่วยบอกคนอ่านว่า ฟังก์ชันนี้ควรเรียกด้วย `new`

````smart header="new function() { ... }"
ถ้ามีโค้ดหลายบรรทัดสำหรับสร้างออบเจ็กต์ซับซ้อนเพียงตัวเดียว เราครอบโค้ดทั้งหมดไว้ในฟังก์ชันคอนสตรักเตอร์ที่เรียกทันทีได้:

```js
// สร้างฟังก์ชันแล้วเรียกด้วย new ทันที
let user = new function() {
  this.name = "John";
  this.isAdmin = false;

  // ...โค้ดอื่นสำหรับสร้าง user
  // อาจมีตรรกะและคำสั่งที่ซับซ้อน
  // ตัวแปรภายใน และอื่น ๆ
};
```

คอนสตรักเตอร์นี้เรียกซ้ำไม่ได้ เพราะเราไม่ได้เก็บฟังก์ชันไว้ที่ไหน ฟังก์ชันถูกสร้างแล้วเรียกทันที เทคนิคนี้จึงเหมาะกับการรวบโค้ดที่ใช้สร้างออบเจ็กต์เพียงตัวเดียว โดยไม่ต้องนำกลับมาใช้ภายหลัง
````

## ตรวจว่าเรียกแบบคอนสตรักเตอร์หรือไม่ด้วย `new.target`

```smart header="เนื้อหาขั้นสูง"
ไวยากรณ์ในส่วนนี้ไม่ค่อยได้ใช้ ถ้ายังไม่อยากลงรายละเอียดก็ข้ามไปก่อนได้
```

ภายในฟังก์ชัน เราใช้ค่าพิเศษ `new.target` ตรวจได้ว่าฟังก์ชันถูกเรียกด้วย `new` หรือไม่

ถ้าเรียกแบบปกติ `new.target` จะเป็น `undefined` แต่ถ้าเรียกด้วย `new` ค่านี้จะเท่ากับฟังก์ชันที่กำลังทำงาน:

```js run
function User() {
  alert(new.target);
}

// ไม่ใช้ "new":
*!*
User(); // undefined
*/!*

// ใช้ "new":
*!*
new User(); // function User { ... }
*/!*
```

จึงใช้ `new.target` แยกได้ว่า ตอนนั้นเรียกฟังก์ชันด้วย `new` ในโหมดคอนสตรักเตอร์ หรือเรียกตามปกติ

เราทำให้การเรียกทั้งแบบมีและไม่มี `new` ให้ผลเหมือนกันได้ด้วย:

```js run
function User(name) {
  if (!new.target) { // ถ้าเรียกโดยไม่มี new
    return new User(name); // เรียกใหม่พร้อมเติม new ให้
  }

  this.name = name;
}

let john = User("John"); // เปลี่ยนไปเรียก new User
alert(john.name); // John
```

ไลบรารีบางตัวใช้วิธีนี้เพื่อให้เรียกฟังก์ชันได้ทั้งสองแบบ ไม่ว่าจะใส่ `new` หรือไม่ก็ยังทำงานเหมือนกัน

แต่ไม่ควรใช้วิธีนี้ทุกที่ เพราะถ้าละ `new` คนอ่านจะไม่เห็นทันทีว่าโค้ดกำลังสร้างออบเจ็กต์ใหม่ ต่างจากตอนที่มี `new` บอกไว้ชัดเจน

## การคืนค่าจากคอนสตรักเตอร์

โดยทั่วไปคอนสตรักเตอร์ไม่มีคำสั่ง `return` หน้าที่ของมันคือใส่ข้อมูลที่ต้องการลงใน `this` แล้ว JavaScript จะคืน `this` เป็นผลลัพธ์โดยอัตโนมัติ

ถ้ามีคำสั่ง `return` ให้จำกฎสั้น ๆ สองข้อนี้:

- ถ้า `return` ออบเจ็กต์ จะคืนออบเจ็กต์นั้นแทน `this`
- ถ้า `return` ค่าพื้นฐาน JavaScript จะไม่สนใจค่านั้น

สรุปคือ `return` พร้อมออบเจ็กต์จะคืนออบเจ็กต์นั้น ส่วนกรณีอื่นจะคืน `this`

ตัวอย่างนี้ `return` ทำให้ผลลัพธ์ไม่ใช่ `this` แต่เป็นออบเจ็กต์อีกตัว:

```js run
function BigUser() {

  this.name = "John";

  return { name: "Godzilla" };  // <-- คืนออบเจ็กต์นี้
}

alert( new BigUser().name );  // Godzilla, ได้ออบเจ็กต์ที่คืนออกมา
```

ส่วนตัวอย่างต่อไปใช้ `return` เปล่า ๆ จะใส่ค่าพื้นฐานต่อท้ายก็ได้ ผลลัพธ์ไม่ต่างกัน:

```js run
function SmallUser() {

  this.name = "John";

  return; // <-- คืน this
}

alert( new SmallUser().name );  // John
```

ปกติเราไม่เขียน `return` ในคอนสตรักเตอร์ ที่อธิบายกฎนี้ไว้ก็เพื่อให้เข้าใจพฤติกรรมของคอนสตรักเตอร์ครบถ้วน

````smart header="ละวงเล็บได้"
ถ้าไม่มีอาร์กิวเมนต์ เราละวงเล็บหลัง `new` ได้:

```js
let user = new User; // <-- ไม่มีวงเล็บ
// เหมือนกับ
let user = new User();
```

แม้ข้อกำหนดของภาษาจะอนุญาตให้ละวงเล็บได้ แต่รูปแบบนี้ไม่ถือว่าเป็นสไตล์ที่ดีนัก
````

## เมธอดในคอนสตรักเตอร์

ฟังก์ชันคอนสตรักเตอร์ช่วยให้เราปรับวิธีสร้างออบเจ็กต์ได้ตามต้องการ เพราะใช้พารามิเตอร์กำหนดได้ว่าจะสร้างออบเจ็กต์แบบไหนและใส่ข้อมูลอะไรลงไป

นอกจากพร็อพเพอร์ตี้แล้ว เรายังเพิ่มเมธอดให้ `this` ได้ด้วย

ตัวอย่างนี้ `new User(name)` สร้างออบเจ็กต์ที่มี `name` ตามค่าที่รับมา และมีเมธอด `sayHi`:

```js run
function User(name) {
  this.name = name;

  this.sayHi = function() {
    alert( "My name is: " + this.name );
  };
}

*!*
let john = new User("John");

john.sayHi(); // My name is: John
*/!*

/*
john = {
   name: "John",
   sayHi: function() { ... }
}
*/
```

ถ้าต้องการสร้างออบเจ็กต์ที่ซับซ้อนกว่านี้ ยังมีไวยากรณ์ขั้นสูงอย่าง [คลาส](info:classes) ซึ่งเราจะเรียนกันภายหลัง

## สรุป

- ฟังก์ชันคอนสตรักเตอร์ หรือเรียกสั้น ๆ ว่าคอนสตรักเตอร์ เป็นฟังก์ชันธรรมดา แต่ตามข้อตกลงแล้วชื่อจะขึ้นต้นด้วยตัวพิมพ์ใหญ่
- ฟังก์ชันคอนสตรักเตอร์ควรเรียกด้วย `new` เท่านั้น การเรียกแบบนี้จะสร้าง `this` ว่างขึ้นมาตอนเริ่ม แล้วคืน `this` ที่เติมข้อมูลแล้วออกมาตอนจบ

เราใช้ฟังก์ชันคอนสตรักเตอร์สร้างออบเจ็กต์หน้าตาคล้ายกันได้หลายตัว

JavaScript มีฟังก์ชันคอนสตรักเตอร์สำหรับออบเจ็กต์ที่มีมากับภาษาอยู่หลายตัว เช่น `Date` สำหรับวันที่และ `Set` สำหรับเซ็ต เราจะได้เรียนเรื่องเหล่านี้กันต่อไป

```smart header="เราจะกลับมาเรียนเรื่องออบเจ็กต์กันอีก"
บทนี้พูดถึงออบเจ็กต์และคอนสตรักเตอร์เฉพาะส่วนพื้นฐานที่จำเป็นต่อการเรียนชนิดข้อมูลและฟังก์ชันในบทถัด ๆ ไป

เมื่อเรียนเรื่องเหล่านั้นแล้ว เราจะกลับมาเจาะลึกออบเจ็กต์กันในบท <info:prototypes> และ <info:classes>
```
