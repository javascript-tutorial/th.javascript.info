# ชนิดข้อมูล Symbol

ตาม specification แล้ว คีย์ของพร็อพเพอร์ตี้ในออบเจ็กต์ต้องเป็นค่าพื้นฐานชนิดใดชนิดหนึ่งต่อไปนี้:

- สตริง หรือ
- symbol

ถ้าใช้ค่าชนิดอื่นเป็นคีย์ เช่น ตัวเลข JavaScript จะแปลงค่านั้นเป็นสตริงให้อัตโนมัติ ดังนั้น `obj[1]` จึงหมายถึงพร็อพเพอร์ตี้เดียวกับ `obj["1"]` และ `obj[true]` ก็หมายถึงพร็อพเพอร์ตี้เดียวกับ `obj["true"]`

ที่ผ่านมาเราใช้แต่สตริงเป็นคีย์

ทีนี้มาทำความรู้จัก symbol และดูว่ามันช่วยอะไรเราได้บ้าง

## Symbol

Symbol คือค่าที่ใช้เป็นตัวระบุซึ่งไม่ซ้ำกับค่าอื่น

เราสร้างค่า symbol ได้ด้วย `Symbol()`:

```js
let id = Symbol();
```

ตอนสร้าง symbol จะใส่คำอธิบายหรือชื่อกำกับไว้ก็ได้ ส่วนใหญ่มีไว้ช่วยให้ดูค่าได้ง่ายขึ้นตอนดีบั๊ก:

```js
// id คือ symbol ที่มีคำอธิบายว่า "id"
let id = Symbol("id");
```

JavaScript รับประกันว่า symbol แต่ละตัวที่สร้างขึ้นจะไม่ซ้ำกัน ต่อให้สร้างหลายตัวด้วยคำอธิบายเดียวกัน ค่าที่ได้ก็ยังเป็นคนละค่า เพราะคำอธิบายเป็นเพียงป้ายกำกับและไม่มีผลต่อค่าของ symbol

ตัวอย่างนี้สร้าง symbol สองตัวที่มีคำอธิบายเหมือนกัน แต่ทั้งคู่ไม่เท่ากัน:

```js run
let id1 = Symbol("id");
let id2 = Symbol("id");

*!*
alert(id1 == id2); // false
*/!*
```

ถ้าเคยใช้ symbol ใน Ruby หรือภาษาอื่นที่มีแนวคิดคล้ายกัน อย่าเพิ่งคิดว่า symbol ของ JavaScript จะทำงานเหมือนกัน เพราะแต่ละภาษานิยามไว้ต่างกัน

สรุปสั้น ๆ ได้ว่า symbol เป็นค่าพื้นฐานที่ไม่ซ้ำกัน และจะมีคำอธิบายกำกับหรือไม่ก็ได้ ต่อไปมาดูว่าเรานำไปใช้ตรงไหนได้บ้าง

````warn header="Symbol ไม่แปลงเป็นสตริงอัตโนมัติ"
ค่าทั่วไปใน JavaScript แปลงเป็นสตริงได้โดยอัตโนมัติ เช่น เราส่งค่าแทบทุกชนิดให้ `alert` แสดงผลได้ แต่ symbol ไม่ยอมให้แปลงแบบนั้น

ถ้าส่ง symbol ให้ `alert` โดยตรง จะเกิดข้อผิดพลาด:

```js run
let id = Symbol("id");
*!*
alert(id); // TypeError: Cannot convert a Symbol value to a string
*/!*
```

JavaScript ตั้งกฎนี้ไว้เพื่อไม่ให้เราเผลอปะปนสตริงกับ symbol เพราะทั้งสองอย่างเป็นคนละชนิดกันอย่างชัดเจน เราจึงไม่ควรเผลอแปลงค่าจากชนิดหนึ่งเป็นอีกชนิดหนึ่ง

ถ้าต้องการแสดง symbol ต้องเรียก `.toString()` ให้ชัดเจน:

```js run
let id = Symbol("id");
*!*
alert(id.toString()); // Symbol(id), ใช้งานได้แล้ว
*/!*
```

ถ้าต้องการเฉพาะคำอธิบาย ให้อ่านจากพร็อพเพอร์ตี้ `symbol.description`:

```js run
let id = Symbol("id");
*!*
alert(id.description); // id
*/!*
```

````

## พร็อพเพอร์ตี้ที่ "ซ่อนอยู่"

Symbol ช่วยให้เราเพิ่มพร็อพเพอร์ตี้ที่ "ซ่อนอยู่" ในออบเจ็กต์ได้ โค้ดส่วนอื่นจึงไม่เผลอเข้าถึงหรือเขียนทับพร็อพเพอร์ตี้นั้นโดยบังเอิญ

สมมติว่าเรากำลังใช้ออบเจ็กต์ `user` ซึ่งมาจากโค้ดของคนอื่น และต้องการเพิ่มตัวระบุให้แต่ละออบเจ็กต์ เราสามารถใช้ symbol เป็นคีย์ได้:

```js run
let user = { // มาจากโค้ดส่วนอื่น
  name: "John"
};

let id = Symbol("id");

user[id] = 1;

alert( user[id] ); // เข้าถึงข้อมูลโดยใช้ symbol เป็นคีย์
```

แล้วการใช้ `Symbol("id")` ดีกว่าใช้สตริง `"id"` ตรงไหน?

เมื่อออบเจ็กต์ `user` เป็นของโค้ดอีกชุดหนึ่ง การเพิ่มฟิลด์ทั่วไปเข้าไปอาจไปกระทบพฤติกรรมที่โค้ดชุดนั้นเตรียมไว้ แต่โค้ดนั้นจะไม่รู้จัก symbol ที่เราเพิ่งสร้าง จึงไม่เผลอเข้าถึงพร็อพเพอร์ตี้ใหม่ การใช้ symbol เป็นคีย์จึงช่วยป้องกันไม่ให้ชื่อพร็อพเพอร์ตี้ชนกันโดยบังเอิญ

ลองนึกว่ามีอีกสคริปต์หนึ่งอยากเก็บตัวระบุของตัวเองไว้ใน `user` เช่นกัน สคริปต์นั้นก็สร้าง `Symbol("id")` ของตัวเองขึ้นมา:

```js
// ...
let id = Symbol("id");

user[id] = "Their id value";
```

ตัวระบุของเรากับของอีกสคริปต์จะไม่ชนกัน เพราะ symbol แต่ละตัวเป็นคนละค่ากันเสมอ แม้จะใช้ชื่อเดียวกัน

แต่ถ้าใช้สตริง `"id"` แทน symbol พร็อพเพอร์ตี้จะชนกัน:

```js
let user = { name: "John" };

// สคริปต์ของเราใช้พร็อพเพอร์ตี้ "id"
user.id = "Our id value";

// ...อีกสคริปต์ก็ต้องการใช้ "id" เพื่อเก็บข้อมูลของตัวเอง...

user.id = "Their id value"
// พังแล้ว! อีกสคริปต์เขียนค่าทับไปแล้ว
```

### ใช้ symbol ใน object literal

ถ้าต้องการใช้ symbol เป็นคีย์ใน object literal `{...}` ต้องครอบตัวแปรนั้นด้วยวงเล็บเหลี่ยม

เขียนแบบนี้:

```js
let id = Symbol("id");

let user = {
  name: "John",
*!*
  [id]: 123 // ไม่ใช่ "id": 123
*/!*
};
```
เหตุผลคือเราต้องการนำค่าจากตัวแปร `id` มาใช้เป็นคีย์ ไม่ได้ต้องการสตริง "id"

### for..in จะข้าม symbol

`for..in` จะไม่วนผ่านพร็อพเพอร์ตี้ที่ใช้ symbol เป็นคีย์

ลองดูตัวอย่าง:

```js run
let id = Symbol("id");
let user = {
  name: "John",
  age: 30,
  [id]: 123
};

*!*
for (let key in user) alert(key); // name, age (ไม่มี symbol)
*/!*

// ยังเข้าถึงโดยตรงผ่าน symbol ได้ตามปกติ
alert( "Direct: " + user[id] ); // Direct: 123
```

[Object.keys(user)](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/keys) ก็ข้ามพร็อพเพอร์ตี้เหล่านี้เช่นกัน นี่เป็นส่วนหนึ่งของแนวคิดเรื่องการ "ซ่อนพร็อพเพอร์ตี้ที่ใช้ symbol เป็นคีย์" เมื่อสคริปต์หรือไลบรารีอื่นวนดูพร็อพเพอร์ตี้ในออบเจ็กต์ ก็จะไม่เผลอเจอพร็อพเพอร์ตี้นี้

แต่ [Object.assign](mdn:js/Object/assign) จะคัดลอกทั้งพร็อพเพอร์ตี้ที่ใช้สตริงและ symbol เป็นคีย์:

```js run
let id = Symbol("id");
let user = {
  [id]: 123
};

let clone = Object.assign({}, user);

alert( clone[id] ); // 123
```

พฤติกรรมทั้งสองอย่างไม่ได้ขัดกัน แต่ตั้งใจออกแบบมาแบบนี้ เพราะตอนคัดลอกหรือรวมออบเจ็กต์ เรามักต้องการคัดลอกพร็อพเพอร์ตี้ *ทั้งหมด* รวมถึงพร็อพเพอร์ตี้ที่ใช้ symbol อย่าง `id` ด้วย

## Global symbol

โดยปกติ symbol ทุกตัวเป็นคนละค่ากัน แม้จะมีชื่อเดียวกัน แต่บางครั้งเราก็ต้องการให้ symbol ที่ชื่อเหมือนกันหมายถึงค่าเดียวกัน เช่น ส่วนต่าง ๆ ของแอปพลิเคชันต้องเข้าถึงพร็อพเพอร์ตี้เดียวกันผ่าน symbol `"id"`

กรณีนี้ใช้ *global symbol registry* ได้ เราสร้าง symbol เก็บไว้ใน registry แล้วกลับมาเรียกใช้ภายหลัง เมื่อขอ symbol ด้วยชื่อเดิมกี่ครั้ง registry ก็จะคืน symbol ตัวเดิมให้เสมอ

ถ้าต้องการอ่าน symbol จาก registry หรือสร้างขึ้นใหม่เมื่อยังไม่มี ให้ใช้ `Symbol.for(key)`

เมธอดนี้จะค้นหา global registry ก่อน ถ้ามี symbol ที่ใช้ `key` นั้นอยู่แล้วก็คืนค่ากลับมา ถ้ายังไม่มีก็สร้าง `Symbol(key)` แล้วเก็บไว้ใน registry ด้วย `key` ที่กำหนด

ตัวอย่าง:

```js run
// อ่าน symbol จาก global registry
let id = Symbol.for("id"); // ถ้ายังไม่มี symbol นี้ ก็จะสร้างขึ้นใหม่

// อ่านอีกครั้ง อาจมาจากโค้ดคนละส่วน
let idAgain = Symbol.for("id");

// ทั้งสองตัวคือ symbol เดียวกัน
alert( id === idAgain ); // true
```

Symbol ที่อยู่ใน registry เรียกว่า *global symbol* ถ้าต้องการ symbol ที่โค้ดทุกส่วนในแอปพลิเคชันเข้าถึงร่วมกันได้ ก็ใช้ global symbol

```smart header="ฟังดูเหมือน Ruby"
ในภาษาโปรแกรมบางภาษา เช่น Ruby แต่ละชื่อจะมี symbol อยู่เพียงตัวเดียว

ส่วน JavaScript จะเป็นแบบนั้นเฉพาะ global symbol
```

### Symbol.keyFor

เราใช้ `Symbol.for(key)` หา global symbol จากชื่อได้ ในทางกลับกัน ถ้าต้องการหาชื่อจาก global symbol ให้ใช้ `Symbol.keyFor(sym)`:

ตัวอย่าง:

```js run
// หา symbol จากชื่อ
let sym = Symbol.for("name");
let sym2 = Symbol.for("id");

// หาชื่อจาก symbol
alert( Symbol.keyFor(sym) ); // name
alert( Symbol.keyFor(sym2) ); // id
```

`Symbol.keyFor` ค้นหาคีย์ใน global symbol registry จึงใช้ได้เฉพาะ global symbol เท่านั้น ถ้าส่ง symbol ทั่วไปเข้าไป เมธอดจะคืนค่า `undefined` เพราะหา symbol นั้นใน registry ไม่เจอ

อย่างไรก็ตาม symbol ทุกตัวมีพร็อพเพอร์ตี้ `description`

ตัวอย่าง:

```js run
let globalSymbol = Symbol.for("name");
let localSymbol = Symbol("name");

alert( Symbol.keyFor(globalSymbol) ); // name เพราะเป็น global symbol
alert( Symbol.keyFor(localSymbol) ); // undefined เพราะไม่ใช่ global symbol

alert( localSymbol.description ); // name
```

## Symbol ที่ระบบใช้

JavaScript มี symbol ของระบบอยู่หลายตัว ภาษานำ symbol เหล่านี้ไปใช้ภายใน และเราก็นำมาปรับพฤติกรรมบางอย่างของออบเจ็กต์ได้

ดูรายการทั้งหมดได้จากตาราง [Well-known symbols](https://tc39.github.io/ecma262/#sec-well-known-symbols) ใน specification เช่น:

- `Symbol.hasInstance`
- `Symbol.isConcatSpreadable`
- `Symbol.iterator`
- `Symbol.toPrimitive`
- และอื่น ๆ

ตัวอย่างเช่น `Symbol.toPrimitive` เปิดให้เรากำหนดวิธีแปลงออบเจ็กต์เป็นค่าพื้นฐานได้ อีกไม่นานเราจะได้เห็นวิธีใช้

ส่วน symbol ตัวอื่น ๆ จะทยอยปรากฏในบทที่อธิบายฟีเจอร์ของภาษาซึ่งเกี่ยวข้องกับ symbol เหล่านั้น

## สรุป

`Symbol` เป็นชนิดข้อมูลพื้นฐานสำหรับสร้างตัวระบุที่ไม่ซ้ำกัน

เราสร้าง symbol ด้วย `Symbol()` และจะใส่คำอธิบายหรือชื่อกำกับไว้ก็ได้

Symbol ที่สร้างแต่ละตัวเป็นคนละค่ากันเสมอ แม้จะใช้ชื่อเดียวกัน ถ้าต้องการให้ symbol ชื่อเดียวกันเป็นค่าเดียวกัน ให้ใช้ global registry

`Symbol.for(key)` จะคืน global symbol ที่มี `key` เป็นชื่อ หรือสร้างขึ้นใหม่ถ้ายังไม่มี เมื่อเรียก `Symbol.for` หลายครั้งด้วย `key` เดิม เราจะได้ symbol ตัวเดิมทุกครั้ง

Symbol มีกรณีใช้งานหลักสองอย่าง:

1. พร็อพเพอร์ตี้ที่ "ซ่อนอยู่" ในออบเจ็กต์

    ถ้าต้องการเพิ่มพร็อพเพอร์ตี้ลงในออบเจ็กต์ที่ "เป็นของ" สคริปต์หรือไลบรารีอื่น เราสร้าง symbol แล้วใช้เป็นคีย์ได้ เมื่อพร็อพเพอร์ตี้นี้ไม่ปรากฏใน `for..in` ลูปก็จะไม่หยิบไปประมวลผลปนกับพร็อพเพอร์ตี้อื่นโดยบังเอิญ ส่วนโค้ดอื่นก็เข้าถึงโดยตรงไม่ได้หากไม่มี symbol ตัวเดียวกับเรา จึงไม่เผลอใช้งานหรือเขียนทับพร็อพเพอร์ตี้นี้

    วิธีนี้ช่วยให้เราเก็บข้อมูลไว้ในออบเจ็กต์ที่ต้องใช้ร่วมกับโค้ดอื่น โดยไม่ให้โค้ดนั้นหยิบข้อมูลไปใช้โดยบังเอิญ

2. JavaScript มี symbol ของระบบหลายตัวให้เรียกผ่าน `Symbol.*` เราใช้ symbol เหล่านี้ปรับพฤติกรรมที่ภาษามีให้อยู่แล้วได้ เช่น ในบทถัด ๆ ไป เราจะใช้ `Symbol.iterator` กับ [iterable](info:iterable) และใช้ `Symbol.toPrimitive` เพื่อกำหนดวิธี[แปลงออบเจ็กต์เป็นค่าพื้นฐาน](info:object-toprimitive) เป็นต้น

ในทางเทคนิค symbol ไม่ได้ถูกซ่อนอย่างสมบูรณ์ เมธอด [Object.getOwnPropertySymbols(obj)](mdn:js/Object/getOwnPropertySymbols) ใช้ดึงคีย์ที่เป็น symbol ทั้งหมดซึ่งออบเจ็กต์มีอยู่เอง ส่วน [Reflect.ownKeys(obj)](mdn:js/Reflect/ownKeys) จะคืนคีย์ *ทั้งหมด* ที่ออบเจ็กต์มีอยู่เอง รวมถึง symbol ด้วย

แต่ไลบรารี ฟังก์ชันที่มีมากับภาษา และ syntax ส่วนใหญ่ไม่ใช้เมธอดเหล่านี้
