# โครงสร้างโค้ด

เรื่องแรกที่เราจะเรียนคือส่วนประกอบพื้นฐานของโค้ด

## คำสั่ง

อยากให้โปรแกรมทำอะไรสักอย่าง เราจะบอกมันยังไง?

ก็เขียนเป็นคำสั่ง (statement) เพื่อบอกให้โปรแกรมทำงานตามที่ต้องการ

ก่อนหน้านี้เราได้เห็น `alert('Hello, world!')` กันไปแล้ว คำสั่งนี้จะแสดงข้อความ "Hello, world!"

ในโค้ดหนึ่งชุดจะมีกี่คำสั่งก็ได้ โดยใช้เซมิโคลอน (`;`) คั่นแต่ละคำสั่ง

ตัวอย่างนี้แบ่ง "Hello World" ออกเป็น `alert` สองคำสั่ง:

```js run no-beautify
alert('Hello'); alert('World');
```

แต่ปกติเราจะแยกแต่ละคำสั่งไว้คนละบรรทัด เพื่อให้อ่านง่ายขึ้น:

```js run no-beautify
alert('Hello');
alert('World');
```

## เซมิโคลอน [#semicolon]

ถ้าขึ้นบรรทัดใหม่ เรามักจะละเซมิโคลอนได้

โค้ดนี้จึงทำงานได้เหมือนกัน:

```js run no-beautify
alert('Hello')
alert('World')
```

ตรงนี้ JavaScript จะถือว่าการขึ้นบรรทัดใหม่คือการใส่เซมิโคลอนโดยอัตโนมัติ กลไกนี้เรียกว่า [automatic semicolon insertion](https://tc39.github.io/ecma262/#sec-automatic-semicolon-insertion)

**ส่วนใหญ่การขึ้นบรรทัดใหม่จะหมายถึงมีเซมิโคลอน แต่ "ส่วนใหญ่" ไม่ได้แปลว่า "เสมอไป"**

บางกรณี JavaScript จะไม่ใส่เซมิโคลอนตรงบรรทัดใหม่ เช่น:

```js run no-beautify
alert(3 +
1
+ 2);
```

โค้ดนี้แสดงผลเป็น `6` เพราะ JavaScript ไม่ได้ใส่เซมิโคลอนให้ จะเห็นว่าบรรทัดแรกลงท้ายด้วยเครื่องหมายบวก `+` แสดงว่านิพจน์ยังไม่จบ

ถ้าใส่เซมิโคลอนตรงนั้นโค้ดก็จะผิด กรณีนี้จึงทำงานได้อย่างที่เราต้องการ

**แต่ก็มีบางกรณีที่ JavaScript ไม่ใส่เซมิโคลอน ทั้งที่ตรงนั้นจำเป็นต้องมี**

error จากกรณีแบบนี้มักหาต้นเหตุและแก้ได้ยาก

````smart header="ตัวอย่าง error"
ถ้าอยากเห็นว่า error แบบนี้เกิดขึ้นได้อย่างไร ลองดูโค้ดนี้:

```js run
alert("Hello");

[1, 2].forEach(alert);
```

ตอนนี้ยังไม่ต้องสนใจว่า `[]` กับ `forEach` หมายถึงอะไร เราจะได้เรียนกันในภายหลัง จำไว้ก่อนว่าเมื่อรันโค้ดนี้ จะเห็น `Hello` ตามด้วย `1` และ `2`

ทีนี้ลองลบเซมิโคลอนหลัง `alert` ออก:

```js run no-beautify
alert("Hello")

[1, 2].forEach(alert);
```

โค้ดต่างจากเดิมแค่ตัวอักษรเดียว คือเซมิโคลอนท้ายบรรทัดแรกหายไป

เมื่อรันแล้วจะเห็นเพียง `Hello` จากนั้นก็เกิด error ซึ่งอาจต้องเปิดคอนโซลจึงจะเห็น ส่วนเลข `1` กับ `2` จะไม่แสดงออกมา

สาเหตุคือ JavaScript ไม่ได้ใส่เซมิโคลอนให้ก่อนวงเล็บก้ามปู `[...]` จึงมองโค้ดสองบรรทัดนี้เป็นคำสั่งเดียว

JavaScript engine จะอ่านโค้ดเหมือนเขียนไว้แบบนี้:

```js run no-beautify
alert("Hello")[1, 2].forEach(alert);
```

ดูแปลกใช่ไหม? การรวมคำสั่งแบบนี้ทำให้โค้ดผิด เราต้องใส่เซมิโคลอนหลัง `alert` โค้ดจึงจะทำงานตามที่ตั้งใจ

ปัญหาเดียวกันนี้เกิดกับโค้ดรูปแบบอื่นได้ด้วย
````

เราแนะนำให้ใส่เซมิโคลอนคั่นทุกคำสั่ง แม้จะแยกไว้คนละบรรทัดแล้วก็ตาม แนวทางนี้ใช้กันอย่างแพร่หลาย แม้ส่วนใหญ่จะละเซมิโคลอนได้ แต่การใส่ไว้ปลอดภัยกว่า โดยเฉพาะสำหรับมือใหม่

## คอมเมนต์ [#code-comments]

เมื่อโปรแกรมซับซ้อนขึ้น เราจำเป็นต้องใส่ *คอมเมนต์* เพื่ออธิบายว่าโค้ดทำอะไรและทำไมจึงเขียนแบบนั้น

เราใส่คอมเมนต์ไว้ตรงไหนของสคริปต์ก็ได้ คอมเมนต์ไม่กระทบการทำงาน เพราะ JavaScript engine จะข้ามข้อความเหล่านั้นไป

**คอมเมนต์บรรทัดเดียวเริ่มด้วยเครื่องหมายทับสองตัว `//`**

ทุกอย่างตั้งแต่ `//` ไปจนถึงท้ายบรรทัดจะเป็นคอมเมนต์ จะเขียนแยกไว้ทั้งบรรทัดหรือต่อท้ายคำสั่งก็ได้

ตัวอย่างเช่น:

```js run
// คอมเมนต์นี้อยู่แยกหนึ่งบรรทัด
alert('Hello');

alert('World'); // คอมเมนต์นี้อยู่ท้ายคำสั่ง
```

**คอมเมนต์หลายบรรทัดเริ่มด้วยเครื่องหมายทับและดอกจัน <code>/&#42;</code> แล้วปิดด้วยดอกจันและเครื่องหมายทับ <code>&#42;/</code>**

ตัวอย่างเช่น:

```js run
/* ตัวอย่างการแสดงข้อความสองครั้ง
นี่คือคอมเมนต์หลายบรรทัด
*/
alert('Hello');
alert('World');
```

ข้อความในคอมเมนต์จะถูกข้ามทั้งหมด โค้ดที่ใส่ไว้ระหว่าง <code>/&#42; ... &#42;/</code> ก็จะไม่ทำงานไปด้วย

วิธีนี้มีประโยชน์เมื่อต้องการปิดโค้ดบางส่วนไว้ชั่วคราว:

```js run
/* ปิดโค้ดส่วนนี้ไว้
alert('Hello');
*/
alert('World');
```

```smart header="ใช้ปุ่มลัดใส่คอมเมนต์ได้"
editor ส่วนใหญ่ใช้ `key:Ctrl+/` เพื่อเปลี่ยนโค้ดหนึ่งบรรทัดเป็นคอมเมนต์ หากต้องการคอมเมนต์หลายบรรทัด ให้เลือกโค้ดแล้วกด `key:Ctrl+Shift+/` หรือปุ่มลัดที่ใกล้เคียงกัน บน Mac ให้ลองใช้ `key:Cmd` แทน `key:Ctrl` และ `key:Option` แทน `key:Shift`
```

````warn header="คอมเมนต์ซ้อนกันไม่ได้"
เราใส่ <code>/&#42; ... &#42;/</code> ซ้อนไว้ข้างใน <code>/&#42; ... &#42;/</code> อีกชุดไม่ได้

โค้ดแบบนี้จะเกิด error:

```js run no-beautify
/*
  /* คอมเมนต์ซ้อนกัน ?!? */
*/
alert( 'World' );
```
````

ไม่ต้องลังเลที่จะใส่คอมเมนต์ในโค้ด

คอมเมนต์ทำให้ไฟล์โค้ดใหญ่ขึ้นจริง แต่ไม่ใช่ปัญหา เพราะมีเครื่องมือมากมายที่ช่วยย่อขนาดโค้ดก่อนนำขึ้นเซิร์ฟเวอร์ production เครื่องมือเหล่านี้จะลบคอมเมนต์ออกจากสคริปต์ที่นำไปใช้งานจริง

คอมเมนต์จึงไม่กระทบการทำงานบน production

ในบท <info:code-quality> เราจะได้เรียนวิธีเขียนคอมเมนต์ให้ดีขึ้น
