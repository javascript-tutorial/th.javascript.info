# โครงสร้างโค้ด

ก่อนจะลงลึก มาดูส่วนประกอบพื้นฐานของโค้ดกันก่อน — statements (คำสั่ง) กับ comments (คอมเมนต์)

## Statements (คำสั่ง)

statement ก็คือคำสั่งที่บอกให้โปรแกรมทำอะไรสักอย่าง

ที่เห็นมาแล้วก็คือ `alert('Hello, world!')` — เป็นคำสั่งให้โชว์ข้อความ "Hello, world!" นั่นเอง

เขียน statement ในโค้ดได้หลายอันเลย แค่คั่นแต่ละอันด้วยเครื่องหมายเซมิโคลอน (`;`)

เช่น แยก "Hello World" ออกเป็น 2 alert ก็แบบนี้:

```js run no-beautify
alert('Hello'); alert('World');
```

ปกติแล้วเรามักเขียนแยกคนละบรรทัด อ่านง่ายกว่าเยอะ:

```js run no-beautify
alert('Hello');
alert('World');
```

## เซมิโคลอน (Semicolons) [#semicolon]

ในหลายๆ กรณี JavaScript ยอมให้ละเซมิโคลอนได้ถ้าขึ้นบรรทัดใหม่

เช่น โค้ดนี้ก็ทำงานได้เหมือนกัน:

```js run no-beautify
alert('Hello')
alert('World')
```

JavaScript จะมองว่าการขึ้นบรรทัดใหม่เท่ากับใส่เซมิโคลอนให้เลย ท่านี้เรียกว่า [Automatic Semicolon Insertion](https://tc39.github.io/ecma262/#sec-automatic-semicolon-insertion)

**แต่ "ส่วนใหญ่" ไม่ได้แปลว่า "เสมอไป" นะ!**

มีบางสถานการณ์ที่การขึ้นบรรทัดใหม่ไม่นับเป็นการใส่เซมิโคลอน เช่น:

```js run no-beautify
alert(3 +
1
+ 2);
```

ผลลัพธ์ออกมาเป็น `6` เพราะ JavaScript ไม่ได้แอบใส่เซมิโคลอนให้ตรงนั้น engine รู้เองว่าถ้าบรรทัดจบด้วย `+` แสดงว่า expression ยังไม่จบ ใส่เซมิโคลอนตรงนั้นไปก็ผิด — กรณีนี้ก็เลยทำงานได้ตรงตามที่เราต้องการ

**แต่มีอีกหลายสถานการณ์ที่ JavaScript "ไม่ได้" ใส่เซมิโคลอนให้ในจุดที่ควรจะมี**

error ที่เกิดจากการลืมเซมิโคลอนแบบนี้ มักจะหาต้นเหตุยากมากๆ

````smart header="ตัวอย่าง error"
อยากเห็นตัวอย่างไหม? ลองดูโค้ดนี้:

```js run
alert("Hello");

[1, 2].forEach(alert);
```

ยังไม่ต้องสนใจ `[]` กับ `forEach` ตอนนี้ ยังไม่ได้เรียนหรอก จำแค่ว่าโค้ดนี้จะโชว์ `Hello` แล้วตามด้วย `1` กับ `2` ทีละตัว

ทีนี้ลองลบเซมิโคลอนหลัง `alert` ออก:

```js run no-beautify
alert("Hello")

[1, 2].forEach(alert);
```

ต่างจากเดิมแค่ตัวอักษรเดียว — เซมิโคลอน `;` ท้ายบรรทัดแรก

ลองรันดู — จะโชว์ `Hello` แล้วพ่น error ออกมา (อาจต้องเปิดคอนโซลถึงจะเห็น) เลข 1 กับ 2 ไม่โผล่เลย

ที่เป็นแบบนี้เพราะ JavaScript ไม่ได้แอบใส่เซมิโคลอนให้ก่อนวงเล็บก้ามปู `[...]` ทำให้โค้ดทั้งสองบรรทัดถูกมองรวมกันเป็นคำสั่งเดียว

จริงๆ แล้ว engine มองเห็นโค้ดเป็นแบบนี้:

```js run no-beautify
alert("Hello")[1, 2].forEach(alert);
```

ดูแปลกๆ ใช่ไหม? แบบนี้มันผิดแน่นอน ต้องใส่เซมิโคลอนหลัง `alert` ถึงจะทำงานได้

ปัญหาแบบนี้แอบโผล่มาในสถานการณ์อื่นได้อีกเยอะ
````

แนะนำให้ใส่เซมิโคลอนคั่น statement ทุกครั้ง แม้จะขึ้นบรรทัดใหม่แล้วก็ตาม แนวทางนี้เป็นที่ยอมรับกันในวงกว้าง แม้ *จะ* ละได้ในหลายๆ กรณี แต่โดยเฉพาะกับมือใหม่ ใส่ไว้ตลอดปลอดภัยกว่าเยอะ

## Comments (คอมเมนต์)

พอโปรแกรมเริ่มซับซ้อนขึ้น *คอมเมนต์* ก็จำเป็น — เอาไว้อธิบายว่าโค้ดทำอะไร และทำไมถึงเขียนแบบนี้

คอมเมนต์ใส่ตรงไหนของสคริปต์ก็ได้ ไม่กระทบการทำงานเลย เพราะ engine จะข้ามไปหมด

**คอมเมนต์บรรทัดเดียว เริ่มด้วย `//`**

ทุกอย่างหลัง `//` จนถึงท้ายบรรทัดจะนับเป็นคอมเมนต์ จะเขียนแยกบรรทัดหรือต่อท้าย statement ก็ได้

แบบนี้:

```js run
// คอมเมนต์นี้เป็นบรรทัดเดียว
alert('Hello');

alert('World'); // คอมเมนต์นี้ต่อท้าย statement
```

**คอมเมนต์หลายบรรทัด เริ่มด้วย <code>/&#42;</code> แล้วปิดด้วย <code>&#42;/</code>**

แบบนี้:

```js run
/* ตัวอย่างที่มีสองข้อความ
นี่คือคอมเมนต์
หลายบรรทัด
*/
alert('Hello');
alert('World');
```

เนื้อหาในคอมเมนต์จะโดนข้ามไปทั้งหมด ไม่ถูกรัน — ถ้าใส่โค้ดลงไปใน <code>/&#42; ... &#42;/</code> โค้ดนั้นก็จะไม่ทำงาน

ท่านี้มีประโยชน์เวลาต้องการปิดโค้ดบางส่วนชั่วคราว:

```js run
/* ใส่คอมเมนต์โค้ดนี้
alert('Hello');
*/
alert('World');
```

```smart header="ใช้ปุ่มลัดใส่คอมเมนต์ได้นะ!"
ใน editor ส่วนใหญ่ กด `key:Ctrl+/` เพื่อใส่คอมเมนต์บรรทัดเดียว ส่วนคอมเมนต์หลายบรรทัด ก็เลือกโค้ดแล้วกด `key:Ctrl+Shift+/` (บน Mac ใช้ `key:Cmd` แทน `key:Ctrl` และ `key:Option` แทน `key:Shift`)
```

````warn header="ห้ามซ้อนคอมเมนต์!"
ห้ามมี <code>/&#42; ... &#42;/</code> ซ้อนอยู่ข้างใน <code>/&#42; ... &#42;/</code> อีกอันนะ

โค้ดแบบนี้พ่น error:

```js run no-beautify
/*
  /* คอมเมนต์ซ้อนกัน ?!? */
*/
alert( 'World' );
```
````

อย่าลังเลที่จะใส่คอมเมนต์เยอะๆ

อาจกังวลว่าจะทำให้ไฟล์โค้ดบวมขึ้น — ไม่ต้องห่วง มีเครื่องมือมากมายช่วย minify สคริปต์ก่อนเอาขึ้น production ตัดคอมเมนต์ทิ้งหมด ไม่กระทบการทำงานจริงเลย
