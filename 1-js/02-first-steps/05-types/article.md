# ชนิดข้อมูล

ทุกค่าใน JavaScript มีชนิดข้อมูลกำกับเสมอ เช่น `string` หรือ `number`

JavaScript มีชนิดข้อมูลพื้นฐาน 8 ชนิด — บทนี้จะดูภาพรวมของแต่ละตัวก่อน ส่วนรายละเอียดแยกไว้ในบทถัดๆ ไป

ตัวแปรตัวเดียวอาจเก็บ `string` ตอนหนึ่ง แล้วเปลี่ยนเป็น `number` ตอนต่อมาก็ได้:

```js
// ไม่มี error
let message = "hello";
message = 123456;
```

ภาษาที่ยอมให้ทำแบบนี้ได้อย่าง JavaScript เรียกว่าภาษาแบบ "dynamically typed" — แปลว่ามีชนิดข้อมูลหลากหลาย แต่ตัวแปรไม่ถูกผูกไว้กับชนิดใดชนิดหนึ่งตายตัว

## Number

```js
let n = 123;
n = 12.345;
```

ชนิด *number* ใช้แทนได้ทั้งจำนวนเต็มและทศนิยม

ตัวดำเนินการสำหรับจำนวนก็มีเยอะ — คูณ `*`, หาร `/`, บวก `+`, ลบ `-` และอีกหลายตัว

นอกจากตัวเลขทั่วไปแล้ว ยังมีค่าที่เรียกว่า "ตัวเลขพิเศษ" ซึ่งก็จัดอยู่ในชนิดนี้ด้วย — ได้แก่ `Infinity`, `-Infinity`, และ `NaN`

- `Infinity` หมายถึง [อนันต์](https://en.wikipedia.org/wiki/Infinity) ∞ ในทางคณิตศาสตร์ — เป็นค่าพิเศษที่มากกว่าตัวเลขทุกตัว

    ค่านี้ได้จากการหารด้วยศูนย์:

    ```js run
    alert( 1 / 0 ); // Infinity
    ```

    หรืออ้างถึงตรงๆ ก็ได้:

    ```js run
    alert( Infinity ); // Infinity
    ```

- `NaN` หมายถึงคำนวณผิดพลาด เกิดจากการคำนวณคณิตศาสตร์ที่ไม่ถูกต้องหรือไม่ได้กำหนดไว้ เช่น:

    ```js run
    alert( "not a number" / 2 ); // NaN — การหารแบบนี้ผิด
    ```

    `NaN` มีนิสัย "เหนียว" — เอาไปคำนวณกับอะไรก็จะได้ `NaN` ออกมาเสมอ:

    ```js run
    alert( NaN + 1 ); // NaN
    alert( 3 * NaN ); // NaN
    alert( "not a number" / 2 - 1 ); // NaN
    ```

    เพราะงั้น ถ้ามี `NaN` โผล่มาในนิพจน์ตรงไหนก็ตาม ค่านั้นจะแผ่ไปกินทั้งผลลัพธ์ (มีข้อยกเว้นอย่างเดียวคือ `NaN ** 0` จะได้ `1`)

```smart header="คำนวณคณิตศาสตร์ปลอดภัยไว้ก่อน"
การคำนวณใน JavaScript "ปลอดภัย" — เราจะทำอะไรก็ได้ จะหารด้วยศูนย์ จะเอาสตริงที่ไม่ใช่ตัวเลขมาบวกลบคูณหาร ก็ทำได้

สคริปต์จะไม่ตายด้วย fatal error เด็ดขาด อย่างแย่ที่สุดก็ได้ `NaN` ออกมา
```

ค่าตัวเลขพิเศษพวกนี้จัดอยู่ในชนิด "number" แต่แน่นอนว่าไม่ใช่ตัวเลขในความหมายปกติ

เรื่องของตัวเลขจะลงลึกอีกครั้งในบท <info:number>

## BigInt [#bigint-type]

ใน JavaScript ชนิด "number" เก็บจำนวนเต็มที่มากกว่า <code>(2<sup>53</sup>-1)</code> (ก็คือ `9007199254740991`) หรือเล็กกว่า <code>-(2<sup>53</sup>-1)</code> ได้ "ไม่ปลอดภัย"

ถ้าจะพูดให้แม่นยำ ชนิด "number" เก็บจำนวนที่ใหญ่กว่านั้นได้ (ใหญ่สุดถึง <code>1.7976931348623157 * 10<sup>308</sup></code>) — แต่พ้นช่วงปลอดภัย <code>±(2<sup>53</sup>-1)</code> ไปแล้ว จะเริ่มมีความคลาดเคลื่อนในรายละเอียด เพราะพื้นที่เก็บแบบคงที่ขนาด 64 บิตเก็บทุกหลักไม่ได้ — ค่าที่เก็บก็เลยกลายเป็นค่า "โดยประมาณ"

เช่น สองจำนวนนี้ (ที่อยู่เหนือช่วงปลอดภัยนิดเดียว) ดันมีค่าเท่ากัน:

```js
console.log(9007199254740991 + 1); // 9007199254740992
console.log(9007199254740991 + 2); // 9007199254740992
```

หรือพูดอีกอย่าง — จำนวนเต็มคี่ทุกตัวที่มากกว่า <code>(2<sup>53</sup>-1)</code> เก็บในชนิด "number" ไม่ได้เลย

ในงานส่วนใหญ่ ช่วง <code>±(2<sup>53</sup>-1)</code> ก็เกินพอแล้ว แต่บางครั้งเราต้องการช่วงจำนวนเต็มที่ใหญ่กว่านั้นจริงๆ เช่น งาน cryptography หรือการบอกเวลาในระดับไมโครวินาที

ชนิด `BigInt` ถูกเพิ่มเข้ามาในภาษาเมื่อไม่นานนี้ เอาไว้แทนจำนวนเต็มที่ยาวเท่าไหร่ก็ได้

สร้าง `BigInt` ก็แค่เติม `n` ต่อท้ายจำนวนเต็ม:

```js
// ตัว "n" ต่อท้ายแปลว่าเป็น BigInt
const bigInt = 1234567890123456789012345678901234567890n;
```

`BigInt` ไม่ค่อยได้ใช้บ่อย เลยจะไม่ลงรายละเอียดที่นี่ — ไว้คุยกันยาวๆ ในบท <info:bigint> เปิดอ่านได้ตอนต้องเจอจำนวนขนาดใหญ่มากๆ


```smart header="ปัญหาเรื่อง compatibility"
ตอนนี้ `BigInt` รองรับใน Firefox/Chrome/Edge/Safari แล้ว แต่ยังไม่รองรับใน IE
```

ดูรายละเอียดว่าใช้ได้ในเบราว์เซอร์เวอร์ชันไหนบ้าง ดูได้ที่ [ตาราง BigInt compatibility บน *MDN*](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/BigInt#Browser_compatibility)

## String

ใน JavaScript สตริงต้องครอบด้วยเครื่องหมายคำพูด

```js
let str = "Hello";
let str2 = 'ใช้เครื่องหมายคำพูดเดี่ยวก็ได้';
let phrase = `แทรก ${str} ลงไปก็ได้`;
```

JavaScript มีเครื่องหมายคำพูด 3 แบบ

1. เครื่องหมายคำพูดคู่: `"สวัสดี"`
2. เครื่องหมายคำพูดเดี่ยว: `'สวัสดี'`
3. แบ็กติก (Backticks): <code>&#96;สวัสดี&#96;</code>

แบบคู่กับเดี่ยวเป็นแบบ "ธรรมดา" — ใน JavaScript สองแบบนี้ไม่ต่างกันเลย

ส่วนแบ็กติกมี "ฟีเจอร์พิเศษ" — แทรกตัวแปรและนิพจน์เข้าไปในสตริงได้ โดยครอบด้วย `${…}` แบบนี้:

```js run
let name = "สมชาย";

// แทรกตัวแปร
alert( `สวัสดี *!*${name}*/!*!` ); // สวัสดี สมชาย!

// แทรกนิพจน์
alert( `ผลลัพธ์คือ *!*${1 + 2}*/!*` ); // ผลลัพธ์คือ 3
```

นิพจน์ใน `${…}` จะถูกคำนวณค่าออกมา แล้วเอาผลลัพธ์ไปต่อในสตริง — ใส่อะไรเข้าไปก็ได้ ไม่ว่าจะเป็นตัวแปรอย่าง `name`, นิพจน์คณิตศาสตร์อย่าง `1 + 2`, หรือซับซ้อนกว่านั้น

อย่าลืมว่าท่านี้ใช้ได้แค่กับแบ็กติกเท่านั้นนะ — เครื่องหมายคำพูดแบบอื่นทำไม่ได้!

```js run
alert( "ผลลัพธ์คือ ${1 + 2}" ); // ผลลัพธ์คือ ${1 + 2} (เครื่องหมายคำพูดคู่ไม่แทรกอะไรให้)
```

เรื่องของสตริงจะลงลึกอีกครั้งในบท <info:string>

```smart header="ไม่มีชนิด *character*"
บางภาษามีชนิดพิเศษ "character" ไว้สำหรับอักขระตัวเดียว เช่นในภาษา C กับ Java จะเรียกว่า "char"

แต่ใน JavaScript ไม่มี — มีแค่ `string` ตัวเดียวเท่านั้น สตริงมีอักขระกี่ตัวก็ได้ ตั้งแต่ 0 ตัว (ว่างเปล่า), 1 ตัว, ไปจนถึงเป็นพันตัว
```

## Boolean (ชนิดตรรกะ)

ชนิด boolean มีได้แค่สองค่าเท่านั้น — `true` กับ `false`

ใช้เก็บค่าแบบ ใช่/ไม่ใช่ — `true` แปลว่า "ใช่ ถูกต้อง" ส่วน `false` แปลว่า "ไม่ใช่ ไม่ถูกต้อง"

เช่น:

```js
let nameFieldChecked = true; // ใช่ ช่องชื่อถูกติ๊กแล้ว
let ageFieldChecked = false; // ไม่ ช่องอายุยังไม่ถูกติ๊ก
```

ค่า boolean ยังเป็นผลลัพธ์จากการเปรียบเทียบอีกด้วย:

```js run
let isGreater = 4 > 1;

alert( isGreater ); // true (ผลการเปรียบเทียบคือ "ใช่")
```

เรื่องของ boolean จะลงลึกอีกครั้งในบท <info:logical-operators>

## ค่า "null"

ค่าพิเศษ `null` ไม่ได้อยู่ในชนิดข้อมูลที่พูดมาข้างบนเลย

เป็นชนิดแยกของตัวเอง มีแค่ค่าเดียวคือ `null`:

```js
let age = null;
```

ใน JavaScript `null` ไม่ใช่ "การอ้างถึงออบเจ็กต์ที่ไม่มีจริง" หรือ "null pointer" เหมือนในบางภาษา

แต่เป็นค่าพิเศษที่แทนความหมาย "ไม่มีอะไร", "ว่างเปล่า", หรือ "ไม่รู้ค่า"

ในโค้ดด้านบน `age` เลยแปลว่า "ยังไม่รู้อายุ" นั่นเอง

## ค่า "undefined"

ค่าพิเศษ `undefined` ก็มีคุณลักษณะเป็นของตัวเองเช่นกัน — เป็นชนิดแยก เหมือน `null`

ความหมายของ `undefined` คือ "ยังไม่ได้กำหนดค่า"

ถ้าประกาศตัวแปรแต่ยังไม่กำหนดค่าให้ ค่าของตัวแปรนั้นจะเป็น `undefined`:

```js run
let age;

alert(age); // โชว์ "undefined"
```

จริงๆ แล้วเรากำหนดค่า `undefined` ให้ตัวแปรตรงๆ ก็ได้:

```js run
let age = 100;

// เปลี่ยนค่าเป็น undefined
age = undefined;

alert(age); // โชว์ "undefined"
```

แต่ไม่แนะนำให้ทำแบบนี้ — ปกติจะใช้ `null` แทนความหมาย "ว่างเปล่า" หรือ "ไม่รู้ค่า" ส่วน `undefined` ปล่อยไว้เป็นค่าเริ่มต้นของสิ่งที่ยังไม่ได้กำหนดดีกว่า

## Object และ Symbol

ชนิด `object` พิเศษกว่าชนิดอื่น

ชนิดอื่นๆ ทั้งหมดเรียกว่า "primitive" เพราะค่าแต่ละค่าเก็บได้แค่สิ่งเดียวเท่านั้น (สตริง, ตัวเลข, หรืออะไรก็แล้วแต่) ส่วน object เอาไว้เก็บชุดข้อมูลหรือสิ่งที่มีโครงสร้างซับซ้อนกว่านั้น

ด้วยความสำคัญแบบนี้ object จึงสมควรได้รับการดูแลเป็นพิเศษ เราจะลงรายละเอียดเรื่อง object ในบท <info:object> หลังจากเรียน primitive ครบแล้ว

ส่วน `symbol` เอาไว้สร้าง identifier ที่ไม่ซ้ำกัน ไว้ใช้กับ object — บอกตรงนี้พอเป็นพิธี แต่รายละเอียดเก็บไว้คุยกันหลังเข้าใจเรื่อง object ก่อน

## typeof operator [#type-typeof]

ตัวดำเนินการ `typeof` จะคืนค่าชนิดข้อมูลของ operand ที่ส่งให้ — มีประโยชน์ตอนต้องจัดการค่าหลายชนิด หรือแค่อยากเช็คเร็วๆ ว่าตัวแปรเก็บอะไรอยู่

เรียก `typeof x` จะได้สตริงที่บอกชื่อชนิดข้อมูลกลับมา:

```js
typeof undefined // "undefined"

typeof 0 // "number"

typeof 10n // "bigint"

typeof true // "boolean"

typeof "foo" // "string"

typeof Symbol("id") // "symbol"

*!*
typeof Math // "object"  (1)
*/!*

*!*
typeof null // "object"  (2)
*/!*

*!*
typeof alert // "function"  (3)
*/!*
```

สามบรรทัดสุดท้ายอาจต้องอธิบายเพิ่ม:

1. `Math` เป็น built-in object ที่รวมฟังก์ชันคณิตศาสตร์เอาไว้ — เดี๋ยวเราจะเรียนเพิ่มในบท <info:number> ตรงนี้แค่เอามาเป็นตัวอย่างของ object เฉยๆ
2. ผลลัพธ์ของ `typeof null` คือ `"object"` — อันนี้เป็น error ที่ทางการของ `typeof` ที่มีมาตั้งแต่ยุคแรกๆ ของ JavaScript และยังเก็บไว้เพื่อให้เข้ากันได้กับโค้ดเก่า จริงๆ แล้ว `null` ไม่ใช่ object แต่เป็นค่าพิเศษที่มีชนิดของตัวเอง — พฤติกรรมตรงนี้ของ `typeof` ก็เลยไม่ถูกต้อง
3. ผลลัพธ์ของ `typeof alert` คือ `"function"` เพราะ `alert` เป็นฟังก์ชัน เดี๋ยวเราจะเรียนเรื่องฟังก์ชันในบทถัดๆ ไป — จะเห็นว่า JavaScript ไม่มีชนิด "function" แยกต่างหาก ฟังก์ชันจริงๆ จัดเป็นส่วนหนึ่งของ object — แต่ `typeof` ดันปฏิบัติกับฟังก์ชันต่างจาก object คือคืนค่าเป็น `"function"` ซึ่งเป็นพฤติกรรมที่มีมาตั้งแต่ยุคแรก จริงๆ ไม่ถูกต้องนัก แต่ในทางปฏิบัติก็สะดวกกว่า

```smart header="ไวยากรณ์ `typeof(x)`"
อาจเจออีกแบบ — `typeof(x)` ซึ่งความหมายเหมือนกับ `typeof x`

ขอย้ำให้ชัดๆ — `typeof` เป็นตัวดำเนินการ ไม่ใช่ฟังก์ชัน วงเล็บที่เห็นไม่ใช่ส่วนของ `typeof` แต่เป็นวงเล็บจัดกลุ่มทางคณิตศาสตร์ทั่วไป

ปกติวงเล็บแบบนี้ใช้ครอบนิพจน์เช่น `(2 + 2)` แต่ตรงนี้มีอาร์กิวเมนต์ตัวเดียวคือ `(x)` — ในแง่ไวยากรณ์ ช่วยให้ไม่ต้องเว้นวรรคระหว่างตัวดำเนินการกับอาร์กิวเมนต์ บางคนก็ชอบเขียนแบบนี้

แต่ `typeof x` นิยมกว่า `typeof(x)` มาก
```

## สรุป

JavaScript มีชนิดข้อมูลพื้นฐาน 8 ชนิด ได้แก่

- ชนิด primitive 7 ตัว:
    - `number` สำหรับตัวเลขทุกแบบ ทั้งจำนวนเต็มและทศนิยม จำนวนเต็มมีขอบเขตอยู่ที่ <code>±(2<sup>53</sup>-1)</code>
    - `bigint` สำหรับจำนวนเต็มที่ยาวเท่าไหร่ก็ได้
    - `string` สำหรับข้อความ ยาวกี่ตัวอักษรก็ได้ และไม่มีชนิดแยกสำหรับตัวอักษรตัวเดียว
    - `boolean` สำหรับค่า `true` หรือ `false`
    - `null` สำหรับค่าที่ไม่รู้ เป็นชนิดแยกที่มีค่าเดียวคือ `null`
    - `undefined` สำหรับค่าที่ยังไม่ได้กำหนด เป็นชนิดแยกที่มีค่าเดียวคือ `undefined`
    - `symbol` สำหรับสร้างตัวระบุที่ไม่ซ้ำกัน
- และชนิดที่ไม่ใช่ primitive 1 ตัว:
    - `object` สำหรับโครงสร้างข้อมูลที่ซับซ้อนกว่านั้น

ตัวดำเนินการ `typeof` ช่วยเช็คชนิดข้อมูลที่เก็บในตัวแปร

- ปกติใช้แบบ `typeof x` แต่ `typeof(x)` ก็ใช้ได้เหมือนกัน
- คืนค่าเป็นสตริงที่ระบุชื่อชนิดข้อมูล เช่น `"string"`
- สำหรับ `null` จะได้ `"object"` — ถือเป็น error ในภาษา เพราะจริงๆ แล้ว `null` ไม่ใช่ object

บทถัดๆ ไปเราจะโฟกัสไปที่ค่า primitive ก่อน พอคุ้นแล้วค่อยไปต่อเรื่อง object
