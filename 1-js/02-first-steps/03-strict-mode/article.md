# โหมดสมัยใหม่ "use strict"

JavaScript วิวัฒนาการมานานมาก โดยไม่ค่อยแคร์เรื่อง backward compatibility — เพิ่มฟีเจอร์ใหม่เข้ามาเรื่อยๆ ขณะที่ของเก่ายังทำงานได้เหมือนเดิม

ในแง่หนึ่งก็ดี เพราะโค้ดเก่าไม่พัง แต่อีกแง่ก็แปลว่าทุก error หรือทุกการตัดสินใจที่ไม่ค่อยดีของคนออกแบบภาษา ก็ถูกแบกต่อมาด้วย ไม่หายไปไหน

เป็นแบบนี้มาเรื่อยจนถึงปี 2009 ที่ ECMAScript 5 (ES5) ออกมา — มีฟีเจอร์ใหม่ และมีการปรับปรุงของเดิมหลายอย่าง แต่เพื่อให้โค้ดเก่ายังรันได้ การปรับปรุงพวกนี้เลยถูกปิดไว้เป็นค่าเริ่มต้น ต้องเปิดเองด้วย directive พิเศษชื่อว่า `"use strict"`

## "use strict"

directive ตัวนี้หน้าตาเหมือนสตริงทั่วๆ ไปเลย — `"use strict"` หรือ `'use strict'` วางไว้บนสุดของสคริปต์ ทั้งสคริปต์ก็จะทำงานในโหมด "สมัยใหม่" ทันที

แบบนี้:

```js
"use strict";

// โค้ดนี้จะทำงานในโหมดสมัยใหม่
...
```

อีกไม่นานเราจะได้เรียนเรื่องฟังก์ชัน (วิธีจัดกลุ่มคำสั่ง) ขอบอกไว้ก่อนเลยว่า วาง `"use strict"` ในฟังก์ชันก็ได้ — แค่จะเปิดโหมดเข้มงวดเฉพาะในฟังก์ชันนั้น แต่ปกติแล้วคนนิยมใช้กับทั้งสคริปต์ไปเลย

````warn header="ต้องวาง \"use strict\" ไว้บนสุดของสคริปต์"
ต้องใส่ `"use strict"` ไว้บนสุดของสคริปต์เท่านั้น ไม่งั้นโหมดเข้มงวดจะไม่ถูกเปิด

อย่างในตัวอย่างนี้ โหมดเข้มงวดไม่ทำงาน:

```js no-strict
alert("some code");
// "use strict" ด้านล่างนี้โดนเพิกเฉย -- ต้องอยู่บรรทัดบนสุด

"use strict";

// โหมดเข้มงวดยังไม่เปิดใช้งาน
```

อย่างเดียวที่วางไว้เหนือ `"use strict"` ได้คือคอมเมนต์เท่านั้น
````

```warn header="ปิด `use strict` ไม่ได้นะ"
ไม่มี directive แบบ `"no use strict"` ที่จะย้อนพฤติกรรมกลับไปแบบเก่าได้

พอเข้าโหมดเข้มงวดแล้ว ก็ไปต่อทางเดียว ไม่มีทางย้อนกลับ
```

## คอนโซลเบราว์เซอร์

เวลาใช้ [คอนโซลของ developer tools](info:devtools) รันโค้ด สังเกตว่าคอนโซลไม่ได้เปิด `use strict` ไว้ให้โดยอัตโนมัติ

บางครั้งพฤติกรรมของ `use strict` ต่างจากแบบปกติ ก็อาจได้ผลลัพธ์ที่ไม่ตรงกับที่คิด

แล้วจะใช้ `use strict` ในคอนโซลได้ยังไง?

วิธีแรก ลองกด `key:Shift+Enter` เพื่อพิมพ์หลายบรรทัด แล้ววาง `use strict` ไว้บรรทัดแรก แบบนี้:

```js
'use strict'; <Shift+Enter เพื่อขึ้นบรรทัดใหม่>
//  ...โค้ดของเรา
<Enter เพื่อรันโค้ด>
```

ใช้ได้กับเบราว์เซอร์ส่วนใหญ่ เช่น Firefox กับ Chrome

ถ้าไม่ได้ผล (เช่นในเบราว์เซอร์รุ่นเก่า) มีอีกท่าหนึ่ง — อาจดูไม่หรูแต่ได้ผลแน่นอน นั่นคือห่อโค้ดด้วยฟังก์ชันแบบนี้:

```js
(function() {
  'use strict';

  // ...โค้ดของเราอยู่ตรงนี้...
})()
```

## ควรใช้ "use strict" ไหม?

คำถามดูเหมือนตอบง่าย แต่จริงๆ ไม่เลย

หลายคนอาจแนะนำให้ขึ้นต้นสคริปต์ทุกตัวด้วย `"use strict"`... แต่รู้อะไรไหม? มีเรื่องน่าสนใจกว่านั้น

JavaScript สมัยใหม่มี "classes" กับ "modules" ซึ่งเป็นโครงสร้างขั้นสูง (เดี๋ยวเราจะได้เรียนกันแน่ๆ) — สองตัวนี้เปิด `use strict` ให้อัตโนมัติอยู่แล้ว เลยไม่ต้องเขียน directive `"use strict"` เพิ่ม

**สรุปสั้นๆ: ตอนนี้ `"use strict"` เป็นเหมือนแขกที่น่าเชื้อเชิญไว้ต้นสคริปต์ แต่ในอนาคตเมื่อโค้ดทั้งหมดอยู่ใน class กับ module กันหมด ก็จะละทิ้งไปได้**

ตอนนี้ก็พอรู้จัก `use strict` ในภาพรวมแล้ว

บทถัดๆ ไปพอเรียนฟีเจอร์ของภาษาแต่ละอย่าง เราจะเห็นความต่างระหว่างโหมดเข้มงวดกับโหมดปกติ — โชคดีที่ต่างกันไม่เยอะ และพูดตรงๆ โหมดเข้มงวดช่วยให้ชีวิตเราสบายขึ้นด้วยซ้ำ

ทุกตัวอย่างในบทเรียนนี้จะถือว่าใช้โหมดเข้มงวด ยกเว้นที่ระบุไว้เป็นอย่างอื่น (ซึ่งเจอน้อยมาก)
