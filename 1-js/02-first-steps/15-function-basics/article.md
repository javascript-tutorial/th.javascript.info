# ฟังก์ชัน

หลายครั้งเราต้องให้สคริปต์ทำงานแบบเดิมซ้ำกันหลายจุด

เช่น แสดงข้อความตอนผู้ใช้เข้าสู่ระบบ ออกจากระบบ หรือในจุดอื่น

ฟังก์ชันคือส่วนประกอบหลักอย่างหนึ่งของโปรแกรม เราเขียนขั้นตอนไว้ครั้งเดียวแล้วเรียกใช้ซ้ำได้ทุกที่ที่ต้องการ

ก่อนหน้านี้เราใช้ฟังก์ชันที่ JavaScript มีมาให้แล้ว เช่น `alert(message)`, `prompt(message, default)` และ `confirm(question)` บทนี้เราจะมาสร้างฟังก์ชันของตัวเองกัน

## การประกาศฟังก์ชัน

วิธีหนึ่งในการสร้างฟังก์ชันคือใช้ *การประกาศฟังก์ชัน* (function declaration)

หน้าตาเป็นแบบนี้:

```js
function showMessage() {
  alert( 'Hello everyone!' );
}
```

เริ่มจากคีย์เวิร์ด `function` ตามด้วย *ชื่อฟังก์ชัน* แล้วใส่ *พารามิเตอร์* ไว้ในวงเล็บ ถ้ามีหลายตัวให้คั่นด้วยจุลภาค ตัวอย่างนี้ยังไม่มีพารามิเตอร์ วงเล็บจึงว่างอยู่ ส่วนคำสั่งในวงเล็บปีกกาเรียกว่า "เนื้อหาของฟังก์ชัน" (function body)

```js
function name(parameter1, parameter2, ... parameterN) {
  // เนื้อหาฟังก์ชัน
}
```

เมื่อสร้างเสร็จแล้ว เราเรียกฟังก์ชันด้วยชื่อได้ เช่น `showMessage()`

ลองเรียกสองครั้งติดกัน:

```js run
function showMessage() {
  alert( 'Hello everyone!' );
}

*!*
showMessage();
showMessage();
*/!*  
```

ทุกครั้งที่เรียก `showMessage()` โค้ดในฟังก์ชันจะทำงาน ตัวอย่างนี้จึงแสดงข้อความสองครั้ง

ตัวอย่างนี้แสดงประโยชน์สำคัญของฟังก์ชัน: เราเรียกใช้โค้ดชุดเดิมซ้ำได้โดยไม่ต้องเขียนใหม่

ถ้าต้องการเปลี่ยนข้อความหรือวิธีแสดงผล ก็แก้เพียงจุดเดียวในฟังก์ชัน

## ตัวแปรภายใน

ตัวแปรที่ประกาศไว้ในฟังก์ชันจะใช้ได้เฉพาะภายในฟังก์ชันนั้น

ตัวอย่างเช่น:

```js run
function showMessage() {
*!*
  let message = "Hello, I'm JavaScript!"; // ตัวแปรภายในฟังก์ชัน
*/!*

  alert( message );
}

showMessage(); // Hello, I'm JavaScript!

alert( message ); // <-- เกิดข้อผิดพลาด! ตัวแปรภายในใช้จากด้านนอกไม่ได้
```

## ตัวแปรภายนอก

ฟังก์ชันเข้าถึงตัวแปรที่ประกาศไว้นอกฟังก์ชันได้ด้วย:

```js run no-beautify
let *!*userName*/!* = 'John';

function showMessage() {
  let message = 'Hello, ' + *!*userName*/!*;
  alert(message);
}

showMessage(); // Hello, John
```

นอกจากอ่านค่าแล้ว ฟังก์ชันยังเปลี่ยนค่าตัวแปรภายนอกได้

ลองดูตัวอย่าง:

```js run
let *!*userName*/!* = 'John';

function showMessage() {
  *!*userName*/!* = "Bob"; // (1) เปลี่ยนค่าตัวแปรภายนอก

  let message = 'Hello, ' + *!*userName*/!*;
  alert(message);
}

alert( userName ); // *!*John*/!* ก่อนเรียกฟังก์ชัน

showMessage();

alert( userName ); // *!*Bob*/!*, ฟังก์ชันเปลี่ยนค่าแล้ว
```

ฟังก์ชันจะใช้ตัวแปรภายนอกก็ต่อเมื่อภายในฟังก์ชันไม่มีตัวแปรชื่อเดียวกัน

ถ้าประกาศตัวแปรชื่อซ้ำกันไว้ในฟังก์ชัน ตัวแปรภายในจะ *บดบัง* ตัวแปรภายนอก โค้ดต่อไปนี้จึงใช้ `userName` ภายในฟังก์ชัน โดยไม่ใช้ตัวแปรภายนอกชื่อเดียวกัน:

```js run
let userName = 'John';

function showMessage() {
*!*
  let userName = "Bob"; // ประกาศตัวแปรภายในฟังก์ชัน
*/!*

  let message = 'Hello, ' + userName; // *!*Bob*/!*
  alert(message);
}

// ฟังก์ชันจะสร้างและใช้ userName ของตัวเอง
showMessage();

alert( userName ); // *!*John*/!*, ค่าเดิม เพราะฟังก์ชันไม่ได้ใช้ตัวแปรภายนอก
```

```smart header="ตัวแปรโกลบอล"
ตัวแปรที่ประกาศไว้นอกทุกฟังก์ชันเรียกว่า *ตัวแปรโกลบอล* เช่น ตัวแปรภายนอก `userName` ในตัวอย่างก่อนหน้า

ทุกฟังก์ชันเข้าถึงตัวแปรโกลบอลได้ เว้นแต่จะมีตัวแปรภายในชื่อเดียวกันมาบดบัง

ควรใช้ตัวแปรโกลบอลให้น้อยที่สุด โค้ดสมัยใหม่มักมีตัวแปรโกลบอลเพียงไม่กี่ตัวหรือไม่มีเลย เพราะเก็บตัวแปรส่วนใหญ่ไว้ในฟังก์ชันที่ใช้งาน แต่บางครั้งตัวแปรโกลบอลก็เหมาะสำหรับเก็บข้อมูลที่ต้องใช้ร่วมกันทั้งโปรเจกต์
```

## พารามิเตอร์

เราใช้พารามิเตอร์เพื่อส่งข้อมูลอะไรก็ได้เข้าไปให้ฟังก์ชัน

ฟังก์ชันต่อไปนี้มีพารามิเตอร์ 2 ตัว คือ `from` กับ `text`:

```js run
function showMessage(*!*from, text*/!*) { // พารามิเตอร์: from, text
  alert(from + ': ' + text);
}

*!*showMessage('Ann', 'Hello!');*/!* // Ann: Hello! (*)
*!*showMessage('Ann', "What's up?");*/!* // Ann: What's up? (**)
```

เมื่อเรียกฟังก์ชันในบรรทัด `(*)` และ `(**)` JavaScript จะคัดลอกค่าที่ส่งเข้ามาไว้ในตัวแปรภายใน `from` กับ `text` แล้วฟังก์ชันจึงนำสองค่านี้ไปใช้

ลองดูอีกตัวอย่าง เราสร้างตัวแปร `from` แล้วส่งค่าของมันเข้าไปในฟังก์ชัน แม้ฟังก์ชันจะเปลี่ยน `from` แต่ตัวแปรภายนอกยังมีค่าเดิม เพราะฟังก์ชันได้รับเพียงสำเนาของค่า:

```js run
function showMessage(from, text) {

*!*
  from = '*' + from + '*'; // ตกแต่ง "from" ให้อ่านง่ายขึ้น
*/!*

  alert( from + ': ' + text );
}

let from = "Ann";

showMessage(from, "Hello"); // *Ann*: Hello

// ค่า "from" ยังเหมือนเดิม เพราะฟังก์ชันเปลี่ยนเฉพาะสำเนา
alert( from ); // Ann
```

ค่าที่ส่งให้ฟังก์ชันตอนเรียกใช้เรียกว่า *อาร์กิวเมนต์*

สรุปความต่างของสองคำนี้:

- พารามิเตอร์คือตัวแปรที่เขียนไว้ในวงเล็บตอนประกาศฟังก์ชัน
- อาร์กิวเมนต์คือค่าที่ส่งให้ฟังก์ชันตอนเรียกใช้

เวลา *ประกาศ* ฟังก์ชันเราจึงระบุพารามิเตอร์ ส่วนเวลา *เรียก* ฟังก์ชันเราส่งอาร์กิวเมนต์

จากตัวอย่างข้างบน เราพูดได้ว่า "ฟังก์ชัน `showMessage` ประกาศด้วยพารามิเตอร์ 2 ตัว และตอนเรียกใช้เราให้อาร์กิวเมนต์เป็น `from` กับ `"Hello"`"

## ค่าเริ่มต้น

ถ้าเรียกฟังก์ชันโดยไม่ส่งอาร์กิวเมนต์ให้พารามิเตอร์ตัวใด พารามิเตอร์ตัวนั้นจะมีค่าเป็น `undefined`

อย่างฟังก์ชัน `showMessage(from, text)` ที่เพิ่งใช้ไป เราเรียกโดยส่งอาร์กิวเมนต์เพียงตัวเดียวได้:

```js
showMessage("Ann");
```

โค้ดนี้ไม่ทำให้เกิดข้อผิดพลาด แต่จะแสดง `"*Ann*: undefined"` เพราะเราไม่ได้ส่งค่าให้ `text` ค่าของมันจึงเป็น `undefined`

ถ้าต้องการใช้ค่าอื่นแทนเมื่อไม่มีอาร์กิวเมนต์ เรากำหนด *ค่าเริ่มต้น* ให้พารามิเตอร์ด้วย `=` ตอนประกาศฟังก์ชันได้:

```js run
function showMessage(from, *!*text = "no text given"*/!*) {
  alert( from + ": " + text );
}

showMessage("Ann"); // Ann: no text given
```

ทีนี้ถ้าไม่ได้ส่งอาร์กิวเมนต์ให้ `text` ค่าของมันจะเป็น `"no text given"`

JavaScript จะใช้ค่าเริ่มต้นด้วยถ้าอาร์กิวเมนต์ที่ส่งให้มีค่าเป็น `undefined`:

```js
showMessage("Ann", undefined); // Ann: no text given
```

ตัวอย่างนี้ใช้สตริง `"no text given"` เป็นค่าเริ่มต้น แต่เราจะใช้นิพจน์ที่ซับซ้อนกว่านั้นก็ได้ JavaScript จะคำนวณนิพจน์นี้และนำผลลัพธ์มาใช้เฉพาะตอนที่ไม่ได้ส่งอาร์กิวเมนต์ให้พารามิเตอร์นั้น หรือส่ง `undefined`:

```js run
function showMessage(from, text = anotherFunction()) {
  // เรียก anotherFunction() เฉพาะเมื่อไม่ได้ส่ง text หรือส่ง undefined
  // แล้วนำผลลัพธ์มาเป็นค่าของ text
}
```

```smart header="JavaScript คำนวณค่าเริ่มต้นเมื่อไร"
JavaScript จะคำนวณค่าเริ่มต้นทุกครั้งที่เรียกฟังก์ชันโดยไม่ได้ส่งอาร์กิวเมนต์ให้พารามิเตอร์ตัวนั้น หรือส่ง `undefined`

ในตัวอย่างข้างบน ถ้าส่งค่าที่ไม่ใช่ `undefined` ให้ `text` แล้ว JavaScript จะไม่เรียก `anotherFunction()`

ถ้าไม่ได้ส่งอาร์กิวเมนต์ให้ `text` หรือส่ง `undefined` JavaScript จะเรียก `anotherFunction()` ใหม่ทุกครั้ง โดยไม่นำผลลัพธ์จากครั้งก่อนกลับมาใช้
```

````smart header="พารามิเตอร์เริ่มต้นในโค้ด JavaScript เก่า"
JavaScript ในอดีตยังไม่รองรับรูปแบบพารามิเตอร์เริ่มต้น นักพัฒนาจึงต้องกำหนดค่าเริ่มต้นด้วยวิธีอื่น

ทุกวันนี้เรายังอาจเจอวิธีเหล่านี้ในสคริปต์เก่า

วิธีแรกคือตรวจค่า `undefined` โดยตรง:

```js
function showMessage(from, text) {
*!*
  if (text === undefined) {
    text = 'no text given';
  }
*/!*

  alert( from + ": " + text );
}
```

อีกวิธีคือใช้ตัวดำเนินการ `||`:

```js  
function showMessage(from, text) {
  // ถ้า text เป็น falsy ให้ใช้ค่าเริ่มต้น
  // วิธีนี้ถือว่า text == "" ไม่ต่างจากการไม่มี text
  text = text || 'no text given';
  ...
}
```
````

### กำหนดค่าเริ่มต้นภายในฟังก์ชัน

บางครั้งเราอาจต้องรอให้ฟังก์ชันเริ่มทำงานก่อน แล้วค่อยกำหนดค่าเริ่มต้นให้พารามิเตอร์

วิธีตรงไปตรงมาคือตรวจว่าพารามิเตอร์เป็น `undefined` หรือไม่:

```js run
function showMessage(text) {
  // ...

*!*
  if (text === undefined) { // ถ้า text เป็น undefined
    text = 'empty message';
  }
*/!*

  alert(text);
}

showMessage(); // empty message
```

หรือจะใช้ตัวดำเนินการ `||` ก็ได้:

```js
function showMessage(text) {
  // ถ้า text เป็น undefined หรือ falsy ค่าอื่น ให้ใช้ 'empty'
  text = text || 'empty';
  ...  
}
```

JavaScript รุ่นใหม่รองรับ [ตัวดำเนินการ nullish coalescing](info:nullish-coalescing-operator) `??` ตัวนี้เหมาะกว่าเมื่อค่า falsy (ค่าที่ JavaScript มองเป็น `false` เมื่อนำไปใช้เป็นเงื่อนไข) อย่าง `0` ยังถือเป็นค่าปกติที่ต้องนำไปใช้:

```js run
function showCount(count) {
  // ถ้า count เป็น undefined หรือ null ให้แสดง "unknown"
  alert(count ?? "unknown");
}

showCount(0); // 0
showCount(null); // unknown 
showCount(); // unknown
```

## การคืนค่า

ฟังก์ชันส่งผลลัพธ์กลับไปให้โค้ดที่เรียกใช้ได้

ตัวอย่างง่าย ๆ คือฟังก์ชันที่บวกตัวเลขสองตัว:

```js run no-beautify
function sum(a, b) {
  *!*return*/!* a + b;
}

let result = sum(1, 2);
alert( result ); // 3
```

เราเขียน `return` ไว้ตรงไหนในฟังก์ชันก็ได้ เมื่อทำงานมาถึงจุดนั้น ฟังก์ชันจะหยุดและคืนค่าให้โค้ดที่เรียกใช้ ในตัวอย่างข้างบน โค้ดเก็บค่าที่ฟังก์ชันคืนมาไว้ใน `result`

ฟังก์ชันเดียวมี `return` หลายจุดได้:

```js run
function checkAge(age) {
  if (age >= 18) {
*!*
    return true;
*/!*
  } else {
*!*
    return confirm('Do you have permission from your parents?');
*/!*
  }
}

let age = prompt('How old are you?', 18);

if ( checkAge(age) ) {
  alert( 'Access granted' );
} else {
  alert( 'Access denied' );
}
```

เราจะใช้ `return` โดยไม่ตามด้วยค่าก็ได้ เพื่อหยุดการทำงานของฟังก์ชันทันที

ตัวอย่างเช่น:

```js
function showMovie(age) {
  if ( !checkAge(age) ) {
*!*
    return;
*/!*
  }

  alert( "Showing you the movie" ); // (*)
  // ...
}
```

ถ้า `checkAge(age)` คืนค่า `false` ฟังก์ชัน `showMovie` จะจบลงตรง `return` และไม่ทำงานต่อไปถึง `alert`

````smart header="ฟังก์ชันที่มี `return` ว่างหรือไม่มี `return` จะคืน `undefined`"
ถ้าฟังก์ชันไม่คืนค่า ผลลัพธ์จะเหมือนกับการคืนค่า `undefined`:

```js run
function doNothing() { /* ว่าง */ }

alert( doNothing() === undefined ); // true
```

ส่วน `return` ที่ไม่มีค่าตามหลังก็มีผลเหมือน `return undefined`:

```js run  
function doNothing() {
  return;
}

alert( doNothing() === undefined ); // true
```
````

````warn header="อย่าขึ้นบรรทัดใหม่ระหว่าง `return` กับค่าที่คืน"
ถ้านิพจน์ที่จะคืนค่ายาวมาก เราอาจอยากย้ายไปขึ้นบรรทัดใหม่แบบนี้:

```js
return
 (some + long + expression + or + whatever * f(a) + f(b))
```
แต่โค้ดนี้ใช้ไม่ได้ เพราะ JavaScript จะเติมเซมิโคลอนหลัง `return` ให้โดยอัตโนมัติ จึงทำงานเหมือนโค้ดต่อไปนี้:

```js  
return*!*;*/!*
 (some + long + expression + or + whatever * f(a) + f(b))
```

สุดท้าย `return` จึงไม่มีค่าตามหลัง

ถ้าต้องการแบ่งนิพจน์ออกเป็นหลายบรรทัด ให้เริ่มนิพจน์ในบรรทัดเดียวกับ `return` หรืออย่างน้อยใส่วงเล็บเปิดไว้ในบรรทัดนั้น:

```js
return (
  some + long + expression
  + or +
  whatever * f(a) + f(b)
  )
```

แบบนี้ JavaScript จะรู้ว่านิพจน์ยังไม่จบและคืนค่าได้ตามที่ต้องการ
````

## การตั้งชื่อฟังก์ชัน [#function-naming]

ฟังก์ชันใช้ทำงานบางอย่าง ชื่อฟังก์ชันจึงมักเป็นคำกริยา ชื่อที่ดีควรสั้น ตรงความหมาย และบอกได้ว่าฟังก์ชันทำอะไร คนที่อ่านโค้ดจะได้เข้าใจหน้าที่ของมันโดยไม่ต้องเปิดดูเนื้อหาข้างใน

วิธีที่นิยมใช้คือขึ้นต้นชื่อด้วยคำที่บอกลักษณะงานคร่าว ๆ และตกลงกันในทีมว่าคำนำหน้าแต่ละคำมีความหมายอย่างไร

เช่น ฟังก์ชันที่ขึ้นต้นด้วย `"show"` มักมีหน้าที่แสดงบางอย่าง

คำนำหน้าที่พบบ่อยมีดังนี้:

- `"get…"` — อ่านหรือหาค่าแล้วคืนค่านั้น
- `"calc…"` — คำนวณแล้วคืนผลลัพธ์
- `"create…"` — สร้างสิ่งใหม่
- `"check…"` — ตรวจสอบเงื่อนไขแล้วคืนค่าบูลีน เป็นต้น

ตัวอย่างเช่น:

```js no-beautify
showMessage(..)     // แสดงข้อความ
getAge(..)          // หาค่าอายุแล้วคืนค่านั้น
calcSum(..)         // คำนวณผลรวมและคืนผลลัพธ์
createForm(..)      // สร้างฟอร์ม (และมักจะคืนฟอร์มนั้นกลับมา)
checkPermission(..) // ตรวจสอบสิทธิ์แล้วคืนค่า true/false
```

เมื่อทีมใช้คำนำหน้าเหล่านี้สม่ำเสมอ แค่อ่านชื่อก็พอรู้ว่าฟังก์ชันทำงานแบบไหนและน่าจะคืนค่าอะไร

```smart header="หนึ่งฟังก์ชัน — หนึ่งการกระทำ"
ฟังก์ชันควรทำเฉพาะงานที่ชื่อบอกไว้ ไม่ควรแอบทำงานอื่นเพิ่ม

ถ้ามีงานสองอย่างที่แยกจากกันได้ ก็ควรแยกเป็นสองฟังก์ชัน แม้ปกติจะเรียกใช้งานคู่กันก็ตาม ถ้าจำเป็น เราสร้างฟังก์ชันที่สามขึ้นมาเรียกสองฟังก์ชันนั้นตามลำดับได้

ตัวอย่างที่ไม่ควรทำ:

- `getAge` — ไม่ควรเรียก `alert` เพื่อแสดงอายุ เพราะชื่อบอกเพียงว่าจะอ่านค่าอายุ
- `createForm` — ไม่ควรเพิ่มฟอร์มลงในเอกสาร เพราะชื่อบอกเพียงว่าจะสร้างฟอร์มและคืนค่า
- `checkPermission` — ไม่ควรแสดงข้อความว่าอนุญาตหรือปฏิเสธ เพราะชื่อบอกเพียงว่าจะตรวจสอบและคืนผลลัพธ์

ตัวอย่างเหล่านี้อิงความหมายทั่วไปของแต่ละคำนำหน้า ทีมจะตกลงใช้ความหมายอื่นก็ได้ แม้ปกติจะไม่ต่างจากนี้มากนัก จุดสำคัญคือทุกคนต้องเข้าใจตรงกันว่าฟังก์ชันที่ใช้คำนำหน้านั้นทำอะไรได้และทำอะไรไม่ได้ รวมถึงใช้กติกาเดียวกันกับทุกฟังก์ชันที่ขึ้นต้นเหมือนกัน
```

```smart header="ชื่อฟังก์ชันที่สั้นมาก"
ฟังก์ชันที่เราเรียกใช้ *บ่อยมาก* อาจมีชื่อสั้นเป็นพิเศษ

ตัวอย่างเช่น เฟรมเวิร์ก [jQuery](https://jquery.com/) มีฟังก์ชันชื่อ `$` ส่วนไลบรารี [Lodash](https://lodash.com/) ใช้ `_` เป็นชื่อฟังก์ชันหลัก

สองชื่อนี้เป็นข้อยกเว้น โดยทั่วไปชื่อฟังก์ชันควรกระชับและบอกหน้าที่ให้ชัดเจน
```

## ฟังก์ชันทำหน้าที่เหมือนคอมเมนต์

ฟังก์ชันควรสั้นและรับผิดชอบงานเดียว ถ้างานนั้นใหญ่เกินไป ลองแบ่งออกเป็นฟังก์ชันเล็ก ๆ หลายตัว แม้จะทำได้ไม่ง่ายทุกครั้ง แต่โค้ดที่ได้มักดูแลง่ายกว่า

ฟังก์ชันที่แยกหน้าที่ชัดเจนไม่เพียงทดสอบและแก้บั๊กง่ายขึ้น แต่ชื่อของมันยังช่วยอธิบายว่าโค้ดส่วนนั้นกำลังทำอะไร

ลองเปรียบเทียบฟังก์ชัน `showPrimes(n)` สองแบบต่อไปนี้ ทั้งคู่รับ `n` เป็นขอบเขตแล้วแสดง [จำนวนเฉพาะ](https://en.wikipedia.org/wiki/Prime_number)

แบบแรกใช้ป้ายกำกับ (label) เพื่อข้ามไปตรวจเลขตัวถัดไป:

```js
function showPrimes(n) {
  nextPrime: for (let i = 2; i < n; i++) {

    for (let j = 2; j < i; j++) {
      if (i % j == 0) continue nextPrime;
    }

    alert( i ); // จำนวนเฉพาะ
  }
}
```

แบบที่สองแยกการตรวจว่าเป็นจำนวนเฉพาะหรือไม่ออกไปไว้ในฟังก์ชัน `isPrime(n)`:

```js
function showPrimes(n) {

  for (let i = 2; i < n; i++) {
    *!*if (!isPrime(i)) continue;*/!*

    alert(i);  // จำนวนเฉพาะ
  }
}

function isPrime(n) {
  for (let i = 2; i < n; i++) {
    if ( n % i == 0) return false;
  }
  return true;
}
```

แบบที่สองอ่านง่ายกว่า เพราะเพียงเห็นชื่อ `isPrime` เราก็รู้ทันทีว่าโค้ดกำลังตรวจว่าตัวเลขเป็นจำนวนเฉพาะหรือไม่ โดยไม่ต้องไล่แกะลูปด้านใน โค้ดลักษณะนี้มักเรียกว่าโค้ดที่ *อธิบายตัวเอง* (self-describing)

เพราะฉะนั้น เราสร้างฟังก์ชันได้แม้จะไม่ได้ตั้งใจเรียกซ้ำ จุดประสงค์อาจเป็นเพียงการจัดโครงสร้างและทำให้โค้ดอ่านง่ายขึ้น

## สรุป

รูปแบบของการประกาศฟังก์ชันคือ:

```js
function name(parameters, delimited, by, comma) {
  /* โค้ด */
}
```

- JavaScript จะคัดลอกค่าที่ส่งให้ฟังก์ชันมาเก็บไว้ในพารามิเตอร์ ซึ่งเป็นตัวแปรภายใน
- ฟังก์ชันเข้าถึงตัวแปรภายนอกได้ แต่โค้ดภายนอกเข้าถึงตัวแปรภายในฟังก์ชันไม่ได้
- ฟังก์ชันคืนค่าได้ ถ้าไม่ได้คืนค่า ผลลัพธ์จะเป็น `undefined`

โค้ดจะอ่านง่ายกว่าเมื่อฟังก์ชันใช้พารามิเตอร์และตัวแปรภายในเป็นหลัก แทนที่จะพึ่งตัวแปรภายนอก

ฟังก์ชันที่รับข้อมูลผ่านพารามิเตอร์ ประมวลผล แล้วคืนผลลัพธ์ มักเข้าใจง่ายกว่าฟังก์ชันที่ไม่รับพารามิเตอร์แต่เปลี่ยนตัวแปรภายนอกเป็นผลข้างเคียง

การตั้งชื่อฟังก์ชัน:

- ชื่อควรบอกชัดเจนว่าฟังก์ชันทำอะไรและคืนค่าอะไร
- ฟังก์ชันทำงานบางอย่าง ชื่อฟังก์ชันจึงมักเป็นคำกริยา
- คำนำหน้าอย่าง `create…`, `show…`, `get…` และ `check…` ช่วยบอกลักษณะงานของฟังก์ชันได้

ฟังก์ชันเป็นส่วนประกอบหลักของสคริปต์ เมื่อเข้าใจพื้นฐานในบทนี้แล้ว เราก็เริ่มสร้างและเรียกใช้ฟังก์ชันเองได้ และจะได้กลับมาเรียนเรื่องฟังก์ชันอีกหลายครั้งเพื่อทำความรู้จักความสามารถที่ลึกขึ้น
