# ฟังก์ชัน

บ่อยครั้งที่เราต้องทำของคล้ายๆ กันในหลายๆ จุดของสคริปต์

เช่น เราอาจต้องโชว์ข้อความที่ดูดีๆ ตอนผู้ใช้ login, logout, หรือที่อื่นๆ

ฟังก์ชันเป็น "บล็อกสร้าง" หลักของโปรแกรม — ช่วยให้เรียกใช้โค้ดเดิมซ้ำได้โดยไม่ต้องเขียนใหม่

เราคุ้นกับฟังก์ชัน built-in มาแล้ว เช่น `alert(message)`, `prompt(message, default)`, และ `confirm(question)` — แต่เราสร้างฟังก์ชันของตัวเองก็ได้

## การประกาศฟังก์ชัน

วิธีสร้างฟังก์ชัน ใช้ *การประกาศฟังก์ชัน*

รูปแบบเป็นแบบนี้:

```js
function showMessage() {
  alert( 'Hello everyone!' );
}
```

ใช้คีย์เวิร์ด `function` ก่อน ตามด้วย *ชื่อฟังก์ชัน* แล้วก็ list ของ *พารามิเตอร์* ในวงเล็บ (คั่นด้วยจุลภาค — ในตัวอย่างข้างบนเว้นว่าง เดี๋ยวจะมีตัวอย่างอีก) สุดท้ายคือโค้ดของฟังก์ชันในวงเล็บปีกกา ที่เรียกว่า "ตัวฟังก์ชัน" หรือ "function body"

```js
function name(parameter1, parameter2, ... parameterN) {
  // ตัวฟังก์ชัน
}
```

เรียกใช้ฟังก์ชันด้วยชื่อของมัน เช่น `showMessage()`

ตัวอย่าง:

```js run
function showMessage() {
  alert( 'Hello everyone!' );
}

*!*
showMessage();
showMessage();
*/!*  
```

พอเรียก `showMessage()` ก็จะรันโค้ดในตัวฟังก์ชัน — ในที่นี้เราจะเห็นข้อความโชว์สองครั้ง

ตัวอย่างนี้แสดงให้เห็นวัตถุประสงค์หลักของฟังก์ชัน — เพื่อเลี่ยงการเขียนโค้ดซ้ำ

ถ้าอยากเปลี่ยนข้อความหรือวิธีโชว์ ก็แก้โค้ดที่เดียว — ในตัวฟังก์ชันที่รับหน้าที่โชว์

## ตัวแปรภายในฟังก์ชัน (Local variables)

ตัวแปรที่ประกาศในฟังก์ชัน จะมองเห็นได้เฉพาะในฟังก์ชันนั้นเท่านั้น

เช่น:

```js run
function showMessage() {
*!*
  let message = "Hello, I'm JavaScript!"; // ตัวแปรภายในฟังก์ชัน
*/!*

  alert( message );
}

showMessage(); // Hello, I'm JavaScript!

alert( message ); // <-- Error! ตัวแปรอยู่ภายในฟังก์ชัน ไม่สามารถเข้าถึงจากภายนอกได้
```

## ตัวแปรภายนอก (Outer variables)

ฟังก์ชันเข้าถึงตัวแปรภายนอกได้ด้วย เช่น:

```js run no-beautify
let *!*userName*/!* = 'John';

function showMessage() {
  let message = 'Hello, ' + *!*userName*/!*;
  alert(message);
}

showMessage(); // Hello, John
```

ฟังก์ชันเข้าถึงตัวแปรภายนอกได้เต็มที่ — แก้ไขค่าก็ได้ด้วย

เช่น:

```js run
let *!*userName*/!* = 'John';

function showMessage() {
  *!*userName*/!* = "Bob"; // (1) เปลี่ยนค่าตัวแปรภายนอก

  let message = 'Hello, ' + *!*userName*/!*;
  alert(message);
}

alert( userName ); // *!*John*/!* ก่อนเรียกฟังก์ชัน

showMessage();

alert( userName ); // *!*Bob*/!*, ค่าถูกเปลี่ยนโดยฟังก์ชัน  
```

ตัวแปรภายนอกจะถูกใช้ก็ต่อเมื่อไม่มีตัวแปรภายในฟังก์ชันชื่อเดียวกัน

ถ้ามีการประกาศตัวแปรชื่อซ้ำในฟังก์ชัน ตัวแปรนั้นจะ *บดบัง* ตัวแปรภายนอก เช่น ในโค้ดข้างล่าง ฟังก์ชันจะใช้ `userName` ของตัวเอง ส่วนตัวภายนอกจะถูกมองข้าม:

```js run
let userName = 'John';

function showMessage() {
*!*
  let userName = "Bob"; // ประกาศตัวแปรภายในฟังก์ชัน
*/!*

  let message = 'Hello, ' + userName; // *!*Bob*/!*
  alert(message);
}

// ฟังก์ชันจะสร้างและใช้ userName ของตัวเอง
showMessage();

alert( userName ); // *!*John*/!*, ไม่เปลี่ยนแปลง เพราะฟังก์ชันไม่ได้เข้าถึงตัวแปรภายนอก
```

```smart header="ตัวแปรโกลบอล (Global variables)"
ตัวแปรที่ประกาศนอกฟังก์ชันใดๆ เช่น `userName` ภายนอกในตัวอย่างข้างต้น เรียกว่า *ตัวแปรโกลบอล*

ตัวแปรโกลบอลมองเห็นได้จากทุกฟังก์ชัน (ยกเว้นจะถูกบดบังโดยตัวแปรภายในฟังก์ชัน)

แนวทางที่ดีคือลดการใช้ตัวแปรโกลบอลให้น้อยที่สุด — โค้ดยุคใหม่มักมีตัวแปรโกลบอลน้อยมากหรือไม่มีเลย ตัวแปรส่วนใหญ่อยู่ในฟังก์ชันของตัวเอง — แต่บางครั้งตัวแปรโกลบอลก็มีประโยชน์ในการเก็บข้อมูลระดับโปรเจกต์
```

## พารามิเตอร์ (Parameters)

เราส่งข้อมูลอะไรเข้าไปในฟังก์ชันก็ได้ผ่านพารามิเตอร์

ในตัวอย่างข้างล่าง ฟังก์ชันมีพารามิเตอร์ 2 ตัว — `from` กับ `text`

```js run
function showMessage(*!*from, text*/!*) { // พารามิเตอร์: from, text
  alert(from + ': ' + text);
}

*!*showMessage('Ann', 'Hello!');*/!* // Ann: Hello! (*)
*!*showMessage('Ann', "What's up?");*/!* // Ann: What's up? (**)
```

พอฟังก์ชันถูกเรียกในบรรทัด `(*)` และ `(**)` ค่าที่ส่งเข้าไปจะถูกก็อปไปเป็นตัวแปรภายในฟังก์ชัน `from` กับ `text` แล้วฟังก์ชันก็เอาตัวแปรพวกนั้นไปใช้

นี่คืออีกตัวอย่าง — เรามีตัวแปร `from` แล้วส่งเข้าไปในฟังก์ชัน สังเกตว่า ฟังก์ชันเปลี่ยนค่า `from` แต่การเปลี่ยนแปลงนั้นไม่กระทบภายนอก เพราะฟังก์ชันจะได้รับสำเนาของค่าเสมอ:

```js run
function showMessage(from, text) {

*!*
  from = '*' + from + '*'; // ทำให้ "from" ดูสวยงามขึ้น
*/!*

  alert( from + ': ' + text );
}

let from = "Ann";

showMessage(from, "Hello"); // *Ann*: Hello

// ค่าของ "from" ยังเหมือนเดิม ฟังก์ชันแก้ไขสำเนาในตัวเอง
alert( from ); // Ann  
```

เวลาที่ค่าถูกส่งเข้าไปเป็นพารามิเตอร์ของฟังก์ชัน เราเรียกค่านั้นว่า *อาร์กิวเมนต์ (argument)*

พูดให้ชัดเจน:

- พารามิเตอร์ คือตัวแปรที่ระบุในวงเล็บตอนประกาศฟังก์ชัน (เป็นคำศัพท์ตอนประกาศ)
- อาร์กิวเมนต์ คือค่าที่ส่งเข้าไปตอนเรียกใช้ฟังก์ชัน (เป็นคำศัพท์ตอนเรียกใช้)

เราประกาศฟังก์ชันโดยระบุพารามิเตอร์ไว้ — แล้วเรียกใช้โดยส่งอาร์กิวเมนต์เข้าไป

ในตัวอย่างข้างบนก็จะพูดได้ว่า "ฟังก์ชัน `showMessage` ถูกประกาศด้วยพารามิเตอร์ 2 ตัว แล้วถูกเรียกใช้ด้วยอาร์กิวเมนต์สองตัวคือ `from` และ `"Hello"`"

## ค่าเริ่มต้น (Default values)

ถ้าเรียกใช้ฟังก์ชันแต่ไม่ได้ส่งอาร์กิวเมนต์มาด้วย ค่าที่สอดคล้องกันจะกลายเป็น `undefined`

เช่น ฟังก์ชัน `showMessage(from, text)` ที่พูดถึงก่อนหน้า เรียกใช้ด้วยอาร์กิวเมนต์ตัวเดียวก็ได้:

```js
showMessage("Ann");
```

ไม่ใช่ error นะ — แค่จะโชว์ออกมาเป็น `"*Ann*: undefined"` เพราะไม่ได้ส่งค่าให้พารามิเตอร์ `text` ก็เลยมีค่าเป็น `undefined`

เราระบุ "ค่าเริ่มต้น" (default value — ใช้เมื่อไม่ได้ส่งค่ามา) ให้พารามิเตอร์ตอนประกาศฟังก์ชันได้ ผ่าน `=`:

```js run
function showMessage(from, *!*text = "no text given"*/!*) {
  alert( from + ": " + text );
}

showMessage("Ann"); // Ann: no text given
```

ทีนี้ถ้าไม่ได้ส่งพารามิเตอร์ `text` มา ค่าของมันจะเป็น `"no text given"`

ค่าเริ่มต้นจะถูกใช้ด้วยถ้าพารามิเตอร์มีอยู่แต่ค่าเป็น `undefined` ตรงๆ แบบนี้:

```js
showMessage("Ann", undefined); // Ann: no text given
```

ในที่นี้ `"no text given"` เป็นสตริง — แต่ค่าเริ่มต้นจะเป็นนิพจน์ที่ซับซ้อนกว่านั้นก็ได้ — จะถูกคำนวณและกำหนดให้เฉพาะเมื่อไม่ได้ส่งพารามิเตอร์มาเท่านั้น เช่น:

```js run
function showMessage(from, text = anotherFunction()) {
  // anotherFunction() จะถูกเรียกเฉพาะเมื่อไม่ได้ส่ง text มา
  // ผลลัพธ์ของมันจะกลายเป็นค่าของ text
}
```

```smart header="คำนวณค่าพารามิเตอร์เริ่มต้น"
ใน JavaScript พารามิเตอร์เริ่มต้นจะถูกคำนวณใหม่ทุกครั้งที่เรียกใช้ฟังก์ชันโดยไม่ส่งพารามิเตอร์ที่เกี่ยวข้องเข้ามา

ในตัวอย่างข้างบน `anotherFunction()` จะไม่ถูกเรียกเลยถ้าส่งพารามิเตอร์ `text` มา

แต่จะถูกเรียกใหม่ทุกครั้งที่ไม่ได้ส่ง `text` มา
```

````smart header="พารามิเตอร์เริ่มต้นในโค้ด JavaScript เก่า"
หลายปีก่อน JavaScript ยังไม่รองรับไวยากรณ์พารามิเตอร์เริ่มต้น คนก็เลยใช้ท่าอื่นในการระบุค่าเริ่มต้น

ทุกวันนี้เราอาจเจอท่าพวกนี้ในสคริปต์เก่าๆ

เช่น เช็ค `undefined` ตรงๆ:

```js
function showMessage(from, text) {
*!*
  if (text === undefined) {
    text = 'no text given';
  }
*/!*

  alert( from + ": " + text );
}
```

...หรือใช้ตัวดำเนินการ `||`:

```js  
function showMessage(from, text) {
  // ถ้าค่าของ text เป็น falsy ให้กำหนดค่าเริ่มต้น
  // ซึ่งสมมติว่า text == "" เหมือนกับไม่มี text เลย
  text = text || 'no text given';
  ...
}
```
````

### พารามิเตอร์เริ่มต้นแบบทางเลือก

บางครั้งการกำหนดค่าเริ่มต้นให้พารามิเตอร์ทีหลัง หลังประกาศฟังก์ชันไปแล้ว ก็มีเหตุผลเหมือนกัน

เราเช็คได้ว่ามีการส่งพารามิเตอร์มาหรือเปล่าระหว่างที่ฟังก์ชันทำงาน — โดยเทียบกับ `undefined`:

```js run
function showMessage(text) {
  // ...

*!*
  if (text === undefined) { // ถ้าไม่มีพารามิเตอร์ส่งมา
    text = 'empty message';
  }
*/!*

  alert(text);
}

showMessage(); // ข้อความว่าง
```

...หรือเราสามารถใช้ตัวดำเนินการ `||`:

```js
function showMessage(text) {
  // ถ้า text เป็น undefined หรือ falsy อื่นๆ ให้กำหนดเป็น 'empty'
  text = text || 'empty';
  ...  
}
```

JavaScript engine ยุคใหม่รองรับ [ตัวดำเนินการ nullish coalescing](info:nullish-coalescing-operator) `??` ซึ่งเหมาะกว่าเมื่ออยากให้ค่า falsy ส่วนใหญ่อย่าง `0` ถือเป็นค่า "ปกติ":

```js run
function showCount(count) {
  // ถ้า count เป็น undefined หรือ null ให้แสดง "unknown"
  alert(count ?? "unknown");
}

showCount(0); // 0
showCount(null); // unknown 
showCount(); // unknown
```

## การคืนค่า (Returning a value)

ฟังก์ชันคืนค่ากลับไปยังโค้ดที่เรียกใช้เป็นผลลัพธ์ได้

ตัวอย่างง่ายๆ คือฟังก์ชันบวกค่าสองค่า:

```js run no-beautify
function sum(a, b) {
  *!*return*/!* a + b;
}

let result = sum(1, 2);
alert( result ); // 3
```

คำสั่ง `return` อยู่ที่ไหนก็ได้ในฟังก์ชัน — พอโปรแกรมทำงานมาถึง `return` ฟังก์ชันจะหยุดทันทีและคืนค่ากลับไปยังโค้ดที่เรียกใช้ (เก็บใน `result` ในตัวอย่างข้างต้น)

ในฟังก์ชันเดียวมี `return` ได้หลายจุดเลย เช่น:

```js run
function checkAge(age) {
  if (age >= 18) {
*!*
    return true;
*/!*
  } else {
*!*
    return confirm('Do you have permission from your parents?');
*/!*
  }
}

let age = prompt('How old are you?', 18);

if ( checkAge(age) ) {
  alert( 'Access granted' );
} else {
  alert( 'Access denied' );
}
```

ใช้ `return` โดยไม่มีค่าก็ได้ — จะทำให้ฟังก์ชันจบทันที

เช่น:

```js
function showMovie(age) {
  if ( !checkAge(age) ) {
*!*
    return;
*/!*
  }

  alert( "Showing you the movie" ); // (*)
  // ...
}
```

ในโค้ดข้างบน ถ้า `checkAge(age)` คืนค่า `false` ฟังก์ชัน `showMovie` ก็จะไม่ทำงานต่อไปที่ `alert`

````smart header="ฟังก์ชันที่มี `return` ว่างหรือไม่มี `return` จะคืน `undefined`"
ถ้าฟังก์ชันไม่ได้คืนค่า ก็เหมือนกับคืนค่า `undefined`:

```js run
function doNothing() { /* ว่าง */ }

alert( doNothing() === undefined ); // true
```

`return` ว่างก็เหมือนกับ `return undefined`:

```js run  
function doNothing() {
  return;
}

alert( doNothing() === undefined ); // true
```
````

````warn header="อย่าขึ้นบรรทัดใหม่ระหว่าง `return` กับค่าที่คืน"
สำหรับนิพจน์ยาวๆ ใน `return` อาจอยากแยกเป็นบรรทัดใหม่ แบบนี้:

```js
return
 (some + long + expression + or + whatever * f(a) + f(b))
```
แบบนั้นไม่ทำงาน — เพราะ JavaScript จะถือว่ามีเซมิโคลอนหลัง `return` — ทำงานเหมือนกับ:

```js  
return*!*;*/!*
 (some + long + expression + or + whatever * f(a) + f(b))
```

มันก็เลยกลายเป็น return เปล่าๆ ไปเลย

ถ้าอยากให้นิพจน์ที่คืนค่าขึ้นบรรทัดใหม่ ต้องเริ่มต้นในบรรทัดเดียวกับ `return` หรืออย่างน้อยใส่วงเล็บเปิดไว้ตรงนั้น แบบนี้:

```js
return (
  some + long + expression
  + or +
  whatever * f(a) + f(b)
  )
```

แค่นี้ก็ทำงานตามที่คิดได้แล้ว
````

## การตั้งชื่อฟังก์ชัน [#function-naming]

ฟังก์ชันคือการกระทำ — ชื่อก็เลยมักเป็นคำกริยา ควรสั้นกระชับ ตรงประเด็น และบอกได้ชัดเจนว่าฟังก์ชันทำอะไร เพื่อให้คนอ่านโค้ดเข้าใจทันทีว่าฟังก์ชันนั้นทำหน้าที่อะไร

แนวทางที่ใช้กันแพร่หลายคือ ขึ้นต้นชื่อฟังก์ชันด้วยคำกริยาเพื่อบอกการกระทำคร่าวๆ ทีมควรตกลงกันให้ชัดเจนว่าคำนำหน้าแต่ละตัวหมายถึงอะไร

เช่น ฟังก์ชันที่ขึ้นต้นด้วย `"show"` มักจะโชว์อะไรสักอย่าง

ฟังก์ชันที่ขึ้นต้นด้วย...

- `"get…"` — คืนค่าอะไรสักอย่าง
- `"calc…"` — คำนวณอะไรสักอย่าง
- `"create…"` — สร้างอะไรสักอย่าง
- `"check…"` — เช็คอะไรสักอย่างแล้วคืนค่า boolean ฯลฯ

ตัวอย่างชื่อฟังก์ชันแบบนี้:

```js no-beautify
showMessage(..)     // โชว์ข้อความ
getAge(..)          // คืนค่าอายุ (ได้มาด้วยท่าใดท่าหนึ่ง)
calcSum(..)         // คำนวณผลรวมและคืนผลลัพธ์
createForm(..)      // สร้างฟอร์ม (และมักจะคืนฟอร์มนั้นกลับมา)
checkPermission(..) // เช็คสิทธิ์ คืนค่า true/false
```

พอใช้คำนำหน้าแบบนี้ แค่มองชื่อฟังก์ชันก็พอเดาได้ว่าทำงานยังไงและคืนค่าชนิดไหน

```smart header="หนึ่งฟังก์ชัน — หนึ่งการกระทำ"
ฟังก์ชันควรทำเฉพาะสิ่งที่ชื่อบอก — ไม่มากไปกว่านั้น

การกระทำสองอย่างที่เป็นอิสระจากกัน ก็ควรแยกเป็นสองฟังก์ชัน — แม้ว่าปกติจะถูกเรียกใช้พร้อมกัน (ในกรณีนั้นอาจสร้างฟังก์ชันที่สามเพื่อเรียกทั้งสองฟังก์ชันนั้น)

ตัวอย่างที่ผิดกฎข้อนี้:

- `getAge` — ไม่ดีถ้าโชว์ `alert` บอกอายุด้วย (ควรแค่ดึงค่าอายุพอ)
- `createForm` — ไม่ดีถ้าไปแก้เอกสารด้วยการเพิ่มฟอร์มเข้าไป (ควรแค่สร้างฟอร์มและคืนค่า)
- `checkPermission` — ไม่ดีถ้าโชว์ข้อความ `อนุญาต/ไม่อนุญาตให้เข้าถึง` (ควรแค่เช็คและคืนผลลัพธ์)

ตัวอย่างพวกนี้ใช้ความหมายทั่วไปของคำนำหน้า — ทีมจะตกลงกันใช้ความหมายอื่นก็ได้ แต่ปกติก็ไม่ค่อยต่างกันมาก จุดสำคัญคือทุกคนในทีมต้องเข้าใจตรงกันว่าคำนำหน้าแต่ละตัวหมายความว่าอะไร — ฟังก์ชันที่ใช้คำนำหน้าเดียวกันก็ควรทำตามกฎเดียวกัน
```

```smart header="ชื่อฟังก์ชันสั้นมากๆ"
ฟังก์ชันที่ถูกใช้ *บ่อยมากๆ* บางทีอาจมีชื่อสั้นมากๆ

เช่น framework [jQuery](https://jquery.com/) กำหนดฟังก์ชันชื่อ `$` ส่วน library [Lodash](https://lodash.com/) มีฟังก์ชันหลักชื่อ `_`

แต่นี่เป็นข้อยกเว้น — โดยทั่วไปชื่อฟังก์ชันควรสั้น กระชับ และสื่อความหมายชัดเจน
```

## ฟังก์ชัน == คอมเมนต์

ฟังก์ชันควรสั้นและทำสิ่งเดียวอย่างชัดเจน — ถ้าสิ่งนั้นใหญ่ไป ก็อาจคุ้มที่จะแยกออกเป็นฟังก์ชันเล็กๆ หลายๆ ตัว บางทีก็ไม่ง่ายที่จะทำตามกฎนี้ แต่ก็เป็นสิ่งที่ดีแน่นอน

ฟังก์ชันที่แยกออกมาดีๆ นอกจากจะ test และ debug ได้ง่ายกว่าแล้ว การมีอยู่ของมันยังทำหน้าที่เป็นคอมเมนต์ได้ด้วย!

เช่น ลองเทียบฟังก์ชัน `showPrimes(n)` สองตัวข้างล่าง — แต่ละตัวโชว์ [จำนวนเฉพาะ](https://en.wikipedia.org/wiki/Prime_number) ตั้งแต่ 1 ถึง `n`

แบบแรกใช้ label:

```js
function showPrimes(n) {
  nextPrime: for (let i = 2; i < n; i++) {

    for (let j = 2; j < i; j++) {
      if (i % j == 0) continue nextPrime;
    }

    alert( i ); // จำนวนเฉพาะ
  }
}
```

แบบที่สองใช้ฟังก์ชันเสริม `isPrime(n)` เพื่อเช็คว่าเป็นจำนวนเฉพาะหรือไม่:

```js
function showPrimes(n) {

  for (let i = 2; i < n; i++) {
    *!*if (!isPrime(i)) continue;*/!*

    alert(i);  // จำนวนเฉพาะ
  }
}

function isPrime(n) {
  for (let i = 2; i < n; i++) {
    if ( n % i == 0) return false;
  }
  return true;
}
```

แบบที่สองเข้าใจง่ายกว่าใช่ไหม? แทนที่จะเห็นชิ้นส่วนของโค้ด เราเห็นชื่อของการกระทำ (`isPrime`) — บางทีคนก็เรียกโค้ดแบบนี้ว่า *อธิบายตัวเอง*

ก็เลย — เราจะสร้างฟังก์ชันแม้ไม่ได้ตั้งใจจะนำกลับมาใช้ซ้ำก็ได้ เพราะช่วยจัดโครงสร้างโค้ดและทำให้อ่านง่ายขึ้น

## สรุป

การประกาศฟังก์ชันมีหน้าตาแบบนี้:

```js
function name(parameters, delimited, by, comma) {
  /* code */
}
```

- ค่าที่ส่งเข้าฟังก์ชันผ่านพารามิเตอร์จะถูกก็อปไปเป็นตัวแปรภายในฟังก์ชัน
- ฟังก์ชันเข้าถึงตัวแปรภายนอกได้ — แต่ทำได้ทางเดียวคือจากในออกนอก โค้ดภายนอกฟังก์ชันมองไม่เห็นตัวแปรในฟังก์ชัน
- ฟังก์ชันคืนค่าได้ — ถ้าไม่คืน ผลลัพธ์จะเป็น `undefined`

เพื่อให้โค้ดสะอาดและเข้าใจง่าย แนะนำให้ใช้ตัวแปรภายในฟังก์ชันกับพารามิเตอร์เป็นหลัก ไม่พึ่งตัวแปรภายนอก

ฟังก์ชันที่รับพารามิเตอร์ ทำงานกับข้อมูลนั้น และคืนผลลัพธ์ออกมา — จะเข้าใจง่ายกว่าฟังก์ชันที่ไม่รับพารามิเตอร์แต่แอบไปแก้ตัวแปรภายนอก ซึ่งถือเป็นผลข้างเคียงที่ไม่พึงประสงค์

การตั้งชื่อฟังก์ชัน:

- ชื่อควรบอกชัดเจนว่าฟังก์ชันทำอะไร — พอเห็นการเรียกฟังก์ชันในโค้ด ชื่อที่ดีจะทำให้เข้าใจทันทีว่าทำอะไรและคืนค่าอะไร
- ฟังก์ชันคือการกระทำ — ชื่อฟังก์ชันก็เลยมักเป็นคำกริยา
- มีคำนำหน้าฟังก์ชันที่ใช้กันแพร่หลาย เช่น `create…`, `show…`, `get…`, `check…` — ใช้เป็นสัญญาณบอกว่าฟังก์ชันทำอะไรได้

ฟังก์ชันเป็นบล็อกสำคัญในการสร้างสคริปต์ ตอนนี้เราเรียนพื้นฐานแล้ว — พร้อมเริ่มสร้างและใช้งานได้เลย — แต่นี่เป็นแค่จุดเริ่มต้น เราจะกลับมาที่ฟังก์ชันอีกหลายครั้งเพื่อเจาะลึกฟีเจอร์ขั้นสูง
