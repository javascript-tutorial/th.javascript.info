# นิพจน์ฟังก์ชัน

ใน JavaScript ฟังก์ชันไม่ได้เป็น "โครงสร้างพิเศษของภาษา" ที่แยกออกจากค่าอื่น จริง ๆ แล้วฟังก์ชันก็คือค่าชนิดหนึ่ง เพียงแต่เป็นค่าที่เรียกให้ทำงานได้

รูปแบบที่เราใช้กันมาก่อนหน้านี้เรียกว่า *การประกาศฟังก์ชัน* (Function Declaration):

```js
function sayHi() {
  alert( "Hello" );
}
```

เรายังสร้างฟังก์ชันได้อีกรูปแบบหนึ่ง เรียกว่า *นิพจน์ฟังก์ชัน* (Function Expression)

รูปแบบนี้ใช้สร้างฟังก์ชันเป็นส่วนหนึ่งของนิพจน์ใด ๆ ได้ เช่น:

```js
let sayHi = function() {
  alert( "Hello" );
};
```

บรรทัดนี้สร้างฟังก์ชันใหม่จาก `function() { alert("Hello"); }` แล้วนำฟังก์ชันนั้นไปเก็บไว้ในตัวแปร `sayHi`

การสร้างฟังก์ชันเกิดขึ้นภายในนิพจน์การกำหนดค่า ตรงด้านขวาของเครื่องหมาย `=` เราจึงเรียกรูปแบบนี้ว่า *นิพจน์ฟังก์ชัน*

สังเกตว่าหลังคีย์เวิร์ด `function` ไม่มีชื่อฟังก์ชัน นิพจน์ฟังก์ชันจะไม่ใส่ชื่อก็ได้

ตัวอย่างนี้เก็บฟังก์ชันลงในตัวแปรทันที ผลที่ได้จึงเหมือนกับตัวอย่างการประกาศฟังก์ชันก่อนหน้า นั่นคือ "สร้างฟังก์ชันแล้วเก็บไว้ในตัวแปร `sayHi`"

ในบทต่อ ๆ ไป เราจะเจอกรณีที่สร้างฟังก์ชันแล้วเรียกทันที หรือนัดให้ทำงานทีหลังโดยไม่ได้เก็บไว้ที่ไหน ฟังก์ชันแบบนั้นจึงไม่มีชื่อ

## ฟังก์ชันคือค่า

ไม่ว่าจะสร้างด้วยรูปแบบไหน ฟังก์ชันก็คือค่าชนิดหนึ่ง ตัวอย่างทั้งสองแบบข้างต้นต่างก็เก็บค่าฟังก์ชันไว้ในตัวแปร `sayHi`

เราลองใช้ `alert` แสดงค่านั้นได้ด้วย:

```js run
function sayHi() {
  alert( "Hello" );
}

*!*
alert( sayHi ); // แสดงโค้ดของฟังก์ชัน
*/!*
```

บรรทัดสุดท้ายไม่ได้เรียกฟังก์ชัน เพราะไม่มีวงเล็บต่อท้าย `sayHi` บางภาษาอาจเรียกฟังก์ชันทันทีที่อ้างถึงชื่อ แต่ JavaScript ไม่ได้ทำงานแบบนั้น

เมื่อฟังก์ชันเป็นค่า เราจึงนำมันมาใช้งานเหมือนค่าอื่นได้ โค้ดด้านบนจะแสดงฟังก์ชันในรูปสตริง ซึ่งก็คือซอร์สโค้ดของฟังก์ชัน

แน่นอนว่าฟังก์ชันต่างจากค่าทั่วไปตรงที่เรียกให้ทำงานผ่าน `sayHi()` ได้

ถึงอย่างนั้นมันก็ยังเป็นค่า เราจึงคัดลอกไปเก็บในตัวแปรอื่นได้:

```js run no-beautify
function sayHi() {   // (1) สร้างฟังก์ชัน
  alert( "Hello" );
}

let func = sayHi;    // (2) คัดลอก

func(); // Hello     // (3) เรียกฟังก์ชันผ่านตัวแปรใหม่ (ใช้ได้)
sayHi(); // Hello    //     ตัวแปรเดิมก็ยังเรียกได้เหมือนเดิม
```

โค้ดนี้ทำงานตามลำดับดังนี้:

1. การประกาศฟังก์ชันในบรรทัด `(1)` สร้างฟังก์ชันแล้วเก็บไว้ในตัวแปรชื่อ `sayHi`
2. บรรทัด `(2)` คัดลอกค่าฟังก์ชันไปไว้ในตัวแปร `func` ตรงนี้ไม่มีวงเล็บต่อท้าย `sayHi` ถ้าเขียนเป็น `func = sayHi()` ค่าที่เก็บใน `func` จะเป็น *ผลลัพธ์จากการเรียก* `sayHi()` ไม่ใช่ *ตัวฟังก์ชัน* `sayHi`
3. ตอนนี้เราจึงเรียกฟังก์ชันได้ทั้งผ่าน `sayHi()` และ `func()`

ถ้าเปลี่ยนบรรทัดแรกมาใช้นิพจน์ฟังก์ชันก็ได้เหมือนกัน:

```js
let sayHi = function() { // (1) สร้างฟังก์ชัน
  alert( "Hello" );
};

let func = sayHi;  //(2)
// ...
```

ผลลัพธ์ไม่ต่างกัน

```smart header="ทำไมต้องมีเซมิโคลอนตามท้าย?"
อาจสงสัยว่าทำไมนิพจน์ฟังก์ชันมีเซมิโคลอน `;` ต่อท้าย แต่การประกาศฟังก์ชันไม่มี:

```js
function sayHi() {
  // ...
}

let sayHi = function() {
  // ...
}*!*;*/!*
```

เหตุผลคือ `function(…) {…}` ในตัวอย่างนี้เป็นนิพจน์ฟังก์ชันที่อยู่ภายในคำสั่งกำหนดค่า `let sayHi = …;` เซมิโคลอน `;` ใช้ปิดท้ายคำสั่งนี้และไม่ได้เป็นส่วนหนึ่งของไวยากรณ์ฟังก์ชัน โดยทั่วไปจึงแนะนำให้ใส่ไว้ตรงนี้

ถ้ากำหนดค่าธรรมดาอย่าง `let sayHi = 5;` เราก็ใส่เซมิโคลอนแบบเดียวกัน การกำหนดค่าฟังก์ชันจึงมีเซมิโคลอนด้วย

## ฟังก์ชันคอลแบ็ก

ลองดูตัวอย่างการส่งฟังก์ชันในฐานะค่าพร้อมกับการใช้นิพจน์ฟังก์ชันกันอีกสักหน่อย

เราจะเขียนฟังก์ชัน `ask(question, yes, no)` ที่รับพารามิเตอร์สามตัว:

`question`
: ข้อความคำถาม

`yes`
: ฟังก์ชันที่จะทำงานเมื่อผู้ใช้ตอบ "ใช่"

`no`
: ฟังก์ชันที่จะทำงานเมื่อผู้ใช้ตอบ "ไม่"

ฟังก์ชัน `ask` จะถามคำถามจากข้อความใน `question` แล้วเรียก `yes()` หรือ `no()` ตามคำตอบของผู้ใช้:

```js run
*!*
function ask(question, yes, no) {
  if (confirm(question)) yes()
  else no();
}
*/!*

function showOk() {
  alert( "You agreed." );
}

function showCancel() {
  alert( "You canceled the execution." );
}

// วิธีใช้: ส่งฟังก์ชัน showOk และ showCancel เป็นอาร์กิวเมนต์ให้ ask
ask("Do you agree?", showOk, showCancel);
```

ฟังก์ชันลักษณะนี้มีประโยชน์มากในงานจริง เพียงแต่ `ask` ที่ใช้จริงมักโต้ตอบกับผู้ใช้ด้วยวิธีที่ซับซ้อนกว่า `confirm` เช่น แสดงหน้าต่างคำถามที่ตกแต่งไว้เรียบร้อยในเบราว์เซอร์ ซึ่งเป็นเรื่องของบทอื่น

**อาร์กิวเมนต์ `showOk` และ `showCancel` ที่ส่งให้ `ask` เรียกว่า *ฟังก์ชันคอลแบ็ก* หรือเรียกสั้น ๆ ว่า *คอลแบ็ก***

แนวคิดคือ เราส่งฟังก์ชันเข้าไปก่อน เพื่อให้ `ask` เรียกฟังก์ชันนั้นกลับมาเมื่อถึงเวลาที่ต้องใช้ ในตัวอย่างนี้ `showOk` เป็นคอลแบ็กสำหรับคำตอบ "ใช่" ส่วน `showCancel` เป็นคอลแบ็กสำหรับคำตอบ "ไม่"

เราใช้นิพจน์ฟังก์ชันเขียนโค้ดเดียวกันให้สั้นลงได้:

```js run no-beautify
function ask(question, yes, no) {
  if (confirm(question)) yes()
  else no();
}

*!*
ask(
  "Do you agree?",
  function() { alert("You agreed."); },
  function() { alert("You canceled the execution."); }
);
*/!*
```

โค้ดตรงนี้สร้างฟังก์ชันสองตัวขึ้นมาภายในคำสั่งเรียก `ask(...)` โดยตรง ฟังก์ชันทั้งคู่ไม่มีชื่อ จึงเรียกว่า *ฟังก์ชันไม่มีชื่อ* (anonymous function) โค้ดด้านนอก `ask` จึงไม่มีชื่อไว้อ้างถึงฟังก์ชันเหล่านี้โดยตรง แต่กรณีนี้เราไม่ได้ต้องการนำมันไปใช้ที่อื่นอยู่แล้ว

ใน JavaScript เราพบโค้ดแบบนี้ได้เป็นเรื่องปกติ

```smart header="ฟังก์ชันคือค่าที่แทน \"การกระทำ\""
ค่าทั่วไปอย่างสตริงหรือตัวเลขใช้แทน *ข้อมูล*

ส่วนฟังก์ชันมองได้ว่าเป็น *การกระทำ*

เราส่งฟังก์ชันไปเก็บในตัวแปรต่าง ๆ แล้วเรียกให้ทำงานเมื่อไรก็ได้
```

## นิพจน์ฟังก์ชัน (Function Expression) กับการประกาศฟังก์ชัน (Function Declaration)

มาสรุปความต่างสำคัญระหว่างการประกาศฟังก์ชันกับนิพจน์ฟังก์ชันกัน

ความต่างแรกคือรูปแบบการเขียน เราแยกสองแบบนี้ในโค้ดได้ดังนี้:

- *การประกาศฟังก์ชัน:* ประกาศฟังก์ชันเป็นคำสั่งแยกต่างหากในลำดับการทำงานหลักของโค้ด:

    ```js
    // การประกาศฟังก์ชัน
    function sum(a, b) {
      return a + b;
    }
    ```
- *นิพจน์ฟังก์ชัน:* สร้างฟังก์ชันไว้ภายในนิพจน์หรือโครงสร้างไวยากรณ์อื่น ตัวอย่างนี้สร้างฟังก์ชันทางขวาของนิพจน์การกำหนดค่า `=`:

    ```js
    // นิพจน์ฟังก์ชัน
    let sum = function(a, b) {
      return a + b;
    };
    ```

ความต่างที่ต้องสังเกตให้ดีคือ JavaScript สร้างฟังก์ชันแต่ละแบบขึ้นมา *เมื่อไร*

**JavaScript จะสร้างฟังก์ชันจากนิพจน์ฟังก์ชันเมื่อโค้ดทำงานมาถึงบรรทัดนั้น และเราจะใช้ฟังก์ชันได้ตั้งแต่นั้นเป็นต้นไปเท่านั้น**

เมื่อการทำงานมาถึงด้านขวาของ `let sum = function…` JavaScript จึงสร้างฟังก์ชันขึ้นมา หลังจากนั้นเราถึงจะนำไปกำหนดค่า เรียกใช้งาน หรือทำอย่างอื่นต่อได้

การประกาศฟังก์ชันทำงานต่างออกไป

**เราเรียกฟังก์ชันที่สร้างด้วยการประกาศฟังก์ชันได้ก่อนบรรทัดที่ประกาศ**

ตัวอย่างเช่น ฟังก์ชันที่ประกาศไว้ที่ระดับบนสุดของสคริปต์จะเรียกใช้ได้ทั่วทั้งสคริปต์ ไม่ว่าบรรทัดประกาศจะอยู่ตรงไหน

สาเหตุอยู่ที่ขั้นตอนเตรียมรันสคริปต์: ก่อนเริ่มทำงาน JavaScript จะค้นหาการประกาศฟังก์ชันทั้งหมดที่อยู่ระดับบนสุด แล้วสร้างฟังก์ชันเหล่านั้นเตรียมไว้ก่อน เรามองขั้นตอนนี้ว่าเป็นช่วงเตรียมความพร้อมก็ได้

เมื่อจัดการการประกาศฟังก์ชันทั้งหมดเรียบร้อยแล้ว JavaScript จึงเริ่มรันโค้ดตามลำดับ ทำให้โค้ดเรียกฟังก์ชันเหล่านี้ได้แม้บรรทัดประกาศจะอยู่ถัดลงไป

โค้ดนี้จึงทำงานได้:

```js run refresh untrusted
*!*
sayHi("John"); // Hello, John
*/!*

function sayHi(name) {
  alert( `Hello, ${name}` );
}
```

JavaScript สร้างฟังก์ชัน `sayHi` จากการประกาศฟังก์ชันไว้ตั้งแต่ช่วงเตรียมรันสคริปต์ เราจึงเรียกมันจากตรงไหนของสคริปต์ก็ได้

แต่ถ้าเปลี่ยนเป็นนิพจน์ฟังก์ชัน โค้ดจะใช้ไม่ได้:

```js run refresh untrusted
*!*
sayHi("John"); // error!
*/!*

let sayHi = function(name) {  // (*) ยังไม่มีฟังก์ชันให้เรียกก่อนบรรทัดนี้
  alert( `Hello, ${name}` );
};
```

JavaScript จะสร้างฟังก์ชันจากนิพจน์นี้เมื่อการทำงานมาถึงบรรทัด `(*)` เท่านั้น แต่โค้ดพยายามเรียก `sayHi` ไปก่อนแล้ว จึงสายเกินไป

การประกาศฟังก์ชันยังมีพฤติกรรมสำคัญอีกอย่างเกี่ยวกับสโคปของบล็อก

**ในโหมดเข้มงวด ถ้าประกาศฟังก์ชันไว้ในบล็อกโค้ด เราจะมองเห็นฟังก์ชันนั้นได้ทั่วทั้งบล็อก แต่จะมองไม่เห็นจากภายนอกบล็อก**

สมมติว่าเราต้องสร้างฟังก์ชัน `welcome()` ให้ต่างกันตามค่า `age` ที่รู้ตอนโปรแกรมกำลังทำงาน แล้วค่อยเรียกฟังก์ชันนี้ในภายหลัง

ถ้าใช้การประกาศฟังก์ชัน โค้ดจะไม่ทำงานอย่างที่ตั้งใจ:

```js run
let age = prompt("What is your age?", 18);

// ประกาศฟังก์ชันตามเงื่อนไข
if (age < 18) {

  function welcome() {
    alert("Hello!");
  }

} else {

  function welcome() {
    alert("Greetings!");
  }

}

// ...เรียกใช้ในภายหลัง
*!*
welcome(); // Error: welcome is not defined
*/!*
```

สาเหตุคือการประกาศฟังก์ชันจะมองเห็นได้เฉพาะภายในบล็อกโค้ดที่ประกาศฟังก์ชันนั้นไว้

ลองดูอีกตัวอย่างให้ชัดขึ้น:

```js run
let age = 16; // กำหนดเป็น 16 เพื่อใช้ในตัวอย่าง

if (age < 18) {
*!*
  welcome();               // \   (ทำงานได้)
*/!*
                           //  |
  function welcome() {     //  |
    alert("Hello!");       //  |  การประกาศฟังก์ชันมองเห็นได้
  }                        //  |  ทั่วทั้งบล็อกที่ประกาศไว้
                           //  |
*!*
  welcome();               // /   (ทำงานได้)
*/!*

} else {

  function welcome() {
    alert("Greetings!");
  }
}

// ตอนนี้ออกมานอกวงเล็บปีกกาแล้ว
// จึงมองไม่เห็นฟังก์ชันที่ประกาศไว้ภายในบล็อก

*!*
welcome(); // Error: welcome is not defined
*/!*
```

ถ้าต้องการให้ `welcome` มองเห็นได้จากภายนอก `if` ต้องทำอย่างไร?

วิธีที่เหมาะคือประกาศตัวแปร `welcome` ไว้นอก `if` เพื่อให้มีสโคปกว้างพอ แล้วกำหนดค่าให้ตัวแปรนี้ด้วยนิพจน์ฟังก์ชันตามเงื่อนไข

โค้ดต่อไปนี้จึงทำงานตามที่ตั้งใจ:

```js run
let age = prompt("What is your age?", 18);

let welcome;

if (age < 18) {

  welcome = function() {
    alert("Hello!");
  };

} else {

  welcome = function() {
    alert("Greetings!");
  };

}

*!*
welcome(); // ตอนนี้เรียกได้แล้ว
*/!*
```

หรือเขียนให้สั้นลงด้วยตัวดำเนินการ `?`:

```js run
let age = prompt("What is your age?", 18);

let welcome = (age < 18) ?
  function() { alert("Hello!"); } :
  function() { alert("Greetings!"); };

*!*
welcome(); // ตอนนี้เรียกได้แล้ว
*/!*
```


```smart header="เมื่อไหร่ควรเลือกใช้การประกาศฟังก์ชัน หรือนิพจน์ฟังก์ชัน?"
โดยทั่วไป ถ้าต้องประกาศฟังก์ชัน ให้ลองใช้รูปแบบการประกาศฟังก์ชันก่อน เพราะเรียกฟังก์ชันได้ตั้งแต่ก่อนถึงบรรทัดที่ประกาศ จึงจัดวางโค้ดได้ยืดหยุ่นกว่า

รูปแบบนี้มักอ่านง่ายกว่าด้วย เวลาไล่หาในโค้ด `function f(…) {…}` จะสะดุดตากว่า `let f = function(…) {…};`

แต่ถ้าการประกาศฟังก์ชันไม่เหมาะกับงาน หรือต้องเลือกสร้างฟังก์ชันตามเงื่อนไขอย่างตัวอย่างที่ผ่านมา ให้ใช้นิพจน์ฟังก์ชันแทน
```

## สรุป

- ฟังก์ชันคือค่า เราจึงกำหนดฟังก์ชันให้ตัวแปร คัดลอกไปยังตัวแปรอื่น หรือสร้างไว้ตรงไหนของโค้ดก็ได้
- ถ้าประกาศฟังก์ชันเป็นคำสั่งแยกต่างหากในลำดับการทำงานหลักของโค้ด รูปแบบนั้นเรียกว่า "การประกาศฟังก์ชัน"
- ถ้าสร้างฟังก์ชันขึ้นมาเป็นส่วนหนึ่งของนิพจน์ รูปแบบนั้นเรียกว่า "นิพจน์ฟังก์ชัน"
- JavaScript จะประมวลผลการประกาศฟังก์ชันก่อนเริ่มรันบล็อกโค้ด เราจึงมองเห็นฟังก์ชันได้ทั่วทั้งบล็อก
- JavaScript จะสร้างฟังก์ชันจากนิพจน์ฟังก์ชันเมื่อการทำงานมาถึงบรรทัดนั้น

เวลาต้องประกาศฟังก์ชัน ส่วนใหญ่การประกาศฟังก์ชันเป็นตัวเลือกที่เหมาะกว่า เพราะเรียกใช้ได้ก่อนบรรทัดที่ประกาศ ทำให้จัดวางโค้ดได้ยืดหยุ่นและมักอ่านง่ายกว่า

เมื่อการประกาศฟังก์ชันไม่เหมาะกับงานจึงค่อยใช้นิพจน์ฟังก์ชันแทน ในบทนี้เราเห็นตัวอย่างไปบ้างแล้ว และจะได้เจอเพิ่มอีกในบทต่อ ๆ ไป
