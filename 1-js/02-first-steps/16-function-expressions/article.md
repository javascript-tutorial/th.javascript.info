# นิพจน์ฟังก์ชัน

ใน JavaScript ฟังก์ชันไม่ใช่ "โครงสร้างพิเศษของภาษา" — แต่เป็นค่าชนิดหนึ่งที่มีลักษณะเฉพาะตัว

รูปแบบที่เราใช้ก่อนหน้านี้เรียกว่า *การประกาศฟังก์ชัน* (Function Declaration):

```js
function sayHi() {
  alert( "Hello" );
}
```

อีกท่าหนึ่งในการสร้างฟังก์ชันเรียกว่า *นิพจน์ฟังก์ชัน* (Function Expression)

ท่านี้ช่วยให้เราสร้างฟังก์ชันใหม่ได้ในทุกๆ นิพจน์ (expression)

เช่น:

```js
let sayHi = function() {
  alert( "Hello" );
};
```

ตัวแปร `sayHi` ได้รับค่าเป็นฟังก์ชันใหม่ที่สร้างจาก `function() { alert("Hello"); }`

เพราะการสร้างฟังก์ชันเกิดขึ้นในบริบทของนิพจน์การกำหนดค่า (ทางขวาของเครื่องหมาย `=`) ก็เลยเรียกว่านิพจน์ฟังก์ชัน

สังเกตว่าไม่มีชื่อหลังคีย์เวิร์ด `function` — สำหรับนิพจน์ฟังก์ชัน การไม่มีชื่อถือเป็นเรื่องปกติ

เรากำหนดค่าให้ตัวแปรทันที — ตัวอย่างโค้ดทั้งสองก็เลยมีความหมายเดียวกัน — "สร้างฟังก์ชันและเก็บไว้ในตัวแปร `sayHi`"

ในสถานการณ์ที่ซับซ้อนกว่านี้ที่จะเจอในภายหลัง ฟังก์ชันอาจถูกสร้างและเรียกใช้ทันที หรือกำหนดเวลาไว้ใช้ทีหลัง โดยไม่ถูกเก็บไว้ที่ใดเลย ก็เลยไม่มีชื่อ (anonymous)

## ฟังก์ชันคือค่า

ขอย้ำอีกครั้ง — ไม่ว่าฟังก์ชันจะถูกสร้างยังไง ก็คือค่าชนิดหนึ่งทั้งนั้น ตัวอย่างทั้งสองข้างบนต่างก็เก็บฟังก์ชันไว้ในตัวแปร `sayHi`

เราโชว์ค่านั้นผ่าน `alert` ก็ได้ด้วย:

```js run
function sayHi() {
  alert( "Hello" );
}

*!*
alert( sayHi ); // โชว์โค้ดของฟังก์ชัน
*/!*
```

สังเกตว่าบรรทัดสุดท้ายไม่ได้เรียกใช้ฟังก์ชัน เพราะไม่มีวงเล็บหลัง `sayHi` — บางภาษาแค่กล่าวถึงชื่อฟังก์ชันก็เรียกใช้ทันทีเลย แต่ JavaScript ไม่ใช่แบบนั้น

ใน JavaScript ฟังก์ชันเป็นค่าชนิดหนึ่ง — เราก็เลยจัดการกับมันได้เหมือนค่าชนิดอื่นๆ โค้ดข้างบนโชว์ผลลัพธ์เป็นสตริง ซึ่งก็คือซอร์สโค้ดของฟังก์ชันนั่นเอง

แน่นอนว่าฟังก์ชันเป็นค่าพิเศษ ตรงที่เราเรียกใช้งานได้ผ่าน `sayHi()`

แต่ก็ยังเป็นค่าอยู่ดี — เลยจัดการได้เหมือนค่าชนิดอื่นๆ

ก็อปฟังก์ชันไปยังตัวแปรอื่นก็ได้:

```js run no-beautify
function sayHi() {   // (1) สร้าง
  alert( "Hello" );
}

let func = sayHi;    // (2) ก็อป

func(); // Hello     // (3) เรียกใช้สำเนา (ใช้ได้)!
sayHi(); // Hello    //     ตัวต้นฉบับยังใช้ได้เหมือนเดิม (แน่นอน)
```

ที่เกิดขึ้นมาจากนี้คือ:

1. การประกาศฟังก์ชัน `(1)` สร้างฟังก์ชันและเก็บไว้ในตัวแปรชื่อ `sayHi`
2. บรรทัด `(2)` ก็อปไปยังตัวแปร `func` — สังเกตอีกครั้งนะ — ไม่มีวงเล็บหลัง `sayHi` ถ้าใส่เป็น `func = sayHi()` จะเขียน *ผลลัพธ์ของการเรียกใช้* `sayHi()` ลงใน `func` ไม่ใช่ตัว *ฟังก์ชัน* `sayHi` เอง
3. ตอนนี้เรียกฟังก์ชันได้ทั้งในชื่อ `sayHi()` และ `func()`

เราใช้นิพจน์ฟังก์ชันประกาศ `sayHi` ในบรรทัดแรกก็ได้:

```js
let sayHi = function() { // (1) สร้าง
  alert( "Hello" );
};

let func = sayHi;  //(2)
// ...
```

ทุกอย่างทำงานเหมือนกัน

```smart header="ทำไมต้องมีเซมิโคลอนตามท้าย?"
อาจสงสัยว่าทำไมนิพจน์ฟังก์ชันถึงต้องมีเซมิโคลอน `;` ท้ายประโยค แต่การประกาศฟังก์ชันไม่ต้องมี:

```js
function sayHi() {
  // ...
}

let sayHi = function() {
  // ...
}*!*;*/!*
```

คำตอบคือ — นิพจน์ฟังก์ชันถูกสร้างในรูปแบบ `function(…) {…}` ภายในประโยคการกำหนดค่า — `let sayHi = …;` ซึ่งควรมีเซมิโคลอน `;` ท้ายประโยค — ไม่ใช่ส่วนหนึ่งของไวยากรณ์ฟังก์ชัน

เซมิโคลอนอยู่ในการกำหนดค่าทั่วไปอยู่แล้ว เช่น `let sayHi = 5;` ก็เลยมีในการกำหนดค่าฟังก์ชันด้วยเหมือนกัน

## ฟังก์ชันคอลแบ็ก

ทีนี้มาดูตัวอย่างเพิ่มเติมเรื่องการส่งฟังก์ชันเป็นค่าและการใช้นิพจน์ฟังก์ชันกัน

จะเขียนฟังก์ชัน `ask(question, yes, no)` ที่มีพารามิเตอร์ 3 ตัว:

`question`
: ข้อความคำถาม

`yes`
: ฟังก์ชันที่จะรันถ้าคำตอบคือ "ใช่"

`no`
: ฟังก์ชันที่จะรันถ้าคำตอบคือ "ไม่"

ฟังก์ชันจะถาม `question` แล้วเรียก `yes()` หรือ `no()` ตามคำตอบของผู้ใช้:

```js run
*!*
function ask(question, yes, no) {
  if (confirm(question)) yes()
  else no();
}
*/!*

function showOk() {
  alert( "You agreed." );
}

function showCancel() {
  alert( "You canceled the execution." );
}

// การใช้งาน: ส่งฟังก์ชัน showOk, showCancel เป็นอาร์กิวเมนต์ให้ ask
ask("Do you agree?", showOk, showCancel);
```

ในการใช้งานจริง ฟังก์ชันแบบนี้มีประโยชน์มาก — ความต่างหลักระหว่าง `ask` ในชีวิตจริงกับตัวอย่างข้างบนคือ ฟังก์ชันจริงจะใช้ท่าโต้ตอบกับผู้ใช้ที่ซับซ้อนกว่า `confirm` ธรรมดา — ในเบราว์เซอร์มักสร้างหน้าต่างคำถามสวยๆ แต่นั่นเป็นอีกเรื่อง

**อาร์กิวเมนต์ `showOk` และ `showCancel` ของ `ask` เรียกว่า *ฟังก์ชันคอลแบ็ก* หรือ *คอลแบ็ก***

แนวคิดคือ — เราส่งฟังก์ชันไป แล้วคาดว่ามันจะถูก "เรียกกลับ (called back)" ในภายหลังเมื่อจำเป็น ในเคสนี้ `showOk` เป็นคอลแบ็กสำหรับคำตอบ "ใช่" และ `showCancel` สำหรับคำตอบ "ไม่"

ใช้นิพจน์ฟังก์ชันเขียนแบบเดียวกันให้สั้นลงก็ได้:

```js run no-beautify
function ask(question, yes, no) {
  if (confirm(question)) yes()
  else no();
}

*!*
ask(
  "Do you agree?",
  function() { alert("You agreed."); },
  function() { alert("You canceled the execution."); }
);
*/!*
```

ฟังก์ชันถูกประกาศในการเรียก `ask(...)` โดยตรง โดยไม่มีชื่อ ก็เลยเรียกว่า *anonymous (ไม่มีชื่อ)* — ฟังก์ชันพวกนี้เข้าถึงจากภายนอก `ask` ไม่ได้ (เพราะไม่ได้ถูกกำหนดให้ตัวแปรไหน) แต่นั่นแหละคือสิ่งที่เราต้องการ

โค้ดแบบนี้เจอบ่อยมากในสคริปต์ JavaScript — เป็นสไตล์ที่ฝังอยู่ในจิตวิญญาณของภาษานี้เลย

```smart header="ฟังก์ชันคือค่าที่แทน \"การกระทำ\""
ค่าปกติอย่างสตริงหรือตัวเลขแทน *ข้อมูล*

ส่วนฟังก์ชันมองได้ว่าเป็น *การกระทำ*

เราส่งมันไปมาระหว่างตัวแปร และสั่งให้ทำงานเมื่อไหร่ก็ได้
```

## นิพจน์ฟังก์ชัน (Function Expression) กับ การประกาศฟังก์ชัน (Function Declaration)

มาสรุปความต่างที่สำคัญระหว่างการประกาศฟังก์ชันกับนิพจน์ฟังก์ชันกัน

เริ่มจากด้านไวยากรณ์ก่อน — เราจะแยกสองแบบนี้ในโค้ดได้ยังไง

- *การประกาศฟังก์ชัน:* ฟังก์ชันที่ประกาศเป็นประโยคแยกต่างหาก ในเนื้อหาหลักของโค้ด:

    ```js
    // การประกาศฟังก์ชัน
    function sum(a, b) {
      return a + b;
    }
    ```
- *นิพจน์ฟังก์ชัน:* ฟังก์ชันที่ถูกสร้างในนิพจน์ หรือในโครงสร้างทางไวยากรณ์อื่นๆ ในที่นี้ ฟังก์ชันถูกสร้างทางขวาของ "นิพจน์การกำหนดค่า" `=`:

    ```js
    // นิพจน์ฟังก์ชัน
    let sum = function(a, b) {
      return a + b;
    };
    ```

ความต่างที่ลึกกว่านั้นคือ *เวลา* ที่ JavaScript engine สร้างฟังก์ชันขึ้นมา

**นิพจน์ฟังก์ชันถูกสร้างเมื่อโค้ดทำงานมาถึงมัน — และใช้งานได้ตั้งแต่จุดนั้นเป็นต้นไป**

พอลำดับการทำงานมาถึงทางด้านขวาของการกำหนดค่า `let sum = function…` — ฟังก์ชันก็จะถูกสร้างขึ้น และใช้งานได้ตั้งแต่จุดนั้นเป็นต้นไป (กำหนดค่า เรียกใช้ ฯลฯ)

การประกาศฟังก์ชันต่างออกไป

**การประกาศฟังก์ชันเรียกใช้ได้ก่อนที่จะมีการประกาศ**

เช่น การประกาศฟังก์ชันระดับโกลบอลจะมองเห็นได้ทั่วทั้งสคริปต์ ไม่ว่าจะอยู่ตรงไหนก็ตาม

ที่เป็นแบบนี้เพราะ algorithm ภายใน — พอ JavaScript เตรียมจะรันสคริปต์ จะมองหาการประกาศฟังก์ชันระดับโกลบอลทั้งหมดก่อน แล้วสร้างขึ้นมาล่วงหน้า — มองได้ว่าเป็น "ขั้นตอนเตรียมการ"

หลังจากประมวลผลการประกาศฟังก์ชันทั้งหมดแล้ว ค่อยประมวลผลโค้ดตามปกติ — โค้ดก็เลยเข้าถึงฟังก์ชันพวกนี้ได้

เช่น โค้ดนี้ทำงานได้:

```js run refresh untrusted
*!*
sayHi("John"); // Hello, John
*/!*

function sayHi(name) {
  alert( `Hello, ${name}` );
}
```

การประกาศฟังก์ชัน `sayHi` ถูกสร้างตอน JavaScript กำลังเตรียมเริ่มสคริปต์ — เลยมองเห็นได้ทั่วทั้งสคริปต์

...แต่ถ้าเป็นนิพจน์ฟังก์ชัน จะใช้ไม่ได้:

```js run refresh untrusted
*!*
sayHi("John"); // error!
*/!*

let sayHi = function(name) {  // (*) ไม่มีเวทมนต์อีกต่อไป
  alert( `Hello, ${name}` );
};
```

นิพจน์ฟังก์ชันจะถูกสร้างก็ต่อเมื่อโค้ดทำงานมาถึงมัน — ซึ่งเกิดขึ้นที่บรรทัด `(*)` — ช้าไปแล้ว

อีกฟีเจอร์พิเศษของการประกาศฟังก์ชันคือขอบเขตแบบ block

**ในโหมดเข้มงวด พอการประกาศฟังก์ชันอยู่ในบล็อกโค้ด ก็จะมองเห็นได้ทั่วบล็อกนั้น แต่มองไม่เห็นจากนอกบล็อก**

สมมติว่าอยากประกาศฟังก์ชัน `welcome()` โดยขึ้นกับค่าตัวแปร `age` ที่ได้ระหว่าง runtime แล้ววางแผนจะใช้ทีหลัง

ถ้าใช้การประกาศฟังก์ชัน จะไม่ทำงานตามที่คิด:

```js run
let age = prompt("What is your age?", 18);

// ประกาศฟังก์ชันตามเงื่อนไข
if (age < 18) {

  function welcome() {
    alert("Hello!");
  }

} else {

  function welcome() {
    alert("Greetings!");
  }

}

// ...ใช้ในภายหลัง
*!*
welcome(); // Error: welcome is not defined
*/!*
```

นี่คืออีกตัวอย่างหนึ่งที่แสดงให้เห็น:

```js run
let age = 16; // ใช้ 16 เป็นตัวอย่าง

if (age < 18) {
*!*
  welcome();               // \   (ทำงานได้)
*/!*
                           //  |
  function welcome() {     //  |
    alert("Hello!");       //  |  การประกาศฟังก์ชันมองเห็นได้
  }                        //  |  ทั่วทั้งบล็อกที่ประกาศ
                           //  |
*!*
  welcome();               // /   (ทำงานได้)
*/!*

} else {

  function welcome() {
    alert("Greetings!");
  }
}

// ออกจากวงเล็บปีกกาแล้ว
// จึงมองไม่เห็นการประกาศฟังก์ชันที่อยู่ข้างใน

*!*
welcome(); // Error: welcome is not defined
*/!*
```

จะทำยังไงให้ `welcome` มองเห็นได้จากนอก `if`?

ท่าที่ถูกต้องคือใช้นิพจน์ฟังก์ชัน แล้วกำหนดค่า `welcome` ให้ตัวแปรที่ประกาศไว้นอก `if` — ซึ่งมองเห็นได้ครอบคลุมกว่า

โค้ดนี้ทำงานตามที่ตั้งใจ:

```js run
let age = prompt("What is your age?", 18);

let welcome;

if (age < 18) {

  welcome = function() {
    alert("Hello!");
  };

} else {

  welcome = function() {
    alert("Greetings!");
  };

}

*!*
welcome(); // ตอนนี้ใช้ได้แล้ว
*/!*
```

หรือทำให้สั้นลงอีกด้วยตัวดำเนินการ `?`:

```js run
let age = prompt("What is your age?", 18);

let welcome = (age < 18) ?
  function() { alert("Hello!"); } :
  function() { alert("Greetings!"); };

*!*
welcome(); // ตอนนี้ใช้ได้แล้ว
*/!*
```


```smart header="เมื่อไหร่ควรเลือกใช้การประกาศฟังก์ชัน หรือนิพจน์ฟังก์ชัน?"
โดยหลักการทั่วไป — เวลาต้องประกาศฟังก์ชัน ให้พิจารณาใช้รูปแบบการประกาศฟังก์ชันเป็นอันดับแรก — เพราะให้อิสระในการจัดวางโค้ดมากกว่า — เรียกใช้ฟังก์ชันก่อนที่จะมีการประกาศได้เลย

แถมยังอ่านง่ายกว่าด้วย — มองหา `function f(…) {…}` ในโค้ดได้ง่ายกว่า `let f = function(…) {…};` — การประกาศฟังก์ชัน "เด่นกว่า"

...แต่ถ้าการประกาศฟังก์ชันไม่เหมาะด้วยเหตุผลใดเหตุผลหนึ่ง หรือต้องประกาศแบบมีเงื่อนไข (เราเพิ่งเห็นตัวอย่างไปแล้ว) ก็ใช้นิพจน์ฟังก์ชันแทน
```

## สรุป

- ฟังก์ชันคือค่า — กำหนด ก็อป หรือประกาศไว้ที่ไหนก็ได้ในโค้ด
- ถ้าฟังก์ชันถูกประกาศเป็นประโยคแยกต่างหากในลำดับการทำงานหลัก เรียกว่า "การประกาศฟังก์ชัน"
- ถ้าฟังก์ชันถูกสร้างเป็นส่วนหนึ่งของนิพจน์ เรียกว่า "นิพจน์ฟังก์ชัน"
- การประกาศฟังก์ชัน (Function Declaration) จะถูกประมวลผลก่อนที่บล็อกโค้ดจะเริ่มทำงาน — เลยมองเห็นได้ทั่วทั้งบล็อก
- นิพจน์ฟังก์ชัน (Function Expression) จะถูกสร้างเมื่อโค้ดทำงานมาถึงจุดที่มันอยู่

ในเคสส่วนใหญ่ที่อยากประกาศฟังก์ชัน — การประกาศฟังก์ชัน (Function Declaration) เป็นตัวเลือกที่ดีกว่า เพราะมองเห็นได้ก่อนการประกาศจริง — ให้ความยืดหยุ่นในการจัดวางโค้ด และมักอ่านเข้าใจง่ายกว่า

ใช้นิพจน์ฟังก์ชันเฉพาะตอนที่การประกาศฟังก์ชันไม่เหมาะกับงาน — เราเห็นตัวอย่างไปบ้างแล้วในบทนี้ — แล้วจะเจอเพิ่มเติมอีกในอนาคต
