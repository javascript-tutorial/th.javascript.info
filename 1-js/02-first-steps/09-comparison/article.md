# การเปรียบเทียบ

เครื่องหมายเปรียบเทียบหลายตัวเราคงคุ้นกันมาตั้งแต่เรียนคณิตศาสตร์แล้ว

ใน JavaScript เขียนแบบนี้:

- มากกว่า/น้อยกว่า: <code>a &gt; b</code>, <code>a &lt; b</code>
- มากกว่าหรือเท่ากับ/น้อยกว่าหรือเท่ากับ: <code>a &gt;= b</code>, <code>a &lt;= b</code>
- เท่ากับ: `a == b` — สังเกตว่าต้องใช้เครื่องหมายเท่ากับ *สอง* ตัว `==` สำหรับเช็คความเท่ากัน ส่วน `a = b` ใช้สำหรับกำหนดค่า
- ไม่เท่ากับ: ในคณิตศาสตร์ใช้สัญลักษณ์ <code>&ne;</code> แต่ใน JavaScript เขียนเป็น <code>a != b</code>

บทนี้เราจะลงลึกการเปรียบเทียบแบบต่างๆ — JavaScript ทำงานยังไง และมีข้อควรระวังอะไรบ้าง

ท้ายบทมีเคล็ดลับดีๆ ในการเลี่ยงปัญหาที่เจอบ่อยๆ ใน JavaScript

## ผลลัพธ์เป็น Boolean

ผลการเปรียบเทียบทุกแบบจะคืนค่า boolean:

- `true` หมายถึง "ใช่", "ถูกต้อง", "จริง"
- `false` หมายถึง "ไม่ใช่", "ไม่ถูกต้อง", "ไม่จริง"

เช่น:

```js run
alert( 2 > 1 );  // true (ถูก)
alert( 2 == 1 ); // false (ไม่ถูก)
alert( 2 != 1 ); // true (ถูก)
```

ผลการเปรียบเทียบเก็บในตัวแปรได้เหมือนค่าอื่นๆ:

```js run
let result = 5 > 4; // เก็บผลการเปรียบเทียบ
alert( result ); // true
```

## การเปรียบเทียบสตริง

ตอนเช็คว่าสตริงตัวหนึ่งมากกว่าอีกตัวไหม JavaScript จะใช้การเรียงลำดับแบบ "พจนานุกรม" หรือ "ตามตัวอักษร"

พูดง่ายๆ คือเปรียบเทียบสตริงทีละตัวอักษร

เช่น:

```js run
alert( 'Z' > 'A' ); // true
alert( 'Glow' > 'Glee' ); // true
alert( 'Bee' > 'Be' ); // true
```

ขั้นตอนการเปรียบเทียบสตริงสองตัว:

1. เทียบตัวอักษรตัวแรกของสตริงทั้งสอง
2. ถ้าตัวอักษรตัวแรกจากสตริงแรกมากกว่า (หรือน้อยกว่า) สตริงที่สอง แปลว่าสตริงแรกมากกว่า (หรือน้อยกว่า) สตริงที่สอง จบ
3. ถ้าตัวอักษรตัวแรกเท่ากัน ก็ไปเทียบตัวที่สองต่อในแบบเดียวกัน
4. ทำซ้ำไปเรื่อยๆ จนเจอตัวอักษรที่ต่างกัน หรือจนหมดสตริง
5. ถ้าหมดสตริงพร้อมกันและความยาวเท่ากัน แปลว่าเท่ากัน ไม่งั้นสตริงที่ยาวกว่าก็มากกว่า

ในตัวอย่างแรกข้างบน `'Z' > 'A'` ได้ผลตั้งแต่ขั้นตอนแรกเลย

ส่วนการเปรียบเทียบที่สองระหว่าง `'Glow'` กับ `'Glee'` ต้องใช้หลายขั้นตอนกว่า เพราะเทียบตัวอักษรทีละตัว:

1. `G` เท่ากับ `G`
2. `l` เท่ากับ `l`
3. `o` มากกว่า `e` — หยุด สตริงแรกมากกว่า

```smart header="ไม่ใช่พจนานุกรมจริงๆ แต่เป็นลำดับ Unicode"
ขั้นตอนเปรียบเทียบข้างบนใกล้เคียงกับในพจนานุกรมหรือสมุดโทรศัพท์ แต่ไม่ตรงเป๊ะ

เช่น ตัวพิมพ์ใหญ่เล็กไม่เท่ากัน — `"A"` ไม่เท่ากับ `"a"` แล้วตัวไหนมากกว่า? `"a"` มากกว่า เพราะมีค่า index ที่สูงกว่าในตารางเข้ารหัสภายใน (Unicode) ที่ JavaScript ใช้ — เราจะกลับมาดูรายละเอียดและผลที่ตามมาในบท <info:string>
```

## เปรียบเทียบข้อมูลต่างชนิด

เวลาเปรียบเทียบค่าที่ชนิดต่างกัน JavaScript จะแปลงค่าเป็นตัวเลขก่อน

เช่น:

```js run
alert( '2' > 1 ); // true, สตริง '2' ถูกแปลงเป็นตัวเลข 2
alert( '01' == 1 ); // true, สตริง '01' ถูกแปลงเป็นตัวเลข 1
```

ส่วนค่า boolean — `true` กลายเป็น `1` และ `false` กลายเป็น `0`

เช่น:

```js run
alert( true == 1 ); // true
alert( false == 0 ); // true
```

````smart header="ผลลัพธ์แปลกๆ"
มีกรณีที่ในเวลาเดียวกัน:

- สองค่าเท่ากัน
- แต่ค่าหนึ่งเป็น `true` เมื่อแปลงเป็น boolean ส่วนอีกค่าเป็น `false`

เช่น:

```js run
let a = 0;
alert( Boolean(a) ); // false

let b = "0";
alert( Boolean(b) ); // true

alert(a == b); // true!
```

ในมุมของ JavaScript ผลลัพธ์นี้ถือว่าปกติ — การเช็คความเท่ากันแปลงค่าด้วยกฎของตัวเลข (ทำให้ `"0"` กลายเป็น `0`) ส่วนการแปลงเป็น `Boolean` ตรงๆ ใช้กฎคนละชุด
````

## ความเท่ากันแบบเข้มงวด

การเช็คความเท่ากันแบบปกติด้วย `==` มีปัญหา — แยก `0` กับ `false` ไม่ออก:

```js run
alert( 0 == false ); // true
```

สตริงว่างก็เจอแบบเดียวกัน:

```js run
alert( '' == false ); // true
```

ที่เป็นแบบนี้เพราะเวลาเปรียบเทียบข้อมูลคนละชนิดด้วย `==` JavaScript จะแปลงเป็นตัวเลขก่อน — สตริงว่างกับ `false` ต่างก็กลายเป็นศูนย์

แล้วถ้าเราอยากแยก `0` กับ `false` ออกจากกันล่ะ จะทำยังไง?

**เครื่องหมายเท่ากันแบบเข้มงวด `===` เปรียบเทียบความเท่ากันโดยไม่แปลงชนิดข้อมูล**

พูดอีกอย่างก็คือ ถ้า `a` กับ `b` เป็นคนละชนิด `a === b` จะคืน `false` ทันที โดยไม่พยายามแปลงชนิดข้อมูลก่อน

ลองดู:

```js run
alert( 0 === false ); // false เพราะเป็นคนละชนิด
```

ส่วนเครื่องหมาย "ไม่เท่ากันแบบเข้มงวด" `!==` ก็มีเหมือนกัน คล้ายกับ `!=`

ใช้เครื่องหมายเท่ากันแบบเข้มงวดอาจพิมพ์ยาวขึ้นหน่อย แต่ทำให้เห็นชัดว่าเกิดอะไรขึ้น และลดโอกาสเกิด error ได้ดีกว่า

## เปรียบเทียบกับ null และ undefined

การเปรียบเทียบที่มี `null` หรือ `undefined` เข้ามาเกี่ยว มักให้ผลลัพธ์ที่ไม่ค่อยตรงกับสามัญสำนึก

สำหรับการเช็คความเท่ากันแบบเข้มงวดด้วย `===`:
: สองค่านี้ต่างกัน เพราะเป็นคนละชนิด

```js run
alert( null === undefined ); // false
```

สำหรับการเช็คความเท่ากันแบบไม่เข้มงวดด้วย `==`:
: มีกฎพิเศษ — สองค่านี้เป็น "คู่รักในฝัน" คือเท่ากันในแง่ของ `==` แต่ไม่เท่ากับค่าอื่นใดเลย

```js run
alert( null == undefined ); // true
```

สำหรับการคำนวณคณิตศาสตร์และการเปรียบเทียบอื่นๆ `< > <= >=`:
: `null/undefined` จะถูกแปลงเป็นตัวเลข — `null` กลายเป็น `0` ส่วน `undefined` กลายเป็น `NaN`

ทีนี้มาดูเหตุการณ์แปลกๆ ที่เกิดจากกฎพวกนี้กัน — และที่สำคัญกว่านั้น คือจะเลี่ยงกับดักพวกนี้ได้ยังไง

### ผลลัพธ์แปลกๆ: null เทียบกับ 0

ลองเปรียบเทียบ `null` กับศูนย์ดู:

```js run
alert( null > 0 );  // (1) false
alert( null == 0 ); // (2) false
alert( null >= 0 ); // (3) *!*true*/!*
```

ในแง่คณิตศาสตร์ ผลลัพธ์นี้แปลกมาก — บรรทัดสุดท้ายบอกว่า "`null` มากกว่าหรือเท่ากับศูนย์" ฉะนั้นในสองบรรทัดแรกอย่างน้อยต้องมีอันหนึ่งเป็น `true` ใช่ไหม? — แต่กลับเป็น false ทั้งคู่

ที่เป็นแบบนี้เพราะ การเช็คความเท่ากันด้วย `==` กับการเปรียบเทียบ `> < >= <=` ทำงานต่างกัน — การเปรียบเทียบจะแปลง `null` เป็นตัวเลขและมองเป็น `0` (3) `null >= 0` ก็เลยเป็น true และ (1) `null > 0` เป็น false

ส่วนการเช็ค `==` ระหว่าง `undefined` กับ `null` ถูกกำหนดไว้ว่าให้เท่ากันเองเท่านั้น โดยไม่มีการแปลงชนิด และไม่เท่ากับค่าอื่นใด — นั่นแหละคือเหตุผลที่ (2) `null == 0` เป็น false

### undefined เปรียบเทียบไม่ได้

อย่าเอา `undefined` ไปเปรียบเทียบกับค่าอื่น:

```js run
alert( undefined > 0 ); // false (1)
alert( undefined < 0 ); // false (2)
alert( undefined == 0 ); // false (3)
```

ทำไม `undefined` ถึงเกลียดศูนย์ขนาดนี้? ออกมาเป็น false หมดเลย!

เพราะ:

- การเปรียบเทียบ `(1)` กับ `(2)` ได้ `false` เพราะ `undefined` ถูกแปลงเป็น `NaN` ซึ่งเป็นค่าตัวเลขพิเศษที่จะคืน `false` เสมอเมื่อเปรียบเทียบ
- การเช็คความเท่ากัน `(3)` ได้ `false` เพราะ `undefined` เท่ากับแค่ `null` กับ `undefined` เท่านั้น ไม่เท่ากับค่าอื่น

### เลี่ยงปัญหา

ทำไมถึงยกตัวอย่างพวกนี้มา? ต้องจำเรื่องพิลึกๆ พวกนี้ตลอดเวลาเลยเหรอ? ไม่จำเป็นถึงขนาดนั้น — เรื่องพวกนี้พอเขียนนานๆ ไปก็จะคุ้นเอง — แต่มีท่าที่ดีกว่าในการเลี่ยงปัญหา:

- ระวังเป็นพิเศษเวลาเปรียบเทียบกับ `undefined/null` ยกเว้นเช็คความเท่ากันแบบเข้มงวดด้วย `===`
- อย่าใช้การเปรียบเทียบ `>= > < <=` กับตัวแปรที่อาจเป็น `null/undefined` เว้นแต่มั่นใจจริงๆ ว่ากำลังทำอะไรอยู่ — ถ้าตัวแปรอาจเป็นค่าพวกนี้ได้ ให้เช็ค `null/undefined` แยกออกมาก่อน

## สรุป

- ตัวดำเนินการเปรียบเทียบคืนค่าเป็น boolean
- เปรียบเทียบสตริงทีละตัวอักษรตามลำดับ "พจนานุกรม"
- เวลาเปรียบเทียบค่าคนละชนิด ค่าจะถูกแปลงเป็นตัวเลข (ยกเว้นการเช็คความเท่ากันแบบเข้มงวด)
- `null` กับ `undefined` เท่ากันเฉพาะตอนใช้ `==` และไม่เท่ากับค่าอื่นใดเลย
- ระวังเวลาใช้เปรียบเทียบอย่าง `>` หรือ `<` กับตัวแปรที่อาจเป็น `null/undefined` ได้ — บางครั้งเช็ค `null/undefined` แยกออกมาก่อนก็เป็นท่าที่ดีกว่า
