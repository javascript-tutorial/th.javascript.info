# การเปรียบเทียบ

เราคุ้นเคยกับตัวดำเนินการเปรียบเทียบหลายตัวจากวิชาคณิตศาสตร์อยู่แล้ว

ใน JavaScript เขียนแบบนี้:

- มากกว่า/น้อยกว่า: <code>a &gt; b</code>, <code>a &lt; b</code>
- มากกว่าหรือเท่ากับ/น้อยกว่าหรือเท่ากับ: <code>a &gt;= b</code>, <code>a &lt;= b</code>
- เท่ากับ: `a == b` สังเกตว่าใช้เครื่องหมายเท่ากับสองตัว `==` เพื่อตรวจว่าค่าเท่ากันหรือไม่ ส่วนเครื่องหมายตัวเดียว `a = b` ใช้กำหนดค่า
- ไม่เท่ากับ: ในคณิตศาสตร์ใช้สัญลักษณ์ <code>&ne;</code> แต่ใน JavaScript เขียนเป็น <code>a != b</code>

บทนี้เราจะดูว่าการเปรียบเทียบแต่ละแบบทำงานอย่างไร รวมถึงพฤติกรรมบางอย่างของ JavaScript ที่ควรรู้

ท้ายบทจะมีหลักง่ายๆ ที่ช่วยให้เราไม่พลาดเพราะพฤติกรรมชวนงงเหล่านี้

## ผลลัพธ์เป็นบูลีน

ตัวดำเนินการเปรียบเทียบทุกตัวจะคืนค่าบูลีน:

- `true` หมายถึง "ใช่" หรือ "จริง"
- `false` หมายถึง "ไม่ใช่" หรือ "เท็จ"

ตัวอย่างเช่น:

```js run
alert( 2 > 1 );  // true (ถูก)
alert( 2 == 1 ); // false (ผิด)
alert( 2 != 1 ); // true (ถูก)
```

ผลลัพธ์จากการเปรียบเทียบเก็บไว้ในตัวแปรได้เหมือนค่าอื่นๆ:

```js run
let result = 5 > 4; // เก็บผลลัพธ์จากการเปรียบเทียบ
alert( result ); // true
```

## การเปรียบเทียบสตริง

เมื่อต้องการดูว่าสตริงหนึ่งมากกว่าอีกสตริงหรือไม่ JavaScript จะเปรียบเทียบตามลำดับพจนานุกรม

พูดง่ายๆ คือไล่เทียบอักขระทีละตัวจากซ้ายไปขวา

ตัวอย่างเช่น:

```js run
alert( 'Z' > 'A' ); // true
alert( 'Glow' > 'Glee' ); // true
alert( 'Bee' > 'Be' ); // true
```

ขั้นตอนเปรียบเทียบสตริงสองตัวมีดังนี้:

1. เปรียบเทียบอักขระตัวแรกของทั้งสองสตริง
2. ถ้าอักขระตัวแรกของสตริงหนึ่งมากกว่าหรือน้อยกว่าอักขระตัวแรกของอีกสตริง ก็สรุปผลได้ทันที
3. ถ้าอักขระตัวแรกเหมือนกัน ให้เปรียบเทียบตัวถัดไปด้วยวิธีเดียวกัน
4. ทำซ้ำจนเจออักขระที่ต่างกัน หรือจนสตริงใดสตริงหนึ่งหมด
5. ถ้าทั้งสองสตริงหมดพร้อมกัน แสดงว่าเท่ากัน แต่ถ้ามีสตริงหนึ่งเหลืออักขระอยู่ สตริงที่ยาวกว่าจะถือว่ามากกว่า

ตัวอย่างแรก `'Z' > 'A'` รู้ผลตั้งแต่อักขระตัวแรก

ส่วน `'Glow'` กับ `'Glee'` ต้องไล่เทียบหลายตัว:

1. `G` เหมือนกับ `G`
2. `l` เหมือนกับ `l`
3. `o` มากกว่า `e` จึงหยุดตรงนี้และสรุปว่าสตริงแรกมากกว่า

```smart header="ไม่ใช่ลำดับในพจนานุกรมจริงๆ แต่เป็นลำดับ Unicode"
วิธีข้างต้นคล้ายกับการเรียงคำในพจนานุกรมหรือสมุดโทรศัพท์ แต่ไม่เหมือนเสียทีเดียว

ตัวพิมพ์เล็กกับตัวพิมพ์ใหญ่มีผลต่อการเปรียบเทียบ เช่น `"A"` ไม่เท่ากับ `"a"` แล้วตัวไหนมากกว่ากัน? คำตอบคือ `"a"` เพราะอักขระตัวพิมพ์เล็กอยู่ในตำแหน่งที่สูงกว่าในตารางรหัสภายในที่ JavaScript ใช้ ซึ่งก็คือ Unicode เราจะกลับมาดูรายละเอียดและผลที่ตามมาในบท <info:string>
```

## การเปรียบเทียบค่าต่างชนิด

เมื่อเปรียบเทียบค่าที่มีชนิดข้อมูลต่างกัน JavaScript จะแปลงค่าเหล่านั้นเป็นตัวเลขก่อน

ตัวอย่างเช่น:

```js run
alert( '2' > 1 ); // true เพราะสตริง '2' ถูกแปลงเป็นตัวเลข 2
alert( '01' == 1 ); // true เพราะสตริง '01' ถูกแปลงเป็นตัวเลข 1
```

ค่าบูลีนก็เช่นกัน `true` จะกลายเป็น `1` ส่วน `false` จะกลายเป็น `0`

ตัวอย่างเช่น:

```js run
alert( true == 1 ); // true
alert( false == 0 ); // true
```

````smart header="ผลลัพธ์ที่ชวนแปลกใจ"
ค่าคู่หนึ่งอาจมีคุณสมบัติพร้อมกันสองอย่าง:

- เท่ากันเมื่อเปรียบเทียบด้วย `==`
- แต่เมื่อนำแต่ละค่าไปแปลงเป็นบูลีน ค่าหนึ่งได้ `true` ส่วนอีกค่าได้ `false`

ลองดูตัวอย่าง:

```js run
let a = 0;
alert( Boolean(a) ); // false

let b = "0";
alert( Boolean(b) ); // true

alert(a == b); // true!
```

ในมุมของ JavaScript ผลลัพธ์นี้เป็นไปตามกฎปกติ เพราะ `==` แปลงค่าตามกฎการแปลงเป็นตัวเลข จึงเปลี่ยน `"0"` เป็น `0` ส่วนการเรียก `Boolean` โดยตรงใช้กฎการแปลงอีกชุดหนึ่ง
````

## ความเท่ากันแบบเข้มงวด

การเปรียบเทียบความเท่ากันด้วย `==` มีจุดที่ต้องระวัง เพราะมันแยก `0` ออกจาก `false` ไม่ได้:

```js run
alert( 0 == false ); // true
```

สตริงว่างก็ให้ผลแบบเดียวกัน:

```js run
alert( '' == false ); // true
```

สาเหตุคือเมื่อ `==` เปรียบเทียบค่าต่างชนิด มันจะแปลงค่าทั้งสองเป็นตัวเลขก่อน ทั้งสตริงว่างและ `false` ต่างก็กลายเป็น `0`

แล้วถ้าเราต้องการแยก `0` ออกจาก `false` ล่ะ?

**ตัวดำเนินการเปรียบเทียบความเท่ากันแบบเข้มงวด `===` จะตรวจว่าค่าเท่ากันหรือไม่โดยไม่แปลงชนิดข้อมูล**

ถ้า `a` กับ `b` เป็นคนละชนิด `a === b` จะคืน `false` ทันที โดยไม่ลองแปลงค่าก่อน

ลองดู:

```js run
alert( 0 === false ); // false เพราะเป็นคนละชนิด
```

JavaScript ยังมีตัวดำเนินการเปรียบเทียบความไม่เท่ากันแบบเข้มงวด `!==` ซึ่งทำหน้าที่คล้ายกับ `!=`

แม้ `===` จะพิมพ์ยาวกว่า `==` เล็กน้อย แต่พฤติกรรมชัดเจนกว่าและช่วยลดโอกาสเกิดข้อผิดพลาด

## การเปรียบเทียบกับ null และ undefined

การนำ `null` หรือ `undefined` ไปเปรียบเทียบกับค่าอื่นอาจให้ผลที่ไม่ตรงกับที่เราคาด

เมื่อใช้ `===`
: ค่าทั้งสองไม่เท่ากัน เพราะมีชนิดข้อมูลต่างกัน

    ```js run
    alert( null === undefined ); // false
    ```

เมื่อใช้ `==`
: มีกฎพิเศษว่า `null` กับ `undefined` จะถือว่าเท่ากัน แต่ไม่เท่ากับค่าอื่น

    ```js run
    alert( null == undefined ); // true
    ```

เมื่อใช้ในการคำนวณหรือการเปรียบเทียบอื่นๆ `< > <= >=`
: `null` และ `undefined` จะถูกแปลงเป็นตัวเลข โดย `null` กลายเป็น `0` ส่วน `undefined` กลายเป็น `NaN`

ทีนี้มาดูผลลัพธ์ชวนงงที่เกิดจากกฎเหล่านี้ และดูว่าจะหลีกเลี่ยงกับดักได้อย่างไร

### ผลลัพธ์ชวนงง: null เทียบกับ 0

ลองเปรียบเทียบ `null` กับศูนย์:

```js run
alert( null > 0 );  // (1) false
alert( null == 0 ); // (2) false
alert( null >= 0 ); // (3) *!*true*/!*
```

ถ้ามองแบบคณิตศาสตร์ ผลลัพธ์นี้ดูขัดกัน บรรทัดสุดท้ายบอกว่า `null` มากกว่าหรือเท่ากับศูนย์ ดังนั้น `null > 0` หรือ `null == 0` ก็น่าจะเป็น `true` อย่างน้อยหนึ่งบรรทัด แต่ทั้งสองบรรทัดกลับเป็น `false`

สาเหตุคือ `==` กับตัวดำเนินการ `> < >= <=` ใช้กฎคนละแบบ ตัวดำเนินการเปรียบเทียบจะแปลง `null` เป็นตัวเลข `0` ดังนั้น (3) `null >= 0` จึงเป็น `true` ส่วน (1) `null > 0` เป็น `false`

แต่ `==` มีกฎเฉพาะสำหรับ `null` และ `undefined` ว่าเมื่อเปรียบเทียบกันจะถือว่าเท่ากันโดยไม่ต้องแปลงชนิด และทั้งคู่ไม่เท่ากับค่าอื่น นี่จึงเป็นเหตุผลที่ (2) `null == 0` ได้ `false`

### ไม่ควรเปรียบเทียบ undefined กับค่าอื่น

เราไม่ควรนำ `undefined` ไปเปรียบเทียบกับค่าอื่น:

```js run
alert( undefined > 0 ); // false (1)
alert( undefined < 0 ); // false (2)
alert( undefined == 0 ); // false (3)
```

ทำไมเปรียบเทียบกับศูนย์แล้วได้ `false` ทุกครั้ง?

เหตุผลคือ:

- การเปรียบเทียบ (1) และ (2) ได้ `false` เพราะ `undefined` ถูกแปลงเป็น `NaN` ซึ่งเมื่อนำไปเปรียบเทียบด้วย `>` หรือ `<` จะได้ `false`
- การตรวจความเท่ากันใน (3) ได้ `false` เพราะเมื่อใช้ `==` ค่า `undefined` จะเท่ากับแค่ `null` หรือ `undefined`

### วิธีหลีกเลี่ยงปัญหา

เราไม่จำเป็นต้องท่องจำผลลัพธ์แปลกๆ เหล่านี้ทั้งหมด เมื่อเขียน JavaScript ไปสักพักก็จะค่อยๆ คุ้นเอง แต่มีหลักง่ายๆ ที่ช่วยหลีกเลี่ยงปัญหาได้:

- ระวังเป็นพิเศษเมื่อเปรียบเทียบกับ `undefined` หรือ `null` ยกเว้นการตรวจแบบเข้มงวดด้วย `===`
- อย่าใช้ `>= > < <=` กับตัวแปรที่อาจเป็น `null` หรือ `undefined` เว้นแต่จะเข้าใจกฎการแปลงค่าที่เกิดขึ้น ถ้าตัวแปรอาจมีค่าเหล่านี้ ให้ตรวจ `null` และ `undefined` แยกก่อน

## สรุป

- ตัวดำเนินการเปรียบเทียบคืนค่าเป็นบูลีน
- สตริงจะถูกเปรียบเทียบทีละอักขระตามลำดับแบบพจนานุกรม
- เมื่อเปรียบเทียบค่าต่างชนิด JavaScript จะแปลงค่าเป็นตัวเลขก่อน ยกเว้นการเปรียบเทียบความเท่ากันแบบเข้มงวด
- `null` และ `undefined` ต่างก็เท่ากับตัวเอง และยังถือว่าเท่ากันเมื่อใช้ `==` แต่ไม่เท่ากับค่าอื่น
- ระวังการใช้ `>` หรือ `<` กับตัวแปรที่อาจเป็น `null` หรือ `undefined` ควรตรวจค่าเหล่านี้แยกก่อน
