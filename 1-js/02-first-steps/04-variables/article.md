# ตัวแปร

เวลาเขียนแอปด้วย JavaScript เราแทบเลี่ยงการทำงานกับข้อมูลไม่ได้ ลองดูสองตัวอย่างนี้:

1. ร้านค้าออนไลน์ — มีทั้งข้อมูลสินค้าและตะกร้าสินค้า
2. แอปแชท — มีข้อมูลผู้ใช้ ข้อความ และข้อมูลอื่นๆ อีกมากมาย

เราใช้ตัวแปรเก็บข้อมูลเหล่านี้

## ตัวแปรคืออะไร

ถ้าต้องเก็บข้อมูลไว้ใช้ต่อ ลองนึกว่าเรามีกล่องแต่ละใบที่ติดชื่อไว้ กล่องนี้คือ [ตัวแปร](https://en.wikipedia.org/wiki/Variable_(computer_science)) จะใส่ข้อมูลสินค้า ข้อมูลผู้เข้าชม หรือข้อมูลอื่นๆ ก็ได้

ถ้าจะสร้างตัวแปรใน JavaScript ให้ใช้คีย์เวิร์ด `let`

คำสั่งนี้สร้างตัวแปรชื่อ `message` หรือที่เรียกว่า *ประกาศ* ตัวแปร:

```js
let message;
```

ทีนี้ก็ใส่ข้อมูลลงไปได้ด้วยตัวดำเนินการกำหนดค่า `=`:

```js
let message;

*!*
message = 'สวัสดี'; // เก็บสตริง 'สวัสดี' ไว้ในตัวแปรชื่อ message
*/!*
```

JavaScript จะเก็บสตริงไว้ในพื้นที่หน่วยความจำของตัวแปร เมื่อต้องการใช้ค่าข้างใน ก็เรียกผ่านชื่อตัวแปรได้เลย:

```js run
let message;
message = 'สวัสดี!';

*!*
alert(message); // แสดงค่าที่เก็บอยู่ในตัวแปร
*/!*
```

ถ้าอยากเขียนให้สั้นลง จะประกาศตัวแปรและกำหนดค่าในบรรทัดเดียวกันก็ได้:

```js run
let message = 'สวัสดี!'; // ประกาศตัวแปรพร้อมกำหนดค่า

alert(message); // สวัสดี!
```

จะประกาศหลายตัวแปรในบรรทัดเดียวก็ได้เหมือนกัน:

```js no-beautify
let user = 'จอห์น', age = 25, message = 'สวัสดี';
```

แบบนี้ดูสั้นดี แต่ไม่แนะนำ เพราะแยกตัวแปรละบรรทัดแล้วอ่านง่ายกว่า

แม้จะยาวขึ้นนิดหน่อย แต่เห็นแต่ละตัวแปรชัดเจน:

```js
let user = 'จอห์น';
let age = 25;
let message = 'สวัสดี';
```

บางคนประกาศหลายตัวแปรโดยแยกบรรทัดแบบนี้:

```js no-beautify
let user = 'จอห์น',
  age = 25,
  message = 'สวัสดี';
```

หรือเขียนแบบ "comma-first" ที่วางจุลภาคไว้ต้นบรรทัด:

```js no-beautify
let user = 'จอห์น'
  , age = 25
  , message = 'สวัสดี';
```

ทั้งหมดนี้ทำงานเหมือนกัน จะเลือกแบบไหนก็ขึ้นอยู่กับความชอบและรูปแบบการเขียนโค้ดของแต่ละคน

````smart header="ใช้ `var` แทน `let`"
ในสคริปต์เก่าๆ เราอาจเจอคีย์เวิร์ด `var` แทน `let`:

```js
*!*var*/!* message = 'สวัสดี';
```

`var` *เกือบจะ* เหมือน `let` เพราะใช้ประกาศตัวแปรเหมือนกัน แต่รายละเอียดการทำงานบางอย่างต่างกันตามรูปแบบ JavaScript ยุคเก่า

ตอนนี้ยังไม่ต้องกังวลเรื่องความต่างเหล่านั้น เราจะดูอย่างละเอียดอีกทีในบท <info:var>
````

## เปรียบเทียบกับชีวิตจริง

ถ้ายังนึกภาพตัวแปรไม่ออก ลองมองว่าเป็น "กล่อง" ใส่ข้อมูลที่มีป้ายชื่อไม่ซ้ำกันแปะอยู่

ตัวแปร `message` ก็เหมือนกล่องที่ติดป้ายว่า `"message"` และมีค่า `"สวัสดี!"` อยู่ข้างใน:

![](variable.svg)

เราจะใส่ค่าอะไรก็ได้ลงในกล่อง และเปลี่ยนค่ากี่ครั้งก็ได้:

```js run
let message;

message = 'สวัสดี!';

message = 'ชาวโลก!'; // เปลี่ยนค่าแล้ว

alert(message);
```

เมื่อใส่ค่าใหม่ ค่าเก่าก็จะหายไปจากตัวแปร:

![](variable-change.svg)

เรายังประกาศตัวแปรสองตัว แล้วคัดลอกข้อมูลจากตัวหนึ่งไปไว้อีกตัวได้ด้วย:

```js run
let hello = 'สวัสดีชาวโลก!';

let message;

*!*
// คัดลอก 'สวัสดีชาวโลก!' จาก hello ไปไว้ใน message
message = hello;
*/!*

// ตอนนี้ตัวแปรทั้งสองเก็บข้อมูลเดียวกัน
alert(hello); // สวัสดีชาวโลก!
alert(message); // สวัสดีชาวโลก!
```

````warn header="ประกาศซ้ำแล้วเกิด error"
ตัวแปรแต่ละตัวควรประกาศเพียงครั้งเดียว

ถ้าประกาศตัวแปรชื่อเดิมซ้ำ JavaScript จะพ่น error:

```js run
let message = "นี่";

// ใส่ 'let' ซ้ำจึงเกิด error
let message = "นั่น"; // SyntaxError: 'message' has already been declared
```

จำง่ายๆ ว่าประกาศด้วย `let` ครั้งเดียว หลังจากนั้นก็เรียกชื่อตัวแปรได้เลย
````

```smart header="ภาษาแบบ functional"
มีภาษาโปรแกรมแบบ [pure functional](https://en.wikipedia.org/wiki/Purely_functional_programming) เช่น [Haskell](https://en.wikipedia.org/wiki/Haskell) ที่ไม่ยอมให้เราเปลี่ยนค่าของตัวแปรเลย

พอใส่ค่าลงใน "กล่อง" แล้ว ค่านั้นจะอยู่ตลอดไป หากอยากเก็บข้อมูลใหม่ก็ต้องสร้างกล่องใหม่ หรือประกาศตัวแปรใหม่นั่นเอง กล่องเดิมนำกลับมาใช้ซ้ำไม่ได้

ฟังดูแปลกใช่ไหม? ภาษาเหล่านี้ใช้พัฒนาโปรแกรมจริงจังได้ และข้อจำกัดนี้ยังมีประโยชน์กับงานบางประเภท เช่น การประมวลผลแบบขนาน
```

## การตั้งชื่อตัวแปร [#variable-naming]

JavaScript มีกฎตั้งชื่อตัวแปรอยู่ 2 ข้อ:

1. ชื่อต้องมีเฉพาะตัวอักษร ตัวเลข หรือสัญลักษณ์ `$` กับ `_`
2. ตัวแรกของชื่อต้องไม่ใช่ตัวเลข

ตัวอย่างชื่อที่ใช้ได้:

```js
let userName;
let test123;
```

ถ้าชื่อมีหลายคำ เรานิยมเขียนแบบ [camelCase](https://en.wikipedia.org/wiki/CamelCase) โดยนำคำมาต่อกัน คำแรกขึ้นต้นด้วยตัวพิมพ์เล็ก ส่วนคำถัดไปขึ้นต้นด้วยตัวพิมพ์ใหญ่ เช่น `myVeryLongName`

สัญลักษณ์ดอลลาร์ `'$'` และขีดล่าง `'_'` ก็ใช้ในชื่อตัวแปรได้เหมือนตัวอักษรทั่วไป ทั้งคู่ไม่มีความหมายพิเศษ

ชื่อเหล่านี้ใช้ได้:

```js run untrusted
let $ = 1; // ประกาศตัวแปรชื่อ "$"
let _ = 2; // ประกาศตัวแปรชื่อ "_"

alert($ + _); // 3
```

ส่วนชื่อเหล่านี้ใช้ไม่ได้:

```js no-beautify
let 1a; // ห้ามขึ้นต้นด้วยตัวเลข

let my-name; // ใช้ขีดกลาง '-' ในชื่อไม่ได้
```

```smart header="ตัวพิมพ์เล็กและตัวพิมพ์ใหญ่ถือเป็นคนละชื่อ"
`apple` กับ `APPLE` เป็นตัวแปรคนละตัวกัน
```

````smart header="ใช้อักษรภาษาอื่นได้ แต่ไม่แนะนำ"
เราตั้งชื่อตัวแปรด้วยอักษรภาษาอื่นได้ ไม่ว่าจะเป็นอักษรซีริลลิก อักษรจีน หรือภาษาอื่นๆ เช่น:

```js
let имя = '...';
let 我 = '...';
```

ชื่อแบบนี้ไม่ผิดกฎและใช้งานได้จริง แต่คนเขียนโปรแกรมทั่วโลกตกลงกันว่าจะตั้งชื่อตัวแปรเป็นภาษาอังกฤษ แม้วันนี้จะเป็นเพียงสคริปต์สั้นๆ วันข้างหน้าก็อาจมีคนจากประเทศอื่นต้องมาอ่านต่อ
````

````warn header="คำสงวน"
JavaScript มี [รายการคำสงวน](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Lexical_grammar#Keywords) ที่ตัวภาษาเก็บไว้ใช้เอง เราจึงนำคำเหล่านี้มาตั้งเป็นชื่อตัวแปรไม่ได้

ตัวอย่างคำสงวน ได้แก่ `let`, `class`, `return` และ `function`

โค้ดด้านล่างจะพ่น syntax error:

```js run no-beautify
let let = 5; // ตั้งชื่อตัวแปรว่า "let" ไม่ได้ เพราะเป็นคำสงวน
let return = 5; // ตั้งชื่อว่า "return" ไม่ได้เช่นกัน
```
````

````warn header="กำหนดค่าโดยไม่ใช้ `use strict`"

ตามปกติ เราต้องประกาศตัวแปรก่อนนำมาใช้ แต่ JavaScript สมัยก่อนยอมให้สร้างตัวแปรด้วยการกำหนดค่าโดยตรงโดยไม่ต้องใส่ `let` ทุกวันนี้วิธีนี้ยังใช้ได้ถ้าสคริปต์ไม่มี `use strict` เพื่อให้โค้ดเก่ายังทำงานต่อไปได้

```js run no-strict
// หมายเหตุ: ตัวอย่างนี้ไม่มี "use strict"

num = 5; // ถ้ายังไม่มีตัวแปร "num" JavaScript จะสร้างให้

alert(num); // 5
```

วิธีนี้ไม่ควรใช้ และจะเกิด error ทันทีเมื่อเปิดโหมดเข้มงวด (strict mode):

```js
"use strict";

*!*
num = 5; // error: num is not defined
*/!*
```
````

## ค่าคงที่

ถ้าจะประกาศตัวแปรที่ค่าไม่เปลี่ยน ให้ใช้ `const` แทน `let`:

```js
const myBirthday = '18.04.1982';
```

ตัวแปรที่ประกาศด้วย `const` เรียกว่า "ค่าคงที่" เรากำหนดค่าใหม่ให้ไม่ได้ และถ้าลองทำก็จะเกิด error:

```js run
const myBirthday = '18.04.1982';

myBirthday = '01.01.2001'; // error: กำหนดค่าใหม่ให้ค่าคงที่ไม่ได้
```

เมื่อมั่นใจว่าค่าของตัวแปรจะไม่เปลี่ยน ก็ประกาศด้วย `const` ได้เลย ทั้งช่วยป้องกันการเปลี่ยนค่าและบอกคนอ่านโค้ดไปพร้อมกัน

### ค่าคงที่ที่ใช้ตัวพิมพ์ใหญ่

เรานิยมใช้ค่าคงที่เป็นชื่อแทนค่าที่จำยากและรู้ค่าอยู่แล้วก่อนโปรแกรมเริ่มทำงาน

ค่าคงที่แบบนี้จะตั้งชื่อด้วยตัวพิมพ์ใหญ่และคั่นแต่ละคำด้วยขีดล่าง

ลองสร้างค่าคงที่แทนรหัสสีแบบเว็บ หรือเลขฐานสิบหก:

```js run
const COLOR_RED = "#F00";
const COLOR_GREEN = "#0F0";
const COLOR_BLUE = "#00F";
const COLOR_ORANGE = "#FF7F00";

// เมื่อต้องการเลือกสี
let color = COLOR_ORANGE;
alert(color); // #FF7F00
```

ข้อดีมีอยู่หลายอย่าง:

- `COLOR_ORANGE` จำง่ายกว่า `"#FF7F00"`
- `"#FF7F00"` พิมพ์ผิดได้ง่ายกว่า `COLOR_ORANGE`
- เวลาอ่านโค้ด `COLOR_ORANGE` สื่อความหมายชัดกว่า `#FF7F00`

แล้วเมื่อไหร่ควรตั้งชื่อค่าคงที่ด้วยตัวพิมพ์ใหญ่ เมื่อไหร่ควรตั้งแบบปกติ?

คำว่า "ค่าคงที่" บอกเพียงว่าค่านั้นจะไม่เปลี่ยน บางค่ารู้ได้ตั้งแต่ก่อนโปรแกรมเริ่มทำงาน เช่น รหัสเลขฐานสิบหกของสีแดง ส่วนบางค่าต้องรอ *คำนวณ* ระหว่างที่โปรแกรมทำงาน แต่เมื่อกำหนดแล้วก็จะไม่เปลี่ยนอีก

ตัวอย่างเช่น:

```js
const pageLoadTime = /* เวลาที่หน้าเว็บใช้ในการโหลด */;
```

เรายังไม่รู้ค่า `pageLoadTime` จนกว่าหน้าเว็บจะโหลด จึงตั้งชื่อแบบปกติ แต่ตัวแปรนี้ยังเป็นค่าคงที่ เพราะค่าจะไม่เปลี่ยนหลังจากกำหนดแล้ว

สรุปคือ ชื่อค่าคงที่แบบตัวพิมพ์ใหญ่ใช้เป็นชื่อแทนค่าที่ "ฮาร์ดโค้ด" ไว้เท่านั้น

## ตั้งชื่อให้สื่อความหมาย

เรื่องสำคัญอีกอย่างของตัวแปรคือ ชื่อต้องอ่านแล้วเข้าใจได้ทันทีว่าเก็บข้อมูลอะไรอยู่

การตั้งชื่อเป็นหนึ่งในทักษะที่สำคัญและไม่ง่ายเลยในการเขียนโปรแกรม แค่มองชื่อตัวแปรก็มักพอเดาได้ว่าโค้ดนั้นเขียนโดยมือใหม่หรือคนที่มีประสบการณ์

ในโปรเจกต์จริง เราใช้เวลาส่วนใหญ่แก้ไขและต่อยอดโค้ดเดิม ไม่ได้เขียนทุกอย่างใหม่จากศูนย์ พอกลับมาอ่านโค้ดหลังจากห่างไปสักพัก ชื่อตัวแปรที่ชัดเจนจะช่วยให้หาข้อมูลที่ต้องการเจอเร็วขึ้นมาก

เสียเวลาคิดชื่อก่อนประกาศตัวแปรสักนิด แล้วจะประหยัดเวลาได้อีกเยอะในภายหลัง

หลักที่ควรใช้มีดังนี้:

- ตั้งชื่อให้อ่านแล้วเข้าใจ เช่น `userName` หรือ `shoppingCart`
- เลี่ยงคำย่อหรือชื่อสั้นๆ อย่าง `a`, `b` และ `c` เว้นแต่จะรู้ชัดว่ากำลังทำอะไร
- ตั้งชื่อให้สื่อความหมายที่สุดโดยไม่เยิ่นเย้อ ชื่ออย่าง `data` หรือ `value` ไม่ได้บอกว่าเก็บอะไร จึงควรใช้เฉพาะตอนที่บริบทรอบข้างชัดเจนมากเท่านั้น
- ตกลงคำเรียกให้ตรงกันทั้งทีมและใช้ให้คงเส้นคงวา ถ้าเรียกผู้เข้าชมเว็บไซต์ว่า "user" ก็ควรใช้ชื่ออย่าง `currentUser` หรือ `newUser` ไม่ใช่ `currentVisitor` หรือ `newManInTown`

ฟังดูง่ายใช่ไหม? แต่พอลงมือจริง การตั้งชื่อให้ทั้งชัดเจนและกระชับไม่ง่ายอย่างที่คิด ลองฝึกกันดู

ข้อสุดท้าย มีโปรแกรมเมอร์บางคนที่ไม่อยากประกาศตัวแปรเพิ่ม จึงนำตัวแปรเดิมกลับมาใช้ซ้ำ

## สรุป

เราประกาศตัวแปรเพื่อเก็บข้อมูลได้ด้วยคีย์เวิร์ด `var`, `let` หรือ `const`

- `let` — ใช้ประกาศตัวแปรแบบสมัยใหม่
- `var` — ใช้ประกาศตัวแปรแบบเก่า ปกติเราไม่ใช้แล้ว แต่จะอธิบายความต่างจาก `let` ไว้ในบท <info:var> เผื่อต้องเจอโค้ดที่ยังใช้อยู่
- `const` — คล้าย `let` แต่เปลี่ยนค่าของตัวแปรไม่ได้

ควรตั้งชื่อตัวแปรให้อ่านแล้วเข้าใจได้ง่ายว่าข้างในเก็บอะไรอยู่
