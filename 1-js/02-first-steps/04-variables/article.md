# ตัวแปร

แทบทุกแอป JavaScript ก็ต้องมีการจัดการข้อมูลเป็นเรื่องปกติ เช่น
1. ร้านค้าออนไลน์ — ข้อมูลก็อาจเป็นสินค้าที่ขายและตะกร้าสินค้า
2. แอปแชท — ข้อมูลก็เป็นพวกผู้ใช้ ข้อความ และอื่นๆ อีกเพียบ

ของพวกนี้แหละที่เราใช้ตัวแปรเก็บไว้

## ตัวแปรคืออะไร

[ตัวแปร](https://en.wikipedia.org/wiki/Variable_(computer_science)) ก็คือ "พื้นที่เก็บข้อมูลที่มีชื่อกำกับ" — เอาไว้เก็บสินค้า ข้อมูลผู้เข้าชม หรืออะไรก็ได้

วิธีสร้างตัวแปรใน JavaScript ใช้คีย์เวิร์ด `let`

คำสั่งข้างล่างนี้สร้าง (หรือที่เรียกว่า *ประกาศ*) ตัวแปรชื่อ "message":

```js
let message;
```

ทีนี้เอาข้อมูลใส่ลงในตัวแปรได้แล้วผ่านเครื่องหมาย `=` หรือที่เรียกว่าตัวดำเนินการกำหนดค่า (assignment operator):

```js
let message;

*!*
message = 'สวัสดี'; // เก็บข้อความ 'สวัสดี' ในตัวแปรที่ชื่อว่า message
*/!*
```

ข้อความจะไปเก็บอยู่ในพื้นที่หน่วยความจำที่ผูกกับตัวแปรนั้น เรียกใช้ก็แค่อ้างชื่อตัวแปร:

```js run
let message;
message = 'สวัสดี!';

*!*
alert(message); // โชว์ค่าในตัวแปร
*/!*
```

ให้สั้นลง รวมการประกาศกับการกำหนดค่าไว้ในบรรทัดเดียวก็ได้:

```js run
let message = 'สวัสดี!'; // ประกาศตัวแปรและกำหนดค่าในคำสั่งเดียว

alert(message); // สวัสดี!
```

ประกาศหลายตัวในบรรทัดเดียวก็ทำได้เหมือนกัน:

```js no-beautify
let user = 'จอห์น', age = 25, message = 'สวัสดี';
```

วิธีนี้ดูสั้นดี — แต่ไม่แนะนำ ถ้าอยากให้อ่านง่ายควรแยกตัวแปรคนละบรรทัดจะดีกว่า

แบบนี้ยาวกว่านิดหน่อย แต่อ่านง่ายขึ้นเยอะ:

```js
let user = 'จอห์น';
let age = 25;
let message = 'สวัสดี';
```

บางคนยังชอบประกาศตัวแปรหลายตัวแบบหลายบรรทัดแบบนี้:

```js no-beautify
let user = 'จอห์น',
  age = 25,
  message = 'สวัสดี';
```

หรือเขียนแบบ "comma-first" (เริ่มต้นด้วยจุลภาค) ก็ได้:

```js no-beautify
let user = 'จอห์น'
  , age = 25
  , message = 'สวัสดี';
```

จริงๆ แล้วทุกแบบที่ยกมาทำงานเหมือนกันหมด — เลือกใช้ตามรสนิยมได้เลย

````smart header="`var` กับ `let`"
ในสคริปต์เก่าๆ อาจเจอ `var` แทนที่จะเป็น `let`:

```js
*!*var*/!* message = 'สวัสดี';
```

`var` ก็ *เกือบจะ* เหมือน `let` คือใช้ประกาศตัวแปรเหมือนกัน แต่ทำงานต่างกันนิดหน่อยในแบบที่ "เชยๆ"

ความต่างระหว่าง `let` กับ `var` ตอนนี้ยังไม่ใช่ประเด็นสำคัญ ไว้คุยกันละเอียดในบท <info:var>

````

# เปรียบเทียบกับชีวิตจริง

ลองนึกภาพ "ตัวแปร" เป็น "กล่อง" ที่เอาไว้ใส่ข้อมูล มีสติกเกอร์ชื่อแปะข้างนอก

เช่น ตัวแปร `message` ก็เหมือนกล่องที่มีป้ายชื่อ `"message"` แปะอยู่ ข้างในมีค่า `"สวัสดี!"`:

![](variable.svg)

ใส่อะไรลงในกล่องก็ได้ จะเปลี่ยนกี่ครั้งก็ได้ตามใจ:

```js run
let message;

message = 'สวัสดี!';

message = 'ชาวโลก!'; // เปลี่ยนค่าแล้ว

alert(message);
```

พอเปลี่ยนค่าใหม่ ค่าเก่าก็จะหายไปจากตัวแปร:

![](variable-change.svg)

ประกาศตัวแปรสองตัว แล้วก็อปข้อมูลจากตัวหนึ่งไปอีกตัวก็ได้:

```js run
let hello = 'สวัสดีชาวโลก!';

let message;

*!*
// ก็อป 'สวัสดีชาวโลก!' จาก hello มาเก็บใน message
message = hello;
*/!*

// ตอนนี้ทั้งสองตัวเก็บค่าเดียวกัน
alert(hello); // สวัสดีชาวโลก!
alert(message); // สวัสดีชาวโลก!
```

````warn header="ประกาศตัวแปรซ้ำ จะพ่น error"
ตัวแปรหนึ่งตัวประกาศได้แค่ครั้งเดียวเท่านั้น

ถ้าประกาศซ้ำ จะกลายเป็น error ทันที:

```js run
let message = "นี่";

// ประกาศ 'let' ซ้ำ พ่น error
let message = "นั่น"; // SyntaxError: 'message' ถูกประกาศไปแล้ว
```

ก็คือ ประกาศแค่ครั้งเดียวพอ หลังจากนั้นอ้างถึงได้เลยโดยไม่ต้องใส่ `let` อีก
````

```smart header="ภาษาแบบ functional"
น่าสนใจว่า มีภาษาที่เรียกว่า [functional แบบบริสุทธิ์](https://en.wikipedia.org/wiki/Purely_functional_programming) อย่าง [Haskell](https://en.wikipedia.org/wiki/Haskell) ที่ห้ามเปลี่ยนค่าตัวแปรเด็ดขาด

พอใส่ค่าลง "กล่อง" ไปแล้ว ก็อยู่ในนั้นตลอดไป ถ้าจะเก็บข้อมูลอย่างอื่น ภาษาบังคับให้สร้างกล่องใหม่ (ประกาศตัวแปรใหม่) เลย — ใช้กล่องเดิมซ้ำไม่ได้

ฟังดูแปลกๆ ใช่ไหม? แต่ภาษาพวกนี้ก็เขียนโปรแกรมจริงจังได้ ยิ่งไปกว่านั้น พอเป็นเรื่องการประมวลผลแบบขนาน ข้อจำกัดแบบนี้กลับมีประโยชน์เสียด้วยซ้ำ
```

## การตั้งชื่อตัวแปร [#variable-naming]

JavaScript มีกฎตั้งชื่อตัวแปรอยู่ 2 ข้อ:

1. ชื่อต้องประกอบด้วยตัวอักษร ตัวเลข หรือสัญลักษณ์ `$` กับ `_` เท่านั้น
2. ตัวแรกต้องไม่ใช่ตัวเลข

ตัวอย่างชื่อที่ใช้ได้:

```js
let userName;
let test123;
```

ถ้าชื่อมีหลายคำ คนนิยมเขียนแบบ [camelCase](https://en.wikipedia.org/wiki/CamelCase) — เขียนคำต่อๆ กัน คำแรกขึ้นต้นด้วยตัวพิมพ์เล็ก คำถัดๆ ไปขึ้นต้นด้วยตัวพิมพ์ใหญ่ เช่น `myVeryLongName`

ที่น่าสนใจคือ เครื่องหมายดอลลาร์ `'$'` กับอันเดอร์สกอร์ `'_'` ก็ใช้ในชื่อตัวแปรได้เหมือนตัวอักษรทั่วไป ไม่ได้มีความหมายพิเศษอะไร

ชื่อพวกนี้ใช้ได้:

```js run untrusted
let $ = 1; // ประกาศตัวแปรชื่อ "$"
let _ = 2; // และนี่ตัวแปรชื่อ "_"

alert($ + _); // 3
```

ตัวอย่างชื่อตัวแปรที่ใช้ไม่ได้:

```js no-beautify
let 1a; // ห้ามขึ้นต้นด้วยตัวเลข

let my-name; // เครื่องหมายขีด '-' ใช้ในชื่อไม่ได้
```

```smart header="ตัวพิมพ์ใหญ่-เล็กไม่เหมือนกัน"
`apple` กับ `APPLE` ถือเป็นคนละตัวแปร
```

```smart header="ภาษาอื่นนอกจากอังกฤษก็ใช้ได้ แต่ไม่แนะนำ"
ใช้อักษรภาษาอื่นได้นะ จะเป็นรัสเซีย จีน หรืออะไรก็ตาม เช่น:

```js
let имя = '...';
let 我 = '...';
```

จริงๆ แล้วเขียนแบบนี้ไม่ผิดไวยากรณ์ ทำได้ แต่มีข้อตกลงสากลกันว่าให้ตั้งชื่อตัวแปรเป็นภาษาอังกฤษ เพราะแม้จะเป็นสคริปต์สั้นๆ ก็อาจอยู่นานมาก และวันหนึ่งคนจากประเทศอื่นอาจต้องเข้ามาอ่านโค้ดเรา
```

```warn header="คำสงวน"
มี[รายการคำสงวน](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Lexical_grammar#Keywords) ที่ตัวภาษาจองไว้ใช้เอง เลยเอามาตั้งเป็นชื่อตัวแปรไม่ได้

เช่น `let`, `class`, `return`, `function` เป็นคำสงวนทั้งหมด

โค้ดข้างล่างนี้จะพ่น syntax error:

```js run no-beautify
let let = 5; // ตั้งชื่อตัวแปรว่า "let" ไม่ได้ เพราะเป็นคำสงวน — error!
let return = 5; // เหมือนกัน ห้ามตั้งชื่อว่า "return" — error!
```
```

```warn header="กำหนดค่าโดยไม่ใช้ `use strict`"

ปกติต้องประกาศตัวแปรก่อนใช้งาน แต่สมัยก่อนมีช่องโหว่ที่สร้างตัวแปรได้แค่กำหนดค่าให้มันตรงๆ ไม่ต้องใส่ `let` ก็ได้ ท่านี้ยังใช้ได้ถ้าไม่ใส่ `use strict` ในสคริปต์ — เก็บไว้เพื่อให้โค้ดเก่ายังรันได้

```js run no-strict
// หมายเหตุ: ตัวอย่างนี้ไม่มี "use strict"

num = 5; // ถ้าไม่มีตัวแปร "num" มาก่อน จะถูกสร้างให้อัตโนมัติ

alert(num); // 5
```

เป็นท่าที่ไม่ดี — จะพ่น error ทันทีในโหมดเข้มงวด (strict mode):

```js
"use strict";

*!*
num = 5; // error: ตัวแปร num ยังไม่ได้ประกาศ
*/!*
```

## ค่าคงที่ (Constants)

ถ้าจะประกาศตัวแปรที่ไม่เปลี่ยนค่า ให้ใช้ `const` แทน `let`:

```js
const myBirthday = '18.04.1982';
```

ตัวแปรที่ประกาศด้วย `const` เรียกว่า "ค่าคงที่" — เปลี่ยนค่าใหม่ไม่ได้ ถ้าพยายามทำจะพ่น error ออกมา:

```js run
const myBirthday = '18.04.1982';

myBirthday = '01.01.2001'; // error — ค่าคงที่กำหนดค่าใหม่ไม่ได้!
```

เวลาที่เรามั่นใจว่าตัวแปรนี้จะไม่เปลี่ยนค่าแน่ๆ ก็ใช้ `const` ประกาศได้เลย เพื่อการันตีและบอกให้คนอ่านโค้ดรู้ด้วยว่ามันจะไม่เปลี่ยน

### ค่าคงที่ที่ใช้ตัวพิมพ์ใหญ่

อีกท่าที่นิยมกัน คือใช้ค่าคงที่เป็น alias สำหรับค่าที่จำยาก — ค่าที่เรารู้แล้วก่อนรันโปรแกรม

ค่าคงที่แบบนี้นิยมตั้งชื่อด้วยตัวพิมพ์ใหญ่ทั้งหมดและคั่นด้วยอันเดอร์สกอร์

เช่น ลองสร้างค่าคงที่แทนรหัสสีในฟอร์แมต "web" (เลขฐานสิบหก):

```js run
const COLOR_RED = "#F00";
const COLOR_GREEN = "#0F0";
const COLOR_BLUE = "#00F";
const COLOR_ORANGE = "#FF7F00";

// พอจะเอามาใช้
let color = COLOR_ORANGE;
alert(color); // #FF7F00
```

ข้อดี:

- `COLOR_ORANGE` จำง่ายกว่า `"#FF7F00"` เยอะ
- พิมพ์ `"#FF7F00"` ผิดง่ายกว่า `COLOR_ORANGE`
- เวลาอ่านโค้ด `COLOR_ORANGE` สื่อความหมายชัดเจนกว่า `#FF7F00`

แล้วเมื่อไหร่ควรใช้ตัวพิมพ์ใหญ่ เมื่อไหร่ควรใช้ชื่อปกติล่ะ? มาดูกัน

คำว่า "ค่าคงที่" แปลว่าค่าจะไม่เปลี่ยนเท่านั้นเอง — แต่ค่าคงที่บางตัวเรารู้ค่าตั้งแต่ก่อนรันโปรแกรม (เช่นรหัสฐานสิบหกของสีแดง) ส่วนอีกประเภทคือถูก *คำนวณ* ตอนรันไทม์ แต่หลังจากกำหนดแล้วก็จะไม่เปลี่ยนอีก

เช่น:

```js
const pageLoadTime = /* เวลาที่ใช้โหลดเว็บเพจ */;
```

ค่าของ `pageLoadTime` ไม่รู้ล่วงหน้าก่อนเพจโหลดเสร็จ ก็เลยตั้งชื่อแบบปกติ — แต่มันก็ยังเป็นค่าคงที่อยู่ดี เพราะหลังจากกำหนดแล้วก็ไม่เปลี่ยน

พูดอีกอย่างก็คือ ค่าคงที่ตัวพิมพ์ใหญ่ใช้เป็นแค่ alias สำหรับค่าที่ "ฮาร์ดโค้ด" เอาไว้เท่านั้น

## ตั้งชื่อให้ถูกต้อง

มีอีกเรื่องที่สำคัญมากเกี่ยวกับตัวแปร — ชื่อต้องสื่อความหมาย เข้าใจง่าย และบอกได้ว่าข้างในเก็บข้อมูลอะไร

การตั้งชื่อตัวแปรเป็นหนึ่งในทักษะที่สำคัญที่สุดในการเขียนโปรแกรม แค่กวาดตามองชื่อตัวแปรก็พอจะบอกได้ว่าโค้ดนี้เขียนโดยมือใหม่หรือมือเก๋า

ในโปรเจกต์จริง เราใช้เวลาส่วนใหญ่ไปกับการแก้และต่อยอดโค้ดเดิม มากกว่าเขียนใหม่จากศูนย์ — พอกลับมาดูโค้ดเดิมหลังจากห่างไปสักพัก ตัวแปรที่ตั้งชื่อดีๆ จะช่วยให้หาเจอเร็วขึ้นเยอะ

เพราะงั้น เสียเวลาคิดชื่อให้ดีก่อนประกาศตัวแปรสักนิด คุ้มแน่นอน

กฎที่ควรทำตาม:

- ใช้ชื่อที่คนอ่านเข้าใจได้ เช่น `userName` หรือ `shoppingCart`
- เลี่ยงคำย่อหรือชื่อสั้นๆ อย่าง `a`, `b`, `c` ยกเว้นจะมั่นใจจริงๆ ว่ากำลังทำอะไรอยู่
- ตั้งชื่อให้อธิบายได้ชัดเจนแต่กระชับ ตัวอย่างชื่อที่ไม่ดีคือ `data` กับ `value` — ไม่สื่อเลยว่าคืออะไร ยกเว้นบริบทรอบข้างจะบอกชัดมากๆ
- ตกลงศัพท์กันในทีมด้วย ถ้าเรียกผู้เข้าชมเว็บว่า "user" ก็ควรตั้งชื่อตัวแปรว่า `currentUser` หรือ `newUser` ไม่ใช่ `currentVisitor` หรือ `newManInTown`

ฟังดูง่ายใช่ไหม? แต่เอาเข้าจริง การตั้งชื่อให้สื่อความหมายและกระชับไม่ง่ายเลย — ลองทำดู

```smart header="ใช้ซ้ำหรือสร้างใหม่"
อีกข้อสังเกต — มีโปรแกรมเมอร์บางคนขี้เกียจ ชอบเอาตัวแปรเดิมมาใช้ซ้ำ แทนที่จะประกาศตัวใหม่

ผลคือตัวแปรของพวกเขาก็เหมือนกล่องที่มีคนเอาของต่างๆ ใส่เข้าใส่ออก แต่ไม่เคยเปลี่ยนป้ายข้างนอกเลย — แล้วตอนนี้ในกล่องมีอะไรล่ะ? ไม่มีใครรู้ ต้องเข้าไปดูใกล้ๆ ถึงจะรู้

## สรุป

ประกาศตัวแปรเก็บข้อมูลด้วยคีย์เวิร์ด `var`, `let`, หรือ `const`

- `let` — รูปแบบสมัยใหม่
- `var` — รูปแบบเก่า ปกติไม่ใช้แล้ว แต่จะคุยเรื่องความต่างจาก `let` ในบท <info:var> สำหรับคนที่ต้องเจอ
- `const` — คล้าย `let` แต่ค่าเปลี่ยนไม่ได้

ตัวแปรควรตั้งชื่อให้รู้ทันทีว่าเก็บข้อมูลอะไร
