

# ไวยากรณ์ (syntax) "new Function"

เรายังมีอีกวิธีในการสร้างฟังก์ชัน (function) นั่นคือ `new Function` แม้จะไม่ค่อยได้ใช้ แต่บางกรณีก็ต้องอาศัยวิธีนี้

## ไวยากรณ์

การสร้างฟังก์ชันด้วย `new Function` เขียนได้ดังนี้:

```js
let func = new Function ([arg1, arg2, ...argN], functionBody);
```

`arg1...argN` คือชื่อพารามิเตอร์ (parameter) ของฟังก์ชันที่จะสร้าง ส่วน `functionBody` คือโค้ด (code) ที่จะทำงานเมื่อเรียกฟังก์ชัน เราส่งทั้งชื่อพารามิเตอร์และโค้ดให้ `new Function` ในรูปสตริง (string)

ลองดูฟังก์ชัน `sum` ที่รับพารามิเตอร์สองตัวคือ `a` และ `b` แล้วหาผลรวม:

```js run
let sum = new Function('a', 'b', 'return a + b');

alert( sum(1, 2) ); // 3
```

ถ้าจะสร้างฟังก์ชันที่ไม่รับพารามิเตอร์ ก็ส่งเฉพาะสตริงที่เป็นโค้ดได้ ตัวอย่างนี้สร้างฟังก์ชัน `sayHi` ซึ่งแสดง `Hello` เมื่อเรียกใช้:

```js run
let sayHi = new Function('alert("Hello")');

sayHi(); // Hello
```

จุดที่ต่างจากวิธีสร้างฟังก์ชันที่เราเคยเรียนมา คือ `new Function` สร้างฟังก์ชันจากสตริงที่ส่งเข้ามาขณะโปรแกรมทำงาน

วิธีก่อนหน้านี้ต้องเขียนโค้ดของฟังก์ชันไว้ในสคริปต์ (script) ตั้งแต่แรก

แต่เมื่อใช้ `new Function` เราสามารถนำสตริงที่มีโค้ดมาสร้างเป็นฟังก์ชันภายหลังได้ เช่น รับโค้ดจากเซิร์ฟเวอร์ (server) แล้วสร้างฟังก์ชันเพื่อนำมาเรียกใช้ ตัวอย่างต่อไปนี้แสดงแนวทางโดยละส่วนที่รับโค้ดไว้:

```js
let str = ... receive the code from a server dynamically ...

let func = new Function(str);
func();
```

วิธีนี้ใช้กับงานเฉพาะบางอย่าง เช่น การรับโค้ดจากเซิร์ฟเวอร์ หรือการสร้างฟังก์ชันจากแม่แบบ (template) ขณะโปรแกรมทำงาน ซึ่งอาจพบในโปรแกรมบนเว็บที่ซับซ้อน

## คลอเชอร์ (closure)

ในบท <info:closure> เราได้เรียนไปแล้วว่า ปกติฟังก์ชันจะจดจำว่าตัวเองถูกสร้างขึ้นที่ไหน โดยมีพร็อพเพอร์ตี้ (property) พิเศษชื่อ `[[Environment]]` อ้างอิงไปยัง Lexical Environment ของบริเวณที่สร้างฟังก์ชันนั้น

สำหรับฟังก์ชันที่สร้างด้วย `new Function` นั้น `[[Environment]]` จะอ้างอิงไปยัง Lexical Environment ระดับ global โดยไม่อ้างอิงบริเวณที่สร้างฟังก์ชัน

ดังนั้น ฟังก์ชันนี้จะเข้าถึงตัวแปร (variable) ภายนอกได้เฉพาะที่อยู่ในระดับ global เท่านั้น ลองดูตัวอย่างที่สร้าง `func` ไว้ภายใน `getFunc`:

```js run
function getFunc() {
  let value = "test";

*!*
  let func = new Function('alert(value)');
*/!*

  return func;
}

getFunc()(); // error: value is not defined
```

เมื่อเรียกฟังก์ชันที่ได้จาก `getFunc()` จึงเกิดข้อผิดพลาด `value is not defined` เพราะฟังก์ชันที่สร้างด้วย `new Function` เข้าถึง `value` ของ `getFunc` ไม่ได้

ถ้าเปลี่ยนมาสร้างฟังก์ชันแบบปกติ ฟังก์ชันจะเข้าถึง `value` ของ `getFunc` ได้ และแสดง `test`:

```js run
function getFunc() {
  let value = "test";

*!*
  let func = function() { alert(value); };
*/!*

  return func;
}

getFunc()(); // *!*"test"*/!*, จาก Lexical Environment ของ getFunc
```

แม้พฤติกรรมของ `new Function` ตรงนี้จะดูแปลก แต่ก็มีประโยชน์ในการใช้งานจริง

สมมติว่าเราต้องสร้างฟังก์ชันจากโค้ดที่ยังไม่รู้ตอนเขียนสคริปต์ จึงเขียนฟังก์ชันนั้นไว้ล่วงหน้าแบบปกติไม่ได้ เราจะได้รับโค้ดเมื่อโปรแกรมทำงานแล้ว โดยอาจมาจากเซิร์ฟเวอร์หรือแหล่งอื่น

ฟังก์ชันที่สร้างขึ้นใหม่นี้ต้องทำงานร่วมกับสคริปต์หลัก

ถ้าฟังก์ชันนี้เข้าถึงตัวแปรภายนอกที่ไม่ใช่ระดับ global ได้ จะมีปัญหาอะไร?

ก่อนนำ JavaScript ไปใช้งานจริง เรามักลดขนาดโค้ดด้วยโปรแกรมที่เรียกว่า *minifier* โปรแกรมนี้จะตัดคอมเมนต์ (comment) และช่องว่างที่ไม่จำเป็นออก รวมถึงเปลี่ยนชื่อตัวแปรภายใน (local variable) ให้สั้นลงด้วย

เช่น ถ้าฟังก์ชันมี `let userName` ตัว minifier อาจเปลี่ยนเป็น `let a` หรือใช้ตัวอักษรอื่นถ้าชื่อ `a` ถูกใช้ไปแล้ว พร้อมเปลี่ยนชื่อทุกจุดที่อ้างถึงตัวแปรนี้ด้วย

โดยทั่วไป การเปลี่ยนชื่อแบบนี้ไม่ทำให้โค้ดทำงานผิดไป เพราะโค้ดนอกฟังก์ชันเข้าถึงตัวแปรภายในโดยตรงไม่ได้ ส่วนจุดที่ใช้ตัวแปรนั้นภายในฟังก์ชันก็ได้รับการเปลี่ยนชื่อครบทุกจุด ตัว minifier วิเคราะห์โครงสร้างโค้ดเพื่อดูว่าตรงไหนอ้างถึงตัวแปรเดียวกัน จึงเปลี่ยนชื่อได้ถูกจุด ต่างจากการค้นหาแล้วแทนที่ข้อความโดยไม่ดูโครงสร้าง

ทีนี้ สมมติว่าฟังก์ชันที่สร้างด้วย `new Function` เข้าถึง `userName` ของฟังก์ชันชั้นนอกได้ โค้ดที่ได้รับมาภายหลังและยังใช้ชื่อ `userName` ก็จะหาตัวแปรนั้นไม่เจอ เพราะ minifier เปลี่ยนชื่อในสคริปต์หลักไปแล้ว

**ถ้า `new Function` เข้าถึงตัวแปรภายนอกที่ไม่ใช่ระดับ global ได้ ก็จะเกิดปัญหาเมื่อใช้ minifier**

การออกแบบให้ฟังก์ชันต้องรู้ชื่อตัวแปรของโค้ดส่วนอื่นแบบนี้ยังทำให้เกิดข้อผิดพลาดได้ง่าย

หากต้องการส่งข้อมูลให้ฟังก์ชันที่สร้างด้วย `new Function` ควรส่งเป็นอาร์กิวเมนต์ (argument) ตอนเรียกใช้ฟังก์ชัน เช่น ค่า `1` และ `2` ที่ส่งให้ `sum` ในตัวอย่างแรก

## สรุป

ไวยากรณ์:

```js
let func = new Function ([arg1, arg2, ...argN], functionBody);
```

นอกจากส่งชื่อพารามิเตอร์เป็นสตริงแยกกันแล้ว ยังเขียนหลายชื่อรวมในสตริงเดียวโดยคั่นด้วยจุลภาคได้ด้วย รูปแบบนี้รองรับไว้ด้วยเหตุผลทางประวัติศาสตร์

ทั้งสามแบบนี้มีความหมายเหมือนกัน:

```js
new Function('a', 'b', 'return a + b'); // ไวยากรณ์พื้นฐาน
new Function('a,b', 'return a + b'); // คั่นด้วยจุลภาค
new Function('a , b', 'return a + b'); // คั่นด้วยจุลภาคและช่องว่าง
```

ฟังก์ชันที่สร้างด้วย `new Function` มี `[[Environment]]` อ้างอิงไปยัง Lexical Environment ระดับ global จึงเข้าถึงตัวแปรภายนอกได้เฉพาะที่ระดับ global เท่านั้น ข้อจำกัดนี้ช่วยลดข้อผิดพลาดจากการพึ่งพาตัวแปรรอบจุดที่สร้างฟังก์ชัน เราควรส่งข้อมูลที่ต้องใช้ผ่านอาร์กิวเมนต์ให้ชัดเจน วิธีนี้ทำให้เห็นว่าฟังก์ชันต้องรับข้อมูลอะไร และไม่เกิดปัญหาเมื่อ minifier เปลี่ยนชื่อตัวแปร
