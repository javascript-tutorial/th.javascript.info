

# ออบเจ็กต์ส่วนกลาง (global object)

global object เป็นออบเจ็กต์ (object) ที่เก็บตัวแปร (variable) และฟังก์ชัน (function) ให้เราเข้าถึงได้จากทุกที่ในโปรแกรม โดยมีตัวแปรและฟังก์ชันที่มากับภาษา JavaScript หรือสภาพแวดล้อมการทำงาน (environment) อยู่แล้ว

ในเบราว์เซอร์ (browser) เราเข้าถึง global object ผ่านชื่อ `window` ส่วนใน Node.js ใช้ชื่อ `global` สภาพแวดล้อมอื่น ๆ อาจใช้ชื่อต่างออกไป

JavaScript จึงเพิ่มชื่อมาตรฐาน `globalThis` เพื่อให้เราเข้าถึง global object ด้วยชื่อเดียวกันได้ในทุกสภาพแวดล้อม ณ เดือนกันยายน 2026 เบราว์เซอร์หลัก ๆ รองรับชื่อนี้แล้ว

ตัวอย่างในบทนี้ใช้ `window` เพราะเราจะรันโค้ดในเบราว์เซอร์ แต่ถ้าสคริปต์ (script) ของเราอาจทำงานในสภาพแวดล้อมอื่นด้วย ควรใช้ `globalThis` แทน

เราเข้าถึงพร็อพเพอร์ตี้ (property) ของ global object ได้โดยไม่ต้องเขียนชื่อออบเจ็กต์นำหน้า เช่น เรียก `alert()` ได้เลย หรือจะเขียน `window.alert()` ก็ได้ผลเหมือนกัน:

```js run
alert("Hello");
// เหมือนกับ
window.alert("Hello");
```

ในสคริปต์ที่รันบนเบราว์เซอร์และไม่ได้ใช้โมดูล (module) ตัวแปรที่ประกาศด้วย `var` ที่ระดับบนสุดของสคริปต์จะเป็นตัวแปรส่วนกลาง (global variable) และกลายเป็นพร็อพเพอร์ตี้ของ global object ด้วย ส่วนการประกาศด้วย `let` หรือ `const` จะไม่เพิ่มพร็อพเพอร์ตี้ให้ global object:

```js run untrusted refresh
var gVar = 5;

alert(window.gVar); // 5 (กลายเป็นพร็อพเพอร์ตี้ของ global object)
```

การประกาศฟังก์ชัน (function declaration) ที่ระดับบนสุดของสคริปต์ก็ทำให้ฟังก์ชันนั้นกลายเป็นพร็อพเพอร์ตี้ของ global object เช่นกัน เราหมายถึงการเขียน `function` เพื่อประกาศฟังก์ชันโดยตรง ไม่ใช่การเขียนฟังก์ชันในรูปนิพจน์ (function expression)

เราไม่ควรพึ่งพาพฤติกรรมนี้ เพราะ JavaScript คงไว้เพื่อให้โค้ดเก่ายังทำงานได้ สคริปต์สมัยใหม่ใช้ [โมดูลของ JavaScript](info:modules) ซึ่งการประกาศตัวแปรและฟังก์ชันจะไม่เพิ่มพร็อพเพอร์ตี้ให้ global object แบบนี้

ลองเปลี่ยนมาใช้ `let` ตัวแปร `gLet` จะไม่กลายเป็นพร็อพเพอร์ตี้ของ `window` ดังนั้น `window.gLet` จึงเป็น `undefined`:

```js run untrusted refresh
let gLet = 5;

alert(window.gLet); // undefined (ไม่ได้กลายเป็นพร็อพเพอร์ตี้ของ global object)
```

ถ้ามีค่าที่จำเป็นต้องใช้ร่วมกันทั่วทั้งโปรแกรม ให้กำหนดค่านั้นเป็นพร็อพเพอร์ตี้ของ global object โดยตรง เช่น ข้อมูลผู้ใช้ปัจจุบันในตัวอย่างนี้:

```js run
*!*
// กำหนดข้อมูลผู้ใช้ปัจจุบันเป็น global เพื่อให้ทุกสคริปต์เข้าถึงได้
window.currentUser = {
  name: "John"
};
*/!*

// ที่อื่นในโค้ด
alert(currentUser.name);  // John

// หรือถ้ามีตัวแปรภายใน (local variable) ชื่อ "currentUser" อยู่แล้ว
// ก็ระบุ window เพื่ออ่านข้อมูลผู้ใช้ส่วนกลางแทนตัวแปรที่ชื่อซ้ำกัน
alert(window.currentUser.name); // John
```

เมื่อกำหนด `window.currentUser` แล้ว เราอ่านค่าได้ทั้งผ่าน `currentUser` และ `window.currentUser` แต่ถ้ามีตัวแปรภายในชื่อ `currentUser` อยู่ด้วย การระบุ `window.currentUser` จะทำให้ชัดเจนว่าเราต้องการค่าจาก global object

ถึงจะทำได้ เราก็ควรใช้ตัวแปรส่วนกลางให้น้อยที่สุด โดยทั่วไป การให้ฟังก์ชันรับข้อมูลเข้าแล้วส่งผลลัพธ์กลับออกมา จะทำให้โค้ดชัดเจนกว่า มีโอกาสผิดพลาดน้อยกว่า และทดสอบง่ายกว่าการให้ฟังก์ชันไปใช้ตัวแปรภายนอกหรือตัวแปรส่วนกลาง

## ใช้ตรวจการรองรับและเพิ่ม polyfill

เรายังใช้ global object ตรวจได้ว่าสภาพแวดล้อมที่รันโค้ดรองรับความสามารถของ JavaScript ที่ต้องการใช้หรือไม่

เช่น ตรวจว่าเบราว์เซอร์มีออบเจ็กต์ `Promise` มาให้หรือยัง เบราว์เซอร์รุ่นเก่ามาก ๆ จะไม่มี ถ้าไม่พบ `window.Promise` โค้ดนี้จะแสดงข้อความ `Your browser is really old!` เพื่อบอกว่าเบราว์เซอร์เก่ามาก:
```js run
if (!window.Promise) {
  alert("Your browser is really old!");
}
```

ถ้าสภาพแวดล้อมยังไม่รองรับ เราสามารถเพิ่มโค้ดที่ทำงานทดแทนความสามารถตามมาตรฐานนั้นได้ โค้ดทดแทนนี้เรียกว่า *polyfill* ตัวอย่างต่อไปแสดงตำแหน่งที่จะใส่ polyfill ให้ `Promise` โดย `...` เป็นส่วนที่เว้นไว้สำหรับโค้ดจริง จึงยังนำตัวอย่างนี้ไปรันตรง ๆ ไม่ได้:

```js run
if (!window.Promise) {
  window.Promise = ... // โค้ดที่เราเขียนขึ้นมาเองเพื่อทดแทนฟีเจอร์ที่ขาดไป
}
```

## สรุป

- global object เก็บตัวแปรและฟังก์ชันที่ต้องการให้เข้าถึงได้จากทุกที่

    รวมทั้งสิ่งที่ JavaScript มีให้ เช่น `Array` และค่าเฉพาะของสภาพแวดล้อม เช่น `window.innerHeight` ซึ่งบอกความสูงของพื้นที่แสดงหน้าเว็บในหน้าต่างเบราว์เซอร์
- global object มีชื่อมาตรฐานคือ `globalThis`

    แต่ในโค้ดมักพบชื่อเฉพาะของแต่ละสภาพแวดล้อม เช่น `window` ในเบราว์เซอร์ และ `global` ใน Node.js
- ควรเก็บค่าไว้ใน global object เฉพาะค่าที่จำเป็นต้องใช้ร่วมกันทั่วทั้งโปรแกรมจริง ๆ และเก็บให้น้อยที่สุด
- ในเบราว์เซอร์ หากสคริปต์ไม่ได้ใช้ [โมดูล](info:modules) ตัวแปรที่ประกาศด้วย `var` และฟังก์ชันที่เขียนแบบ function declaration ที่ระดับบนสุดของสคริปต์ จะกลายเป็นพร็อพเพอร์ตี้ของ global object
- ควรเข้าถึงพร็อพเพอร์ตี้โดยระบุชื่อ global object ให้ชัดเจน เช่น `window.x` เพื่อให้โค้ดอ่านเข้าใจง่ายและลดปัญหาเมื่อปรับโค้ดในภายหลัง
