# Throttle decorator

สร้าง decorator `throttle(f, ms)` ที่คืน wrapper หรือฟังก์ชัน (function) ที่ครอบการเรียก `f`

แม้ wrapper จะถูกเรียกหลายครั้ง ก็ต้องส่งต่อไปยัง `f` ไม่เกินหนึ่งครั้งต่อช่วงเวลา `ms` มิลลิวินาที

พฤติกรรมนี้ต่างจาก `debounce`:

- `debounce` รอจนไม่มีการเรียกเพิ่มตามเวลาที่กำหนด แล้วทำงานครั้งเดียว เหมาะเมื่อต้องการประมวลผลครั้งสุดท้ายหลังการเรียกที่มาติด ๆ กัน
- `throttle` ให้ฟังก์ชันทำงานเป็นระยะ โดยแต่ละครั้งห่างกันอย่างน้อย `ms` มิลลิวินาที เหมาะกับการอัปเดตที่ต้องทำต่อเนื่อง แต่ไม่ต้องการให้ถี่เกินไป

ดังนั้น ต่อให้มีการเรียก wrapper เข้ามาต่อเนื่อง `throttle` ก็ยังให้ `f` ทำงานระหว่างนั้นได้ โดยจำกัดความถี่ตามเวลาที่กำหนด

ลองดูกรณีใช้งานจริงเพื่อให้เห็นว่าต้องการพฤติกรรมแบบนี้ไปทำไม

**สมมติว่าเราต้องการติดตามการขยับเมาส์**

ในเบราว์เซอร์ (browser) เรากำหนดฟังก์ชันให้ทำงานเมื่อเมาส์ขยับ และอ่านตำแหน่งของตัวชี้เมาส์ได้ ขณะขยับเมาส์ ฟังก์ชันนี้อาจถูกเรียกถี่ถึงประมาณ 100 ครั้งต่อวินาที หรือทุก 10 มิลลิวินาที

**เราต้องการอัปเดตข้อมูลบนหน้าเว็บให้ตามตำแหน่งเมาส์** แต่สมมติว่า `update()` ใช้เวลาประมวลผลมากเกินกว่าจะเรียกทุกครั้งที่เมาส์ขยับ และในงานนี้อัปเดตทุก 100 มิลลิวินาทีก็เพียงพอแล้ว

เราจึงใช้ `throttle(update, 100)` เป็นฟังก์ชันรับการเรียกเมื่อเมาส์ขยับแทน `update` โดยตรง wrapper อาจถูกเรียกบ่อย แต่จะส่งต่อให้ `update` ทำงานไม่เกินหนึ่งครั้งต่อ 100 มิลลิวินาที

ลำดับการทำงานเป็นดังนี้:

1. เมื่อเมาส์ขยับครั้งแรก wrapper เรียก `update` ทันที เพื่อให้ผู้ใช้เห็นผลตอบสนองจากการขยับเมาส์
2. ถ้าเมาส์ยังขยับต่อในช่วงที่ยังไม่ครบ 100 มิลลิวินาที wrapper จะยังไม่เรียก `update` ซ้ำ
3. เมื่อครบ 100 มิลลิวินาที จึงเรียก `update` อีกครั้งโดยใช้พิกัดล่าสุด
4. เมื่อเมาส์หยุดขยับ หากยังมีการเรียกที่รออยู่ wrapper จะรอให้ครบช่วง 100 มิลลิวินาทีของรอบนั้น แล้วเรียก `update` ด้วยพิกัดสุดท้าย จึงไม่ตกหล่นตำแหน่งที่เมาส์หยุดอยู่

ตัวอย่างโค้ด:

```js
function f(a) {
  console.log(a);
}

// f1000 ส่งต่อการเรียกไปยัง f ได้มากสุดครั้งเดียวต่อ 1000ms
let f1000 = throttle(f, 1000);

f1000(1); // แสดง 1
f1000(2); // (ถูก throttle, ยังไม่ครบ 1000ms)
f1000(3); // (ถูก throttle, ยังไม่ครบ 1000ms)

// เมื่อครบ 1000ms...
// ...แสดง 3 ส่วนค่า 2 ที่อยู่ระหว่างกลางถูกข้ามไป
```

คำตอบต้องส่งต่ออาร์กิวเมนต์ (argument) ทั้งหมดและค่า `this` ที่ `f1000` ได้รับไปยัง `f` เดิมด้วย
