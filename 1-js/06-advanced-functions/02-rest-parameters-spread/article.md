# Rest parameters และ spread syntax

ฟังก์ชัน (function) หลายตัวที่มีมาให้ใน JavaScript รับอาร์กิวเมนต์ (argument) ได้โดยไม่ต้องกำหนดจำนวนไว้ล่วงหน้า

ยกตัวอย่างเช่น:

- `Math.max(arg1, arg2, ..., argN)` คืนค่าที่มากที่สุดจากอาร์กิวเมนต์ทั้งหมด
- `Object.assign(dest, src1, ..., srcN)` คัดลอกพร็อพเพอร์ตี้ (property) ของออบเจ็กต์ (object) `src1` จนถึง `srcN` ไปยัง `dest`
- ...และอื่น ๆ อีกมากมาย

ในบทนี้ เราจะเรียนวิธีเขียนฟังก์ชันให้รับอาร์กิวเมนต์แบบนี้ และวิธีนำสมาชิกของอาร์เรย์ (array) ไปส่งเป็นอาร์กิวเมนต์แยกกันในการเรียกฟังก์ชันครั้งเดียว

## Rest parameters `...`

จำนวนอาร์กิวเมนต์ที่ส่งตอนเรียกฟังก์ชันไม่จำเป็นต้องเท่ากับจำนวนพารามิเตอร์ (parameter) ที่ประกาศไว้ตอนเขียนฟังก์ชัน

ลองดูตัวอย่าง:
```js run
function sum(a, b) {
  return a + b;
}

alert( sum(1, 2, 3, 4, 5) );
```

การส่งอาร์กิวเมนต์เกินจำนวนพารามิเตอร์ไม่ได้ทำให้เกิดข้อผิดพลาด ในตัวอย่างนี้ `a` รับค่า `1` และ `b` รับค่า `2` ส่วนค่าที่เหลือไม่ได้ใช้ในการคำนวณ ผลลัพธ์จึงเป็น `3`

ถ้าต้องการรับอาร์กิวเมนต์ที่เหลือด้วย ให้เขียน `...` นำหน้าพารามิเตอร์ตัวสุดท้ายของฟังก์ชัน รูปแบบนี้เรียกว่า *rest parameters* โดย JavaScript จะรวบรวมอาร์กิวเมนต์ที่เหลือทั้งหมดเป็นอาร์เรย์ให้พารามิเตอร์นี้

ตัวอย่างนี้ใช้ `...args` รับอาร์กิวเมนต์ทั้งหมดไว้ในอาร์เรย์ `args` แล้วบวกค่าทีละตัวเพื่อหาผลรวม:

```js run
function sumAll(...args) { // args คือชื่อของ array
  let sum = 0;

  for (let arg of args) sum += arg;

  return sum;
}

alert( sumAll(1) ); // 1
alert( sumAll(1, 2) ); // 3
alert( sumAll(1, 2, 3) ); // 6
```

เราเลือกให้อาร์กิวเมนต์ตัวแรก ๆ อยู่ในตัวแปร (variable) แยกกัน แล้วใช้ rest parameters รวบรวมเฉพาะอาร์กิวเมนต์ที่เหลือก็ได้

ในตัวอย่างต่อไปนี้ `firstName` รับค่า `"Julius"` และ `lastName` รับค่า `"Caesar"` ส่วน `"Consul"` กับ `"Imperator"` จะอยู่ในอาร์เรย์ `titles`:

```js run
function showName(firstName, lastName, ...titles) {
  alert( firstName + ' ' + lastName ); // Julius Caesar

  // พารามิเตอร์ที่เหลือจะรวมอยู่ในอาร์เรย์ titles
  // เช่น titles = ["Consul", "Imperator"]
  alert( titles[0] ); // Consul
  alert( titles[1] ); // Imperator
  alert( titles.length ); // 2
}

showName("Julius", "Caesar", "Consul", "Imperator");
```

````warn header="Rest parameters ต้องอยู่ท้ายสุดเสมอ"
Rest parameters รวบรวมอาร์กิวเมนต์ที่เหลือทั้งหมด จึงต้องอยู่ท้ายรายการพารามิเตอร์ ถ้าวาง `arg2` ไว้หลัง `...rest` อย่างตัวอย่างนี้ จะเกิดข้อผิดพลาด:

```js
function f(arg1, ...rest, arg2) { // arg2 หลังจาก ...rest ?!
  // error
}
```

ดังนั้น `...rest` ต้องเป็นพารามิเตอร์ตัวสุดท้ายเสมอ
````

## ตัวแปร "arguments"

เรายังเข้าถึงอาร์กิวเมนต์ทั้งหมดได้ผ่านออบเจ็กต์พิเศษชื่อ `arguments` ซึ่งมีลักษณะคล้ายอาร์เรย์ เรียกว่า *array-like* เราอ่านค่าแต่ละตัวด้วยหมายเลขตำแหน่ง (index) เช่น `arguments[0]` และดูจำนวนอาร์กิวเมนต์ได้จาก `arguments.length`

ลองดูตัวอย่าง

```js run
function showName() {
  alert( arguments.length );
  alert( arguments[0] );
  alert( arguments[1] );

  // วนลูปได้เช่นกัน
  // for(let arg of arguments) alert(arg);
}

// แสดงผลเป็น: 2, Julius, Caesar
showName("Julius", "Caesar");

// แสดงผลเป็น: 1, Ilya, undefined (ไม่มีอาร์กิวเมนต์ตัวที่สอง)
showName("Ilya");
```

สมัยก่อนที่จะมี rest parameters การใช้ `arguments` เป็นวิธีเดียวที่จะเข้าถึงอาร์กิวเมนต์ทั้งหมดของฟังก์ชัน ซึ่งยังใช้งานได้อยู่ และอาจเจอได้ในโค้ดเก่า ๆ

`arguments` ยังเป็น *iterable* ด้วย หมายความว่าเราใช้ `for..of` อ่านค่าทีละตัวได้ แต่ถึงจะใช้ได้คล้ายอาร์เรย์ ก็ไม่ใช่อาร์เรย์จริง ๆ จึงเรียกเมธอด (method) ของอาร์เรย์โดยตรงไม่ได้ เช่น `arguments.map(...)`

นอกจากนี้ `arguments` เก็บอาร์กิวเมนต์ทุกตัวเสมอ เราจึงกำหนดให้เก็บเฉพาะส่วนที่เหลือแบบ `titles` ในตัวอย่าง rest parameters ไม่ได้

ถ้าต้องการใช้เมธอดของอาร์เรย์กับค่าที่รับมา หรือรวบรวมเฉพาะอาร์กิวเมนต์ที่เหลือ ก็ควรใช้ rest parameters

````smart header="Arrow function ไม่มี `\"arguments\"`"
Arrow function ไม่มี `arguments` เป็นของตัวเอง เมื่อเข้าถึง `arguments` จากภายใน arrow function จึงใช้ของฟังก์ชันปกติที่ครอบอยู่แทน

ตัวอย่าง:

```js run
function f() {
  let showArg = () => alert(arguments[0]);
  showArg();
}

f(1); // 1
```

ในตัวอย่างนี้ `showArg` ใช้ `arguments` ของ `f` จึงแสดง `1` ซึ่งเป็นอาร์กิวเมนต์ที่ส่งให้ `f`

เราเคยเรียนมาแล้วว่า arrow function ไม่มี `this` เป็นของตัวเอง และตอนนี้ก็ได้รู้ว่า `arguments` เป็นอีกอย่างที่ arrow function ไม่มีเป็นของตัวเองเช่นกัน
````


## Spread syntax [#spread-syntax]

Rest parameters ช่วยรวบรวมอาร์กิวเมนต์ไว้ในอาร์เรย์ แต่บางครั้งเรามีอาร์เรย์อยู่แล้ว และต้องการนำสมาชิกไปส่งให้ฟังก์ชันเป็นอาร์กิวเมนต์แยกกัน

เช่น ฟังก์ชัน [Math.max](mdn:js/Math/max) จะคืนค่าตัวเลขที่มากที่สุดจากอาร์กิวเมนต์ที่ส่งเข้าไป:

```js run
alert( Math.max(3, 5, 1) ); // 5
```

ทีนี้ถ้าตัวเลขอยู่ในอาร์เรย์ `[3, 5, 1]` เราจะส่งให้ `Math.max` หาค่าที่มากที่สุดได้อย่างไร?

ถ้าส่งอาร์เรย์นี้เข้าไปตรง ๆ จะได้ `NaN` เพราะ `Math.max` ต้องการอาร์กิวเมนต์ที่เป็นตัวเลขแยกกัน ไม่ใช่อาร์เรย์หนึ่งตัว:

```js run
let arr = [3, 5, 1];

*!*
alert( Math.max(arr) ); // NaN
*/!*
```

การเขียน `Math.max(arr[0], arr[1], arr[2])` โดยระบุสมาชิกทีละตัวก็ไม่เหมาะ หากเราไม่รู้จำนวนสมาชิกของอาร์เรย์ล่วงหน้า ตอนโปรแกรมทำงาน อาร์เรย์อาจมีสมาชิกหลายตัวหรือไม่มีเลยก็ได้

เราใช้ *spread syntax* แก้ปัญหานี้ได้ โดยเขียน `...` เหมือน rest parameters แต่คราวนี้จะกระจายค่าออกมา แทนที่จะรวบรวมค่าเข้าเป็นอาร์เรย์

เมื่อเขียน `...arr` ตอนเรียกฟังก์ชัน spread syntax จะกระจายค่าจาก iterable `arr` เป็นอาร์กิวเมนต์แยกกัน ในตัวอย่างนี้ `Math.max(...arr)` จึงให้ผลเหมือนเรียก `Math.max(3, 5, 1)`:

```js run
let arr = [3, 5, 1];

alert( Math.max(...arr) ); // 5 (spread กระจายอาร์เรย์ออกเป็นอาร์กิวเมนต์แยกทีละตัว)
```

นอกจากนี้ยังส่ง iterable หลายตัวพร้อมกันได้:

```js run
let arr1 = [1, -2, 3, 4];
let arr2 = [8, 3, -8, 1];

alert( Math.max(...arr1, ...arr2) ); // 8
```

จะใช้ spread syntax ร่วมกับค่าที่ส่งตามปกติก็ได้:


```js run
let arr1 = [1, -2, 3, 4];
let arr2 = [8, 3, -8, 1];

alert( Math.max(1, ...arr1, 2, ...arr2, 25) ); // 25
```

Spread syntax ยังใช้รวมอาร์เรย์เข้าด้วยกันได้อีกด้วย:

```js run
let arr = [3, 5, 1];
let arr2 = [8, 9, 15];

*!*
let merged = [0, ...arr, 2, ...arr2];
*/!*

alert(merged); // 0,3,5,1,2,8,9,15 (0, ต่อด้วย arr, ต่อด้วย 2, ต่อด้วย arr2)
```

ตัวอย่างข้างต้นใช้อาร์เรย์ แต่การกระจายค่าแบบนี้ใช้กับ iterable ได้ทุกชนิด

เช่น ใช้ spread syntax แยกตัวอักษรในสตริง (string) ออกมาเป็นสมาชิกของอาร์เรย์:

```js run
let str = "Hello";

alert( [...str] ); // H,e,l,l,o
```

การกระจายค่าแบบนี้ใช้ iterator อ่านค่าทีละตัว เช่นเดียวกับ `for..of`

เมื่ออ่านสตริง `"Hello"` ค่าที่ได้จึงเป็นตัวอักษร `"H"`, `"e"`, `"l"`, `"l"`, `"o"` ตามลำดับ การเขียน `[...str]` ก็คือนำตัวอักษรเหล่านี้มาใส่ในอาร์เรย์ใหม่

งานแบบนี้เราใช้ `Array.from` ก็ได้เช่นกัน เพราะมันแปลง iterable (เช่น สตริง) ให้เป็นอาร์เรย์ได้:

```js run
let str = "Hello";

// Array.from แปลง iterable ให้เป็นอาร์เรย์
alert( Array.from(str) ); // H,e,l,l,o
```

ผลลัพธ์ที่ได้เหมือนกับ `[...str]`

แต่ `Array.from(obj)` กับ `[...obj]` รับข้อมูลได้ต่างกัน:

- `Array.from` ใช้ได้ทั้งกับ array-like และ iterable
- Spread syntax ใน `[...obj]` ใช้ได้กับ iterable เท่านั้น

ถ้าต้องการแปลงข้อมูลให้เป็นอาร์เรย์ `Array.from` จึงรองรับข้อมูลได้หลายแบบกว่า


## การคัดลอกอาร์เรย์และออบเจ็กต์

เราเคยใช้ `Object.assign()` คัดลอกข้อมูลใน[บทการคัดลอกออบเจ็กต์](info:object-copy#cloning-and-merging-object-assign) มาแล้ว

เราทำแบบเดียวกันด้วย spread syntax ได้ ในตัวอย่างนี้ `[...arr]` สร้างอาร์เรย์ใหม่จากสมาชิกของ `arr` แล้วเก็บไว้ในตัวแปร `arrCopy` ทั้งสองอาร์เรย์จึงมีสมาชิกเหมือนกัน แต่เป็นคนละอาร์เรย์:

```js run
let arr = [1, 2, 3];

*!*
let arrCopy = [...arr]; // กระจายอาร์เรย์ออกเป็นรายการค่า
                        // แล้วนำไปสร้างอาร์เรย์ตัวใหม่
*/!*

// อาร์เรย์ทั้งสองมีค่าเหมือนกันไหม?
alert(JSON.stringify(arr) === JSON.stringify(arrCopy)); // true

// แต่อ้างอิงตัวเดียวกันไหม?
alert(arr === arrCopy); // false (คนละตัวกัน)

// แก้ไขต้นฉบับจะไม่กระทบสำเนา:
arr.push(4);
alert(arr); // 1, 2, 3, 4
alert(arrCopy); // 1, 2, 3
```

ในตัวอย่างนี้ การเพิ่ม `4` เข้าไปใน `arr` จึงไม่ทำให้ `arrCopy` เปลี่ยนตาม

สำหรับออบเจ็กต์ เราใช้ `{ ...obj }` คัดลอกพร็อพเพอร์ตี้ของ `obj` ไปใส่ในออบเจ็กต์ใหม่ได้เช่นกัน:

```js run
let obj = { a: 1, b: 2, c: 3 };

*!*
let objCopy = { ...obj }; // กระจายออบเจ็กต์ออกเป็นพร็อพเพอร์ตี้แยกทีละตัว
                          // แล้วนำไปสร้างออบเจ็กต์ตัวใหม่
*/!*

// ออบเจ็กต์ทั้งสองมีค่าเหมือนกันไหม?
alert(JSON.stringify(obj) === JSON.stringify(objCopy)); // true

// แต่อ้างอิงตัวเดียวกันไหม?
alert(obj === objCopy); // false (คนละตัวกัน)

// แก้ไขต้นฉบับจะไม่กระทบสำเนา:
obj.d = 4;
alert(JSON.stringify(obj)); // {"a":1,"b":2,"c":3,"d":4}
alert(JSON.stringify(objCopy)); // {"a":1,"b":2,"c":3}
```

เมื่อเพิ่มพร็อพเพอร์ตี้ `d` ให้ `obj` ในตัวอย่างนี้ `objCopy` ก็ยังคงมีแค่ `a`, `b` และ `c` เหมือนเดิม

การเขียนแบบนี้สั้นกว่า `let objCopy = Object.assign({}, obj)` หรือ `let arrCopy = Object.assign([], arr)` จึงเป็นวิธีที่เราเลือกใช้ได้เมื่อจะคัดลอกข้อมูลแบบตัวอย่างข้างต้น


## สรุป

พอเห็น `"..."` ในโค้ด อาจเป็นได้ทั้ง rest parameters หรือ spread syntax

ให้ดูว่า `...` อยู่ตรงไหน:

- ถ้า `...` อยู่ท้ายรายการพารามิเตอร์ตอนประกาศฟังก์ชัน นั่นคือ rest parameters ซึ่งจะรวมอาร์กิวเมนต์ที่เหลือไว้ในอาร์เรย์
- ถ้า `...` อยู่ตอนเรียกฟังก์ชันหรือสร้างอาร์เรย์ นั่นคือ spread syntax ซึ่งจะกระจายค่าออกมาเป็นอาร์กิวเมนต์แยกกันหรือเป็นสมาชิกของอาร์เรย์ใหม่ ส่วน `{ ...obj }` ใช้กระจายพร็อพเพอร์ตี้ลงในออบเจ็กต์ใหม่

รูปแบบการใช้งาน:

- Rest parameters ใช้สร้างฟังก์ชันที่รับอาร์กิวเมนต์ได้โดยไม่ต้องกำหนดจำนวนไว้ล่วงหน้า
- Spread syntax ใช้นำค่าจากอาร์เรย์ไปส่งให้ฟังก์ชันที่รับอาร์กิวเมนต์แยกกัน

ทั้งสองอย่างนี้ช่วยให้เราสลับไปมาระหว่างรายการค่ากับอาร์เรย์ได้สะดวก

เรายังเข้าถึงอาร์กิวเมนต์ทั้งหมดของฟังก์ชันปกติได้ผ่าน `arguments` ซึ่งเป็นวิธีที่ใช้กันมาก่อนมี rest parameters โดย `arguments` เป็นทั้ง array-like และ iterable แต่ไม่ใช่อาร์เรย์
