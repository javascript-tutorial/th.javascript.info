
# ฟังก์ชัน (function) ในฐานะออบเจ็กต์ (object) และ NFE

จากบทก่อน ๆ เรารู้แล้วว่าฟังก์ชันใน JavaScript เป็นค่าค่าหนึ่ง

ค่าทุกค่าใน JavaScript มีชนิดข้อมูล (type) แล้วฟังก์ชันเป็นข้อมูลชนิดไหน?

ใน JavaScript ฟังก์ชันคือออบเจ็กต์

เราจึงมองฟังก์ชันเป็น "ออบเจ็กต์ที่เรียกใช้ได้" นอกจากเรียกให้ทำงานแล้ว เรายังเพิ่มหรือลบพร็อพเพอร์ตี้ (property) และส่งต่อค่าการอ้างอิง (reference) ของฟังก์ชันได้เหมือนออบเจ็กต์ทั่วไป


## พร็อพเพอร์ตี้ "name"

ฟังก์ชันมีพร็อพเพอร์ตี้บางตัวมาให้แล้ว

เช่น เราอ่านชื่อฟังก์ชันได้จากพร็อพเพอร์ตี้ `name`:

```js run
function sayHi() {
  alert("Hi");
}

alert(sayHi.name); // sayHi
```

แม้เราจะไม่ได้เขียนชื่อไว้หลัง `function` แต่ถ้าสร้างฟังก์ชันแล้วกำหนดให้ตัวแปร (variable) ทันที JavaScript จะใช้ชื่อตัวแปรนั้นเป็นชื่อฟังก์ชัน:

```js run
let sayHi = function() {
  alert("Hi");
};

alert(sayHi.name); // sayHi (มีชื่อนะ!)
```

การตั้งชื่อแบบนี้ใช้ได้กับฟังก์ชันที่กำหนดเป็นค่าเริ่มต้น (default value) ของพารามิเตอร์ (parameter) ด้วย:

```js run
function f(sayHi = function() {}) {
  alert(sayHi.name); // sayHi (ใช้ได้!)
}

f();
```

การตั้งชื่อตามบริบทแบบนี้เรียกว่า "contextual name" คือเมื่อฟังก์ชันไม่ได้ระบุชื่อไว้ JavaScript จะตั้งชื่อให้ตามบริบทที่กำหนดค่าฟังก์ชันนั้น

เมธอด (method) ของออบเจ็กต์ก็มีชื่อเช่นกัน:

```js run
let user = {

  sayHi() {
    // ...
  },

  sayBye: function() {
    // ...
  }

}

alert(user.sayHi.name); // sayHi
alert(user.sayBye.name); // sayBye
```

แต่บางบริบทก็ไม่มีชื่อให้ JavaScript นำมาใช้ได้ เช่น เมื่อสร้างฟังก์ชันไว้ในอาร์เรย์ (array) ตามตัวอย่างนี้ พร็อพเพอร์ตี้ `name` จะเป็นสตริง (string) ว่าง:

```js run
// ฟังก์ชันที่สร้างภายในอาร์เรย์
let arr = [function() {}];

alert( arr[0].name ); // <สตริงว่าง>
// engine ไม่มีทางรู้ว่าควรตั้งชื่ออะไร จึงเป็นค่าว่าง
```

ในการเขียนโค้ดทั่วไป ฟังก์ชันส่วนใหญ่จะมีชื่อ

## พร็อพเพอร์ตี้ "length"

ฟังก์ชันยังมีพร็อพเพอร์ตี้ `length` ซึ่งบอกจำนวนพารามิเตอร์ที่คาดว่าจะรับ ลองดูตัวอย่างนี้:

```js run
function f1(a) {}
function f2(a, b) {}
function many(a, b, ...more) {}

alert(f1.length); // 1
alert(f2.length); // 2
alert(many.length); // 2
```

จะเห็นว่า rest parameter อย่าง `...more` ไม่ถูกนับรวมด้วย `many.length` จึงมีค่าเป็น `2` ถ้าฟังก์ชันมีพารามิเตอร์ที่กำหนดค่าเริ่มต้นไว้ `length` จะนับเฉพาะพารามิเตอร์ก่อนตัวแรกที่มีค่าเริ่มต้นเท่านั้น

เมื่อเขียนฟังก์ชันที่รับฟังก์ชันอื่นมาทำงาน เราอาจใช้ `length` ตรวจข้อมูลของฟังก์ชันที่รับมา การตรวจข้อมูลขณะโปรแกรมทำงานแบบนี้เรียกว่า [introspection](https://en.wikipedia.org/wiki/Type_introspection)

ตัวอย่างด้านล่าง ฟังก์ชัน `ask` รับคำถาม `question` และฟังก์ชันสำหรับจัดการคำตอบที่เรียกว่า handler กี่ตัวก็ได้

เมื่อผู้ใช้ตอบ `ask` จะเลือกเรียก handler ตามรูปแบบของฟังก์ชัน เราส่ง handler เข้ามาได้สองแบบ:

- ฟังก์ชันที่ไม่รับอาร์กิวเมนต์ (argument) จะถูกเรียกเฉพาะเมื่อผู้ใช้ตอบ "ใช่"
- ฟังก์ชันที่รับอาร์กิวเมนต์ จะถูกเรียกทั้งกรณีตอบ "ใช่" และ "ไม่ใช่" โดยได้รับคำตอบเป็นอาร์กิวเมนต์

โค้ดจะตรวจ `handler.length` เพื่อเลือกว่าจะเรียก handler นั้นอย่างไร

วิธีนี้ทำให้เราเขียน handler แบบไม่รับอาร์กิวเมนต์สำหรับกรณีตอบ "ใช่" ที่ใช้บ่อยได้สั้น ๆ และยังเขียน handler ที่จัดการได้ทั้งสองคำตอบได้ด้วย:

```js run
function ask(question, ...handlers) {
  let isYes = confirm(question);

  for(let handler of handlers) {
    if (handler.length == 0) {
      if (isYes) handler();
    } else {
      handler(isYes);
    }
  }

}

// ถ้าตอบ "ใช่" จะเรียก handler ทั้งสองตัว
// ถ้าตอบ "ไม่ใช่" จะเรียกแค่ตัวที่สอง
ask("Question?", () => alert('You said yes'), result => alert(result));
```

นี่เป็นตัวอย่างหนึ่งของ [polymorphism](https://en.wikipedia.org/wiki/Polymorphism_(computer_science)) ซึ่งหมายถึงการเลือกวิธีจัดการอาร์กิวเมนต์ตามชนิดของมัน ในตัวอย่างนี้เราเลือกตาม `length` ของฟังก์ชันที่รับมา แนวคิดแบบนี้มีใช้ในไลบรารี (library) JavaScript ด้วย

## พร็อพเพอร์ตี้ที่กำหนดเอง

เราสามารถเพิ่มพร็อพเพอร์ตี้ของเราเองให้ฟังก์ชันได้ด้วย

ตัวอย่างนี้เพิ่มพร็อพเพอร์ตี้ `counter` เพื่อนับว่าเรียกฟังก์ชันไปแล้วกี่ครั้ง:

```js run
function sayHi() {
  alert("Hi");

  *!*
  // นับว่าเรียกฟังก์ชันนี้ไปกี่ครั้งแล้ว
  sayHi.counter++;
  */!*
}
sayHi.counter = 0; // ค่าเริ่มต้น

sayHi(); // Hi
sayHi(); // Hi

alert( `Called ${sayHi.counter} times` ); // Called 2 times
```

```warn header="พร็อพเพอร์ตี้ ≠ ตัวแปร"
การกำหนดพร็อพเพอร์ตี้ให้ฟังก์ชัน เช่น `sayHi.counter = 0` *ไม่ได้* สร้างตัวแปรภายใน (local variable) ชื่อ `counter` ขึ้นมาในฟังก์ชัน พร็อพเพอร์ตี้ `counter` กับตัวแปรที่ประกาศด้วย `let counter` เป็นคนละสิ่งกัน

เราเก็บพร็อพเพอร์ตี้ไว้ในฟังก์ชันได้เพราะฟังก์ชันเป็นออบเจ็กต์ แต่โค้ดภายในฟังก์ชันยังใช้ตัวแปรตามปกติ การเพิ่มพร็อพเพอร์ตี้ไม่ได้เพิ่มตัวแปรภายในให้ด้วย และการสร้างตัวแปรภายในก็ไม่ได้เพิ่มพร็อพเพอร์ตี้ให้ฟังก์ชัน
```

บางกรณีเราใช้พร็อพเพอร์ตี้ของฟังก์ชันเก็บค่าแทนคลอเชอร์ (closure) ได้ ลองนำฟังก์ชันตัวนับจากบท <info:closure> มาเขียนใหม่โดยเก็บค่าไว้ในพร็อพเพอร์ตี้:

```js run
function makeCounter() {
  // แทนที่จะใช้:
  // let count = 0

  function counter() {
    return counter.count++;
  };

  counter.count = 0;

  return counter;
}

let counter = makeCounter();
alert( counter() ); // 0
alert( counter() ); // 1
```

คราวนี้เราเก็บ `count` เป็นพร็อพเพอร์ตี้ของฟังก์ชัน `counter` โดยตรง แทนที่จะเก็บเป็นตัวแปรใน Lexical Environment ชั้นนอก

แล้วการเก็บค่าแบบนี้ต่างจากการใช้คลอเชอร์อย่างไร?

ถ้าเก็บ `count` เป็นตัวแปรใน `makeCounter` โค้ดภายนอก `makeCounter` จะเข้าถึงตัวแปรนี้ไม่ได้ มีเพียงฟังก์ชันที่อยู่ข้างในเท่านั้นที่แก้ค่าได้ แต่ถ้าเก็บเป็นพร็อพเพอร์ตี้ของ `counter` โค้ดภายนอกก็แก้ค่าได้โดยตรง:

```js run
function makeCounter() {

  function counter() {
    return counter.count++;
  };

  counter.count = 0;

  return counter;
}

let counter = makeCounter();

*!*
counter.count = 10;
alert( counter() ); // 10
*/!*
```

จึงควรเลือกวิธีเก็บค่าให้ตรงกับว่าเราต้องการให้โค้ดภายนอกแก้ค่านั้นได้หรือไม่

## Named Function Expression

Named Function Expression หรือเรียกสั้น ๆ ว่า NFE คือ Function Expression ที่ระบุชื่อฟังก์ชันไว้หลังคำว่า `function`

ลองดู Function Expression ธรรมดาก่อน:

```js
let sayHi = function(who) {
  alert(`Hello, ${who}`);
};
```

ทีนี้ลองเพิ่มชื่อ `func` หลัง `function`:

```js
let sayHi = function *!*func*/!*(who) {
  alert(`Hello, ${who}`);
};
```

ชื่อ `func` ที่เพิ่มมามีประโยชน์อย่างไร?

ก่อนอื่น ฟังก์ชันนี้ยังเป็น Function Expression เหมือนเดิม เพราะเรายังสร้างฟังก์ชันเป็นส่วนหนึ่งของนิพจน์ (expression) ที่กำหนดค่าให้ `sayHi` การเพิ่มชื่อ `func` จึงไม่ได้เปลี่ยนให้เป็น Function Declaration

เรายังเรียกฟังก์ชันผ่าน `sayHi()` ได้ตามปกติ:

```js run
let sayHi = function *!*func*/!*(who) {
  alert(`Hello, ${who}`);
};

sayHi("John"); // Hello, John
```

ชื่อ `func` มีความพิเศษอยู่ 2 อย่าง:

1. ทำให้ฟังก์ชันสามารถอ้างอิงถึงตัวเองจากภายในได้
2. โค้ดภายนอกฟังก์ชันใช้ชื่อนี้ไม่ได้

ตัวอย่างนี้ ถ้าเรียก `sayHi` โดยไม่ส่งค่า `who` ฟังก์ชันจะเรียกตัวเองอีกครั้งผ่านชื่อ `func` พร้อมส่งค่า `"Guest"` เข้าไป:

```js run
let sayHi = function *!*func*/!*(who) {
  if (who) {
    alert(`Hello, ${who}`);
  } else {
*!*
    func("Guest"); // ใช้ func เพื่อเรียกตัวเองซ้ำ
*/!*
  }
};

sayHi(); // Hello, Guest

// แต่แบบนี้ใช้ไม่ได้:
func(); // Error, func is not defined (มองไม่เห็นจากภายนอก)
```

แล้วใช้ชื่อ `sayHi` เรียกตัวเองแทน `func` ได้ไหม?


ส่วนใหญ่ก็ทำได้:

```js
let sayHi = function(who) {
  if (who) {
    alert(`Hello, ${who}`);
  } else {
*!*
    sayHi("Guest");
*/!*
  }
};
```

ปัญหาจะเกิดเมื่อโค้ดภายนอกเปลี่ยนค่าของ `sayHi` เช่น เราเก็บฟังก์ชันไว้ในตัวแปร `welcome` แล้วเปลี่ยน `sayHi` เป็น `null` การเรียกตัวเองผ่าน `sayHi` ก็จะเกิดข้อผิดพลาด:

```js run
let sayHi = function(who) {
  if (who) {
    alert(`Hello, ${who}`);
  } else {
*!*
    sayHi("Guest"); // Error: sayHi is not a function
*/!*
  }
};

let welcome = sayHi;
sayHi = null;

welcome(); // Error, การเรียก sayHi ซ้อนข้างในใช้ไม่ได้อีกแล้ว!
```

ในฟังก์ชันไม่มีตัวแปรภายในชื่อ `sayHi` จึงต้องค้นหา `sayHi` จาก Lexical Environment ชั้นนอก แต่เมื่อเรียก `welcome()` ตัวแปร `sayHi` กลายเป็น `null` ไปแล้ว จึงเรียก `sayHi("Guest")` ไม่ได้

ชื่อที่เพิ่มให้ Function Expression ช่วยแก้ปัญหานี้ได้

ลองเปลี่ยนมาใช้ชื่อ `func` เพื่อเรียกตัวเอง:

```js run
let sayHi = function *!*func*/!*(who) {
  if (who) {
    alert(`Hello, ${who}`);
  } else {
*!*
    func("Guest"); // ทำงานได้ปกติ
*/!*
  }
};

let welcome = sayHi;
sayHi = null;

welcome(); // Hello, Guest (การเรียกซ้อนทำงานได้)
```

คราวนี้โค้ดทำงานได้ เพราะ `func` เป็นชื่อที่ใช้ได้เฉพาะภายในฟังก์ชัน ไม่ได้อาศัยตัวแปรจากภายนอก ข้อกำหนดของภาษารับประกันว่าชื่อนี้จะอ้างอิงถึงฟังก์ชันนั้นเสมอ

โค้ดภายนอกยังใช้ตัวแปร `sayHi` หรือ `welcome` ตามปกติ ส่วนภายในใช้ชื่อ `func` เรียกตัวเองได้ แม้ค่าของตัวแปรภายนอกจะเปลี่ยนไป

```smart header="Function Declaration ไม่มีฟีเจอร์นี้"
ชื่อที่ใช้ได้เฉพาะภายในตามที่อธิบายข้างต้นมีให้ใช้ใน Function Expression เท่านั้น ส่วน Function Declaration ไม่มีรูปแบบการเขียนที่เพิ่มชื่อภายในอีกชื่อหนึ่งได้

หากต้องการชื่อสำหรับเรียกตัวเองที่ไม่ขึ้นกับตัวแปรภายนอก เราจึงอาจเปลี่ยนจาก Function Declaration มาเขียนเป็น Named Function Expression
```

## สรุป

ฟังก์ชันคือออบเจ็กต์

พร็อพเพอร์ตี้ที่มีมาให้ ได้แก่:

- `name` คือชื่อฟังก์ชัน โดยปกติจะใช้ชื่อที่ระบุไว้ตอนสร้างฟังก์ชัน ถ้าไม่ได้ระบุ JavaScript จะพยายามตั้งชื่อให้ตามบริบท เช่น ชื่อตัวแปรที่นำฟังก์ชันไปกำหนดค่าให้
- `length` คือจำนวนพารามิเตอร์ก่อนตัวแรกที่มีค่าเริ่มต้น ถ้าไม่มีค่าเริ่มต้นก็นับทุกตัว โดยไม่นับ rest parameter

Function Expression ที่ระบุชื่อไว้หลัง `function` เรียกว่า Named Function Expression เราใช้ชื่อนั้นอ้างอิงถึงฟังก์ชันจากภายในได้ เช่น ใช้เรียกตัวเองซ้ำ (recursive call)

เรายังเพิ่มพร็อพเพอร์ตี้ให้ฟังก์ชันได้ด้วย ไลบรารี JavaScript หลายตัวใช้วิธีนี้

ไลบรารีจะสร้างฟังก์ชันหลักขึ้นมาตัวหนึ่ง แล้วเก็บฟังก์ชันอื่น ๆ ที่ช่วยงานไว้เป็นพร็อพเพอร์ตี้ เช่น [jQuery](https://jquery.com) มีฟังก์ชัน `$` ส่วน [lodash](https://lodash.com) มีฟังก์ชัน `_` พร้อมพร็อพเพอร์ตี้อย่าง `_.clone` และ `_.keyBy` ดูรายละเอียดได้ใน[เอกสารของ lodash](https://lodash.com/docs) วิธีนี้ทำให้แต่ละไลบรารีรวมความสามารถไว้ภายใต้ตัวแปรส่วนกลาง (global variable) ตัวเดียว จึงลดโอกาสที่ชื่อตัวแปรจะซ้ำกับโค้ดส่วนอื่น


ฟังก์ชันจึงทำงานของตัวเองไปพร้อมกับเก็บฟังก์ชันอื่น ๆ ไว้ให้เรียกใช้ผ่านพร็อพเพอร์ตี้ได้
