
# "var" แบบเก่า

```smart header="บทความนี้มีไว้สำหรับทำความเข้าใจโค้ดเก่า"
บทนี้อธิบายพฤติกรรมของ `var` เพื่อให้เราอ่านและแก้ไขโค้ดเก่าได้

สำหรับโค้ดใหม่ เราใช้ `let` และ `const` เป็นหลัก
```

ในบทเรื่อง[ตัวแปร (variable)](info:variables) เรารู้จักการประกาศ (declaration) ตัวแปร 3 แบบมาแล้ว คือ

1. `let`
2. `const`
3. `var`

ถ้าดูแค่การประกาศและใช้งานตัวแปร `var` ก็คล้ายกับ `let` ส่วนใหญ่เราเปลี่ยนจากแบบหนึ่งไปเป็นอีกแบบแล้วโค้ดยังทำงานได้ เช่น

```js run
var message = "Hi";
alert(message); // Hi
```

อย่างไรก็ตาม กติกาของ `var` ต่างจาก `let` อยู่หลายจุด เพราะ `var` มีมาตั้งแต่ยุคแรกของ JavaScript เราจึงยังพบ `var` ได้ในโค้ดเก่า แม้เวลาเขียนโค้ดใหม่จะใช้ `let` และ `const` กันเป็นหลัก

ถ้ายังไม่ต้องทำงานกับโค้ดเก่า จะข้ามบทนี้ไปก่อนแล้วกลับมาอ่านภายหลังก็ได้

แต่ถ้าจะเปลี่ยนโค้ดเก่าจาก `var` มาใช้ `let` เราต้องเข้าใจความแตกต่างเหล่านี้ก่อน เพราะการเปลี่ยนคำประกาศอาจทำให้โค้ดที่เคยทำงานได้เกิดข้อผิดพลาด

## "var" ไม่มีบล็อกสโคป (block scope)

สโคป (scope) คือขอบเขตที่เราเข้าถึงตัวแปรได้ ถ้าประกาศ `var` ในฟังก์ชัน (function) เราจะเข้าถึงตัวแปรได้ภายในฟังก์ชันนั้น แต่ถ้าประกาศนอกฟังก์ชันในสคริปต์ (script) ตัวแปรจะเป็นตัวแปรส่วนกลาง (global variable)

บล็อก (block) เช่น ส่วนที่อยู่ใน `{...}` ของ `if` ไม่ได้จำกัดสโคปของ `var` ลองดูตัวอย่างนี้

```js run
if (true) {
  var test = true; // ใช้ "var" แทน "let"
}

*!*
alert(test); // true, ตัวแปรยังอยู่หลังจบ if
*/!*
```

ในตัวอย่างนี้ `test` ไม่ได้อยู่ภายในฟังก์ชัน และบล็อกของ `if` ก็ไม่ได้จำกัดสโคปของ `var` ดังนั้น `test` จึงเป็นตัวแปรส่วนกลาง เรายังอ่านค่า `true` ได้หลังออกจาก `if`

ถ้าเปลี่ยนเป็น `let test` เราจะเข้าถึงตัวแปรได้เฉพาะในบล็อกของ `if` เมื่ออ่านค่าจากข้างนอกจึงเกิด `ReferenceError`

```js run
if (true) {
  let test = true; // ใช้ "let"
}

*!*
alert(test); // ReferenceError: test is not defined
*/!*
```

ลูป (loop) ก็เช่นกัน การประกาศด้วย `var` ไม่ได้จำกัดตัวแปรไว้เฉพาะในลูป พอ `for` ทำงานจบ เรายังอ่านค่า `i` และ `one` ได้

```js run
for (var i = 0; i < 10; i++) {
  var one = 1;
  // ...
}

*!*
alert(i);   // 10, "i" ยังเห็นอยู่หลังจบลูป เพราะเป็นตัวแปร global
alert(one); // 1, "one" ก็ยังเห็นอยู่หลังจบลูปเช่นกัน
*/!*
```

แต่ถ้าบล็อกนั้นอยู่ในฟังก์ชัน ตัวแปรที่ประกาศด้วย `var` จะมีสโคปอยู่ภายในฟังก์ชันนั้น เช่น `phrase` ด้านล่าง เราอ่านค่าได้ใน `sayHi` แม้จะอยู่นอกบล็อกของ `if` แต่เข้าถึงจากนอกฟังก์ชันไม่ได้

```js run
function sayHi() {
  if (true) {
    var phrase = "Hello";
  }

  alert(phrase); // ใช้งานได้
}

sayHi();
alert(phrase); // ReferenceError: phrase is not defined
```

ดังนั้น บล็อกของ `if`, `for` หรือบล็อกโค้ดอื่น ๆ จึงไม่ได้สร้างสโคปแยกให้ `var` พฤติกรรมนี้มาจาก JavaScript ในยุคที่บล็อกยังไม่มี Lexical Environment ของตัวเอง และ `var` ก็ยังทำงานตามกติกาเดิม

## "var" ประกาศซ้ำได้

ถ้าเราประกาศตัวแปรชื่อเดียวกันด้วย `let` สองครั้งในสโคปเดียวกัน จะเกิด `SyntaxError`

```js run
let user;
let user; // SyntaxError: 'user' has already been declared
```

ส่วนตัวแปรที่ประกาศด้วย `var` จะใช้ `var` ประกาศชื่อเดิมซ้ำกี่ครั้งก็ได้ JavaScript จะข้ามเฉพาะการประกาศซ้ำ ส่วนการกำหนดค่า (assignment) ยังทำงานตามปกติ ในตัวอย่างนี้ `user` จึงเปลี่ยนจาก `"Pete"` เป็น `"John"`

```js run
var user = "Pete";

var user = "John"; // "var" นี้ไม่ทำอะไร (ประกาศไว้แล้ว)
// ...ไม่เกิด error

alert(user); // John
```

## ใช้ตัวแปร "var" ก่อนบรรทัดที่ประกาศได้

JavaScript จัดการการประกาศ `var` ตั้งแต่เริ่มทำงานในฟังก์ชัน ส่วนตัวแปรส่วนกลางจะจัดการตั้งแต่เริ่มทำงานในสคริปต์

นั่นหมายความว่าตัวแปรมีอยู่แล้วตั้งแต่เริ่มฟังก์ชัน แม้เราจะเขียน `var` ไว้ด้านล่างก็ตาม ทั้งนี้ไม่นับ `var` ที่ประกาศอยู่ในฟังก์ชันซ้อน เพราะตัวแปรนั้นเป็นของฟังก์ชันที่อยู่ข้างใน

ลองดูโค้ดนี้ เรากำหนดค่าและอ่านค่า `phrase` ก่อนบรรทัด `var phrase` ได้

```js run
function sayHi() {
  phrase = "Hello";

  alert(phrase);

*!*
  var phrase;
*/!*
}
sayHi();
```

ผลที่ได้เหมือนกับการย้าย `var phrase` ขึ้นไปไว้ต้นฟังก์ชัน

```js run
function sayHi() {
*!*
  var phrase;
*/!*

  phrase = "Hello";

  alert(phrase);
}
sayHi();
```

แม้จะเขียน `var phrase` ไว้ใน `if (false)` ผลก็ยังเหมือนเดิม เพราะบล็อกของ `if` ไม่ได้สร้างสโคปแยกให้ `var`

```js run
function sayHi() {
  phrase = "Hello"; // (*)

  *!*
  if (false) {
    var phrase;
  }
  */!*

  alert(phrase);
}
sayHi();
```

พฤติกรรมนี้เรียกว่า *hoisting* เราอธิบายได้ว่าการประกาศ `var` ทำงานเสมือนถูกย้ายขึ้นไปไว้ต้นฟังก์ชัน จึงใช้ตัวแปรก่อนบรรทัดที่ประกาศได้

ในตัวอย่างข้างบน โค้ดใน `if (false)` ไม่ได้ทำงานเลย แต่ JavaScript จัดการการประกาศ `var phrase` ตั้งแต่เริ่มฟังก์ชันแล้ว พอถึงบรรทัด `(*)` จึงมีตัวแปร `phrase` ให้กำหนดค่าได้

**hoisting มีผลกับการประกาศตัวแปร ส่วนการกำหนดค่ายังทำงานเมื่อถึงบรรทัดนั้น**

ลองดูว่าจะเกิดอะไรขึ้นถ้าอ่านค่า `phrase` ก่อนบรรทัด `var phrase = "Hello"`

```js run
function sayHi() {
  alert(phrase);

*!*
  var phrase = "Hello";
*/!*
}

sayHi();
```

บรรทัด `var phrase = "Hello"` ทำสองอย่างด้วยกัน

1. ประกาศตัวแปรด้วย `var`
2. กำหนดค่าให้ตัวแปรด้วย `=`

JavaScript จัดการส่วนที่ประกาศตัวแปรตั้งแต่เริ่มฟังก์ชัน แต่จะกำหนดค่า `"Hello"` ให้ก็ต่อเมื่อทำงานมาถึงบรรทัดนั้น โค้ดจึงทำงานเหมือนกับการแยกสองส่วนออกมาเขียนแบบนี้

```js run
function sayHi() {
*!*
  var phrase; // การประกาศถูกประมวลผลตั้งแต่ต้น...
*/!*

  alert(phrase); // undefined

*!*
  phrase = "Hello"; // ...การกำหนดค่าทำงานตอนที่รันถึงบรรทัดนี้
*/!*
}

sayHi();
```

เราจึงเข้าถึงตัวแปร `var` ได้ตลอดสโคปของมัน แต่ก่อนจะกำหนดค่า ตัวแปรจะมีค่าเป็น `undefined`

ในสองตัวอย่างล่าสุด `alert` ไม่เกิดข้อผิดพลาด เพราะมีตัวแปร `phrase` อยู่แล้ว เพียงแต่ยังทำงานมาไม่ถึงส่วนที่กำหนดค่า `"Hello"` จึงแสดง `undefined`

## IIFE

ก่อนจะมี `let` และ `const` เราใช้ `var` ซึ่งจำกัดตัวแปรไว้ในบล็อกไม่ได้ โปรแกรมเมอร์จึงใช้ฟังก์ชันสร้างสโคปแยก แล้วเรียกฟังก์ชันนั้นทันที วิธีนี้เรียกว่า *Immediately Invoked Function Expression* หรือย่อว่า *IIFE*

ถ้าต้องการเพียงจำกัดสโคปของตัวแปรไว้ในบล็อก เราใช้ `let` หรือ `const` ได้ จึงไม่จำเป็นต้องใช้ IIFE เพื่อจุดประสงค์นี้ แต่เรายังพบรูปแบบนี้ได้ในโค้ดเก่า

ลองดูตัวอย่าง IIFE

```js run
(function() {

  var message = "Hello";

  alert(message); // Hello

})();
```

ในตัวอย่างนี้ เราสร้างฟังก์ชันในรูปของนิพจน์ (expression) ที่เรียกว่า Function Expression แล้วใช้ `()` ด้านท้ายเรียกทันที โค้ดในฟังก์ชันจึงทำงานทันที และตัวแปร `message` ก็อยู่ในสโคปของฟังก์ชันนี้

ที่ต้องใช้วงเล็บครอบฟังก์ชัน ก็เพราะถ้า JavaScript พบ `function` ที่จุดเริ่มต้นของคำสั่ง (statement) จะตีความว่าเป็นการประกาศฟังก์ชันแบบ Function Declaration ซึ่งต้องมีชื่อ ลองเอาวงเล็บที่ครอบออก โค้ดจะเกิด `SyntaxError` เพราะฟังก์ชันไม่มีชื่อ

```js run
// พยายามประกาศฟังก์ชันแล้วเรียกใช้ทันที
function() { // <-- SyntaxError: Function statements require a function name

  var message = "Hello";

  alert(message); // Hello

}();
```

แม้จะใส่ชื่อฟังก์ชันเข้าไป ก็ยังเกิดข้อผิดพลาด เพราะเราต่อท้าย Function Declaration ด้วย `()` เพื่อเรียกทันทีแบบนี้ไม่ได้

```js run
// syntax error เพราะวงเล็บด้านล่าง
function go() {

}(); // <-- เรียก Function Declaration ทันทีไม่ได้
```

วงเล็บที่ครอบฟังก์ชันจึงบอก JavaScript ให้ตีความฟังก์ชันเป็นส่วนหนึ่งของนิพจน์ ทำให้ได้ Function Expression ซึ่งไม่จำเป็นต้องมีชื่อ และใช้ `()` ต่อท้ายเพื่อเรียกได้ทันที

นอกจากการครอบวงเล็บแล้ว ยังเขียนแบบอื่นให้ JavaScript ตีความเป็น Function Expression ได้ด้วย ตัวอย่างต่อไปนี้มีทั้งการใช้วงเล็บ และการใช้ตัวดำเนินการ (operator) `!` หรือ `+` นำหน้าฟังก์ชัน

```js run
// วิธีสร้าง IIFE

*!*(*/!*function() {
  alert("Parentheses around the function");
}*!*)*/!*();

*!*(*/!*function() {
  alert("Parentheses around the whole thing");
}()*!*)*/!*;

*!*!*/!*function() {
  alert("Logical NOT operator starts the expression");
}();

*!*+*/!*function() {
  alert("Unary plus starts the expression");
}();
```

ทุกแบบข้างต้นสร้าง Function Expression แล้วเรียกทันทีเหมือนกัน สำหรับการจำกัดสโคปของตัวแปรไว้ในบล็อก เราใช้ `let` และ `const` แทนการห่อโค้ดด้วย IIFE ได้

## สรุป

`var` ต่างจาก `let` และ `const` อยู่สองประเด็นหลัก

1. บล็อกโค้ดไม่ได้จำกัดสโคปของ `var` ตัวแปรจะมีสโคปอยู่ในฟังก์ชันที่ประกาศไว้ หรือเป็นตัวแปรส่วนกลางถ้าประกาศนอกฟังก์ชันในสคริปต์
2. JavaScript จัดการการประกาศ `var` ตั้งแต่เริ่มทำงานในฟังก์ชัน หรือเริ่มทำงานในสคริปต์สำหรับตัวแปรส่วนกลาง

ยังมีความต่างเล็กน้อยอีกเรื่องหนึ่งที่เกี่ยวกับออบเจ็กต์ส่วนกลาง (global object) ซึ่งเราจะเรียนกันในบทถัดไป

กติกาเหล่านี้ทำให้ `var` เหมาะกับการใช้งานน้อยกว่า `let` ในกรณีส่วนใหญ่ การจำกัดสโคปให้อยู่ในบล็อกช่วยให้เราควบคุมได้ว่าตัวแปรจะใช้ได้ตรงไหน นี่คือเหตุผลที่มาตรฐาน JavaScript เพิ่ม `let` เข้ามา และเราใช้ `let` ร่วมกับ `const` เป็นหลักในการประกาศตัวแปร
