
# WeakMap และ WeakSet

ในบท <info:garbage-collection> เราได้เรียนว่า JavaScript engine จะเก็บค่าไว้ในหน่วยความจำตราบเท่าที่ยัง "เข้าถึงได้" (reachable) และอาจมีการนำค่านั้นไปใช้

ตัวอย่างเช่น:

```js
let john = { name: "John" };

// เข้าถึงออบเจ็กต์ได้ผ่าน john ซึ่งเป็น reference ของมัน

// เขียนทับ reference
john = null;

*!*
// ออบเจ็กต์ไม่สามารถเข้าถึงได้แล้ว ระบบจึงเก็บกวาดหน่วยความจำส่วนนี้ได้
*/!*
```

โดยทั่วไป พร็อพเพอร์ตี้ (property) ของออบเจ็กต์ (object) สมาชิกของอาร์เรย์ (array) และข้อมูลในโครงสร้างข้อมูล (data structure) อื่น ๆ จะยังเข้าถึงได้ตราบเท่าที่เรายังเข้าถึงโครงสร้างที่เก็บข้อมูลนั้นได้

เช่น ถ้าใส่ออบเจ็กต์ลงในอาร์เรย์ที่เรายังใช้งานได้ ออบเจ็กต์นั้นก็จะยังอยู่ในหน่วยความจำ แม้จะไม่มีการอ้างอิง (reference) จากที่อื่นมายังออบเจ็กต์นั้นเลย

ลองดูตัวอย่างนี้:

```js
let john = { name: "John" };

let array = [ john ];

john = null; // เขียนทับ reference

*!*
// ออบเจ็กต์ที่ john เคยชี้ไป ยังคงอยู่ในอาร์เรย์
// ดังนั้นจะไม่ถูก garbage-collected
// เราเข้าถึงมันได้ผ่าน array[0]
*/!*
```

การใช้ออบเจ็กต์เป็นคีย์ (key) ใน `Map` ก็เช่นกัน ตราบใดที่เรายังเข้าถึง `Map` ที่เก็บคีย์นั้นได้ ออบเจ็กต์ก็ยังอยู่ในหน่วยความจำ การเก็บกวาดหน่วยความจำ (garbage collection) จึงยังลบออบเจ็กต์นั้นไม่ได้

ตัวอย่าง:

```js
let john = { name: "John" };

let map = new Map();
map.set(john, "...");

john = null; // เขียนทับ reference

*!*
// john ยังคงอยู่ใน map
// เราเข้าถึงมันได้ผ่าน map.keys()
*/!*
```

แต่ [`WeakMap`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap) มีพฤติกรรมต่างออกไป การเก็บออบเจ็กต์ไว้เป็นคีย์ใน `WeakMap` ไม่ได้ขัดขวางการเก็บกวาดหน่วยความจำของออบเจ็กต์นั้น

ลองดูตัวอย่างว่าความต่างนี้ส่งผลอย่างไร

## WeakMap

ความต่างแรกระหว่าง [`Map`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map) กับ [`WeakMap`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap) คือชนิดของค่าที่ใช้เป็นคีย์ได้ `WeakMap` รับออบเจ็กต์และ symbol ที่ไม่ได้ลงทะเบียน (non-registered symbol) เช่น symbol ที่สร้างด้วย `Symbol()` แต่ไม่รับ symbol ที่ได้จาก `Symbol.for()` และค่าพื้นฐาน (primitive) ชนิดอื่น

ในบทนี้เราจะใช้ออบเจ็กต์เป็นคีย์ ลองเปรียบเทียบกับการใช้สตริง (string):

```js run
let weakMap = new WeakMap();

let obj = {};

weakMap.set(obj, "ok"); // ใช้งานได้ปกติ (key เป็นออบเจ็กต์)

*!*
// ไม่สามารถใช้สตริงเป็น key ได้
weakMap.set("test", "Whoops"); // TypeError เพราะใช้สตริงเป็นคีย์ของ WeakMap ไม่ได้
*/!*
```

ถ้าใช้ออบเจ็กต์เป็นคีย์ แล้วไม่มีการอ้างอิงจากที่อื่นที่ทำให้เข้าถึงออบเจ็กต์นั้นได้อีก ระบบก็สามารถลบออบเจ็กต์ออกจากหน่วยความจำ พร้อมลบข้อมูลของคีย์นั้นออกจาก `WeakMap` ได้โดยอัตโนมัติ

```js
let john = { name: "John" };

let weakMap = new WeakMap();
weakMap.set(john, "...");

john = null; // เขียนทับ reference

// ออบเจ็กต์ที่ john เคยอ้างอิงพร้อมให้ระบบเก็บกวาดหน่วยความจำแล้ว
```

เมื่อเทียบกับตัวอย่าง `Map` ข้างต้น ออบเจ็กต์ที่ `john` เคยอ้างอิงไม่ได้ถูกเก็บไว้เพียงเพราะเป็นคีย์ใน `WeakMap` เมื่อไม่มีการอ้างอิงจากที่อื่น ระบบก็เก็บกวาดออบเจ็กต์และข้อมูลของคีย์นั้นได้

`WeakMap` ไม่รองรับการวนซ้ำ (iteration) และไม่มีเมธอด (method) `keys()`, `values()`, `entries()` เราจึงดึงคีย์หรือค่าทั้งหมดออกมาจาก `WeakMap` ไม่ได้

เมธอดหลักที่ใช้ในบทนี้มีดังนี้:

- [`weakMap.set(key, value)`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap/set)
- [`weakMap.get(key)`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap/get)
- [`weakMap.delete(key)`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap/delete)
- [`weakMap.has(key)`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap/has)

เหตุที่ไม่มีเมธอดสำหรับดึงข้อมูลทั้งหมดเกี่ยวข้องกับเวลาที่ระบบเก็บกวาดหน่วยความจำ เมื่อออบเจ็กต์ไม่มีการอ้างอิงจากที่อื่นแล้ว เช่น ออบเจ็กต์ที่ `john` เคยอ้างอิงในตัวอย่างข้างต้น JavaScript engine สามารถเก็บกวาดออบเจ็กต์นั้นได้ แต่ไม่มีข้อกำหนดว่า *ต้องทำเมื่อไร*

JavaScript engine อาจเก็บกวาดทันที หรือรอจนมีออบเจ็กต์ที่ไม่ใช้แล้วหลายตัวจึงค่อยทำพร้อมกัน จำนวนสมาชิกใน `WeakMap` จึงขึ้นอยู่กับว่าระบบเก็บกวาดไปแล้วมากน้อยแค่ไหน การเปิดให้ดูคีย์หรือค่าทั้งหมดจะทำให้ผลที่ได้เปลี่ยนไปตามจังหวะการเก็บกวาด `WeakMap` จึงไม่เปิดให้เข้าถึงข้อมูลในลักษณะนั้น

แล้วเราจะใช้ `WeakMap` ทำอะไรได้บ้าง?

## กรณีใช้งาน: ข้อมูลเสริม

การใช้งานหลักของ `WeakMap` คือเก็บ *ข้อมูลเสริมที่ผูกกับออบเจ็กต์*

สมมติว่าโค้ดส่วนอื่นหรือไลบรารี (library) ภายนอกเป็นผู้จัดการออบเจ็กต์หนึ่ง แต่เราต้องการเก็บข้อมูลเพิ่มเติมเกี่ยวกับออบเจ็กต์นั้น และไม่ต้องการเก็บข้อมูลนี้ต่อเมื่อออบเจ็กต์ไม่อยู่แล้ว `WeakMap` เหมาะกับงานนี้

เราเก็บข้อมูลลงใน `WeakMap` โดยใช้ออบเจ็กต์เป็นคีย์ เมื่อระบบเก็บกวาดออบเจ็กต์นั้น ข้อมูลที่ผูกกับคีย์ก็ถูกลบออกจาก `WeakMap` ตามไปด้วย

```js
weakMap.set(john, "secret documents");
// ถ้า john ถูกลบ เอกสารลับก็จะถูกทำลายโดยอัตโนมัติ
```

ลองดูตัวอย่างการนับจำนวนครั้งที่ผู้ใช้เข้าชม

เราจะเก็บจำนวนครั้งที่เข้าชมไว้ใน `Map` โดยใช้ออบเจ็กต์ของผู้ใช้เป็นคีย์ และจำนวนครั้งเป็นค่าที่ผูกกับคีย์ เมื่อไม่ใช้ออบเจ็กต์ของผู้ใช้แล้วและระบบเก็บกวาดออบเจ็กต์นั้น เราก็ไม่ต้องเก็บจำนวนครั้งที่เข้าชมอีก

เริ่มจากฟังก์ชัน (function) นับการเข้าชมที่ใช้ `Map`:

```js
// 📁 visitsCount.js
let visitsCountMap = new Map(); // map: user => จำนวนครั้งที่เข้าชม

// เพิ่มจำนวนครั้งที่เข้าชม
function countUser(user) {
  let count = visitsCountMap.get(user) || 0;
  visitsCountMap.set(user, count + 1);
}
```

โค้ดอีกส่วนหนึ่ง ซึ่งอาจอยู่คนละไฟล์ เรียกใช้ฟังก์ชันนี้ดังนี้:

```js
// 📁 main.js
let john = { name: "John" };

countUser(john); // นับการเข้าชมของเขา

// ต่อมา john ออกจากระบบ
john = null;
```

เมื่อกำหนด `john = null` เราไม่ต้องใช้ออบเจ็กต์ของผู้ใช้คนนี้แล้ว แต่ออบเจ็กต์ยังอยู่ในหน่วยความจำ เพราะ `visitsCountMap` เก็บออบเจ็กต์นั้นไว้เป็นคีย์

เราจึงต้องลบข้อมูลออกจาก `visitsCountMap` ทุกครั้งที่ลบผู้ใช้ มิฉะนั้นข้อมูลจะสะสมและใช้หน่วยความจำเพิ่มขึ้นเรื่อย ๆ ในระบบที่ซับซ้อน การคอยจัดการข้อมูลเหล่านี้ให้ครบอาจกลายเป็นงานยุ่งยาก

เปลี่ยนมาใช้ `WeakMap` เพื่อให้ระบบจัดการส่วนนี้ได้:

```js
// 📁 visitsCount.js
let visitsCountMap = new WeakMap(); // weakmap: user => จำนวนครั้งที่เข้าชม

// เพิ่มจำนวนครั้งที่เข้าชม
function countUser(user) {
  let count = visitsCountMap.get(user) || 0;
  visitsCountMap.set(user, count + 1);
}
```

ทีนี้เราไม่ต้องคอยลบข้อมูลผู้ใช้ที่เลิกใช้แล้วออกจาก `visitsCountMap` เอง เมื่อไม่มีการอ้างอิงจากที่อื่นที่ทำให้เข้าถึงออบเจ็กต์นั้นได้ ระบบก็สามารถเก็บกวาดออบเจ็กต์ พร้อมลบจำนวนครั้งที่เข้าชมซึ่งผูกกับคีย์นั้นออกจาก `WeakMap`

## กรณีใช้งาน: การแคช (caching)

อีกกรณีที่พบบ่อยคือการแคช หรือการเก็บผลลัพธ์จากฟังก์ชันไว้ใช้ซ้ำ เมื่อเรียกฟังก์ชันด้วยออบเจ็กต์เดิมอีกครั้ง เราก็นำผลลัพธ์ที่เก็บไว้มาใช้ได้โดยไม่ต้องคำนวณใหม่

เราสามารถใช้ `Map` เก็บผลลัพธ์ได้ แต่ยังมีเรื่องการใช้หน่วยความจำที่ต้องจัดการ:

```js run
// 📁 cache.js
let cache = new Map();

// คำนวณและจดจำผลลัพธ์
function process(obj) {
  if (!cache.has(obj)) {
    let result = /* คำนวณผลลัพธ์สำหรับ */ obj;

    cache.set(obj, result);
    return result;
  }

  return cache.get(obj);
}

*!*
// ทีนี้เราใช้ process() ในไฟล์อื่น:
*/!*

// 📁 main.js
let obj = {/* สมมติว่าเรามีออบเจ็กต์นี้ */};

let result1 = process(obj); // คำนวณแล้ว

// ...ต่อมา จากที่อื่นในโค้ด...
let result2 = process(obj); // นำผลลัพธ์จาก cache มาใช้

// ...ต่อมา เมื่อไม่ต้องการออบเจ็กต์แล้ว:
obj = null;

alert(cache.size); // 1 (อุ๊ย! ออบเจ็กต์ยังอยู่ใน cache กินหน่วยความจำ!)
```

เมื่อเรียก `process(obj)` ด้วยออบเจ็กต์เดิม ฟังก์ชันจะคำนวณผลลัพธ์เฉพาะครั้งแรก ส่วนครั้งต่อ ๆ ไปจะดึงผลลัพธ์จาก `cache` แต่เมื่อไม่ต้องใช้ออบเจ็กต์แล้ว เราต้องลบข้อมูลออกจาก `cache` เอง มิฉะนั้น `Map` จะยังเก็บออบเจ็กต์นั้นไว้

หากเปลี่ยนเป็น `WeakMap` ตัวแคชจะไม่ขัดขวางการเก็บกวาดออบเจ็กต์ที่เป็นคีย์ เมื่อระบบเก็บกวาดคีย์แล้ว ข้อมูลที่ผูกกับคีย์จะถูกลบออกจากแคชด้วย ส่วนผลลัพธ์จะถูกเก็บกวาดออกจากหน่วยความจำได้เมื่อไม่มีการอ้างอิงจากที่อื่นที่ทำให้เข้าถึงผลลัพธ์นั้นได้อีก

```js run
// 📁 cache.js
*!*
let cache = new WeakMap();
*/!*

// คำนวณและจดจำผลลัพธ์
function process(obj) {
  if (!cache.has(obj)) {
    let result = /* คำนวณผลลัพธ์สำหรับ */ obj;

    cache.set(obj, result);
    return result;
  }

  return cache.get(obj);
}

// 📁 main.js
let obj = {/* ออบเจ็กต์ตัวหนึ่ง */};

let result1 = process(obj);
let result2 = process(obj);

// ...ต่อมา เมื่อไม่ต้องการออบเจ็กต์แล้ว:
obj = null;

// ไม่สามารถดู cache.size ได้ เพราะเป็น WeakMap
// ตัวอย่างนี้ result1 และ result2 ยังอ้างอิงออบเจ็กต์เดิมอยู่
// การกำหนด obj = null เพียงอย่างเดียวจึงยังไม่ทำให้ข้อมูลถูกลบจาก cache
// เมื่อไม่มีการอ้างอิงจากที่อื่น ระบบจึงเก็บกวาดออบเจ็กต์และข้อมูลใน cache ได้
```

สังเกตว่าตัวอย่างนี้ใช้ `obj` แทนผลการคำนวณ ฟังก์ชันจึงคืนออบเจ็กต์เดิมออกมา ตัวแปร (variable) `result1` และ `result2` ยังอ้างอิงออบเจ็กต์นั้นอยู่ แม้จะกำหนด `obj = null` แล้วก็ตาม `WeakMap` เพียงเปิดทางให้ระบบเก็บกวาดออบเจ็กต์เมื่อไม่สามารถเข้าถึงจากที่อื่นได้ ไม่ได้ลบออบเจ็กต์ที่ยังใช้งานได้อยู่

## WeakSet

[`WeakSet`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakSet) ใช้หลักการเดียวกัน:

- คล้ายกับ `Set` แต่รับเฉพาะออบเจ็กต์และ symbol ที่ไม่ได้ลงทะเบียน ไม่รับค่าพื้นฐานชนิดอื่น
- ออบเจ็กต์ที่เพิ่มไว้จะยังอยู่ใน `WeakSet` ตราบเท่าที่ยังเข้าถึงได้จากที่อื่น เมื่อไม่มีการอ้างอิงจากที่อื่นแล้ว ระบบก็เก็บกวาดออบเจ็กต์นั้นได้
- รองรับ [`add`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Weakset/add), [`has`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Weakset/has) และ [`delete`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Weakset/delete) เหมือน `Set` แต่ไม่มี `size`, `keys()` และไม่รองรับการวนซ้ำ

`WeakSet` เหมาะกับการเก็บข้อมูลเสริมเช่นเดียวกับ `WeakMap` แต่เก็บเป็นสถานะแบบ "ใช่/ไม่ใช่" โดยใช้การเป็นสมาชิกของ `WeakSet` แทนสถานะนั้น

เช่น เราอาจเพิ่มออบเจ็กต์ของผู้ใช้ลงใน `WeakSet` เพื่อบันทึกว่าผู้ใช้คนนี้เคยเข้าชมเว็บไซต์แล้ว:

```js run
let visitedSet = new WeakSet();

let john = { name: "John" };
let pete = { name: "Pete" };
let mary = { name: "Mary" };

visitedSet.add(john); // John เข้าเยี่ยมชม
visitedSet.add(pete); // แล้ว Pete ก็เข้ามา
visitedSet.add(john); // John เข้ามาอีกครั้ง

// ตอนนี้ visitedSet มี 2 user

// ตรวจสอบว่า John เคยเข้าเยี่ยมชมหรือยัง?
alert(visitedSet.has(john)); // true

// ตรวจสอบว่า Mary เคยเข้าเยี่ยมชมหรือยัง?
alert(visitedSet.has(mary)); // false

john = null;

// visitedSet จะถูกทำความสะอาดโดยอัตโนมัติ
```

ข้อจำกัดหลักของ `WeakMap` และ `WeakSet` คือเราไม่สามารถวนซ้ำหรือดึงข้อมูลทั้งหมดออกมาได้ ถึงอย่างนั้น ทั้งสองก็ยังเหมาะกับการเก็บข้อมูลเสริมของออบเจ็กต์ที่โค้ดส่วนอื่นเป็นผู้เก็บและจัดการ

## สรุป

[`WeakMap`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakMap) เป็นคอลเล็กชัน (collection) คล้าย `Map` ที่ใช้ได้เฉพาะออบเจ็กต์หรือ symbol ที่ไม่ได้ลงทะเบียนเป็นคีย์ เมื่อคีย์ไม่สามารถเข้าถึงได้จากที่อื่น ระบบก็เก็บกวาดคีย์และลบข้อมูลที่ผูกกับคีย์ออกจาก `WeakMap` ได้

[`WeakSet`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/WeakSet) เป็นคอลเล็กชันคล้าย `Set` ที่เก็บได้เฉพาะออบเจ็กต์หรือ symbol ที่ไม่ได้ลงทะเบียน เมื่อสมาชิกไม่สามารถเข้าถึงได้จากที่อื่น ระบบก็เก็บกวาดสมาชิกนั้นได้

ข้อดีหลักคือทั้งสองใช้การอ้างอิงแบบอ่อน (weak reference) ซึ่งไม่ทำให้ออบเจ็กต์ต้องอยู่ในหน่วยความจำต่อเพียงเพราะเป็นคีย์หรือสมาชิก ระบบเก็บกวาดหน่วยความจำ (garbage collector) จึงลบออบเจ็กต์ที่ไม่ใช้แล้วได้

ข้อจำกัดคือไม่มี `clear`, `size`, `keys`, `values` และไม่รองรับการวนซ้ำ

เราจึงมักใช้ `WeakMap` และ `WeakSet` เก็บข้อมูลเสริมควบคู่กับโครงสร้างหลักที่เก็บออบเจ็กต์ เมื่อออบเจ็กต์ถูกลบออกจากโครงสร้างหลักและไม่มีการอ้างอิงจากที่อื่นอีก การเป็นคีย์ของ `WeakMap` หรือสมาชิกของ `WeakSet` จะไม่ขัดขวางการเก็บกวาดออบเจ็กต์นั้น
