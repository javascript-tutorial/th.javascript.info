# ตัวเลข

JavaScript มีตัวเลขอยู่สองชนิด:

1. ตัวเลขทั่วไปเก็บด้วยรูปแบบ 64 บิต [IEEE-754](https://en.wikipedia.org/wiki/IEEE_754) หรือที่เรียกว่า "double precision floating point numbers" ตัวเลขที่เราใช้กันเกือบทั้งหมดเป็นชนิดนี้ และบทนี้จะพูดถึงตัวเลขชนิดนี้

2. BigInt ใช้เก็บจำนวนเต็มที่ยาวเท่าไรก็ได้ เราจำเป็นต้องใช้ BigInt ในบางกรณี เพราะตัวเลขทั่วไปเก็บจำนวนเต็มได้อย่างปลอดภัยไม่เกิน <code>(2<sup>53</sup>-1)</code> และไม่น้อยกว่า <code>-(2<sup>53</sup>-1)</code> ตามที่พูดถึงไปแล้วในบท <info:types> เนื่องจาก BigInt ใช้กับงานเฉพาะทางเพียงไม่กี่แบบ เราจึงแยกอธิบายไว้ในบท <info:bigint>

บทนี้จะพาไปรู้จักตัวเลขทั่วไปให้มากขึ้น

## วิธีเขียนตัวเลขแบบอื่น

สมมติว่าต้องเขียนหนึ่งพันล้าน วิธีตรงไปตรงมาคือ:

```js
let billion = 1000000000;
```

เราใช้ขีดล่าง `_` คั่นหลักตัวเลขให้อ่านง่ายขึ้นได้ด้วย:

```js
let billion = 1_000_000_000;
```

ขีดล่าง `_` ช่วยให้เราเขียนตัวเลขให้อ่านง่ายขึ้น รูปแบบที่ช่วยให้เขียนสะดวกโดยไม่เพิ่มความสามารถใหม่แบบนี้เรียกว่า [syntactic sugar](https://en.wikipedia.org/wiki/Syntactic_sugar) เอนจิน JavaScript จะข้าม `_` ที่อยู่ระหว่างหลักตัวเลขไป ค่านี้จึงเท่ากับหนึ่งพันล้านในตัวอย่างก่อนหน้า

เวลาใช้งานจริง เรามักไม่อยากพิมพ์ศูนย์ติดกันยาว ๆ ถ้าเขียนข้อความทั่วไป เราอาจย่อหนึ่งพันล้านเป็น `"1bn"` หรือเจ็ดพันสามร้อยล้านเป็น `"7.3bn"` ตัวเลขขนาดใหญ่อื่นก็คล้ายกัน

ใน JavaScript เราย่อตัวเลขได้ด้วยการเติม `"e"` แล้วตามด้วยจำนวนศูนย์:

```js run
let billion = 1e9;  // หนึ่งพันล้าน หรือ 1 ตามด้วยศูนย์ 9 ตัว

alert( 7.3e9 );  // 7.3 พันล้าน (เท่ากับ 7300000000 หรือ 7_300_000_000)
```

พูดง่าย ๆ คือ `e` จะคูณตัวเลขข้างหน้าด้วย `1` ที่ตามด้วยศูนย์ตามจำนวนที่ระบุ

```js
1e3 === 1 * 1000; // e3 หมายถึง *1000
1.23e6 === 1.23 * 1000000; // e6 หมายถึง *1000000
```

ทีนี้ลองเขียนตัวเลขที่เล็กมากอย่าง 1 ไมโครวินาที หรือหนึ่งในล้านของวินาที:

```js
let mсs = 0.000001;
```

เราใช้ `"e"` เพื่อไม่ต้องพิมพ์ศูนย์ทั้งหมดได้เหมือนกัน:

```js
let mcs = 1e-6; // มีศูนย์ 5 ตัวอยู่ทางซ้ายของ 1
```

จาก `1` ไปเป็น `0.000001` จุดทศนิยมต้องเลื่อนไปทางซ้าย 6 ตำแหน่ง จึงเขียนเป็น `1e-6`

เลขติดลบหลัง `"e"` หมายถึงนำค่าด้านหน้าไปหารด้วย `1` ที่ตามด้วยศูนย์ตามจำนวนที่ระบุ:

```js
// -3 หมายถึงหารด้วย 1 ที่ตามด้วยศูนย์ 3 ตัว
1e-3 === 1 / 1000; // 0.001

// -6 หมายถึงหารด้วย 1 ที่ตามด้วยศูนย์ 6 ตัว
1.23e-6 === 1.23 / 1000000; // 0.00000123

// ตัวอย่างที่เริ่มจากตัวเลขใหญ่ขึ้น
1234e-2 === 1234 / 100; // 12.34 จุดทศนิยมเลื่อนไป 2 ตำแหน่ง
```

### เลขฐานสิบหก ฐานสอง และฐานแปด

[เลขฐานสิบหก](https://en.wikipedia.org/wiki/Hexadecimal) ใช้ใน JavaScript บ่อย ทั้งกับค่าสี การเข้ารหัสอักขระ และงานอื่น ๆ เราจึงเขียนแบบย่อได้โดยใส่ `0x` ไว้หน้าตัวเลข

ตัวอย่างเช่น:

```js run
alert( 0xff ); // 255
alert( 0xFF ); // 255 (เหมือนกัน ตัวพิมพ์เล็กหรือใหญ่ไม่มีผล)
```

เลขฐานสองและฐานแปดพบได้น้อยกว่า แต่ JavaScript ก็รองรับด้วยคำนำหน้า `0b` และ `0o`:


```js run
let a = 0b11111111; // 255 ในรูปเลขฐานสอง
let b = 0o377; // 255 ในรูปเลขฐานแปด

alert( a == b ); // true ทั้งสองฝั่งเป็นเลข 255 เหมือนกัน
```

มีเพียงสามฐานนี้ที่เขียนตรง ๆ ได้แบบนี้ ถ้าต้องใช้เลขฐานอื่น ให้ใช้ฟังก์ชัน `parseInt` ซึ่งเราจะเจอช่วงท้ายบท

## toString(base)

เมธอด `num.toString(base)` จะคืนค่าสตริงที่แทนค่า `num` ในเลขฐาน `base`

ตัวอย่าง:
```js run
let num = 255;

alert( num.toString(16) );  // ff
alert( num.toString(2) );   // 11111111
```

`base` มีค่าได้ตั้งแต่ `2` ถึง `36` ถ้าไม่ระบุจะใช้ฐาน `10`

ฐานที่ใช้กันบ่อยมีดังนี้:

- **base=16** ใช้กับค่าสีแบบเลขฐานสิบหก การเข้ารหัสอักขระ และงานอื่น ๆ หลักของเลขฐานนี้มีตั้งแต่ `0..9` และ `A..F`
- **base=2** มักใช้ตอนดีบักการทำงานของตัวดำเนินการระดับบิต มีหลักเป็น `0` หรือ `1`
- **base=36** เป็นค่าสูงสุด ใช้ตัวเลข `0..9` และตัวอักษร `A..Z` ครบทั้งชุด กรณีที่ดูแปลกแต่ใช้ได้จริงคือการย่อรหัสตัวเลขยาว ๆ เช่น URL แบบสั้น โดยเปลี่ยนตัวเลขนั้นเป็นสตริงฐาน `36`:

    ```js run
    alert( 123456..toString(36) ); // 2n9c
    ```

```warn header="ต้องใช้จุดสองจุดเพื่อเรียกเมธอด"
จุดสองจุดใน `123456..toString(36)` ไม่ได้พิมพ์ผิด ถ้าจะเรียกเมธอดอย่าง `toString` จากตัวเลขโดยตรง ต้องใส่จุดสองจุด `..` หลังตัวเลข

ถ้าเขียนจุดเดียวเป็น `123456.toString(36)` JavaScript จะมองว่าตัวเลขหลังจุดคือส่วนทศนิยม จึงเกิดข้อผิดพลาด เมื่อเพิ่มจุดอีกหนึ่งจุด JavaScript จะรู้ว่าส่วนทศนิยมว่าง และจุดถัดไปใช้เรียกเมธอด

เขียนเป็น `(123456).toString(36)` ก็ได้เช่นกัน

```

## การปัดเศษ

การปัดเศษเป็นงานที่เจอบ่อยมากเมื่อทำงานกับตัวเลข

JavaScript มีฟังก์ชันสำหรับปัดเศษอยู่หลายตัว:

`Math.floor`
: ปัดลง: `3.1` เป็น `3` และ `-1.1` เป็น `-2`

`Math.ceil`
: ปัดขึ้น: `3.1` เป็น `4` และ `-1.1` เป็น `-1`

`Math.round`
: ปัดเป็นจำนวนเต็มที่ใกล้ที่สุด: `3.1` เป็น `3` และ `3.6` เป็น `4` ถ้าอยู่กึ่งกลางพอดี `3.5` จะปัดขึ้นเป็น `4` ส่วน `-3.5` จะปัดขึ้นเป็น `-3`

`Math.trunc` (Internet Explorer ไม่รองรับ)
: ตัดทุกอย่างหลังจุดทศนิยมทิ้งโดยไม่ปัด: `3.1` เป็น `3` และ `-1.1` เป็น `-1`

ตารางนี้ช่วยให้เห็นความต่างชัดขึ้น:

|   | `Math.floor` | `Math.ceil` | `Math.round` | `Math.trunc` |
|---|---------|--------|---------|---------|
|`3.1`|  `3`    |   `4`  |    `3`  |   `3`   |
|`3.5`|  `3`    |   `4`  |    `4`  |   `3`   |
|`3.6`|  `3`    |   `4`  |    `4`  |   `3`   |
|`-1.1`|  `-2`    |   `-1`  |    `-1`  |   `-1`   |
|`-1.5`|  `-2`    |   `-1`  |    `-1`  |   `-1`   |
|`-1.6`|  `-2`    |   `-1`  |    `-2`  |   `-1`   |


ฟังก์ชันเหล่านี้จัดการส่วนทศนิยมได้ครบทุกแบบ แต่ถ้าต้องการปัดให้เหลือทศนิยม `n` ตำแหน่งล่ะ?

สมมติว่ามีค่า `1.2345` และต้องการให้เหลือทศนิยมสองตำแหน่งเป็น `1.23`

ทำได้สองวิธี:

1. คูณ ปัด แล้วหารกลับ

    ถ้าจะปัดให้เหลือทศนิยมสองตำแหน่ง ให้คูณด้วย `100` ก่อน เรียกฟังก์ชันปัดเศษ แล้วหารด้วย `100` เพื่อเลื่อนจุดทศนิยมกลับมา
    ```js run
    let num = 1.23456;

    alert( Math.round(num * 100) / 100 ); // 1.23456 -> 123.456 -> 123 -> 1.23
    ```

2. เมธอด [toFixed(n)](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/toFixed) จะปัดตัวเลขให้เหลือ `n` ตำแหน่งหลังจุดทศนิยม แล้วคืนผลลัพธ์เป็นสตริง

    ```js run
    let num = 12.34;
    alert( num.toFixed(1) ); // "12.3"
    ```

    เมธอดนี้ปัดขึ้นหรือลงไปหาค่าที่ใกล้ที่สุดคล้าย `Math.round`:

    ```js run
    let num = 12.36;
    alert( num.toFixed(1) ); // "12.4"
    ```

    จุดสำคัญคือ `toFixed` คืนค่าเป็นสตริง ถ้าส่วนทศนิยมสั้นกว่าที่กำหนด เมธอดจะเติมศูนย์ต่อท้ายให้ครบ:

    ```js run
    let num = 12.34;
    alert( num.toFixed(5) ); // "12.34000" เติมศูนย์ให้ครบ 5 ตำแหน่ง
    ```

    ถ้าต้องการตัวเลข ให้แปลงด้วยเครื่องหมายบวกหน้าเดียวหรือเรียก `Number()` เช่น `+num.toFixed(5)`

## การคำนวณที่คลาดเคลื่อน

ภายใน JavaScript เก็บตัวเลขด้วยรูปแบบ 64 บิต [IEEE-754](https://en.wikipedia.org/wiki/IEEE_754) โดยใช้ 52 บิตเก็บส่วนตัวเลข 11 บิตเก็บตำแหน่งของจุดทศนิยม และอีก 1 บิตเก็บเครื่องหมาย

ถ้าตัวเลขใหญ่เกินกว่าพื้นที่ 64 บิตจะเก็บได้ ค่านั้นจะล้นจนกลายเป็นค่าพิเศษ `Infinity`:

```js run
alert( 1e500 ); // Infinity
```

ปัญหาที่สังเกตยากกว่าแต่เจอบ่อยคือความแม่นยำของตัวเลขหายไปบางส่วน

ลองเดาผลของการเปรียบเทียบนี้:

```js run
alert( 0.1 + 0.2 == 0.3 ); // *!*false*/!*
```

ผลรวมของ `0.1` กับ `0.2` กลับไม่เท่ากับ `0.3`

ถ้าไม่ใช่ `0.3` แล้วค่าจริงเป็นเท่าไร?

```js run
alert( 0.1 + 0.2 ); // 0.30000000000000004
```

ถ้าเว็บขายของรวมสินค้าราคา `$0.10` กับ `$0.20` แล้วยอดกลายเป็น `$0.30000000000000004` คนซื้อคงงงไม่น้อย

สาเหตุอยู่ที่ตัวเลขถูกเก็บในหน่วยความจำเป็นเลขฐานสอง หรือลำดับของบิต `0` กับ `1` เศษส่วนอย่าง `0.1` และ `0.2` ที่เขียนได้สั้น ๆ ในเลขฐานสิบ กลับเป็นเศษส่วนที่ยาวไม่รู้จบเมื่ออยู่ในเลขฐานสอง

```js run
alert(0.1.toString(2)); // 0.0001100110011001100110011001100110011001100110011001101
alert(0.2.toString(2)); // 0.001100110011001100110011001100110011001100110011001101
alert((0.1 + 0.2).toString(2)); // 0.0100110011001100110011001100110011001100110011001101
```

ค่า `0.1` คือหนึ่งส่วนสิบ (`1/10`) ซึ่งเขียนในระบบฐานสิบได้พอดี ลองเทียบกับหนึ่งส่วนสาม (`1/3`) ที่กลายเป็นทศนิยมซ้ำไม่รู้จบอย่าง `0.33333(3)`

ในระบบฐานสิบ การหารด้วยกำลังของ `10` ให้ผลที่เขียนได้พอดี แต่การหารด้วย `3` ทำแบบนั้นไม่ได้ เลขฐานสองก็ใช้หลักเดียวกัน การหารด้วยกำลังของ `2` เขียนได้พอดี แต่ `1/10` จะกลายเป็นเศษส่วนฐานสองที่ยาวไม่รู้จบ

ระบบฐานสองจึงเก็บค่า *0.1 พอดี* หรือ *0.2 พอดี* ไม่ได้ เช่นเดียวกับที่ระบบฐานสิบเขียนหนึ่งส่วนสามเป็นทศนิยมแบบพอดีไม่ได้

รูปแบบ IEEE-754 จัดการข้อจำกัดนี้ด้วยการปัดไปยังค่าที่ใกล้ที่สุด ปกติความคลาดเคลื่อนเล็ก ๆ นี้มองไม่เห็น แต่ค่าที่เก็บอยู่คลาดเคลื่อนจริง

ดูความคลาดเคลื่อนได้ด้วยตัวอย่างนี้:
```js run
alert( 0.1.toFixed(20) ); // 0.10000000000000000555
```

เมื่อบวกตัวเลขสองตัว ความคลาดเคลื่อนของแต่ละตัวก็รวมกันไปด้วย

นี่คือเหตุผลที่ `0.1 + 0.2` ไม่เท่ากับ `0.3` พอดี

```smart header="ไม่ได้เกิดเฉพาะใน JavaScript"
ภาษาโปรแกรมอื่นจำนวนมากก็เจอปัญหาเดียวกัน

PHP, Java, C, Perl และ Ruby ให้ผลแบบเดียวกัน เพราะใช้รูปแบบตัวเลขเดียวกัน
```

เราแก้ปัญหานี้ได้ วิธีที่ไว้ใจได้ที่สุดคือใช้เมธอด [toFixed(n)](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/toFixed) ปัดผลลัพธ์:

```js run
let sum = 0.1 + 0.2;
alert( sum.toFixed(2) ); // "0.30"
```

`toFixed` คืนค่าเป็นสตริงเสมอ และทำให้มีตัวเลขหลังจุดทศนิยมครบสองตำแหน่งพอดี เหมาะกับเว็บขายของที่ต้องแสดงราคา `$0.30` ถ้าต้องการนำผลไปคำนวณต่อ ให้ใช้เครื่องหมายบวกหน้าเดียวแปลงกลับเป็นตัวเลข:

```js run
let sum = 0.1 + 0.2;
alert( +sum.toFixed(2) ); // 0.3
```

อีกทางหนึ่งคือคูณตัวเลขแต่ละตัวด้วย `100` หรือจำนวนที่มากกว่านั้นชั่วคราวเพื่อให้เป็นจำนวนเต็ม คำนวณเสร็จแล้วจึงหารกลับ การคำนวณด้วยจำนวนเต็มช่วยลดความคลาดเคลื่อนได้ แต่ตอนหารก็ยังอาจเกิดความคลาดเคลื่อนขึ้นอีก:

```js run
alert( (0.1 * 10 + 0.2 * 10) / 10 ); // 0.3
alert( (0.28 * 100 + 0.14 * 100) / 100); // 0.4200000000000001
```

วิธีคูณแล้วหารจึงช่วยลดความคลาดเคลื่อน แต่กำจัดไม่ได้ทั้งหมด

บางงานอาจเลี่ยงเศษส่วนด้วยการเก็บราคาเป็นเซนต์แทนดอลลาร์ แต่ถ้าต้องคำนวณส่วนลด 30% เราก็กลับมาเจอเศษส่วนอยู่ดี ในงานจริงจึงแทบเลี่ยงเศษส่วนทั้งหมดไม่ได้ วิธีที่เหมาะกว่าคือปัดเพื่อตัดเลขส่วนเกินเมื่อจำเป็น

````smart header="เรื่องชวนงง"
ลองรันโค้ดนี้:

```js run
// สวัสดี ฉันเป็นตัวเลขที่เพิ่มค่าตัวเองได้
alert( 9999999999999999 ); // แสดง 10000000000000000
```

ปัญหานี้เกิดจากความแม่นยำที่หายไปเหมือนกัน แม้ตัวเลขหนึ่งค่าจะมีพื้นที่ 64 บิต แต่ส่วนที่เก็บตัวเลขมีเพียง 52 บิต ซึ่งไม่พอในกรณีนี้ หลักท้าย ๆ จึงหายไป

JavaScript จะไม่แจ้งข้อผิดพลาด แต่จะพยายามเก็บตัวเลขให้อยู่ในรูปแบบที่กำหนดให้ได้ เพียงแต่รูปแบบนี้มีพื้นที่ไม่พอ
````

```smart header="ศูนย์สองแบบ"
ผลอีกอย่างจากวิธีเก็บตัวเลขภายในคือ JavaScript มีศูนย์สองแบบ ได้แก่ `0` และ `-0`

สาเหตุคือเครื่องหมายบวกหรือลบเก็บด้วยหนึ่งบิต ตัวเลขทุกค่าจึงมีบิตเครื่องหมายได้ทั้งสองแบบ รวมถึงศูนย์ด้วย

ส่วนใหญ่เราจะไม่เห็นความต่าง เพราะตัวดำเนินการต่าง ๆ ออกแบบมาให้ใช้สองค่านี้เหมือนกัน
```

## การตรวจด้วย isFinite และ isNaN

จำค่าตัวเลขพิเศษสองแบบนี้ได้ไหม?

- `Infinity` เป็นค่าพิเศษที่มากกว่าค่าอื่นทุกค่า ส่วน `-Infinity` น้อยกว่าค่าอื่นทุกค่า
- `NaN` ใช้แทนผลลัพธ์ที่ผิดพลาด

ค่าเหล่านี้มีชนิดเป็น `number` แต่ไม่ใช่ตัวเลข "ปกติ" จึงต้องใช้ฟังก์ชันเฉพาะเพื่อตรวจสอบ:


- `isNaN(value)` จะแปลงอาร์กิวเมนต์เป็นตัวเลขก่อน แล้วตรวจว่าผลลัพธ์เป็น `NaN` หรือไม่:

    ```js run
    alert( isNaN(NaN) ); // true
    alert( isNaN("str") ); // true
    ```

    เราเปรียบเทียบด้วย `=== NaN` แทนได้ไหม? ทำไม่ได้ เพราะ `NaN` ไม่เท่ากับค่าใดเลย แม้แต่ตัวมันเอง:

    ```js run
    alert( NaN === NaN ); // false
    ```

- `isFinite(value)` จะแปลงอาร์กิวเมนต์เป็นตัวเลข แล้วคืนค่า `true` เมื่อเป็นตัวเลขปกติที่ไม่ใช่ `NaN/Infinity/-Infinity`:

    ```js run
    alert( isFinite("15") ); // true
    alert( isFinite("str") ); // false เพราะได้ค่าพิเศษ NaN
    alert( isFinite(Infinity) ); // false เพราะเป็นค่าพิเศษ Infinity
    ```

บางครั้งเราใช้ `isFinite` เพื่อตรวจว่าสตริงที่รับมาเป็นตัวเลขปกติหรือไม่:


```js run
let num = +prompt("Enter a number", '');

// เป็น true เว้นแต่จะป้อน Infinity, -Infinity หรือค่าที่ไม่ใช่ตัวเลข
alert( isFinite(num) );
```

สตริงว่างหรือสตริงที่มีแต่ช่องว่างจะถูกมองเป็น `0` เมื่อใช้กับฟังก์ชันเกี่ยวกับตัวเลขทุกตัว รวมถึง `isFinite`

````smart header="`Number.isNaN` และ `Number.isFinite`"
เมธอด [Number.isNaN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/isNaN) และ [Number.isFinite](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/isFinite) เป็นเวอร์ชันที่ "เข้มงวด" กว่าฟังก์ชัน `isNaN` และ `isFinite` เพราะไม่แปลงอาร์กิวเมนต์เป็นตัวเลขอัตโนมัติ แต่จะตรวจชนิด `number` ก่อน

- `Number.isNaN(value)` คืนค่า `true` เมื่ออาร์กิวเมนต์มีชนิดเป็น `number` และมีค่าเป็น `NaN` กรณีอื่นจะคืนค่า `false`

    ```js run
    alert( Number.isNaN(NaN) ); // true
    alert( Number.isNaN("str" / 2) ); // true

    // สังเกตความต่าง:
    alert( Number.isNaN("str") ); // false เพราะ "str" เป็นสตริง ไม่ใช่ตัวเลข
    alert( isNaN("str") ); // true เพราะ isNaN แปลงสตริง "str" เป็นตัวเลขแล้วได้ NaN
    ```

- `Number.isFinite(value)` คืนค่า `true` เมื่ออาร์กิวเมนต์มีชนิดเป็น `number` และไม่ใช่ `NaN/Infinity/-Infinity` กรณีอื่นจะคืนค่า `false`

    ```js run
    alert( Number.isFinite(123) ); // true
    alert( Number.isFinite(Infinity) ); // false
    alert( Number.isFinite(2 / 0) ); // false

    // สังเกตความต่าง:
    alert( Number.isFinite("123") ); // false เพราะ "123" เป็นสตริง ไม่ใช่ตัวเลข
    alert( isFinite("123") ); // true เพราะ isFinite แปลงสตริง "123" เป็นตัวเลข 123
    ```

ถ้ามองที่พฤติกรรม `Number.isNaN` และ `Number.isFinite` จะเข้าใจง่ายและตรงไปตรงมากว่า แต่ในงานจริงมักพบ `isNaN` และ `isFinite` มากกว่าเพราะเขียนสั้นกว่า
````

```smart header="เปรียบเทียบกับ `Object.is`"
JavaScript มีเมธอด `Object.is` สำหรับเปรียบเทียบค่า คล้าย `===` แต่จัดการสองกรณีพิเศษได้ตรงกับค่าภายในมากกว่า:

1. ใช้กับ `NaN` ได้ โดย `Object.is(NaN, NaN) === true`
2. แยก `0` กับ `-0` ออกจากกัน โดย `Object.is(0, -0) === false` ซึ่งตรงกับการเก็บค่าภายใน เพราะบิตเครื่องหมายอาจต่างกันแม้บิตอื่นจะเป็นศูนย์ทั้งหมด

กรณีอื่น `Object.is(a, b)` ให้ผลเหมือน `a === b`

ที่พูดถึง `Object.is` ตรงนี้เพราะสเปค JavaScript ใช้การเปรียบเทียบแบบนี้บ่อย เมื่ออัลกอริทึมภายในต้องตรวจว่าสองค่าเหมือนกันทุกประการ จะใช้ `Object.is` การเปรียบเทียบนี้เรียกในสเปคว่า [SameValue](https://tc39.github.io/ecma262/#sec-samevalue)
```


## parseInt และ parseFloat

การแปลงเป็นตัวเลขด้วยเครื่องหมายบวก `+` หรือ `Number()` ค่อนข้างเข้มงวด ถ้าค่าไม่ได้อยู่ในรูปที่แปลงเป็นตัวเลขได้ทั้งค่า การแปลงจะล้มเหลว:

```js run
alert( +"100px" ); // NaN
```

ข้อยกเว้นมีเพียงช่องว่างที่ต้นหรือท้ายสตริง ซึ่งจะถูกข้ามไป

แต่ค่าที่ใช้จริงมักมีหน่วยติดมาด้วย เช่น `"100px"` หรือ `"12pt"` ใน CSS หลายประเทศยังเขียนสัญลักษณ์สกุลเงินไว้หลังจำนวนเงินอย่าง `"19€"` ซึ่งเราต้องแยกตัวเลขออกมาใช้

งานนี้เหมาะกับ `parseInt` และ `parseFloat`

ฟังก์ชันทั้งสองจะ "อ่าน" ตัวเลขจากสตริงไปจนเจออักขระที่อ่านต่อไม่ได้ แล้วคืนค่าตัวเลขที่อ่านมาได้ `parseInt` คืนเฉพาะส่วนจำนวนเต็ม ส่วน `parseFloat` เก็บส่วนทศนิยมไว้ด้วย:

```js run
alert( parseInt('100px') ); // 100
alert( parseFloat('12.5em') ); // 12.5

alert( parseInt('12.3') ); // 12 คืนเฉพาะส่วนจำนวนเต็ม
alert( parseFloat('12.3.4') ); // 12.3 จุดที่สองทำให้หยุดอ่าน
```

ถ้าอ่านตัวเลขไม่ได้เลย `parseInt/parseFloat` จะคืนค่า `NaN`:

```js run
alert( parseInt('a123') ); // NaN อักขระตัวแรกทำให้หยุดอ่านทันที
```

````smart header="อาร์กิวเมนต์ที่สองของ `parseInt(str, radix)`"
ฟังก์ชัน `parseInt()` รับพารามิเตอร์ตัวที่สองได้ พารามิเตอร์นี้กำหนดฐานของตัวเลข ทำให้ `parseInt` อ่านสตริงที่เป็นเลขฐานสิบหก ฐานสอง หรือฐานอื่นได้:

```js run
alert( parseInt('0xff', 16) ); // 255
alert( parseInt('ff', 16) ); // 255 ไม่ใส่ 0x ก็ได้

alert( parseInt('2n9c', 36) ); // 123456
```
````

## ฟังก์ชันคณิตศาสตร์อื่น

JavaScript มีออบเจ็กต์ [Math](https://developer.mozilla.org/en/docs/Web/JavaScript/Reference/Global_Objects/Math) ซึ่งรวมฟังก์ชันและค่าคงที่ทางคณิตศาสตร์พื้นฐานไว้ให้แล้ว

ตัวอย่างเช่น:

`Math.random()`
: คืนค่าตัวเลขสุ่มตั้งแต่ 0 ถึง 1 โดยไม่รวม 1

    ```js run
    alert( Math.random() ); // 0.1234567894322
    alert( Math.random() ); // 0.5435252343232
    alert( Math.random() ); // ... (ตัวเลขสุ่มค่าใดก็ได้)
    ```

`Math.max(a, b, c...)` และ `Math.min(a, b, c...)`
: คืนค่าที่มากที่สุดและน้อยที่สุดจากอาร์กิวเมนต์จำนวนเท่าไรก็ได้

    ```js run
    alert( Math.max(3, 5, -10, 0, 1) ); // 5
    alert( Math.min(1, 2) ); // 1
    ```

`Math.pow(n, power)`
: คืนค่า `n` ยกกำลังตามค่าที่กำหนด

    ```js run
    alert( Math.pow(2, 10) ); // 2 ยกกำลัง 10 = 1024
    ```

ออบเจ็กต์ `Math` ยังมีฟังก์ชันและค่าคงที่อื่น รวมถึงฟังก์ชันตรีโกณมิติ ดูทั้งหมดได้ใน [เอกสารของออบเจ็กต์ Math](https://developer.mozilla.org/en/docs/Web/JavaScript/Reference/Global_Objects/Math)

## สรุป

เมื่อต้องเขียนตัวเลขที่มีศูนย์หลายตัว:

- เติม `"e"` และจำนวนศูนย์ต่อท้าย เช่น `123e6` เท่ากับ `123` ที่ตามด้วยศูนย์ 6 ตัว หรือ `123000000`
- เลขติดลบหลัง `"e"` หมายถึงนำค่าด้านหน้าไปหารด้วย `1` ที่ตามด้วยศูนย์ตามจำนวนนั้น เช่น `123e-6` คือ `0.000123` หรือ 123 ส่วนในหนึ่งล้าน

เมื่อต้องใช้เลขฐานอื่น:

- เขียนเลขฐานสิบหก (`0x`) ฐานแปด (`0o`) และฐานสอง (`0b`) ได้โดยตรง
- `parseInt(str, base)` อ่านสตริง `str` เป็นจำนวนเต็มในเลขฐาน `base` โดย `2 ≤ base ≤ 36`
- `num.toString(base)` แปลงตัวเลขเป็นสตริงในเลขฐาน `base`

เมื่อต้องตรวจค่าตัวเลขทั่วไป:

- `isNaN(value)` แปลงอาร์กิวเมนต์เป็นตัวเลข แล้วตรวจว่าเป็น `NaN` หรือไม่
- `Number.isNaN(value)` ตรวจว่าอาร์กิวเมนต์มีชนิดเป็น `number` และมีค่าเป็น `NaN` หรือไม่
- `isFinite(value)` แปลงอาร์กิวเมนต์เป็นตัวเลข แล้วตรวจว่าไม่ใช่ `NaN/Infinity/-Infinity`
- `Number.isFinite(value)` ตรวจว่าอาร์กิวเมนต์มีชนิดเป็น `number` และไม่ใช่ `NaN/Infinity/-Infinity`

เมื่อต้องแปลงค่าอย่าง `12pt` หรือ `100px` เป็นตัวเลข:

- ใช้ `parseInt/parseFloat` แปลงแบบยืดหยุ่น ฟังก์ชันจะอ่านตัวเลขจากต้นสตริง แล้วคืนค่าที่อ่านได้ก่อนเจออักขระที่อ่านต่อไม่ได้

เมื่อทำงานกับเศษส่วน:

- ปัดเศษด้วย `Math.floor`, `Math.ceil`, `Math.trunc`, `Math.round` หรือ `num.toFixed(precision)`
- จำไว้เสมอว่าการคำนวณเศษส่วนอาจสูญเสียความแม่นยำ

เมื่อต้องใช้ฟังก์ชันคณิตศาสตร์อื่น:

- ลองดูออบเจ็กต์ [Math](https://developer.mozilla.org/en/docs/Web/JavaScript/Reference/Global_Objects/Math) แม้จะเป็นไลบรารีขนาดเล็ก แต่ครอบคลุมงานพื้นฐานได้
