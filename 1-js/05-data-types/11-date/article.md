# วันที่และเวลา

JavaScript มีออบเจ็กต์ (object) [Date](mdn:js/Date) สำหรับเก็บวันที่และเวลา พร้อมเมธอด (method) ที่ใช้จัดการข้อมูลเหล่านี้

เราใช้ `Date` บันทึกเวลาที่สร้างหรือแก้ไขไฟล์ วัดเวลาที่ใช้ทำงาน หรือแสดงวันที่ปัจจุบันได้

## การสร้างออบเจ็กต์ Date

สร้างออบเจ็กต์ `Date` ด้วย `new Date()` โดยเลือกส่งอาร์กิวเมนต์ (argument) ตามรูปแบบต่อไปนี้:

`new Date()`
: เมื่อไม่ส่งอาร์กิวเมนต์ จะสร้างออบเจ็กต์ `Date` ที่เก็บวันที่และเวลาปัจจุบัน:

    ```js run
    let now = new Date();
    alert( now ); // แสดงวันที่/เวลาปัจจุบัน
    ```

`new Date(milliseconds)`
: สร้างออบเจ็กต์ `Date` โดยกำหนดเวลาจากจำนวนมิลลิวินาที (1/1000 ของวินาที) ที่ผ่านมานับตั้งแต่วันที่ 1 มกราคม 1970 UTC+0

    ```js run
    // 0 หมายถึง 01.01.1970 UTC+0
    let Jan01_1970 = new Date(0);
    alert( Jan01_1970 );

    // เพิ่ม 24 ชั่วโมง ได้ 02.01.1970 UTC+0
    let Jan02_1970 = new Date(24 * 3600 * 1000);
    alert( Jan02_1970 );
    ```

    จำนวนเต็มที่บอกว่าผ่านมากี่มิลลิวินาทีนับจากต้นปี 1970 ตามเวลา UTC+0 เรียกว่า *timestamp*

    timestamp ใช้ตัวเลขเพียงค่าเดียวแทนวันที่และเวลา เราสร้างออบเจ็กต์ `Date` จาก timestamp ได้ด้วย `new Date(timestamp)` และแปลงกลับเป็น timestamp ได้ด้วยเมธอด `date.getTime()` ซึ่งจะอธิบายในหัวข้อถัดไป

    วันที่ก่อน 01.01.1970 จะมี timestamp เป็นค่าลบ เช่น:
    ```js run
    // 31 ธ.ค. 1969
    let Dec31_1969 = new Date(-24 * 3600 * 1000);
    alert( Dec31_1969 );
    ```

`new Date(datestring)`
: ถ้าส่งอาร์กิวเมนต์เพียงตัวเดียวที่เป็นสตริง (string) `Date` จะอ่านวันที่และเวลาจากข้อความนั้นโดยอัตโนมัติ ด้วยวิธีเดียวกับ `Date.parse` ที่เราจะเรียนกันช่วงท้ายบท

    ```js run
    let date = new Date("2017-01-26");
    alert(date);
    // ไม่ได้กำหนดเวลา ระบบจึงถือว่าเป็นเที่ยงคืน GMT และ
    // ปรับตามเขตเวลาที่รันโค้ดอยู่
    // ผลลัพธ์อาจเป็น
    // Thu Jan 26 2017 11:00:00 GMT+1100 (Australian Eastern Daylight Time)
    // หรือ
    // Wed Jan 25 2017 16:00:00 GMT-0800 (Pacific Standard Time)
    ```

`new Date(year, month, date, hours, minutes, seconds, ms)`
: สร้างวันที่และเวลาจากค่าปี เดือน วัน และเวลาที่ระบุ โดยใช้เขตเวลาท้องถิ่น (local time zone) ของเครื่องที่รันโค้ด ต้องส่งอาร์กิวเมนต์สองตัวแรกเสมอ ส่วนที่เหลือละไว้ได้

    - `year` ควรระบุปีเป็นเลข 4 หลัก รูปแบบนี้ยังรับปีแบบ 2 หลักเพื่อรองรับโค้ดเก่า โดยถือว่าเป็นปี `19xx` เช่น `98` หมายถึง `1998` แต่ควรใช้ปีแบบ 4 หลักเสมอ
    - `month` เริ่มนับจาก `0` (ม.ค.) ไปถึง `11` (ธ.ค.)
    - พารามิเตอร์ (parameter) `date` คือวันที่ในเดือน ถ้าไม่ระบุจะใช้ค่า `1`
    - ถ้าไม่ระบุ `hours/minutes/seconds/ms` จะมีค่าเป็น `0`

    ตัวอย่าง:

    ```js
    new Date(2011, 0, 1, 0, 0, 0, 0); // 1 ม.ค. 2011, 00:00:00
    new Date(2011, 0, 1); // เหมือนกัน ค่า hours เป็นต้นจะเป็น 0 โดยค่าเริ่มต้น
    ```

    ความละเอียดสูงสุดคือ 1 ms (1/1000 วินาที):

    ```js run
    let date = new Date(2011, 0, 1, 2, 3, 4, 567);
    alert( date ); // เก็บเวลา 02:03:04.567 แต่ข้อความที่แสดงไม่รวมมิลลิวินาที
    ```

## การอ่านค่าปี เดือน วัน และเวลา

เราสามารถอ่านค่าปี เดือน วัน และเวลาแต่ละส่วนจากออบเจ็กต์ `Date` ได้ด้วยเมธอดต่อไปนี้:

[getFullYear()](mdn:js/Date/getFullYear)
: คืนค่าปีแบบเต็ม (4 หลัก)

[getMonth()](mdn:js/Date/getMonth)
: คืนค่าเดือน **ตั้งแต่ 0 ถึง 11**

[getDate()](mdn:js/Date/getDate)
: คืนค่าวันที่ในเดือน ตั้งแต่ 1 ถึง 31 แม้ชื่อจะเป็น `getDate()` แต่ค่าที่ได้คือวันที่ในเดือนเท่านั้น

[getHours()](mdn:js/Date/getHours), [getMinutes()](mdn:js/Date/getMinutes), [getSeconds()](mdn:js/Date/getSeconds), [getMilliseconds()](mdn:js/Date/getMilliseconds)
: คืนค่าชั่วโมง นาที วินาที และมิลลิวินาทีตามลำดับ

```warn header="ไม่ใช่ `getYear()` แต่ใช้ `getFullYear()`"
`getYear()` เป็นเมธอดเก่าที่ไม่แนะนำให้ใช้แล้ว (deprecated) เมธอดนี้คืนค่าปีตามเวลาท้องถิ่นลบด้วย 1900 จึงไม่ได้คืนค่าปีแบบเต็ม ให้ใช้ `getFullYear()` แทน
```

ถ้าต้องการรู้ว่าเป็นวันอะไรในสัปดาห์ ให้ใช้เมธอดนี้:

[getDay()](mdn:js/Date/getDay)
: คืนค่าวันในสัปดาห์ ตั้งแต่ `0` (วันอาทิตย์) ถึง `6` (วันเสาร์) เมธอดนี้นับวันอาทิตย์เป็นวันแรกเสมอ และเปลี่ยนวิธีนับตามประเทศไม่ได้

**เมธอดทั้งหมดข้างต้นคืนค่าตามเขตเวลาท้องถิ่นของเครื่องที่รันโค้ด**

เมธอดเหล่านี้มีแบบที่อ่านค่าตามเวลา UTC+0 ด้วย เช่น [getUTCFullYear()](mdn:js/Date/getUTCFullYear), [getUTCMonth()](mdn:js/Date/getUTCMonth) และ [getUTCDay()](mdn:js/Date/getUTCDay) ชื่อเมธอดจะมี `"UTC"` ต่อจาก `"get"`

ถ้าชั่วโมงตามเขตเวลาท้องถิ่นต่างจาก UTC โค้ดด้านล่างจะแสดงให้เห็นความต่างนั้น:

```js run
// วันที่ปัจจุบัน
let date = new Date();

// ชั่วโมงในเขตเวลาปัจจุบัน
alert( date.getHours() );

// ชั่วโมงในเขตเวลา UTC+0 (เวลาลอนดอนในช่วงที่ไม่ใช้เวลาออมแสง)
alert( date.getUTCHours() );
```

ส่วนอีกสองเมธอดต่อไปนี้ไม่มีแบบ UTC แยกต่างหาก:

[getTime()](mdn:js/Date/getTime)
: คืนค่า timestamp ของวันที่นั้น ซึ่งเป็นจำนวนมิลลิวินาทีที่ผ่านมานับจากวันที่ 1 มกราคม 1970 UTC+0

[getTimezoneOffset()](mdn:js/Date/getTimezoneOffset)
: คืนค่าความต่างระหว่าง UTC กับเขตเวลาท้องถิ่น เป็นหน่วยนาที:

    ```js run
    // ถ้าอยู่ในเขตเวลา UTC-1 จะแสดง 60
    // ถ้าอยู่ในเขตเวลา UTC+3 จะแสดง -180
    alert( new Date().getTimezoneOffset() );

    ```

## การกำหนดค่าปี เดือน วัน และเวลา

เมธอดต่อไปนี้ใช้กำหนดวันที่และเวลาแต่ละส่วน:

- [`setFullYear(year, [month], [date])`](mdn:js/Date/setFullYear)
- [`setMonth(month, [date])`](mdn:js/Date/setMonth)
- [`setDate(date)`](mdn:js/Date/setDate)
- [`setHours(hour, [min], [sec], [ms])`](mdn:js/Date/setHours)
- [`setMinutes(min, [sec], [ms])`](mdn:js/Date/setMinutes)
- [`setSeconds(sec, [ms])`](mdn:js/Date/setSeconds)
- [`setMilliseconds(ms)`](mdn:js/Date/setMilliseconds)
- [`setTime(milliseconds)`](mdn:js/Date/setTime) (กำหนดวันที่และเวลาด้วยจำนวนมิลลิวินาทีนับจากวันที่ 1 มกราคม 1970 UTC)

ทุกเมธอดยกเว้น `setTime()` มีแบบ UTC เช่น `setUTCHours()`

บางเมธอดกำหนดหลายค่าพร้อมกันได้ เช่น `setHours` กำหนดได้ทั้งชั่วโมง นาที วินาที และมิลลิวินาที ส่วนค่าที่ไม่ได้ระบุจะยังคงเดิม

ตัวอย่าง:

```js run
let today = new Date();

today.setHours(0);
alert(today); // ยังเป็นวันนี้อยู่ แต่ชั่วโมงเปลี่ยนเป็น 0

today.setHours(0, 0, 0, 0);
alert(today); // ยังเป็นวันนี้อยู่ แต่ตอนนี้เป็น 00:00:00 พอดี
```

## การปรับวันที่อัตโนมัติ

ออบเจ็กต์ `Date` มี *การปรับวันที่อัตโนมัติ (autocorrection)* เมื่อเรากำหนดค่าที่เกินช่วงปกติ `Date` จะปรับส่วนอื่นให้สัมพันธ์กันเอง

ตัวอย่าง:

```js run
let date = new Date(2013, 0, *!*32*/!*); // 32 ม.ค. 2013 ?!?
alert(date); // ...กลายเป็น 1 ก.พ. 2013!
```

ในตัวอย่างนี้ เดือนมกราคมมี 31 วัน เมื่อกำหนดวันที่เป็น 32 `Date` จึงเลื่อนไปเป็นวันที่ 1 ของเดือนถัดไป

ถ้าจะบวก 2 วันให้วันที่ 28 กุมภาพันธ์ เราต้องรู้ก่อนว่าปีนั้นมีวันที่ 29 กุมภาพันธ์หรือไม่ ปีที่มีวันนี้เรียกว่าปีอธิกสุรทิน (leap year) ผลจึงอาจเป็นวันที่ 1 หรือ 2 มีนาคม แต่เมื่อใช้ `Date` เราบวก 2 วันได้เลยโดยไม่ต้องตรวจเอง ลองดูวันที่ 28 กุมภาพันธ์ 2016 ในตัวอย่างนี้:

```js run
let date = new Date(2016, 1, 28);
*!*
date.setDate(date.getDate() + 2);
*/!*

alert( date ); // 1 มี.ค. 2016
```

เราใช้การปรับวันที่อัตโนมัติเพื่อหาวันที่และเวลาหลังจากผ่านไปช่วงหนึ่งได้ เช่น อีก 70 วินาทีจะเป็นเวลาใด:

```js run
let date = new Date();
date.setSeconds(date.getSeconds() + 70);

alert( date ); // แสดงวันที่ที่ถูกต้อง
```

กำหนดค่าศูนย์หรือค่าลบก็ได้เช่นกัน:

```js run
let date = new Date(2016, 0, 2); // 2 ม.ค. 2016

date.setDate(1); // กำหนดเป็นวันที่ 1 ของเดือน
alert( date );

date.setDate(0); // วันที่น้อยสุดคือ 1 ระบบจึงถือว่าเป็นวันสุดท้ายของเดือนก่อนหน้า
alert( date ); // 31 ธ.ค. 2015
```

## การแปลงวันที่เป็นตัวเลขและการลบวันที่

เมื่อแปลงออบเจ็กต์ `Date` เป็นตัวเลข จะได้ timestamp ค่าเดียวกับที่ `date.getTime()` คืนมา:

```js run
let date = new Date();
alert(+date); // จำนวนมิลลิวินาที เหมือนกับ date.getTime()
```

ด้วยเหตุนี้ เราจึงนำออบเจ็กต์ `Date` สองตัวมาลบกันได้ ผลที่ได้คือระยะเวลาระหว่างสองวันนั้นในหน่วยมิลลิวินาที

ลองใช้วิธีนี้วัดเวลาที่โค้ดทำงาน โดยบันทึกเวลาก่อนและหลัง แล้วนำมาลบกัน:

```js run
let start = new Date(); // เริ่มจับเวลา

// ทำงานบางอย่าง
for (let i = 0; i < 100000; i++) {
  let doSomething = i * i * i;
}

let end = new Date(); // หยุดจับเวลา

alert( `The loop took ${end - start} ms` );
```

## Date.now()

ถ้าต้องการแค่วัดเวลาที่ใช้ทำงาน เราใช้ timestamp ได้โดยไม่ต้องสร้างออบเจ็กต์ `Date`

เมธอด `Date.now()` คืนค่า timestamp ของเวลาปัจจุบันโดยตรง

ให้ค่าเวลาในรูปแบบเดียวกับ `new Date().getTime()` โดยไม่ต้องสร้างออบเจ็กต์ `Date` ชั่วคราว จึงไม่มีออบเจ็กต์ตัวกลางที่ต้องให้ระบบเก็บคืนหน่วยความจำ (garbage collection) จัดการภายหลัง

จึงนิยมใช้เพื่อความสะดวก หรือในงานที่ต้องคำนึงถึงความเร็ว เช่น เกมที่เขียนด้วย JavaScript และโปรแกรมเฉพาะทาง

ตัวอย่างก่อนหน้าจึงเปลี่ยนมาใช้ `Date.now()` ได้ดังนี้:

```js run
*!*
let start = Date.now(); // นับมิลลิวินาทีตั้งแต่ 1 ม.ค. 1970
*/!*

// ทำงานบางอย่าง
for (let i = 0; i < 100000; i++) {
  let doSomething = i * i * i;
}

*!*
let end = Date.now(); // เสร็จแล้ว
*/!*

alert( `The loop took ${end - start} ms` ); // ลบค่า timestamp ที่เป็นตัวเลข
```

## การวัดประสิทธิภาพ (benchmarking)

การวัดว่าฟังก์ชัน (function) ทำงานเร็วแค่ไหนต้องทำอย่างระมัดระวัง โดยเฉพาะฟังก์ชันที่ใช้เวลาประมวลผลของ CPU มาก

ลองเปรียบเทียบฟังก์ชันสองตัวที่คำนวณระยะเวลาระหว่างวันที่สองวัน เพื่อดูว่าตัวไหนเร็วกว่า การทดสอบวัดประสิทธิภาพแบบนี้เรียกว่า "benchmark"

```js
// มี date1 และ date2 ฟังก์ชันไหนคืนค่าความต่างในหน่วย ms ได้เร็วกว่า?
function diffSubtract(date1, date2) {
  return date2 - date1;
}

// หรือ
function diffGetTime(date1, date2) {
  return date2.getTime() - date1.getTime();
}
```

ทั้งสองฟังก์ชันให้ผลลัพธ์เดียวกัน ต่างกันที่ `diffGetTime` เรียก `date.getTime()` เพื่ออ่านค่ามิลลิวินาทีโดยตรง ส่วน `diffSubtract` อาศัยการแปลงวันที่เป็นตัวเลขขณะลบ

แล้วฟังก์ชันไหนเร็วกว่ากัน?

วิธีแรกที่นึกถึงคือเรียกแต่ละฟังก์ชันซ้ำหลาย ๆ ครั้งแล้ววัดเวลารวม ฟังก์ชันในตัวอย่างทำงานเพียงเล็กน้อย เราจึงจะเรียกอย่างน้อย 100,000 ครั้งเพื่อให้วัดเวลาได้

ลองวัดเวลาดู:

```js run
function diffSubtract(date1, date2) {
  return date2 - date1;
}

function diffGetTime(date1, date2) {
  return date2.getTime() - date1.getTime();
}

function bench(f) {
  let date1 = new Date(0);
  let date2 = new Date();

  let start = Date.now();
  for (let i = 0; i < 100000; i++) f(date1, date2);
  return Date.now() - start;
}

alert( 'Time of diffSubtract: ' + bench(diffSubtract) + 'ms' );
alert( 'Time of diffGetTime: ' + bench(diffGetTime) + 'ms' );
```

`getTime()` อ่านค่ามิลลิวินาทีออกมาโดยตรง จึงไม่ต้องแปลงออบเจ็กต์วันที่เป็นตัวเลขขณะลบ แต่ความเร็วที่วัดได้ขึ้นอยู่กับกลไกที่รัน JavaScript หรือ JavaScript engine และสภาพแวดล้อมที่ใช้ทดสอบ

เราได้ตัวเลขมาแล้ว แต่การวัดเพียงเท่านี้ยังสรุปผลได้ไม่ดีนัก

สมมติว่าขณะรัน `bench(diffSubtract)` CPU ต้องแบ่งเวลาไปทำงานอื่นด้วย แต่พอถึงรอบของ `bench(diffGetTime)` งานอื่นนั้นเสร็จพอดี เหตุการณ์แบบนี้เกิดขึ้นได้ในระบบปฏิบัติการที่รันหลายโปรแกรมพร้อมกัน

ฟังก์ชันแรกจึงได้ใช้ CPU น้อยกว่าฟังก์ชันที่สอง ตัวเลขที่วัดได้อาจทำให้เราเข้าใจผิดว่าความต่างทั้งหมดมาจากโค้ด

**เพื่อให้ผลน่าเชื่อถือขึ้น ควรรัน benchmark ทั้งชุดซ้ำหลายรอบ โดยสลับวัดทั้งสองฟังก์ชันในแต่ละรอบ**

ตัวอย่าง:

```js run
function diffSubtract(date1, date2) {
  return date2 - date1;
}

function diffGetTime(date1, date2) {
  return date2.getTime() - date1.getTime();
}

function bench(f) {
  let date1 = new Date(0);
  let date2 = new Date();

  let start = Date.now();
  for (let i = 0; i < 100000; i++) f(date1, date2);
  return Date.now() - start;
}

let time1 = 0;
let time2 = 0;

*!*
// รัน bench(diffSubtract) และ bench(diffGetTime) สลับกัน 10 รอบ
for (let i = 0; i < 10; i++) {
  time1 += bench(diffSubtract);
  time2 += bench(diffGetTime);
}
*/!*

alert( 'Total time for diffSubtract: ' + time1 );
alert( 'Total time for diffGetTime: ' + time2 );
```

JavaScript engine จะใช้การปรับโค้ดให้ทำงานเร็วขึ้นแบบซับซ้อนกับโค้ดที่ทำงานซ้ำบ่อย ๆ ซึ่งเรียกว่า "hot code" เพราะไม่จำเป็นต้องเสียเวลาปรับโค้ดที่แทบไม่ได้รัน การเรียกฟังก์ชันในช่วงแรกจึงอาจยังไม่เร็วเท่าช่วงหลัง เราอาจเพิ่มรอบ "อุ่นเครื่อง" ก่อนเริ่มวัดเวลาจริง:

```js
// อุ่นเครื่องก่อนเข้าลูปหลัก
bench(diffSubtract);
bench(diffGetTime);

// เริ่ม benchmark จริง
for (let i = 0; i < 10; i++) {
  time1 += bench(diffSubtract);
  time2 += bench(diffGetTime);
}
```

```warn header="ระวังการทำ microbenchmarking"
การวัดโค้ดส่วนเล็กมาก ๆ เช่น ตัวดำเนินการ (operator) หรือฟังก์ชันที่ JavaScript มีให้ เรียกว่า microbenchmarking เราต้องระวังว่ากลไกปรับความเร็วของ JavaScript engine อาจทำให้โค้ดทดสอบให้ผลต่างจากการใช้งานจริง ถ้าต้องการเข้าใจเรื่องประสิทธิภาพอย่างจริงจัง ควรศึกษาการทำงานของ engine ด้วย เมื่อเข้าใจแล้ว เราอาจไม่ต้องพึ่ง microbenchmark เลย

มีบทความอธิบายการทำงานของ V8 ที่ <https://mrale.ph>
```

## การอ่านวันที่จากสตริงด้วย Date.parse

เมธอด [Date.parse(str)](mdn:js/Date/parse) ใช้อ่านวันที่และเวลาจากสตริง

สตริงควรอยู่ในรูปแบบ `YYYY-MM-DDTHH:mm:ss.sssZ` โดยแต่ละส่วนมีความหมายดังนี้:

- `YYYY-MM-DD` คือวันที่ เรียงเป็นปี เดือน และวัน
- อักขระ `"T"` ใช้เป็นตัวคั่น
- `HH:mm:ss.sss` คือเวลา เรียงเป็นชั่วโมง นาที วินาที และมิลลิวินาที
- ส่วน `'Z'` ใช้ระบุเขตเวลาและละไว้ได้ โดยเขียนเป็นผลต่างจาก UTC ในรูปแบบ `+-hh:mm` หรือใช้ตัวอักษร `Z` ตัวเดียวเพื่อระบุ UTC+0

ใช้รูปแบบย่อได้ด้วย เช่น `YYYY-MM-DD`, `YYYY-MM` หรือ `YYYY`

`Date.parse(str)` อ่านสตริงแล้วคืนค่า timestamp ซึ่งเป็นจำนวนมิลลิวินาทีนับจากวันที่ 1 มกราคม 1970 UTC+0 ถ้าอ่านวันที่จากสตริงนั้นไม่ได้ จะคืนค่า `NaN` บางสภาพแวดล้อมยังยอมรับรูปแบบอื่นด้วย แต่ผลอาจต่างกัน จึงควรใช้รูปแบบมาตรฐานข้างต้น

ตัวอย่าง:

```js run
let ms = Date.parse('2012-01-26T13:51:50.417-07:00');

alert(ms); // 1327611110417  (timestamp)
```

นำ timestamp ที่ได้ไปสร้างออบเจ็กต์ `Date` ได้ทันที:

```js run
let date = new Date( Date.parse('2012-01-26T13:51:50.417-07:00') );

alert(date);
```

## สรุป

- ออบเจ็กต์ [Date](mdn:js/Date) เก็บทั้งวันที่และเวลาเสมอ เราจึงใช้ `Date` สร้างค่าที่มีเฉพาะวันที่หรือเฉพาะเวลาไม่ได้
- เดือนเริ่มนับจาก `0` ซึ่งหมายถึงเดือนมกราคม
- `getDay()` คืนค่าวันในสัปดาห์โดยเริ่มจาก `0` ซึ่งหมายถึงวันอาทิตย์
- `Date` ปรับวันที่อัตโนมัติเมื่อกำหนดค่าเกินช่วงปกติ จึงช่วยให้บวกหรือลบวัน เดือน และชั่วโมงได้สะดวก
- เราลบวันที่สองวันเพื่อหาระยะห่างเป็นมิลลิวินาทีได้ เพราะออบเจ็กต์ `Date` จะแปลงเป็น timestamp เมื่อใช้เป็นตัวเลข
- ใช้ `Date.now()` เพื่ออ่าน timestamp ปัจจุบันโดยไม่ต้องสร้างออบเจ็กต์ `Date`

timestamp ใน JavaScript ใช้หน่วยมิลลิวินาที ต่างจากอีกหลายระบบที่ใช้หน่วยวินาที

ถ้าต้องการวัดเวลาให้ละเอียดกว่าที่ `Date` รองรับ ให้ใช้ API ของสภาพแวดล้อมที่รันโค้ด เช่น ในหน้าเว็บมี [performance.now()](mdn:api/Performance/now) ที่คืนค่ามิลลิวินาทีที่ผ่านมานับจากจุดเริ่มต้นอ้างอิง `performance.timeOrigin` ค่านี้มีเศษของมิลลิวินาทีได้ แต่เบราว์เซอร์อาจลดความละเอียดเพื่อปกป้องความเป็นส่วนตัว จึงไม่ได้รับประกันความละเอียดถึง 1 ไมโครวินาที (หนึ่งในล้านของวินาที) เสมอไป:

```js run
alert(`Loading started ${performance.now()}ms ago`);
// ตัวอย่างข้อความ: "Loading started 34731.26000000001ms ago"
// 0.26 มิลลิวินาทีเท่ากับ 260 ไมโครวินาที
// จำนวนหลักทศนิยมที่แสดงไม่ได้บอกความละเอียดจริงของการวัด
```

Node.js มีวิธีวัดเวลาที่ละเอียดกว่า `Date` เช่น `process.hrtime.bigint()` ซึ่งคืนค่าเวลาในหน่วยนาโนวินาที วิธีวัดเวลาเหล่านี้เป็นความสามารถของสภาพแวดล้อมที่รัน JavaScript และแยกจากออบเจ็กต์ `Date`
