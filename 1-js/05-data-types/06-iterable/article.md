
# ข้อมูลที่วนซ้ำได้ (iterable)

ออบเจ็กต์ (object) ที่ใช้ในลูป (loop) `for..of` ได้เรียกว่า *iterable* แนวคิดนี้ขยายการวนซ้ำจากอาร์เรย์ (array) ไปสู่ออบเจ็กต์ชนิดอื่นได้ด้วย

อาร์เรย์เป็น iterable อยู่แล้ว และ JavaScript ยังมีค่าอีกหลายชนิดที่เป็น iterable ในตัว เช่น สตริง (string)

ถ้าเรามีออบเจ็กต์ที่แทนกลุ่มข้อมูล เช่น รายการหรือเซต (set) แม้จะไม่ใช่อาร์เรย์ เราก็อาจอยากใช้ `for..of` วนผ่านข้อมูลเหล่านั้น มาดูกันว่าจะทำให้ออบเจ็กต์ใช้กับลูปนี้ได้อย่างไร


## Symbol.iterator

ลองสร้าง iterable ขึ้นมาเองเพื่อดูว่ามันทำงานอย่างไร

เริ่มจากออบเจ็กต์ที่ไม่ใช่อาร์เรย์ แต่มีข้อมูลที่เราอยากวนผ่านด้วย `for..of`

ตัวอย่างเช่น ออบเจ็กต์ `range` ที่แทนช่วงของตัวเลขดังนี้:

```js
let range = {
  from: 1,
  to: 5
};

// เราอยากให้ for..of ทำงานได้:
// for(let num of range) ... num=1,2,3,4,5
```

การทำให้ `range` เป็น iterable ต้องเพิ่มเมธอด (method) ที่ใช้ `Symbol.iterator` เป็นชื่อ โดย `Symbol.iterator` เป็น symbol ที่ JavaScript กำหนดไว้สำหรับการวนซ้ำโดยเฉพาะ ลูป `for..of` จะทำงานตามขั้นตอนต่อไปนี้:

1. เมื่อ `for..of` เริ่มทำงาน จะเรียกเมธอดนี้หนึ่งครั้ง ถ้าไม่พบจะเกิดข้อผิดพลาด เมธอดนี้ต้องคืนค่าเป็น *iterator* ซึ่งก็คือออบเจ็กต์ที่มีเมธอด `next`
2. จากนั้น `for..of` จะขอค่าที่ใช้วนซ้ำ *จาก iterator ที่ได้กลับมาเท่านั้น*
3. ทุกครั้งที่ต้องการค่าถัดไป `for..of` จะเรียก `next()` ของ iterator
4. `next()` ต้องคืนค่าเป็นออบเจ็กต์ โดยทั่วไปเขียนในรูป `{done: Boolean, value: any}` ถ้า `done=true` หมายถึงการวนซ้ำสิ้นสุดแล้ว หากยังไม่สิ้นสุด `value` คือค่าที่ลูปนำไปใช้ในรอบนั้น ไม่จำเป็นต้องมีทั้งสองพร็อพเพอร์ตี้ (property) เสมอไป ถ้าไม่ระบุ `done` จะถือว่าเป็น `false` และถ้าไม่ระบุ `value` จะได้ค่า `undefined`

เมื่อนำขั้นตอนเหล่านี้มาเขียนเป็นโค้ด `range` จะเป็นดังนี้:

```js run
let range = {
  from: 1,
  to: 5
};

// 1. การเรียก for..of ครั้งแรกจะเรียกฟังก์ชันนี้
range[Symbol.iterator] = function() {

  // ...ซึ่งคืนค่าเป็นออบเจ็กต์ iterator:
  // 2. จากนั้น for..of จะทำงานกับออบเจ็กต์ iterator ด้านล่างเท่านั้น โดยขอค่าถัดไปจากมัน
  return {
    current: this.from,
    last: this.to,

    // 3. next() จะถูกเรียกในแต่ละรอบของ for..of loop
    next() {
      // 4. ต้องคืนค่าในรูปออบเจ็กต์ {done:.., value :...}
      if (this.current <= this.last) {
        return { done: false, value: this.current++ };
      } else {
        return { done: true };
      }
    }
  };
};

// ตอนนี้ใช้งานได้แล้ว!
for (let num of range) {
  alert(num); // 1, แล้วก็ 2, 3, 4, 5
}
```

ในตัวอย่างนี้ `range` กับ iterator ทำหน้าที่แยกกัน:

- `range` เองไม่มีเมธอด `next()`
- การเรียก `range[Symbol.iterator]()` จะสร้างออบเจ็กต์ iterator ขึ้นมาอีกตัว โดยเมธอด `next()` ของ iterator จะให้ค่าทีละค่าเพื่อนำไปใช้วนซ้ำ

iterator จึงเป็นคนละออบเจ็กต์กับ `range` ที่เรากำลังวนซ้ำ

ถ้าต้องการให้โค้ดกระชับขึ้น เราก็รวมหน้าที่ทั้งสองไว้ด้วยกันได้ โดยให้ `range` เป็น iterator ของตัวเอง

โค้ดจะเป็นดังนี้:

```js run
let range = {
  from: 1,
  to: 5,

  [Symbol.iterator]() {
    this.current = this.from;
    return this;
  },

  next() {
    if (this.current <= this.to) {
      return { done: false, value: this.current++ };
    } else {
      return { done: true };
    }
  }
};

for (let num of range) {
  alert(num); // 1, แล้วก็ 2, 3, 4, 5
}
```

คราวนี้ `range[Symbol.iterator]()` คืนค่าเป็น `range` เอง ออบเจ็กต์นี้มีเมธอด `next()` และใช้ `this.current` เก็บว่าตอนนี้วนซ้ำถึงไหนแล้ว โค้ดแบบนี้สั้นลงและใช้ได้ในบางกรณี

ข้อจำกัดคือ `for..of` สองลูปที่วนผ่านออบเจ็กต์นี้พร้อมกันจะทำงานแยกจากกันไม่ได้ เพราะทั้งคู่ใช้ iterator ตัวเดียวกัน จึงใช้สถานะการวนซ้ำร่วมกันด้วย อย่างไรก็ตาม การวนผ่านออบเจ็กต์เดียวกันด้วยสองลูปพร้อมกันพบไม่บ่อยนัก แม้ในงานแบบ async

```smart header="iterator ที่ให้ค่าได้ไม่สิ้นสุด"
iterator ไม่จำเป็นต้องมีจุดสิ้นสุด เช่น ถ้ากำหนด `range.to = Infinity` ก็จะวนซ้ำต่อไปได้เรื่อย ๆ หรือเราอาจสร้าง iterable ที่ให้ลำดับตัวเลขสุ่มเทียม (pseudorandom) อย่างต่อเนื่อง ซึ่งก็มีประโยชน์ในบางงาน

ไม่มีข้อกำหนดว่า `next` ต้องให้ค่าครบแล้วจบลงเมื่อใด มันจึงคืนค่าถัดไปได้เรื่อย ๆ

ลูป `for..of` ที่วนผ่าน iterable แบบนี้จะไม่สิ้นสุดเอง แต่เราหยุดลูปด้วย `break` ได้
```


## สตริงเป็น iterable

อาร์เรย์กับสตริงเป็น iterable ที่ JavaScript เตรียมไว้ให้และเราใช้กันบ่อยที่สุด

เมื่อใช้กับสตริง `for..of` จะวนผ่านอักขระ (character) ทีละตัว:

```js run
for (let char of "test") {
  // ทำงาน 4 รอบ: หนึ่งรอบต่อหนึ่งตัวอักษร
  alert( char ); // t, แล้วก็ e, แล้วก็ s, แล้วก็ t
}
```

การวนซ้ำแบบนี้รองรับ surrogate pairs ด้วย อักขระที่เก็บเป็น surrogate pair จะไม่ถูกแยกออกจากกัน ดังตัวอย่างนี้:

```js run
let str = '𝒳😂';
for (let char of str) {
    alert( char ); // 𝒳, แล้วก็ 😂
}
```

## การเรียก iterator โดยตรง

เราลองเรียก iterator โดยตรงเพื่อดูขั้นตอนที่ `for..of` ทำให้เรา

โค้ดด้านล่างสร้าง iterator ของสตริง แล้วเรียก `next()` เพื่อดึงอักขระออกมาทีละตัว จึงวนผ่านสตริงได้แบบเดียวกับ `for..of`:

```js run
let str = "Hello";

// ทำงานเหมือนกับ
// for (let char of str) alert(char);

*!*
let iterator = str[Symbol.iterator]();
*/!*

while (true) {
  let result = iterator.next();
  if (result.done) break;
  alert(result.value); // แสดงตัวอักษรทีละตัว
}
```

โดยทั่วไปเราไม่จำเป็นต้องเรียก iterator เอง แต่วิธีนี้ช่วยให้ควบคุมการวนซ้ำได้มากกว่า `for..of` เช่น อ่านค่ามาบางส่วนแล้วพักไว้ ไปทำอย่างอื่นก่อน จากนั้นค่อยกลับมาอ่านค่าต่อ

## ความต่างระหว่าง iterable กับ array-like [#array-like]

คำว่า iterable กับ array-like อาจทำให้สับสนได้ ทั้งสองคำนี้ใช้บอกคุณสมบัติคนละอย่าง:

- *Iterable* คือออบเจ็กต์ที่มีเมธอด `Symbol.iterator` ซึ่งทำงานตามที่อธิบายไว้ข้างต้น
- *Array-like* คือออบเจ็กต์ที่มีพร็อพเพอร์ตี้เป็นดัชนี (index) และมี `length` จึงมีลักษณะคล้ายอาร์เรย์

เวลาใช้ JavaScript ในเบราว์เซอร์ (browser) หรือสภาพแวดล้อมอื่น เราอาจพบออบเจ็กต์ที่เป็น iterable เป็น array-like หรือเป็นทั้งสองอย่าง

เช่น สตริงเป็นทั้ง iterable เพราะใช้กับ `for..of` ได้ และเป็น array-like เพราะมีดัชนีแบบตัวเลขและมี `length`

แต่การเป็น iterable ไม่ได้แปลว่าจะต้องเป็น array-like ด้วย และการเป็น array-like ก็ไม่ได้แปลว่าจะต้องเป็น iterable

ตัวอย่างเช่น `range` ข้างต้นเป็น iterable แต่ไม่ใช่ array-like เพราะไม่มีพร็อพเพอร์ตี้ที่เป็นดัชนีและไม่มี `length`

ส่วนออบเจ็กต์ด้านล่างเป็น array-like แต่ไม่ใช่ iterable:

```js run
let arrayLike = { // มี index และ length => array-like
  0: "Hello",
  1: "World",
  length: 2
};

*!*
// เกิดข้อผิดพลาด (ไม่มี Symbol.iterator)
for (let item of arrayLike) {}
*/!*
```

ออบเจ็กต์ที่เป็น iterable หรือ array-like *ไม่จำเป็นต้องเป็นอาร์เรย์* จึงอาจไม่มีเมธอดของอาร์เรย์อย่าง `push` หรือ `pop` ถ้าเราอยากใช้เมธอดเหล่านี้กับข้อมูล เช่น ตัวเลขใน `range` เราสามารถแปลงข้อมูลเป็นอาร์เรย์ก่อนได้

## Array.from

เมธอด [Array.from](mdn:js/Array/from) รับค่า iterable หรือ array-like แล้วสร้างอาร์เรย์ใหม่จากค่านั้น อาร์เรย์ที่ได้มีเมธอดของอาร์เรย์ให้ใช้ตามปกติ

ตัวอย่างเช่น:

```js run
let arrayLike = {
  0: "Hello",
  1: "World",
  length: 2
};

*!*
let arr = Array.from(arrayLike); // (*)
*/!*
alert(arr.pop()); // World (เมธอดทำงานได้แล้ว)
```

ที่บรรทัด `(*)` เมธอด `Array.from` ตรวจว่าออบเจ็กต์ที่รับมาเป็น iterable หรือ array-like จากนั้นสร้างอาร์เรย์ใหม่และคัดลอกข้อมูลแต่ละรายการลงไป

เราใช้วิธีเดียวกันกับ iterable อย่าง `range` ได้:

```js run
// สมมติว่า range มาจากตัวอย่างข้างต้น
let arr = Array.from(range);
alert(arr); // 1,2,3,4,5 (การแปลง array toString ทำงานได้)
```

นอกจากนี้ `Array.from` ยังรับฟังก์ชัน (function) สำหรับแปลงค่าแต่ละรายการ โดยส่งเพิ่มเป็นอาร์กิวเมนต์ (argument) ได้ตามรูปแบบนี้:
```js
Array.from(obj[, mapFn, thisArg])
```

อาร์กิวเมนต์ที่สอง `mapFn` เป็นฟังก์ชันที่เลือกใส่หรือไม่ก็ได้ ถ้าใส่ `Array.from` จะเรียกฟังก์ชันนี้กับแต่ละรายการ แล้วนำค่าที่ฟังก์ชันคืนมาไปเพิ่มในอาร์เรย์ ส่วน `thisArg` ใช้กำหนดค่า `this` ภายในฟังก์ชันนั้น

ตัวอย่างเช่น:

```js run
// สมมติว่า range มาจากตัวอย่างข้างต้น

// ยกกำลังสองตัวเลขแต่ละตัว
let arr = Array.from(range, num => num * num);

alert(arr); // 1,4,9,16,25
```

ทีนี้ลองใช้ `Array.from` แปลงสตริงเป็นอาร์เรย์ของอักขระดูบ้าง:

```js run
let str = '𝒳😂';

// แยก str ออกเป็นอาร์เรย์ของตัวอักษร
let chars = Array.from(str);

alert(chars[0]); // 𝒳
alert(chars[1]); // 😂
alert(chars.length); // 2
```

วิธีนี้ต่างจากการใช้ `str.split` แยกสตริง เพราะ `Array.from` อ่านค่าผ่าน iterator ของสตริง จึงรองรับ surrogate pairs เช่นเดียวกับ `for..of`

ในตัวอย่างนี้ การใช้ `Array.from` ให้ผลเช่นเดียวกับการเขียนลูปเองดังนี้:

```js run
let str = '𝒳😂';

let chars = []; // Array.from ทำลูปแบบเดียวกันภายใน
for (let char of str) {
  chars.push(char);
}

alert(chars);
```

การใช้ `Array.from` จึงช่วยให้เราเขียนโค้ดส่วนนี้ได้สั้นลง

เรายังนำวิธีนี้มาสร้างฟังก์ชัน `slice` ที่ตัดส่วนหนึ่งของสตริงโดยไม่แยก surrogate pair ออกจากกันได้ด้วย:

```js run
function slice(str, start, end) {
  return Array.from(str).slice(start, end).join('');
}

let str = '𝒳😂𩷶';

alert( slice(str, 1, 3) ); // 😂𩷶

// เมธอดดั้งเดิมไม่รองรับ surrogate pairs
alert( str.slice(1, 3) ); // ขยะ (สองชิ้นจาก surrogate pairs ต่างคู่กัน)
```


## สรุป [#summary]

ออบเจ็กต์ที่ใช้กับ `for..of` ได้เรียกว่า *iterable*

- iterable ต้องมีเมธอดที่ใช้ `Symbol.iterator` เป็นชื่อ
    - การเรียก `obj[Symbol.iterator]()` ต้องคืนค่าเป็น *iterator* ซึ่งทำหน้าที่ให้ค่าสำหรับการวนซ้ำ
    - iterator ต้องมีเมธอด `next()` ที่คืนค่าเป็นออบเจ็กต์ โดย `done:true` หมายถึงการวนซ้ำสิ้นสุดแล้ว หากยังไม่สิ้นสุด `value` คือค่าถัดไป ถ้าไม่ระบุ `done` จะถือว่าเป็น `false` และถ้าไม่ระบุ `value` จะได้ค่า `undefined`
- `for..of` เรียกเมธอด `Symbol.iterator` ให้โดยอัตโนมัติ แต่เราจะเรียกเองโดยตรงก็ได้
- สตริงและอาร์เรย์มี `Symbol.iterator` อยู่แล้ว จึงเป็น iterable ในตัว
- iterator ของสตริงรองรับ surrogate pairs


ออบเจ็กต์ที่มีพร็อพเพอร์ตี้เป็นดัชนีและมี `length` เรียกว่า *array-like* ออบเจ็กต์เหล่านี้อาจมีพร็อพเพอร์ตี้และเมธอดอื่น ๆ ด้วย การเป็น array-like ไม่ได้บอกว่าต้องมีหรือไม่มีเมธอดของอาร์เรย์

เมื่ออ่านข้อกำหนดของภาษา (specification) จะเห็นว่าเมธอดของอาร์เรย์จำนวนมากทำงานกับ array-like ได้ และบางเมธอด เช่น `Array.from` ก็รับ iterable ได้ด้วย จึงใช้กับข้อมูลที่ไม่ใช่อาร์เรย์จริง ๆ ได้

`Array.from(obj[, mapFn, thisArg])` สร้างอาร์เรย์จาก `obj` ที่เป็น iterable หรือ array-like ทำให้เราใช้เมธอดของอาร์เรย์กับผลลัพธ์ได้ อาร์กิวเมนต์เสริม `mapFn` ใช้แปลงค่าแต่ละรายการ และ `thisArg` ใช้กำหนด `this` ให้กับฟังก์ชันนั้น
