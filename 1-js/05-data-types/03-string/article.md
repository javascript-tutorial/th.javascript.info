# สตริง

ใน JavaScript เราเก็บข้อมูลที่เป็นข้อความไว้ในสตริง โดยไม่มีชนิดข้อมูลแยกสำหรับอักขระตัวเดียว

รูปแบบภายในของสตริงเป็น [UTF-16](https://en.wikipedia.org/wiki/UTF-16) เสมอ ไม่ได้ขึ้นอยู่กับการเข้ารหัสของหน้าเว็บ

## เครื่องหมายคำพูด

มาทบทวนเครื่องหมายคำพูดแต่ละแบบกัน

เราเขียนสตริงโดยครอบด้วยเครื่องหมายคำพูดเดี่ยว เครื่องหมายคำพูดคู่ หรือ backticks ก็ได้:

```js
let single = 'single-quoted';
let double = "double-quoted";

let backticks = `backticks`;
```

เครื่องหมายคำพูดเดี่ยวกับคู่ทำงานเหมือนกัน ส่วน backticks แทรกนิพจน์อะไรก็ได้ลงในสตริง โดยครอบนิพจน์นั้นด้วย `${…}`:

```js run
function sum(a, b) {
  return a + b;
}

alert(`1 + 2 = ${sum(1, 2)}.`); // 1 + 2 = 3.
```

ข้อดีอีกอย่างของ backticks คือใช้เขียนสตริงหลายบรรทัดได้:

```js run
let guestList = `Guests:
 * John
 * Pete
 * Mary
`;

alert(guestList); // a list of guests, multiple lines
```

เขียนได้ตรงไปตรงมาดี แต่เครื่องหมายคำพูดเดี่ยวหรือคู่ทำแบบนี้ไม่ได้

ถ้าเขียนสตริงด้วยเครื่องหมายสองแบบนั้นแล้วขึ้นบรรทัดใหม่ตรง ๆ จะเกิด error:

```js run
let guestList = "Guests: // Error: Unexpected token ILLEGAL
  * John";
```

เครื่องหมายคำพูดเดี่ยวกับคู่มีมาตั้งแต่ยุคแรกของภาษา ตอนนั้นยังไม่ได้เผื่อการเขียนสตริงหลายบรรทัดไว้ ส่วน backticks เพิ่มเข้ามาทีหลังจึงทำอะไรได้มากกว่า

เรายังระบุ "template function" ไว้หน้า backtick ตัวแรกได้ด้วย โดยเขียนเป็น <code>func&#96;string&#96;</code> JavaScript จะเรียกฟังก์ชัน `func` อัตโนมัติ พร้อมส่งสตริงและนิพจน์ที่แทรกไว้ไปให้ประมวลผล ฟีเจอร์นี้เรียกว่า "tagged templates" แม้จะไม่ค่อยได้เจอ แต่อ่านต่อได้ใน [template literal บน MDN](mdn:/JavaScript/Reference/Template_literals#Tagged_templates)

## อักขระพิเศษ

เครื่องหมายคำพูดเดี่ยวและคู่ก็ใช้สร้างสตริงหลายบรรทัดได้ โดยใส่ "อักขระขึ้นบรรทัดใหม่" ซึ่งเขียนเป็น `\n` แทนจุดที่ต้องการขึ้นบรรทัด:

```js run
let guestList = "Guests:\n * John\n * Pete\n * Mary";

alert(guestList); // a multiline list of guests, same as above
```

ตัวอย่างที่สั้นลงสองแบบนี้ให้ผลเท่ากัน เพียงแต่เขียนคนละวิธี:

```js run
let str1 = "Hello\nWorld"; // สองบรรทัดที่ใช้ "สัญลักษณ์ขึ้นบรรทัดใหม่"

// สองบรรทัดที่ขึ้นบรรทัดตามปกติและใช้ backticks
let str2 = `Hello
World`;

alert(str1 == str2); // true
```

ยังมีอักขระพิเศษอื่นที่พบไม่บ่อยนัก:

| อักขระ | คำอธิบาย |
|-----------|-------------|
|`\n`|ขึ้นบรรทัดใหม่|
|`\r`|ไฟล์ข้อความใน Windows ใช้อักขระสองตัว `\r\n` ร่วมกันแทนการขึ้นบรรทัดใหม่ ส่วนระบบปฏิบัติการอื่นใช้เพียง `\n` ความต่างนี้มาจากเหตุผลทางประวัติศาสตร์ และซอฟต์แวร์ส่วนใหญ่บน Windows ก็เข้าใจ `\n` เช่นกัน|
|`\'`,&nbsp;`\"`,&nbsp;<code>\\`</code>|เครื่องหมายคำพูด|
|`\\`|แบ็กสแลช|
|`\t`|แท็บ|
|`\b`, `\f`, `\v`| Backspace, Form Feed, Vertical Tab -- ใส่ไว้ให้รู้ว่ามี เป็นอักขระเก่าที่ไม่ได้ใช้กันแล้ว (ลืมไปได้เลย)|

อักขระพิเศษทุกตัวขึ้นต้นด้วยแบ็กสแลช `\` ซึ่งเรียกอีกอย่างว่า "escape character"

เพราะแบ็กสแลชมีความหมายพิเศษ ถ้าต้องการให้สตริงมีอักขระ `\` จริง ๆ ต้องเขียนซ้ำสองตัว:

```js run
alert( `The backslash: \\` ); // The backslash: \
```

เครื่องหมายคำพูดที่ escape แล้วอย่าง `\'`, `\"`, <code>\\`</code> ใช้แทรกเครื่องหมายชนิดเดียวกับที่ครอบสตริงอยู่ได้

ตัวอย่างเช่น:

```js run
alert( 'I*!*\'*/!*m the Walrus!' ); // *!*I'm*/!* the Walrus!
```

เราต้องใส่แบ็กสแลชหน้าเครื่องหมายคำพูดด้านในเป็น `\'` ไม่อย่างนั้น JavaScript จะมองว่าเครื่องหมายนั้นปิดสตริงแล้ว

แน่นอนว่าต้อง escape เฉพาะเครื่องหมายคำพูดชนิดเดียวกับที่ครอบสตริงอยู่ วิธีที่อ่านง่ายกว่าคือเปลี่ยนไปใช้เครื่องหมายคำพูดคู่หรือ backticks แทน:

```js run
alert( "I'm the Walrus!" ); // I'm the Walrus!
```

นอกจากอักขระพิเศษเหล่านี้ ยังมีรูปแบบ `\u…` สำหรับรหัส Unicode ซึ่งไม่ค่อยได้ใช้และอธิบายไว้ในบทเสริมเรื่อง [Unicode](info:unicode)

## ความยาวของสตริง

พร็อพเพอร์ตี้ `length` เก็บความยาวของสตริง:

```js run
alert( `My\n`.length ); // 3
```

ตรงนี้ `\n` นับเป็น "อักขระพิเศษ" เพียงตัวเดียว ความยาวจึงเป็น `3`

```warn header="`length` เป็นพร็อพเพอร์ตี้"
คนที่เคยใช้ภาษาอื่นอาจเผลอเขียน `str.length()` แทน `str.length` ซึ่งใช้ไม่ได้

`str.length` เป็นพร็อพเพอร์ตี้ชนิดตัวเลข ไม่ใช่ฟังก์ชัน จึงไม่ต้องใส่วงเล็บ ไม่ใช่ `.length()` แต่เป็น `.length`
```

## การเข้าถึงอักขระ

ถ้าต้องการอักขระที่ตำแหน่ง `pos` ให้ใช้วงเล็บเหลี่ยม `[pos]` หรือเมธอด [str.at(pos)](mdn:js/String/at) อักขระตัวแรกอยู่ที่ตำแหน่งศูนย์:

```js run
let str = `Hello`;

// อักขระตัวแรก
alert( str[0] ); // H
alert( str.at(0) ); // H

// อักขระตัวสุดท้าย
alert( str[str.length - 1] ); // o
alert( str.at(-1) );
```

ข้อดีของ `.at(pos)` คือใช้ค่าลบได้ ถ้า `pos` เป็นลบ จะเริ่มนับจากท้ายสตริง

ดังนั้น `.at(-1)` หมายถึงอักขระตัวสุดท้าย ส่วน `.at(-2)` หมายถึงตัวก่อนสุดท้าย และไล่ต่อไปแบบนี้

วงเล็บเหลี่ยมจะคืนค่า `undefined` เสมอเมื่อตำแหน่งเป็นค่าลบ เช่น:

```js run
let str = `Hello`;

alert( str[-2] ); // undefined
alert( str.at(-2) ); // l
```

เรายังใช้ `for..of` วนผ่านอักขระทีละตัวได้:

```js run
for (let char of "Hello") {
  alert(char); // H,e,l,l,o (char จะเป็น "H" แล้วเปลี่ยนเป็น "e", "l" ไปเรื่อย ๆ)
}
```

## สตริงเปลี่ยนแปลงไม่ได้

สตริงใน JavaScript เปลี่ยนแปลงไม่ได้ เราจึงแก้อักขระในสตริงเดิมไม่ได้

ลองดูตัวอย่างที่ใช้ไม่ได้:

```js run
let str = 'Hi';

str[0] = 'h'; // error
alert( str[0] ); // ใช้ไม่ได้
```

วิธีทั่วไปคือสร้างสตริงใหม่ แล้วกำหนดกลับให้ `str` แทนค่าเดิม

ตัวอย่างเช่น:

```js run
let str = 'Hi';

str = 'h' + str[1]; // แทนที่สตริง

alert( str ); // hi
```

หัวข้อต่อ ๆ ไปจะมีตัวอย่างแบบนี้อีก

## การเปลี่ยนตัวพิมพ์

เมธอด [toLowerCase()](mdn:js/String/toLowerCase) และ [toUpperCase()](mdn:js/String/toUpperCase) ใช้เปลี่ยนตัวพิมพ์:

```js run
alert( 'Interface'.toUpperCase() ); // INTERFACE
alert( 'Interface'.toLowerCase() ); // interface
```

ถ้าต้องการเปลี่ยนเป็นตัวพิมพ์เล็กแค่อักขระเดียว ก็เขียนได้แบบนี้:

```js run
alert( 'Interface'[0].toLowerCase() ); // 'i'
```

## การค้นหาสตริงย่อย

เราค้นหาสตริงย่อยที่อยู่ในสตริงได้หลายวิธี

### str.indexOf

เมธอดแรกคือ [str.indexOf(substr, pos)](mdn:js/String/indexOf)

เมธอดนี้ค้นหา `substr` ใน `str` โดยเริ่มจากตำแหน่ง `pos` แล้วคืนตำแหน่งที่พบ ถ้าไม่พบจะคืน `-1`

ตัวอย่างเช่น:

```js run
let str = 'Widget with id';

alert( str.indexOf('Widget') ); // 0 เพราะพบ 'Widget' ที่จุดเริ่มต้น
alert( str.indexOf('widget') ); // -1 ไม่พบ เพราะแยกตัวพิมพ์เล็ก-ใหญ่

alert( str.indexOf("id") ); // 1 พบ "id" ที่ตำแหน่ง 1 (..idget with id)
```

พารามิเตอร์ตัวที่สองไม่จำเป็นต้องใส่ แต่ใช้กำหนดตำแหน่งเริ่มค้นหาได้

อย่างเช่น `"id"` ปรากฏครั้งแรกที่ตำแหน่ง `1` ถ้าจะหาครั้งถัดไป ให้เริ่มค้นจากตำแหน่ง `2`:

```js run
let str = 'Widget with id';

alert( str.indexOf('id', 2) ) // 12
```

ถ้าต้องการหาทุกตำแหน่งที่พบ ก็เรียก `indexOf` ในลูป โดยเริ่มค้นรอบใหม่จากตำแหน่งถัดจากผลลัพธ์รอบก่อน:

```js run
let str = 'As sly as a fox, as strong as an ox';

let target = 'as'; // ค้นหาคำนี้

let pos = 0;
while (true) {
  let foundPos = str.indexOf(target, pos);
  if (foundPos == -1) break;

  alert( `Found at ${foundPos}` );
  pos = foundPos + 1; // ค้นต่อจากตำแหน่งถัดไป
}
```

อัลกอริทึมเดียวกันเขียนให้สั้นลงได้:

```js run
let str = "As sly as a fox, as strong as an ox";
let target = "as";

*!*
let pos = -1;
while ((pos = str.indexOf(target, pos + 1)) != -1) {
  alert( pos );
}
*/!*
```

```smart header="`str.lastIndexOf(substr, position)`"
ยังมีเมธอดคล้ายกันคือ [str.lastIndexOf(substr, position)](mdn:js/String/lastIndexOf) ซึ่งค้นหาจากท้ายสตริงย้อนกลับไปยังจุดเริ่มต้น

ตำแหน่งที่พบจึงออกมาในลำดับย้อนกลับ
```

มีจุดที่ต้องระวังเล็กน้อยเมื่อใช้ `indexOf` เป็นเงื่อนไขของ `if` เราเอาผลลัพธ์ไปใส่ใน `if` ตรง ๆ แบบนี้ไม่ได้:

```js run
let str = "Widget with id";

if (str.indexOf("Widget")) {
    alert("We found it"); // ใช้ไม่ได้
}
```

ตัวอย่างนี้ไม่แสดง `alert` เพราะ `str.indexOf("Widget")` คืนค่า `0` ซึ่งหมายถึงพบข้อความที่ตำแหน่งเริ่มต้น แต่ `if` มอง `0` เป็น `false`

จึงต้องตรวจว่าไม่ใช่ `-1` แบบนี้:

```js run
let str = "Widget with id";

*!*
if (str.indexOf("Widget") != -1) {
*/!*
    alert("We found it"); // ใช้ได้แล้ว
}
```

### includes, startsWith, endsWith

เมธอดที่ใหม่กว่าคือ [str.includes(substr, pos)](mdn:js/String/includes) ซึ่งจะคืน `true` หรือ `false` ตามว่า `str` มี `substr` อยู่หรือไม่

เมธอดนี้เหมาะเมื่ออยากรู้แค่ว่าพบข้อความหรือไม่ โดยไม่ต้องรู้ตำแหน่ง:

```js run
alert( "Widget with id".includes("Widget") ); // true

alert( "Hello".includes("Bye") ); // false
```

อาร์กิวเมนต์ตัวที่สองของ `str.includes` ไม่จำเป็นต้องใส่ ใช้ระบุตำแหน่งที่จะเริ่มค้นหา:

```js run
alert( "Widget".includes("id") ); // true
alert( "Widget".includes("id", 3) ); // false เพราะตั้งแต่ตำแหน่ง 3 เป็นต้นไปไม่มี "id"
```

เมธอด [str.startsWith](mdn:js/String/startsWith) กับ [str.endsWith](mdn:js/String/endsWith) ทำงานตรงตามชื่อ:

```js run
alert( "*!*Wid*/!*get".startsWith("Wid") ); // true เพราะ "Widget" ขึ้นต้นด้วย "Wid"
alert( "Wid*!*get*/!*".endsWith("get") ); // true เพราะ "Widget" ลงท้ายด้วย "get"
```

## การดึงสตริงย่อย

JavaScript มี 3 เมธอดสำหรับดึงสตริงย่อย ได้แก่ `substring`, `substr` และ `slice`

`str.slice(start [, end])`
: คืนส่วนของสตริงตั้งแต่ `start` ถึงก่อน `end`

    ตัวอย่างเช่น:

    ```js run
    let str = "stringify";
    alert( str.slice(0, 5) ); // 'strin' สตริงย่อยตั้งแต่ 0 ถึงก่อน 5
    alert( str.slice(0, 1) ); // 's' ตั้งแต่ 0 ถึงก่อน 1 จึงมีแค่อักขระที่ 0
    ```

    ถ้าไม่ใส่อาร์กิวเมนต์ตัวที่สอง `slice` จะดึงไปจนถึงท้ายสตริง:

    ```js run
    let str = "st*!*ringify*/!*";
    alert( str.slice(2) ); // 'ringify' ตั้งแต่ตำแหน่ง 2 จนถึงท้ายสตริง
    ```

    `start/end` เป็นค่าลบได้ หมายถึงให้นับตำแหน่งจากท้ายสตริง:

    ```js run
    let str = "strin*!*gif*/!*y";

    // เริ่มจากตำแหน่งที่ 4 นับจากขวา จบก่อนตำแหน่งที่ 1 นับจากขวา
    alert( str.slice(-4, -1) ); // 'gif'
    ```

`str.substring(start [, end])`
: คืนส่วนของสตริงที่อยู่*ระหว่าง* `start` กับ `end` โดยไม่รวม `end`

    ทำงานเกือบเหมือน `slice` แต่ `start` มากกว่า `end` ได้ ถ้าเป็นแบบนั้น `substring` จะสลับค่าของ `start` กับ `end` ให้

    ตัวอย่างเช่น:

    ```js run
    let str = "st*!*ring*/!*ify";

    // สำหรับ substring สองบรรทัดนี้ให้ผลเหมือนกัน
    alert( str.substring(2, 6) ); // "ring"
    alert( str.substring(6, 2) ); // "ring"

    // แต่ slice ให้ผลต่างกัน:
    alert( str.slice(2, 6) ); // "ring" (เหมือนเดิม)
    alert( str.slice(6, 2) ); // "" (สตริงว่าง)

    ```

    `substring` ไม่รองรับอาร์กิวเมนต์ที่เป็นค่าลบเหมือน `slice` แต่จะมองค่าเหล่านั้นเป็น `0`

`str.substr(start [, length])`
: คืนส่วนของสตริงจาก `start` ตามจำนวน `length` ที่กำหนด

    เมธอดนี้ต่างจากสองเมธอดก่อนหน้าตรงที่ระบุ `length` แทนตำแหน่งสิ้นสุด:

    ```js run
    let str = "st*!*ring*/!*ify";
    alert( str.substr(2, 4) ); // 'ring' เริ่มจากตำแหน่ง 2 แล้วดึง 4 อักขระ
    ```

    อาร์กิวเมนต์ตัวแรกเป็นค่าลบได้ เพื่อให้นับจากท้ายสตริง:

    ```js run
    let str = "strin*!*gi*/!*fy";
    alert( str.substr(-4, 2) ); // 'gi' เริ่มจากตำแหน่งที่ 4 นับจากท้าย แล้วดึง 2 อักขระ
    ```

    เมธอดนี้อยู่ใน [Annex B](https://tc39.es/ecma262/#sec-string.prototype.substr) ของข้อกำหนดภาษา หมายความว่ามีเพียง JavaScript engine ในเบราว์เซอร์ที่ต้องรองรับ และไม่แนะนำให้ใช้ แต่ในทางปฏิบัติรองรับทุกที่

มาสรุปเมธอดเหล่านี้ให้เห็นความต่างกันชัด ๆ:

| เมธอด | เลือก... | ค่าลบ |
|--------|-----------|-----------|
| `slice(start, end)` | ตั้งแต่ `start` ถึงก่อน `end` | ใช้ค่าลบได้ |
| `substring(start, end)` | ระหว่าง `start` กับ `end` โดยไม่รวม `end` | ค่าลบจะกลายเป็น `0` |
| `substr(start, length)` | เริ่มจาก `start` แล้วดึง `length` อักขระ | `start` เป็นค่าลบได้ |

```smart header="ควรเลือกตัวไหน?"
ทั้งสามเมธอดทำงานนี้ได้ ตามข้อกำหนดแล้ว `substr` มีข้อเสียเล็กน้อย เพราะไม่ได้อยู่ในข้อกำหนดหลักของ JavaScript แต่อยู่ใน Annex B ซึ่งรวมฟีเจอร์สำหรับเบราว์เซอร์ที่มีไว้ด้วยเหตุผลทางประวัติศาสตร์ สภาพแวดล้อมที่ไม่ใช่เบราว์เซอร์จึงอาจไม่รองรับ แต่ในทางปฏิบัติเมธอดนี้ใช้ได้ทุกที่

ถ้าเทียบอีกสองเมธอด `slice` ยืดหยุ่นกว่าเล็กน้อย เพราะรับอาร์กิวเมนต์ติดลบได้และเขียนสั้นกว่า

ดังนั้นเวลาใช้งานจริง จำแค่ `slice` ก็พอ
```

## การเปรียบเทียบสตริง

จากบท <info:comparison> เรารู้แล้วว่าสตริงจะถูกเปรียบเทียบทีละอักขระตามลำดับตัวอักษร

แต่มีผลลัพธ์แปลก ๆ อยู่บ้าง

1. ตัวพิมพ์เล็กจะ "มากกว่า" ตัวพิมพ์ใหญ่เสมอ:

    ```js run
    alert( 'a' > 'Z' ); // true
    ```

2. ตัวอักษรที่มีเครื่องหมายกำกับจะเรียง "ผิดลำดับ":

    ```js run
    alert( 'Österreich' > 'Zealand' ); // true
    ```

    ถ้าเอาชื่อประเทศเหล่านี้ไปเรียง ผลลัพธ์อาจดูแปลก เพราะคนทั่วไปคาดว่า `Zealand` จะอยู่หลัง `Österreich`

ถ้าจะเข้าใจว่าเกิดอะไรขึ้น ต้องรู้ก่อนว่าสตริงใน JavaScript เข้ารหัสด้วย [UTF-16](https://en.wikipedia.org/wiki/UTF-16) นั่นคืออักขระแต่ละตัวมีรหัสตัวเลขประจำตัว

มีเมธอดสำหรับดูรหัสของอักขระและสร้างอักขระกลับจากรหัส:

`str.codePointAt(pos)`
: คืนตัวเลขฐานสิบซึ่งเป็นรหัสของอักขระที่ตำแหน่ง `pos`:

    ```js run
    // ตัวอักษรที่ต่างกันเฉพาะตัวพิมพ์มีรหัสคนละค่า
    alert( "Z".codePointAt(0) ); // 90
    alert( "z".codePointAt(0) ); // 122
    alert( "z".codePointAt(0).toString(16) ); // 7a (ถ้าต้องการค่าเลขฐานสิบหก)
    ```

`String.fromCodePoint(code)`
: สร้างอักขระจาก `code` ที่เป็นตัวเลข

    ```js run
    alert( String.fromCodePoint(90) ); // Z
    alert( String.fromCodePoint(0x5a) ); // Z (ใช้อาร์กิวเมนต์เป็นค่าเลขฐานสิบหกได้ด้วย)
    ```

ลองสร้างสตริงจากอักขระที่มีรหัส `65..220` ซึ่งครอบคลุมตัวอักษรละตินและอักขระอื่นอีกเล็กน้อย:

```js run
let str = '';

for (let i = 65; i <= 220; i++) {
  str += String.fromCodePoint(i);
}
alert( str );
// ผลลัพธ์:
// ABCDEFGHIJKLMNOPQRSTUVWXYZ[\]^_`abcdefghijklmnopqrstuvwxyz{|}~
// ¡¢£¤¥¦§¨©ª«¬­®¯°±²³´µ¶·¸¹º»¼½¾¿ÀÁÂÃÄÅÆÇÈÉÊËÌÍÎÏÐÑÒÓÔÕÖ×ØÙÚÛÜ
```

จะเห็นว่าตัวพิมพ์ใหญ่อยู่ก่อน ตามด้วยอักขระพิเศษบางตัว แล้วจึงเป็นตัวพิมพ์เล็ก ส่วน `Ö` อยู่เกือบท้ายผลลัพธ์

ทีนี้ก็เห็นชัดแล้วว่าทำไม `a > Z`

JavaScript เปรียบเทียบอักขระด้วยรหัสตัวเลข รหัสยิ่งมาก อักขระก็ยิ่ง "มาก" รหัสของ `a` คือ 97 ซึ่งมากกว่ารหัสของ `Z` ที่เป็น 90

- ตัวพิมพ์เล็กทั้งหมดอยู่หลังตัวพิมพ์ใหญ่ เพราะมีรหัสมากกว่า
- ตัวอักษรบางตัวอย่าง `Ö` ไม่ได้เรียงติดกับตัวอักษรหลัก ในตัวอย่างนี้รหัสของมันมากกว่าทุกตัวตั้งแต่ `a` ถึง `z`

### การเปรียบเทียบตามหลักภาษา [#correct-comparisons]

วิธีเปรียบเทียบสตริงให้ "ถูกต้อง" ซับซ้อนกว่าที่เห็น เพราะแต่ละภาษามีลำดับตัวอักษรไม่เหมือนกัน

เบราว์เซอร์จึงต้องรู้ว่าจะใช้ภาษาใดเปรียบเทียบ

โชคดีที่เบราว์เซอร์สมัยใหม่รองรับมาตรฐานด้านภาษาและภูมิภาค [ECMA-402](https://www.ecma-international.org/publications-and-standards/standards/ecma-402/)

มาตรฐานนี้มีเมธอดสำหรับเปรียบเทียบสตริงตามกฎของภาษาต่าง ๆ

เมื่อเรียก [str.localeCompare(str2)](mdn:js/String/localeCompare) จะได้จำนวนเต็มที่บอกว่า `str` น้อยกว่า เท่ากับ หรือมากกว่า `str2` ตามกฎของภาษานั้น:

- คืนจำนวนลบ ถ้า `str` น้อยกว่า `str2`
- คืนจำนวนบวก ถ้า `str` มากกว่า `str2`
- คืน `0` ถ้าทั้งสองค่าเทียบเท่ากัน

ตัวอย่างเช่น:

```js run
alert( 'Österreich'.localeCompare('Zealand') ); // -1
```

เมธอดนี้รับอาร์กิวเมนต์เพิ่มได้อีกสองตัวตาม[เอกสาร MDN เรื่อง localeCompare](mdn:js/String/localeCompare) ตัวแรกใช้ระบุภาษา ถ้าไม่ใส่จะใช้ภาษาจากสภาพแวดล้อม ส่วนตัวที่สองใช้ตั้งกฎเพิ่มเติม เช่น จะแยกตัวพิมพ์เล็ก-ใหญ่หรือจะมอง `"a"` กับ `"á"` เป็นตัวเดียวกันหรือไม่

## สรุป

- เครื่องหมายคำพูดมี 3 แบบ โดย backticks ใช้เขียนสตริงหลายบรรทัดและแทรกนิพจน์ `${…}` ได้
- ใช้อักขระพิเศษอย่าง `\n` เพื่อขึ้นบรรทัดใหม่ได้
- ถ้าต้องการอักขระหนึ่งตัว ให้ใช้ `[]` หรือเมธอด `at`
- ถ้าต้องการสตริงย่อย ให้ใช้ `slice` หรือ `substring`
- ถ้าต้องการเปลี่ยนสตริงเป็นตัวพิมพ์เล็กหรือใหญ่ ให้ใช้ `toLowerCase/toUpperCase`
- ถ้าต้องการค้นหาสตริงย่อย ให้ใช้ `indexOf` หรือใช้ `includes/startsWith/endsWith` สำหรับการตรวจแบบง่าย ๆ
- ถ้าต้องการเปรียบเทียบสตริงตามกฎของภาษา ให้ใช้ `localeCompare` ส่วนการเปรียบเทียบแบบอื่นจะอิงรหัสอักขระ

สตริงยังมีเมธอดที่มีประโยชน์อีกหลายตัว:

- `str.trim()` -- ตัดช่องว่างออกจากต้นและท้ายสตริง
- `str.repeat(n)` -- ทำสตริงซ้ำ `n` ครั้ง
- ...รวมถึงเมธอดอื่นที่ดูต่อได้ใน[คู่มือ String บน MDN](mdn:js/String)

สตริงยังมีเมธอดสำหรับค้นหาและแทนที่ด้วย regular expression แต่เรื่องนี้มีรายละเอียดเยอะ จึงแยกอธิบายไว้ในบท <info:regular-expressions>

อีกเรื่องสำคัญคือสตริงใช้ Unicode เป็นพื้นฐาน จึงมีข้อควรระวังเวลาเปรียบเทียบ อ่านต่อได้ในบท <info:unicode>
