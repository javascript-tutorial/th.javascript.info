# บทนำสู่ JavaScript

JavaScript มีอะไรพิเศษ? ทำอะไรได้บ้าง? แล้วใช้คู่กับเทคโนโลยีอะไรดี? มาดูกัน

## JavaScript คืออะไร?

*JavaScript* เกิดมาเพื่อ "ทำให้เว็บเพจมีชีวิต"

โปรแกรมที่เขียนด้วยภาษานี้เรียกว่า *สคริปต์* — แทรกลงใน HTML ของเว็บเพจได้เลย แล้วพอเพจโหลดขึ้นมา สคริปต์ก็รันอัตโนมัติ

เขียนเป็นข้อความธรรมดา ไม่ต้องคอมไพล์ก่อน

ตรงนี้ JavaScript ต่างจาก [Java](https://en.wikipedia.org/wiki/Java_(programming_language)) ชัดเจนเลย

```smart header="ทำไมถึงมีชื่อว่า <u>Java</u>Script?"
ตอนแรก JavaScript ชื่อ "LiveScript" แต่ยุคนั้น Java กำลังฮิตมาก เลยเปลี่ยนชื่อให้ดูเหมือน "น้องชาย" ของ Java จะได้เป็นที่สนใจ

แต่พอพัฒนาไปเรื่อยๆ JavaScript ก็กลายเป็นภาษาที่แยกออกมาเลย มีมาตรฐานของตัวเองชื่อ [ECMAScript](http://en.wikipedia.org/wiki/ECMAScript) — ตอนนี้ไม่เกี่ยวกับ Java เลยแม้แต่นิด
```

ทุกวันนี้ JavaScript ไม่ได้อยู่แค่ในเบราว์เซอร์แล้ว — รันบนเซิร์ฟเวอร์หรืออุปกรณ์ไหนก็ได้ ขอแค่มีโปรแกรมที่เรียกว่า [JavaScript engine](https://en.wikipedia.org/wiki/JavaScript_engine)

เบราว์เซอร์แต่ละตัวก็มี engine ฝังมาด้วย บางทีเรียกว่า "JavaScript virtual machine"

แต่ละ engine มีชื่อเรียก (codename) ต่างกัน เช่น:

- [V8](https://en.wikipedia.org/wiki/V8_(JavaScript_engine)) -- ใน Chrome, Opera และ Edge
- [SpiderMonkey](https://en.wikipedia.org/wiki/SpiderMonkey) -- ใน Firefox
- ...มีชื่อเรียกอื่นๆ อีก เช่น "Chakra" ใน IE, "JavaScriptCore", "Nitro" และ "SquirrelFish" ใน Safari เป็นต้น

จำชื่อพวกนี้ไว้ เพราะเจอบ่อยในบทความของ dev ทั่วไป เราก็จะใช้เหมือนกัน เช่น ถ้าเห็นว่า "ฟีเจอร์ X รองรับบน V8" ก็แปลว่าน่าจะใช้ได้ใน Chrome, Opera และ Edge

```smart header="engine ทำงานยังไง?"

Engine ข้างในซับซ้อนอยู่ แต่หลักการง่ายมาก

1. Engine (ที่ฝังมากับเบราว์เซอร์) อ่าน ("parse") สคริปต์
2. แปลง ("compile") สคริปต์ให้เป็นภาษาเครื่อง
3. แล้วก็รันโค้ดภาษาเครื่อง — เร็วมา���

Engine ยัง optimize ทุกขั้นตอนด้วย — ติดตามสคริปต์ที่คอมไพล์แล้ว วิเคราะห์ข้อมูลที่ไหลผ่าน แล้วปรับแต่งโค้ดภาษาเครื่องให้เร็วขึ้นไปอีก
```

## JavaScript ในเบราว์เซอร์ทำอะไรได้บ้าง?

JavaScript สมัยใหม่เป็นภาษา "ปลอดภัย" — เข้าถึง memory หรือ CPU ระดับล่างตรงๆ ไม่ได้ เพราะออกแบบมาให้ใช้ในเบราว์เซอร์ที่ไม่ต้องการแบบนั้น

ทำอะไรได้แค่ไหน ขึ้นอยู่กับว่ารันที่ไหน เช่น [Node.js](https://wikipedia.org/wiki/Node.js) ก็เปิดให้ JavaScript อ่าน/เขียนไฟล์ ส่ง request ผ่านเน็ตเวิร์ค และอื่นๆ อีกเพียบ

ส่วนในเบราว์เซอร์ก็ทำได้ทุกอย่างที่เกี่ยวกับเว็บเพจ — จัดการหน้า โต้ตอบกับผู้ใช้ คุยกับเซิร์ฟเวอร์

เช่น JavaScript ในเบราว์เซอร์ทำพวกนี้ได้:

- เพิ่ม HTML ใหม่ลงหน้าเว็บ เปลี่ยนเนื้อหา แก้ style ได้
- ตอบสนองเมื่อผู้ใช้คลิกเมาส์ เลื่อนเคอร์เซอร์ หรือกดปุ่ม
- ส่ง request ไปเซิร์ฟเวอร์ผ่านเน็ตเวิร์ค ดาวน์โหลด/อัปโหลดไฟล์ (ที่เรียกว่า [AJAX](https://en.wikipedia.org/wiki/Ajax_(programming)) กับ [COMET](https://en.wikipedia.org/wiki/Comet_(programming)))
- รับ/ตั้งค่าคุกกี้ ถามคำถามผู้ใช้ แสดงข้อความ
- เก็บข้อมูลฝั่ง client ("local storage")

## JavaScript ในเบราว์เซอร์ทำอะไรไม่ได้บ้าง? 

JavaScript ในเบราว์เซอร์ทำได้ไม่ทุกอย่างนะ — มีข้อจำกัดไว้เพื่อความปลอดภัยของผู้ใช้ ไม่ให้หน้าเว็บร้ายๆ แอบเข้าถึงข้อมูลส่วนตัว

ข้อจำกัดมีอะไรบ้าง?

- JavaScript ในหน้าเว็บอ่าน/เขียน/ก๊อปไฟล์ในฮาร์ดดิสก์ไม่ได้ เรียกโปรแกรมอื่นก็ไม่ได้ เข้าถึงฟังก์ชันของ OS ตรงๆ ไม่ได้เลย

    เบราว์เซอร์รุ่นใหม่ยอมให้ทำงานกับไฟล์ได้บ้าง แต่จำกัดมาก — ต้องให้ผู้ใช้ทำเองก่อน เช่น "ลาก" ไฟล์มาวางในหน้าเว็บ หรือเลือกผ่านแท็ก `<input>`

    ใช้กล้อง ไมโครโฟน อุปกรณ์อื่นๆ ก็ได้ แต่ต้องขอ permission ชัดเจนทุกครั้ง เลยไม่มีทางที่หน้าเว็บจะแอบเปิดเว็บแคมดูแล้วส่งข้อมูลไป [NSA](https://en.wikipedia.org/wiki/National_Security_Agency) ได้
- แท็บ/วินโดว์ต่างๆ ปกติไม่รู้จักกัน บางทีก็ทำได้ เช่น ตอนที่หน้าต่างนึงใช้ JavaScript เปิดอีกหน้า แต่ถึงอย่างนั้น JavaScript จากหน้านึงก็เข้าถึงอีกหน้าไม่ได้ ถ้า URL มาจากคนละโดเมน โปรโตคอล หรือพอร์ต — เรียกว่า "Same Origin Policy"

    ถ้าจะแลกข้อมูลระหว่างหน้าเว็บ *ทั้งสองฝ่ายต้องตกลงกันก่อน* แล้วก็ต้องมีโค้ด JavaScript พิเศษจัดการให้ ซึ่งจะพูดถึงในบทหลังๆ

    ก็เพื่อความปลอดภัยอีกนั่นแหละ ลองนึกดูว่าจะเป็นยังไงถ้า `http://anysite.com` ที่เปิดอยู่ในแท็บนึงแอบเข้าถึง `http://gmail.com` ในอีกแท็บแล้วขโมยข้อมูลออกไป
- JavaScript คุยกับเซิร์ฟเวอร์ต้นทางของหน้านั้นได้สบาย แต่ถ้าจะดึงข้อมูลจากโดเมนอื่น จำกัดเข้มงวดมาก — ต้องได้รับ OK จากเซิร์ฟเวอร์ปลายทาง (ผ่าน HTTP header) ก่อน ก็เป็นเรื่องความปลอดภัยอีกเช่นกัน

ข้อจำกัดพวกนี้หมดไปเลยถ้า JavaScript รันนอกเบราว์เซอร์ เช่นบนเซิร์ฟเวอร์ แถมเบราว์เซอร์สมัยใหม่ก็ยอมให้ปลั๊กอิน/ส่วนขยายขอสิทธิ์เพิ่มเติมได้ด้วย

## อะไรทำให้ JavaScript โดดเด่น?

JavaScript มีอย่างน้อย *3 จุดเด่น*:

```compare
+ ผสานเข้ากับ HTML/CSS ได้อย่างลงตัว
+ เรื่องง่ายๆ ก็เขียนง่าย
+ รองรับโดยเบราว์เซอร์หลักทั้งหมด และเปิดใช้งานเป็นค่าเริ่มต้น
```

JavaScript เป็นภาษาเดียวในเบราว์เซอร์ที่รวม 3 อย่างนี้ไว้ด้วยกัน

เลยกลายเป็นเครื่องมือยอดนิยมที่สุดสำหรับสร้าง UI บนเบราว์เซอร์

แถมยังเอาไปสร้างเซิร์ฟเวอร์ แอปมือถือ และอื่นๆ ได้อีกด้วย

## ภาษาที่ "transpile" เป็น JavaScript

syntax ของ JavaScript อาจไม่ถูกใจทุกคน แต่ละคนก็อยากได้ฟีเจอร์ไม่เหมือนกัน — เรื่องปกติ เพราะโปรเจกต์แต่ละอันก็ต่างกัน

เลยมีภาษาใหม่ๆ เกิดขึ้นมาเยอะ — พวกนี้จะ *transpile* (แปลง) เป็น JavaScript ก่อนรันในเบราว์เซอร์

เครื่องมือสมัยใหม่ทำให้ขั้นตอน transpile เร็วมากจนแทบไม่รู้สึก เขียนภาษาอื่นแล้วแปลงเป็น JavaScript ให้เบื้องหลังอัตโนมัติเลย

ตัวอย่างเช่น:

- [CoffeeScript](https://coffeescript.org/) เป็นน้ำตาลทางไวยากรณ์ (syntactic sugar) สำหรับ JavaScript — syntax สั้นกว่า เขียนโค้ดได้กระชับขึ้น dev ที่มาจาก Ruby ชอบมาก
- [TypeScript](https://www.typescriptlang.org/) เน้นเพิ่ม "strict data typing" ทำให้พัฒนาและดูแลระบบซับซ้อนง่ายขึ้น โดย Microsoft
- [Flow](https://flow.org/) เพิ่ม data typing เหมือนกัน แต่คนละแนว โดย Facebook
- [Dart](https://www.dartlang.org/) เป็นภาษาแยกต่างหาก มี engine ของตัวเอง รันนอกเบราว์เซอร์ได้ (เช่น แอปมือถือ) แล้วก็ transpile เป็น JavaScript ได้ด้วย โดย Google
- [Brython](https://brython.info/) แปลง Python เป็น JavaScript — เขียนแอปด้วย Python ล้วนๆ ไม่ต้องแตะ JavaScript เลย
- [Kotlin](https://kotlinlang.org/docs/reference/js-overview.html) ภาษาสมัยใหม่ กระชับ ปลอดภัย ใช้กับเบราว์เซอร์หรือ Node ก็ได้

ยังมีอีกเยอะ แต่ถึงจะใช้ภาษาพวกนี้ ก็ยังต้องรู้ JavaScript อยู่ดี — เพราะสุดท้ายมันก็แปลงเป็น JavaScript ถ้าไม่เข้าใจพื้นฐานก็จะไม่รู้ว่าเกิดอะไรขึ้นจริงๆ

## สรุป

- JavaScript เกิดมาเพื่อเบราว์เซอร์ แต่ตอนนี้ใช้ได้ทุกที่แล้ว
- เป็นภาษาเบราว์เซอร์ที่คนใช้มากที่สุด ทำงานร่วมกับ HTML/CSS ได้ลงตัว
- มีหลายภาษาที่ transpile เป็น JavaScript ได้ ลองดูคร่าวๆ หลังจากรู้ JavaScript ดีแล้ว
